先读 `AGENTS.md`、`docs/08-单据状态机规范.md`、`docs/04-数据库规范.md` §7.3、`docs/05-接口设计规范.md`、`docs/09-领域术语与编码规则.md` §2.1、`docs/07-认证与权限规范.md` §2.2，并找 `docs/modules/` 里**最相似的现有单据**照抄结构。

需求：$ARGUMENTS

请输出设计（不写代码）：

1. 单据表与行表结构（沿用 `doc_no/status/doc_date/workshop_id/approved_*` 公共结构 + 行表 `line_no` 唯一）。
2. 状态迁移表：动作 / 起始 / 目标 / 权限点 / 前置校验 / **副作用**。
3. **审核与反审核的副作用逐条成对列出**（审核做什么，反审核就反向做什么，漏一条就数据错）。
4. 需要的权限点清单（对照 `docs/07` §2.2；表里没有的写进"需新增权限点"清单，不要直接用）。
5. 需要的错误码清单（对照 `docs/05` §4；没有的写进"建议新增错误码"清单）。
6. 需要的单据号前缀（对照 `docs/09` §2.1，必须不重复）。
7. 索引与对应的真实查询场景。
8. 测试清单（含"审核→反审核 数据完全还原"）。
9. 待决问题。

需要改规范的话，明确列出"要改哪篇哪一节、改成什么"，等确认后再改文档。
