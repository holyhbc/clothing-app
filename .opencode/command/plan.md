先读 `AGENTS.md` §6、`docs/02-AI开发流水线规范.md` §2.3、`docs/templates/任务卡模板.md`、`docs/10-测试规范.md`。

设计稿：$ARGUMENTS

请执行：

1. 按固定顺序拆任务：**迁移 → 模型/Schema → Repository → Service → Router → 前端 shared 类型 → 前端页面/组件 → 测试 → 文档同步**。
2. 每个任务卡必须：
   - ≤ 1 天、≤ 8 个改动文件
   - 有**可自动化验证**的验收标准（优先给具体命令）
   - 列出"将要改动的文件"
   - 标注 `depends_on` 与被依赖关系
3. 标出哪些任务被 🔴 待决问题阻塞（状态置 `blocked`，并写清阻塞原因）。
4. 识别哪些任务可并行（不同模块、不改同一片代码），哪些必须串行。
5. 每张卡末尾给出闸门 1-5 的执行命令。
6. 输出到 `docs/tasks/`。
7. 最后给出：任务总数、串行关键路径工期、里程碑（P0/P1/P2 分组）。

禁止：
- 拆出"实现整个模块"这种大卡
- 验收标准写成"功能正常"这种不可验证的表述
