# 03 代码规范

> 后端 Python + 前端 TypeScript 的强制约定。**与 ruff / mypy / eslint 配置冲突时，以本文为准并同步修正配置**。

---

## 1. 后端 Python

### 1.1 强制规则

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 全量类型标注 | 所有函数签名有类型；mypy `strict = true` |
| 2 | 全异步 | `async def` / `await`；同步库（`bcrypt`、`reportlab`）必须 `run_in_threadpool` |
| 3 | 不用裸 `dict` | 内部结构用 `TypedDict` / Pydantic Model / `dataclass` |
| 4 | 异常分层 | 抛 `app.core.errors.BusinessError`，**禁止裸 `raise Exception`** |
| 5 | 事务边界唯一 | `async with session.begin():` 只在 service 层方法第一行 |
| 6 | 不在 Router 里查库 | Router 只允许调 service；列表查询也必须经 service（保证数据范围过滤不被绕过） |
| 7 | 枚举集中 | 所有状态/类型枚举在 `app/common/enums.py`，**禁止散落 `Literal` 或魔法字符串** |
| 8 | 金额用 `Decimal` | 禁止 `float`；DB 用 `Numeric(18,4)` |
| 9 | 时间带时区 | 存 `timestamptz`；Python 侧一律 `datetime` 带 tzinfo，禁 `datetime.utcnow()` |
| 10 | 日志用结构化 | `logger.info("piecework_counted", extra={"bundle_no": ...})`，禁止 `print` |

### 1.2 命名

| 对象 | 规范 | 例 |
| --- | --- | --- |
| 模块 / 文件 | `snake_case` | `piecework_service.py` |
| 类 | `PascalCase` | `PieceworkService` |
| 函数 / 变量 | `snake_case` | `create_piecework_log` |
| 常量 | `UPPER_SNAKE` | `DEFAULT_PAGE_SIZE` |
| 私有 | 前缀 `_` | `_calc_amount` |
| Pydantic 模型 | `<资源><In|Out|Patch>` | `PieceworkLogCreate` / `PieceworkLogOut` |
| 测试文件 | `test_<模块>.py` | `test_piecework.py` |
| 数据库迁移 | `NNNN_<slug>.py` | `0031_add_piecework_logs.py` |

**禁止**：缩写到不可读（`qty_ok` 可以，`q` 不行）；`data` / `info` 作为变量名（用领域名词）。

### 1.3 模块内文件职责（逻辑分层固定 5 层；单文件超 400 行时按职责拆为包）

**逻辑分层固定为 5 个职责**（依赖方向 `models → schemas → repository → service → router`，禁止反向 import）：

```python
# models.py       SQLAlchemy 模型，仅字段与约束，无逻辑
# schemas.py      Pydantic 输入输出，含校验规则
# repository.py   查询方法，只读为主，不含业务判断
# service.py      业务逻辑 + 事务边界 + 状态机迁移  ← 核心
# router.py       HTTP 接口，仅声明依赖、校验、调用 service、包装响应
```

**物理文件数不再固定为 5**（[ADR-0031](./adr/0031-模块文件结构按职责拆分.md)）：单层 ≤400 行保持单文件；某层超过 400 行（[ADR-0030](./adr/0030-提交体量上限放宽到1200行.md) 硬线）时，该层改为**包**（目录 + `__init__.py`），按主题 / 域拆成多个文件，包内每个文件仍 ≤400 行：

```
base/
├── models/            # 包：__init__.py 重导出，按域拆 org/dict/style/rate/material/stock
│   ├── __init__.py
│   └── ...
├── schemas/           # 包
│   ├── __init__.py
│   └── ...
├── repository.py      # 未越线，保持单文件
├── service/           # 包
│   ├── __init__.py
│   └── ...
└── router/            # 包（__init__.py 必须导出名为 router 的单个 APIRouter）
    ├── __init__.py
    └── ...
```

包必须用 `__init__.py` **重导出该层原有公开名**，使 `from app.modules.<模块>.<层> import X` 零改动；`__init__.py` 只做聚合与重导出，**不放业务逻辑**。base 模块已按此结构落地并验证（旧导入路径零改动、OpenAPI 零 diff）。

### 1.4 Service 正例（这是 AI 产出代码的模板）

```python
from decimal import Decimal
from uuid import UUID

from sqlalchemy import select
from sqlalchemy.ext.asyncio import AsyncSession

from app.common.enums import PieceworkSource
from app.core.errors import BusinessError, ErrorCode
from app.modules.piecework.models import PieceworkLog
from app.modules.piecework.schemas import PieceworkCountIn


class PieceworkService:
    """计件服务。事务边界唯一入口。"""

    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    async def count_piecework(self, payload: PieceworkCountIn, operator_id: UUID) -> PieceworkLog:
        """记录一次计件。幂等：同 bundle+工序+员工+日期 只记一次。"""
        async with self.session.begin():
            bundle = await self._get_bundle_for_update(payload.bundle_no)
            self._assert_bindable(bundle, payload)

            existing = await self.session.scalar(
                select(PieceworkLog).where(
                    PieceworkLog.bundle_no == payload.bundle_no,
                    PieceworkLog.operation_no == payload.operation_no,
                    PieceworkLog.employee_id == payload.employee_id,
                    PieceworkLog.work_date == payload.work_date,
                    PieceworkLog.log_type == PieceworkSource.SCAN,
                    PieceworkLog.deleted_at.is_(None),
                )
            )
            if existing is not None:
                return existing  # 幂等：重复扫码返回既有记录，不报错

            unit_price = await self._resolve_rate(payload.style_no, payload.operation_no)
            log = PieceworkLog(
                bundle_no=payload.bundle_no,
                style_no=payload.style_no,
                operation_no=payload.operation_no,
                employee_id=payload.employee_id,
                work_date=payload.work_date,
                qty=Decimal("1"),
                unit_price=unit_price,  # INV-3 单价快照
                amount=unit_price,
                log_type=PieceworkSource.SCAN,
                created_by=operator_id,
                updated_by=operator_id,
            )
            self.session.add(log)
            await self.session.flush()
        return log

    async def _get_bundle_for_update(self, bundle_no: str) -> Bundle:
        bundle = await self.session.scalar(
            select(Bundle).where(Bundle.bundle_no == bundle_no).with_for_update()
        )
        if bundle is None:
            raise BusinessError(ErrorCode.BUNDLE_NOT_FOUND, f"打菲号 {bundle_no} 不存在")
        return bundle

    @staticmethod
    def _assert_bindable(bundle: Bundle, payload: PieceworkCountIn) -> None:
        if bundle.style_no != payload.style_no or bundle.operation_no != payload.operation_no:
            raise BusinessError(ErrorCode.BUNDLE_MISMATCH, "款号或工序与打菲号不符")
```

**要点**：`_` 前缀私有方法不自行开事务；校验失败抛 `BusinessError`；事务内只用 `flush`，`commit` 由 unit-of-work 完成。

### 1.5 Service 反例（AI 常犯，务必避免）


## 2. 前端 TypeScript

### 2.1 强制规则

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | `strict: true` + `noUncheckedIndexedAccess` | 禁止 `any`；未知类型用 `unknown` + 收窄 |
| 2 | 全部 SFC 用 `<script setup lang="ts">` | 禁止 Options API |
| 3 | 类型只放 `packages/shared` | 页面不重复定义接口类型；接口类型从 openapi 生成 |
| 4 | 状态：本地 `ref`，跨页 `store`，服务端 `composables` + 查询库 | 禁止把服务端数据塞进 store |
| 5 | 所有请求走 `api/` 层封装 | 禁止页面里直接 `axios.get` |
| 6 | 金额展示统一 `formatMoney` | 禁止手写 `toFixed` |
| 7 | 日期展示统一 `formatDateTime` | 后端统一传 ISO8601 带时区 |
| 8 | 权限控制双层 | `v-can` 指令控制显隐 + 后端 403 兜底；**前端隐藏不是安全** |
| 9 | 扫码枪输入统一走 `useScanner` | 禁止各页面自己监听键盘 |
| 10 | 无 console 残留 | 提交前 lint 拦截 |

### 2.2 命名与目录

| 对象 | 规范 | 例 |
| --- | --- | --- |
| 组件文件 | `PascalCase.vue` | `PieceworkLogTable.vue` |
| composable | `useXxx.ts` | `useScanner.ts` |
| API 模块 | 小写资源名复数 | `piecework.ts` |
| Pinia store | `useXxxStore` | `useAuthStore` |
| 事件名 | `kebab-case` | `@row-selected` |
| CSS | 禁止组件内写大段样式 | 抽到 `styles/` 或用 SCSS 变量；统一用 design token（见 06） |

### 2.4 扫码枪 composable（PC 工位机，工厂关键路径）

```ts
// frontend/packages/admin/src/composables/useScanner.ts
import { onBeforeUnmount, onMounted, ref } from 'vue'

const BUFFER_MAX = 128
const IDLE_RESET_MS = 120 // 扫码枪连续字符间隔极短，人手输入会超时

export interface UseScannerOptions {
  onScan: (code: string) => void | Promise<void>
  onError?: (reason: 'empty' | 'too-long') => void
}

/**
 * 扫码枪 = USB 键盘 HID。全局 keydown 累积字符，遇 Enter 触发。
 * 不依赖焦点，避免"点了别的输入框就扫不出来"。
 */
export function useScanner(options: UseScannerOptions) {
  const buffer = ref('')
  const scanning = ref(false)
  let idleTimer: number | undefined

  function reset(): void {
    buffer.value = ''
    window.clearTimeout(idleTimer)
  }

  function handleKeydown(event: KeyboardEvent): void {
    if (event.ctrlKey || event.altKey || event.metaKey) return

    if (event.key === 'Enter') {
      if (buffer.value.length === 0) return
      const code = buffer.value
      reset()
      void options.onScan(code)
      return
    }

    if (event.key.length !== 1) return
    if (buffer.value.length >= BUFFER_MAX) {
      options.onError?.('too-long')
      reset()
      return
    }

    buffer.value += event.key
    scanning.value = true
    window.clearTimeout(idleTimer)
    idleTimer = window.setTimeout(reset, IDLE_RESET_MS)
  }

  onMounted(() => window.addEventListener('keydown', handleKeydown, true))
  onBeforeUnmount(() => {
    window.removeEventListener('keydown', handleKeydown, true)
    reset()
  })

  return { buffer, scanning }
}
```

## 3. Git 与提交

### 3.1 分支

| 分支 | 用途 | 合并到 |
| --- | --- | --- |
| `main` | 随时可发布 | — |
| `develop` | 集成分支 | `main` |
| `feature/<模块>-<短描述>` | 任务卡实现 | `develop` |
| `hotfix/<短描述>` | 线上紧急修复 | `main` + 回 merge `develop` |

### 3.2 提交信息

```
feat(piecework): 员工扫码计件接口与幂等处理

打菲二维码生成后，工位机扫码枪存在网络抖动与重复触发，
需要以 bundle_no+工序+员工+日期 为幂等键返回既有记录，
避免并发下重复计件导致工资虚高。
Refs: docs/modules/04-计件.md §3
Closes: T-PW-002
```

**禁止**：标题 > 72 字符；`update` / `fix bug` / `修改`；一次提交混多个模块（拆开）。

## 4. 禁止事项速查

| 禁止 | 正确做法 |
| --- | --- |
| `print` / `console.log` 提交进仓库 | 结构化 logger / 调试后删除 |
| `commit -am` 带上无关文件 | `git add` 指定文件，提交前 `git status` 复核 |
| `.env` 进仓库 | `.env.example` 进仓库，`.env` 加 `.gitignore` |
| 注释掉的死代码 | 直接删；需要保留的写 `# TODO(任务号): 说明` |
| 魔法数字 | 命名常量或走基础资料表 |
| 一行超长不折行 | 100 字符，ruff format 自动处理 |
| 跳过测试 | 测试是验收项，跳过等于未完成 |
