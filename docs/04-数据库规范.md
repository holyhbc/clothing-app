# 04 数据库规范

> PostgreSQL 16。所有表必须遵守 §2 公共字段、所有金额遵守 §4、所有删除遵守 §6。

---

## 1. 通用约定

| 项 | 约定 |
| --- | --- |
| 数据库名 | `garment_erp` |
| Schema | 统一 `public`，不跨 schema（模块多但库单，跨 schema 反而增加运维复杂度） |
| 表名 | `snake_case` **复数**（`piecework_logs`、`stock_ledgers`、`customers`） |
| 主键 | `uuid`，`gen_random_uuid()`，类型 `uuid` |
| 外键 | **必须**建外键，命名 `fk_<子表>_<父表>`；禁止裸 id 无约束 |
| 索引 | 命名 `idx_<表>_<列>`（唯一索引 `uq_<表>_<列>`） |
| 唯一约束 | 业务唯一性用**唯一索引**而非 CHECK，便于并发可靠拦截 |
| 时间 | `timestamptz`，默认 `now()` |
| 时区 | 服务端与应用统一 `Asia/Shanghai`，库里存 UTC |
| 布尔 | 命名 `is_xxx` |
| 文本 | 中文长文本 `text`；枚举值 `varchar(32)` + PG enum |
| 软删过滤 | 列表查询默认加 `.where(Model.deleted_at.is_(None))`，**不许忘** |

## 2. 公共字段（所有业务表强制）

```sql
id              uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
created_at      timestamptz NOT NULL DEFAULT now(),
created_by      uuid        NOT NULL,
updated_at      timestamptz NOT NULL DEFAULT now(),
updated_by      uuid        NOT NULL,
deleted_at      timestamptz,                       -- NULL 表示未删除；软删只写这个
version         integer     NOT NULL DEFAULT 1,    -- 乐观锁，UPDATE 时 +1
remark          text,                              -- 备注，长度不设限
CONSTRAINT ck_<table>_version_positive CHECK (version > 0)
```

对应模型（`app/common/models.py`）：

```python
from datetime import datetime
from uuid import UUID

from sqlalchemy import DateTime, Integer, text
from sqlalchemy.dialects.postgresql import UUID as PgUUID
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class AuditMixin:
    created_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=text("now()"), nullable=False
    )
    created_by: Mapped[UUID] = mapped_column(PgUUID(as_uuid=True), nullable=False)
    updated_at: Mapped[datetime] = mapped_column(
        DateTime(timezone=True), server_default=text("now()"), onupdate=text("now()"), nullable=False
    )
    updated_by: Mapped[UUID] = mapped_column(PgUUID(as_uuid=True), nullable=False)
    remark: Mapped[str | None] = mapped_column(nullable=True)


class SoftDeleteMixin:
    deleted_at: Mapped[datetime | None] = mapped_column(DateTime(timezone=True), nullable=True)


class VersionMixin:
    version: Mapped[int] = mapped_column(Integer, nullable=False, default=1, server_default="1")
```

**乐观锁用法**（service 层统一入口，Router/Repository 不得手写）：

```python
stmt = (
    update(Document)
    .where(Document.id == doc_id, Document.version == expected_version)
    .values(status=new_status, version=Document.version + 1, updated_by=operator_id)
)
result = await session.execute(stmt)
if result.rowcount == 0:
    raise BusinessError(ErrorCode.OPTIMISTIC_LOCK_CONFLICT, "数据已被他人修改，请刷新重试")
```

## 3. 枚举规范

所有枚举集中在 `app/common/enums.py`，用 PG 原生 enum，**只能追加值，不能改值**。

```python
from enum import StrEnum


class DocumentStatus(StrEnum):
    DRAFT = "DRAFT"
    SUBMITTED = "SUBMITTED"
    APPROVED = "APPROVED"
    REJECTED = "REJECTED"
    CANCELLED = "CANCELLED"
```

```python
# models.py
from sqlalchemy.dialects.postgresql import ENUM
from app.common.enums import DocumentStatus

status: Mapped[DocumentStatus] = mapped_column(
    ENUM(DocumentStatus, name="document_status", native_enum=True, validate_strings=True),
    nullable=False, server_default=DocumentStatus.DRAFT.value,
)
```

**加枚举值**：新增 Alembic 迁移 + `ALTER TYPE ... ADD VALUE`。禁止改已有值含义——要改就新建枚举 + 双写迁移（写 ADR 说明）。

禁止：`VARCHAR` 存状态 + 应用层手校验（会漏）。

## 4. 金额、数量、比例

| 类型 | 数据库 | Python | 说明 |
| --- | --- | --- | --- |
| 金额 | `numeric(18,4)` | `Decimal` | **禁止 float** |
| 单价 | `numeric(12,6)` | `Decimal` | 工价有小数位（0.35 元/件） |
| 数量 | `numeric(14,3)` | `Decimal` | 面料米数、重量需要小数 |
| 整数件/扎数 | `integer` | `int` | 计件件数、工序序号 |
| 百分比 | `numeric(6,4)` | `Decimal` | 损耗率、税率（存 5.2500 表示 5.25%） |
| 汇率 | `numeric(18,8)` | `Decimal` | 预留 |

校验：`numeric(18,4)` 加 `CHECK (amount >= 0)`。
**REV-2026-10 例外**：append-only 流水类表（`piecework_logs`、`stock_ledgers`、`voucher_entries` 的红字行）
允许负值，因为它们用符号表达冲销，而不是用金额字段存负的"单据金额"。两者不要混用。

## 5. 索引规范

| 场景 | 索引要求 |
| --- | --- |
| 单据号、款号、工号 | 唯一索引 `uq_<表>_<列>` |
| 高频列表筛选列 | B-tree 单列索引 |
| 列表多条件组合 | 组合索引按查询条件顺序，遵循最左前缀 |
| 外键列 | **所有**被用作 JOIN 的外键建索引 |
| 单据行子表 | `(doc_id)` 必建 |
| 统计聚合 | 物化视图或 `pg_stat_statements` 观察后按需 |

工厂典型列表查询（必须被索引覆盖）：

```sql
-- 计件流水按日期+车间+款号查询
CREATE INDEX idx_piecework_logs_work_date_workshop_id_style_no
  ON piecework_logs (work_date DESC, workshop_id, style_no)
  WHERE deleted_at IS NULL;
```

> 部分索引（`WHERE deleted_at IS NULL`）在本项目高频使用，软删后仍能保证索引紧凑。

### 5.1 模糊查询索引（INV-9，REV-2026-10 强制）

主数据（款号 / 客户 / 供应商 / 物料 / 工序 / 缸号）必须支持模糊搜索，**统一走三元组 GIN 索引**，禁止全表 `ILIKE '%q%'` 扫描：

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX idx_styles_trgm            ON styles          USING gin ((style_no || ' ' || style_name) gin_trgm_ops);
CREATE INDEX idx_customers_trgm         ON customers       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_suppliers_trgm         ON suppliers       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_materials_trgm         ON materials       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_operations_trgm        ON operations      USING gin ((op_no || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_colors_trgm            ON colors          USING gin ((color_code || ' ' || color_name) gin_trgm_ops);
CREATE INDEX idx_sizes_trgm             ON sizes           USING gin ((size_code || ' ' || size_name) gin_trgm_ops);
CREATE INDEX idx_material_stocks_trgm   ON material_stocks USING gin (dye_lot_no gin_trgm_ops)
  WHERE deleted_at IS NULL;
```

| 规则 | 说明 |
| --- | --- |
| 迁移必须建扩展 | Alembic 迁移**第一条**建 `pg_trgm` 扩展；闸门 4 需在 PG 16 上验证可用 |
| 验收口径 | 断言「索引表达式与候选查询谓词一致」，而不是断言 planner 一定选它 ⚠️ T-BASE-001 实测修正 |
| 验收口径（实现方式） | `SET LOCAL enable_seqscan = off` 后 `EXPLAIN` 出现 `Bitmap Index Scan on idx_*_trgm`。**不能**直接断言默认 planner 的输出：PG 在小表上会合理地选 Seq Scan（实测 5 万行 / 100 命中时默认走 Seq Scan 42ms，`enable_seqscan=off` 后走 Bitmap Index Scan 2.4ms，快 18 倍）。`enable_seqscan=off` 那一条才是有意义的守卫 —— 它验证「索引表达式 == 查询谓词」，索引名或表达式写错时必然失败；而 planner 选不选是数据分布与成本模型的事，不该写成硬性验收条件 |
| 结果硬上限 | 候选接口最多返回 100 行（选择器 20 行）；禁止"取全量再前端过滤" |
| 深分页禁止 | `offset > 10000` 直接 `10001`，前端改用游标（`search_after`） |
| 排序白名单 | `sort_by` 必须走服务端白名单映射，**禁止字符串拼接进 SQL** |

**禁止**：为不存在的查询建索引。建索引必须在设计文档中写出对应查询场景。

## 6. 删除与迁移

### 6.1 硬删除禁令

- 生产库表：`users`, `roles`, `permissions`, `accounts`, `migrations`（Alembic 版本表）
- 理由：破坏外键完整性，且误删不可恢复
- 其余表：只允许软删（`UPDATE ... SET deleted_at = now()`）

### 6.2.1 数据库账号与权限（与 [ADR-0006](./adr/0006-部署形态-docker-compose.md) 对应）

应用**必须**用无删除权限的账号运行，靠权限而不是靠代码自觉：

```sql
-- 迁移账号（只在 docker compose run api alembic 时用，不进 .env 主配置）
CREATE ROLE erp_ddl LOGIN PASSWORD '<由密钥管理注入>';

-- 应用运行账号
CREATE ROLE erp_app LOGIN PASSWORD '<由密钥管理注入>';

GRANT CONNECT, TEMPORARY ON DATABASE garment_erp TO erp_app;
GRANT USAGE ON SCHEMA public TO erp_app;
GRANT SELECT, INSERT, UPDATE ON ALL TABLES IN SCHEMA public TO erp_app;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO erp_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public
  GRANT SELECT, INSERT, UPDATE ON TABLES TO erp_app;

-- 审计表不可篡改：应用账号连 UPDATE 都没有
REVOKE UPDATE, DELETE ON document_logs FROM erp_app;

-- 硬删白名单（ADR-0025 + ADR-0029）：**只授这 6 张表**，其余一律不给
--  ① 四张字典表：删掉就是不要了，软删会带来历史包袱（ADR-0025）
--  ② 两张关联表 user_roles / role_permissions：一行 = 一条关系，删掉不丢信息，
--     且不参与任何界面回显。授权语义是"整体替换"，没有 DELETE 就无法取消勾选
GRANT DELETE ON colors, sizes, size_groups, size_group_items TO erp_app;   -- ADR-0025
GRANT DELETE ON user_roles, role_permissions TO erp_app;                    -- ADR-0029

-- 生产库不给应用账号任何其他硬删能力
-- 应用账号对上面 6 张之外的表天然不具备 DELETE/TRUNCATE/DROP（GRANT 中未授予）
```

⚠️ **白名单是按表显式列举的**，不是 `GRANT DELETE ON ALL TABLES`。
新增表时若要可硬删，必须同时改三处：迁移的白名单常量、本节的清单、
`tests/test_migrations.py` 的断言 —— 漏任何一处，闸门 4 会失败。

| 角色 | 权限 | 用途 |
| --- | --- | --- |
| `owner`（迁移账号） | 全部 | 建表/改表/DDL |
| `erp_app`（运行账号） | `SELECT/INSERT/UPDATE` + `document_logs` 只读 | 应用连接池 |
| `readonly`（运维/报表） | `SELECT` | `pg_stat_statements` 分析、临时查数 |

**规则**：
- `.env` 里的 `DATABASE_URL` 用 `erp_app`
- 迁移容器通过 `DATABASE_URL_MIGRATION` 临时覆盖为 `owner`
- 新增表后要执行 `ALTER DEFAULT PRIVILEGES` 才让 `erp_app` 自动获得权限
- **禁止**把 `owner` 账号配到应用常驻进程

### 6.2 迁移规范

```bash
# 生成（必须人工检查生成的脚本，禁止直接提交 autogenerate 结果）
uv run alembic revision --autogenerate -m "add piecework_logs"

# 自检（闸门 4）
uv run alembic upgrade head
uv run alembic downgrade -1
uv run alembic upgrade head
```

| 规则 | 说明 |
| --- | --- |
| 迁移只前进 | **已合并到 main 的迁移文件禁止修改**，修正靠新迁移 |
| 生产前必须演练 | 在生产数据脱敏副本上跑过 up/down/再 up |
| 大表加列 | 超过 50 万行的表加 `NOT NULL` 列：先加可空 → 回填 → 加约束，分三次迁移 |
| 加索引 | 生产用 `CREATE INDEX CONCURRENTLY`，需迁移中 `autocommit_block()` |
| 删列 | 分两次迁移：先不用 → 观察一个发布周期 → 再删 |
| 危险操作标注 | `op.drop_table` / `op.drop_column` 加注释写明理由与回滚方式 |
| 数据迁移 | 写在 `upgrade()` 里可重入（幂等），`downgrade()` 必须能还原 |

## 7. 关键表结构约定

### 7.0 打菲件表 `bundles`（一码一手，REV-2026-10，见 [ADR-0016](./adr/0016-打菲按手与扫码得件数.md)）

> **打菲单位是「手」不是「件」**。每一手 = 一个码 = 一个责任单元（一个员工）。
> `bundle_no` 内嵌**尺码码 + 手序号**；`bundle_qty` 存该手件数，扫码即知（**码里不带数量**，ADR-0004 不变）。

```sql
CREATE TABLE bundles (
    id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_id                uuid NOT NULL REFERENCES bundling_orders(id) ON DELETE RESTRICT,
    line_id               uuid NOT NULL REFERENCES bundling_order_lines(id) ON DELETE RESTRICT,
    bundle_no             varchar(64) NOT NULL,
    hands                 integer NOT NULL,           -- **手序号**（同单同尺码内从 1 起）
    style_no              varchar(32) NOT NULL,
    color_code            varchar(32) NOT NULL,
    size_code             varchar(32) NOT NULL,
    operation_no          varchar(16) NOT NULL,
    cutting_size_line_id  uuid NOT NULL,              -- 引用裁剪的尺码明细行（件数权威来源）
    bundle_qty            numeric(14,3) NOT NULL,      -- **该手件数**（= 裁剪该尺码 output_qty / hands，向下取整）
    counted_qty           numeric(14,3) NOT NULL DEFAULT 0,  -- 已计件数量（≤ bundle_qty）
    counted_by            uuid,                       -- **一码一员工**
    counted_at            timestamptz,
    status                bundle_status NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE / VOIDED
    voided_at             timestamptz,
    void_reason           text,
    qr_content            varchar(64) NOT NULL,       -- = bundle_no（ADR-0004：二维码纯文本）
    ...公共字段,
    CONSTRAINT uq_bundles_no   UNIQUE (bundle_no),
    CONSTRAINT uq_bundles_hand UNIQUE (doc_id, color_code, size_code, hands),
    CONSTRAINT ck_bundles_qty  CHECK (bundle_qty > 0 AND bundle_qty = trunc(bundle_qty)),
    CONSTRAINT ck_bundles_cnt  CHECK (counted_qty >= 0 AND counted_qty <= bundle_qty),
    CONSTRAINT ck_bundles_one  CHECK (counted_qty = 0 OR counted_by IS NOT NULL)
);
CREATE INDEX idx_bundles_counted_pending ON bundles (doc_id, color_code, size_code)
       WHERE deleted_at IS NULL AND status = 'ACTIVE' AND counted_at IS NULL;
CREATE TYPE bundle_status AS ENUM ('ACTIVE', 'VOIDED');
```

#### 7.0.1 `bundle_no` 格式（**ADR-0016 修订，取代 ADR-0004 原格式**）

```
{打菲单号}-{尺码码 2 位}{手序号 2 位}-{件序号 4 位}

BD-20261018-000031-XL02-0001      XL 尺码第 2 手，件序号 0001（一码一手）
BD-20261018-000031-L01-0001       L 尺码第 1 手
BD-20261018-000031-XL02-0002      同一手第 2 件（预留"一手拆多码"扩展，一码一手时恒 0001）
```

| 段 | 说明 |
| --- | --- |
| 打菲单号 | `BD-YYYYMMDD-NNNNNN`（09 §2.1） |
| 尺码码 + 手序号 | **手序号在同单同尺码内从 1 递增**；`UNIQUE(doc_id, color_code, size_code, hands)` 保证不重复 |
| 件序号 | 同一手内件序号；**一码一手时恒为 `0001`** |
| 二维码/条码内容 | = `bundle_no` 纯文本（Code128 同内容），**不带数量** |

#### 7.0.2 扫码计件规则（整手默认 + 允许部分生产）

```
扫码 → 事务内 SELECT … FROM bundles WHERE bundle_no = :bn FOR UPDATE
  ├─ 不存在              → 31001
  ├─ status = VOIDED     → 31002
  ├─ counted_at 非空     → 32001（提示 counted_by 姓名与时间）
  └─ 正常：
       default_qty = bundle.bundle_qty        ← 扫码即知这手数量
       qty = 用户手写值（可选），默认 default_qty
       校验 0 < qty ≤ bundle.bundle_qty      ← 超产拒绝 → 32006
       写 piecework_logs（bundle_id 引用，qty = qty）
       回写 bundles.counted_qty / counted_by / counted_at
```

| 规则 | 说明 |
| --- | --- |
| 一码一员工 | `counted_by` 只允许一个；第二个员工扫同一码 → `32001` |
| 部分生产 | `qty < bundle_qty` 允许（如手写 28/60）；剩余量不改码，如需补做走红冲补录（ADR-0005） |
| **禁止超产** | `qty > bundle_qty` → `32006`；要超产必须**追加手**（新裁剪 + 新打菲） |
| 改每手件数 | 必须同步未计件码的 `bundle_qty`；**已计件（`counted_at` 非空）的码不可改** |
| 余数归损耗 | `output_qty ÷ hands` 除不尽的余数进 `balance_qty`（09 §4.2），不生成码 |

### 7.1 计件流水（append-only，INV-2）

```sql
CREATE TABLE piecework_logs (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    bundle_no       varchar(64)  NOT NULL,
    style_no        varchar(32)  NOT NULL,
    operation_no    varchar(16)  NOT NULL,
    employee_id     uuid         NOT NULL,
    workshop_id     uuid         NOT NULL,
    group_no        varchar(32),
    work_date       date         NOT NULL,
    bundle_id       uuid,                             -- 引用 bundles（REV-2026-10 / ADR-0016）
    qty             numeric(14,3) NOT NULL DEFAULT 1, -- 该手件数（可小于 bundles.bundle_qty，ADR-0016）
    unit_price      numeric(12,6) NOT NULL,          -- INV-3 快照
    amount          numeric(18,4) NOT NULL,
    log_type        piecework_log_type NOT NULL,     -- SCAN / MANUAL / REVERSAL / SUPPLEMENT
    payroll_id      uuid,                            -- 结算后可回写（04 §7.1 要点）
    reversal_of_id  uuid,                            -- 红冲指向原流水
    source_station  varchar(32),
    created_at      timestamptz NOT NULL DEFAULT now(),
    created_by      uuid NOT NULL,
    updated_at      timestamptz NOT NULL DEFAULT now(),
    updated_by      uuid NOT NULL,
    deleted_at      timestamptz,
    version         integer NOT NULL DEFAULT 1,
    remark          text,
    CONSTRAINT uq_piecework_logs_idem UNIQUE
      (bundle_no, operation_no, employee_id, work_date, log_type),
    -- 符号规则（REV-2026-10 修订）：只有红冲行为负，其余为正
    CONSTRAINT ck_piecework_logs_sign CHECK (
      (log_type = 'REVERSAL' AND qty < 0 AND amount < 0)
      OR (log_type <> 'REVERSAL' AND qty > 0 AND amount > 0)
    ),
    -- 整件口径：尾数不入库，计件只按整件（09 §4.2）
    CONSTRAINT ck_piecework_logs_whole CHECK (qty = trunc(qty))
);
```

**要点**：
- `UNIQUE (bundle_no, operation_no, employee_id, work_date, log_type)` 就是幂等键，**数据库兜底**。
- `log_type = 'REVERSAL'` 的行 `qty` 与 `amount` 为负，其余为正，由 `ck_piecework_logs_sign` 约束。
- 禁止 `UPDATE qty/amount`；只有 `remark/updated_*` 可改。
- 结算标记用 `payroll_id` 字段（审核时由 service 回写，**不允许手工填**），不另设 `is_settled` 布尔列避免双源。查询"未结算流水"用 `payroll_id IS NULL`。

### 7.2 库存（双栈 + 批次实际成本，INV-4，REV-2026-10 修订）

> **REV-2026-10**：面料成本由「移动加权平均」改为**逐批实际成本**（见 [ADR-0011](./adr/0011-面料批次实际成本.md)）。
> 原因：服装面料同款不同缸号存在色差，成本必须可追溯到具体缸号；同时代工厂常按缸号对账摊销。
> **仓库按批次（缸号 `dye_lot_no` + 匹号 `bolt_no`）独立计价，批次内单位成本恒定不变。**

物料与成衣分表，避免一堆可空列：

| 表 | 内容 |
| --- | --- |

#### 7.2.1 入库：批次成本如何确定

| 场景 | `unit_cost` 来源 |
| --- | --- |
| 到货入库 | `到货行金额 ÷ 到货数量`，精确到 6 位小数（**不含运费 / 染费 / 加工费**，ADR-0019 + ADR-0024）；批次同时写入 `supplier_id` |
| 生产退料 | 退回原批次，沿用该批次原 `unit_cost`（不允许改价） |
| 盘盈 | 用**同物料同缸号**的最近入库批次成本；无同缸则用同物料最近批次成本 + 写日志 |
| 成本调整 | **禁止**直接 UPDATE。必须走红冲原入库单 + 重新入库 |

**★ 运费不进成本**（REV-2026-10，见 [ADR-0019](./adr/0019-采购运费只记录不进成本.md)）：
`allocated_cost` 口径**已取消**，不再有 `freight_allocated` 字段。批次成本固定为 `到货行金额 ÷ 到货数量`；
运费只记在 `purchase_orders.freight_amount` 供采购台账展示（§7.12），**不进批次成本、不进领料成本、不进成衣成本、不进损益、不生成凭证行**。
因此成衣毛利率**不扣运费 / 染费 / 加工费**，毛利报表页头须标注「毛利未扣采购运费/染费/加工费（ADR-0019 / ADR-0024）」。
染费与加工费**同口径只记录**（[ADR-0024](./adr/0024-染费与加工费只记录不进成本.md)）。若日后要算「含采购费用的真实毛利」，应作为**独立管理报表**按期间归集扣减，**不回改批次成本**。

#### 7.2.2 出库：批次选批规则（强制）

出库**必须明确用了哪些批次**，按下列优先级选批，并把结果写入 `stock_ledger_lines`：

| 优先级 | 规则 | 场景 |
| --- | --- | --- |
| 1 | **人工指定批次**（行上选 `dye_lot_no`） | 裁剪单按缸号配料（最常见：客户指定缸号） |
| 2 | **FEFO**（先到期先出，`dye_lot_no` 的 `expiry_date` 或入库日期升序） | 有保质期的辅料 |
| 3 | **FIFO**（先进先出，入库日期升序） | 无保质期物料的默认规则 |

**禁止**：跨批次混合后按平均价出库（这正是被撤销的移动加权，会造成成本漂移）。

```python
async def select_batches(stock_repo, material_id, need_qty, rule: BatchRule) -> list[BatchPick]:
    """按规则选批，返回批次耗用计划。数量不足必须抛 STOCK_INSUFFICIENT，不许部分出库。"""
    if rule.explicit:
        return await stock_repo.pick_specified(stock_repo, material_id, rule.explicit, need_qty)

    stocks = await stock_repo.list_available(
        material_id=material_id,
        order_by=("expiry_date", "in_date") if rule == BatchRule.FEFO else ("in_date",),
    )
    picks: list[BatchPick] = []
    remaining = need_qty
    for stock in stocks:
        if remaining <= 0:
            break
        take = min(stock.stock_qty, remaining)
        picks.append(BatchPick(stock=stock, qty=take, unit_cost=stock.unit_cost))
        remaining -= take
    if remaining > 0:
        raise BusinessError(ErrorCode.STOCK_INSUFFICIENT, "库存不足")
    return picks


async def _issue_for_cutoff(self, order: CuttingOrder) -> None:
    for line in order.lines:
        picks = await select_batches(self.repo, line.material_id, line.fabric_qty, line.batch_rule)
        ledger = await StockLedger.create_issue(
            stock_type="material", direction="OUT", source_doc_type="CuttingOrder", source_doc_id=order.id
        )
        for pick in picks:
            await self.session.execute(
                update(MaterialStock)
                .where(MaterialStock.id == pick.stock.id, MaterialStock.stock_qty >= pick.qty)
                .values(stock_qty=MaterialStock.stock_qty - pick.qty, updated_at=func.now())
            )
            await self.session.execute(
                insert(StockLedgerLine).values(
                    ledger_id=ledger.id,
                    material_id=line.material_id,
                    dye_lot_no=pick.stock.dye_lot_no,
                    bolt_no=pick.stock.bolt_no,
                    qty=pick.qty,
                    unit_cost=pick.unit_cost,     # 批次实际成本快照
                    amount=pick.unit_cost * pick.qty,
                )
            )
```

#### 7.2.3 成衣成本结转

```
成衣单位成本 = 该扎消耗的物料批次实际成本合计 + 该款号已计提的计件工价合计
             = Σ(stock_ledger_lines.amount) + Σ(piecework_logs.amount)
```

- 完工入库审核时计算并写入 `finished_goods_stocks.unit_cost`，**快照后不可改**
- 同一扎若跨批次配料，其成本 = 各批次耗用金额求和（不做平均）
- 红冲时按同一 `stock_ledger_lines` 逐条反向冲回

#### 7.2.4 核心不变式（写 CHECK 约束 + 视图）

```sql
-- 台账流水与结余必须可对账，报表脚本每次发布后跑
CREATE OR REPLACE VIEW v_stock_reconciliation AS
SELECT s.id, s.stock_qty, COALESCE(SUM(l.qty), 0) AS ledger_qty
FROM material_stocks s
LEFT JOIN stock_ledgers l ON l.stock_id = s.id AND l.deleted_at IS NULL
GROUP BY s.id, s.stock_qty
HAVING s.stock_qty <> COALESCE(SUM(l.qty), 0);
-- 视图非空 = 账实不一致，必须为 0 行
```

| 不变量 | 保证方式 |
| --- | --- |
| 结余 = 台账汇总 | `v_stock_reconciliation` 恒 0 行 + 每日巡检 |
| 结余 ≥ 0 | `WHERE stock_qty >= n` 条件 UPDATE + `CHECK (stock_qty >= 0)` |
| 批次成本不可改 | 权限层禁 UPDATE `unit_cost`；只能红冲 + 重入 |
| 每条出库都有批次耗用 | `stock_ledger_lines` 外键 + 出库台账必须有 ≥1 行明细 |
| 账面金额 = Σ 明细金额 | 对账视图扩展 `v_stock_cost_check` |

**报表口径**：毛利分析必须按**实际批次成本**出，不得使用任何平均价。

| --- | --- | --- |
| `seed_baseline` | **跳过，不复活**（插入前查「有 `DELETE` 且没有更新的 `RESTORE`」） | 首次部署 / 新增内置项版本 |

  ⚠️ 「跳过墓碑」这一条如果没做，用户删掉的内置色会在下次加内置项版本时**自己回来** ——

- 因此实现上必须区分两个命令：`seed_baseline`（首次初始化）/ `restore_builtin`（显式恢复），禁止在应用启动时自动 seed

- `style_color_size_ratios`（§7.6）只能配款号尺码集合内的尺码，否则 `20007`
- seed 幂等且**不覆盖用户改动**：用 `ON CONFLICT (code) DO NOTHING`

| `NORMAL` | 正常采购 | 进面料成本 | 混入主料成本 |
| `REWORK_RECEIPT` | 返修补退回厂（供应商免费/低价退回） | **单独成本科目**（`5403 制造费用-返修补布费`） | **单独列示**，不污染正常布料毛利 |
| `RETURN` | 客供料退回 | 冲减在产品成本 | 单独列示 |
| `SAMPLE` | 样布 | 进样品费用（`6602`） | 不进产品成本 |

#### 7.5.2.1 运费（**只做记录，不摊成本**，REV-2026-10，见 [ADR-0019](./adr/0019-采购运费只记录不进成本.md)）

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `freight_no` | `purchase_orders` | 运费单号 |
| `freight_amount` | `purchase_orders` | 运费金额（`numeric(18,4)`） |
| `freight_date` | `purchase_orders` | 运费发生日期 |
| `dyeing_amount` | `purchase_orders` | **染费**（染色加工费，`numeric(18,4)`，默认 `0`） |
| `processing_amount` | `purchase_orders` | **加工费**（后整、缩水等，`numeric(18,4)`，默认 `0`） |

> **★ 采购侧三项费用 = 运费 + 染费 + 加工费，全部只记录**（ADR-0019 + [ADR-0024](./adr/0024-染费与加工费只记录不进成本.md)）。
> 三项均为**单据头一次录入**，不按行、不按到货次分摊，**结构上不设分摊字段**（`freight_allocated` 已删除，不新增 `dyeing_allocated` / `processing_allocated`）。
> 采购单反审核时三项一并冲回；三项在**已到货后仍可改**（只改台账记录，不动已锁定的 `material_stocks.unit_cost`），每次修改写 `document_logs`。

**强制口径（ADR-0019，取代 ADR-0015 的分摊规则）**：

```sql
-- 批次成本 = 到货金额 ÷ 到货数量，**不含运费**
material_stocks.unit_cost = purchase_arrival_lines.amount / purchase_arrival_lines.qty
CONSTRAINT ck_freight_not_in_cost CHECK (TRUE)  -- 无运费分摊字段，结构上即不可摊
```

- 运费**不进批次成本、不进领料成本、不进成衣成本、不进损益、不生成凭证行**。
- 因此**成衣毛利率不扣运费**；毛利报表页头必须标注「毛利未扣采购运费（ADR-0019）」。
- 运费只能通过**采购台账**查看（`purchase:ledger:read`，ADR-0022）。

#### 7.5.2.2 分批到货（`purchase_arrivals`，REV-2026-10）

业务方口径：**采购分批到货录入** —— 一张 `PO` 可以分多次到，每次到的缸号/匹数/重量可以不同。

```sql
CREATE TABLE purchase_arrivals (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_id              uuid NOT NULL REFERENCES purchase_orders(id) ON DELETE RESTRICT,
    arrival_no          integer NOT NULL,                    -- 第几次到货（1,2,3…）
    arrival_date        date NOT NULL,
    arrived_at          timestamptz NOT NULL DEFAULT now(),
    remark              text,                                 -- 到货备注（外包装破损等）
    line_count          integer NOT NULL DEFAULT 0,
    amount              numeric(18,4) NOT NULL DEFAULT 0,
    freight_allocated   numeric(18,4) NOT NULL DEFAULT 0,    -- 本次分摊到的运费
    operator_id         uuid NOT NULL,
    ...公共字段,
    CONSTRAINT uq_purchase_arrivals UNIQUE (doc_id, arrival_no),
    CONSTRAINT ck_purchase_arrivals_amount CHECK (amount >= 0)
);
CREATE INDEX idx_purchase_arrivals_doc ON purchase_arrivals (doc_id, arrival_no)
       WHERE deleted_at IS NULL;

-- 到货明细行：挂在「采购行 + 到货批次」两级上
CREATE TABLE purchase_arrival_lines (
    id               uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    arrival_id       uuid NOT NULL REFERENCES purchase_arrivals(id) ON DELETE RESTRICT,
    order_line_id    uuid NOT NULL REFERENCES purchase_order_lines(id) ON DELETE RESTRICT,
    line_no          integer NOT NULL,
    bolt_count       numeric(14,3) NOT NULL,      -- 本次到货匹数（可 ≤ 订单行的剩余量）
    weight_kg        numeric(14,3) NOT NULL,      -- 本次到货重量
    total_length_m   numeric(14,3),
    dye_lot_no       varchar(64),                -- **可与采购行不同的缸号**（分批染色常见）
    width_cm         numeric(8,2),               -- **实测门幅（覆盖采购行与物料默认值），可空则取采购行**
    -- ~~freight_allocated~~ 已删除（ADR-0019）：运费/染费/加工费只记录在采购单头，不分摊到行
    unit_cost        numeric(12,6),              -- 本批实际成本快照 = amount ÷ 计量（**不含运费/染费/加工费**，ADR-0019 + ADR-0024）
    amount           numeric(18,4) NOT NULL,
    stock_id         uuid,                       -- 生成的批次（入库后回写）
    ...公共字段,
    CONSTRAINT uq_purchase_arrival_lines UNIQUE (arrival_id, line_no),
    CONSTRAINT ck_pal_bolt CHECK (bolt_count > 0),
    CONSTRAINT ck_pal_weight CHECK (weight_kg > 0)
);
```

**关键规则**：
- **到货登记 → 才入库**。采购单审核只是**确认订单**（生成应付承诺）；每登记一次到货，**当场生成批次 + 台账 + 凭证**（`purchase:arrival`）
- 分批到货单号：`PO 单号 + 到货序号` 展示用，如 `PO-20261018-000012 / 第 2 次`
- 到货行允许**覆盖缸号**（同一 PO 第二次到货可能是另一个缸），`dye_lot_no` 以到货行为准
- 到货行**无任何费用分摊列**：运费 `freight_amount` / 染费 `dyeing_amount` / 加工费 `processing_amount` 全在采购单头，只记录不摊成本（ADR-0019 + ADR-0024）
- **累计到货量 ≤ 采购行量**：超了报 `50011`；到齐后自动把采购单标 `ARRIVED_ALL`（内部标记，不改状态机状态）
- **运费按到货比例分摊**：每次到货按 `本次金额 ÷ total_amount` 分摊 `freight_amount`
- **单张到货必须整单事务**：建批次 + 台账 + 明细 + 应付冲减 + 凭证，任一失败整体回滚
- 反审核粒度：**先按到货反审核**（冲回该次批次与凭证），全部冲回后才允许反审核采购单本身
- 未到货的采购行不生成任何库存批次

#### 7.5.2.3 关键规则（原 §7.5.2）
- `purpose = REWORK_RECEIPT` 时 `rework_note` 必填（`10006`），写明是哪款哪单返修回来的
- 返修布**照常入库**（可被裁剪领用），但入库台账带 `purpose`，[ADR-0011](./adr/0011-面料批次实际成本.md) 的批次实际成本独立成立
- 返修布的凭证行走**返修费科目**而不是应付账款（视结算约定，阶段一记入 `2202` 并在 `purpose` 上区分）
- `total_length_m` 若未填，由服务层按 `bolt_count × length_per_bolt_m` 计算；三者不强制一致，只在差异 > 5% 时给出**警告**（不阻断）

#### 7.5.3 审核副作用（与库存模块联动）

| 动作 | 副作用 |
| --- | --- |
| 提交 | 校验供应商启用；行 `material_id/color_code/dye_lot_no/bolt_count/weight_kg/width_cm` 齐全；`purpose` 与 `rework_note` 一致性；运费 ≥ 0 |
| 审核 | **只确认订单，不入库**（REV-2026-10）：① 按行汇总 `total_amount` ② 生成应付承诺（`ap_ledgers`，状态 `PENDING_ARRIVAL`）③ 若勾了「一次到货」且 `arrival_expected_date` 已到，自动生成第 1 次到货并走下面的入库流程 |
| **到货登记**（新动作，权限 `purchase:arrival`） | **入库的唯一入口**：① 校验累计到货 ≤ 订单量（超则 `50011`）② 按到货行生成 `material_stocks` 批次（缸号 + 匹号 + 颜色 + **门幅** + **重量** + `purpose`），单位成本 = `(行金额 + 行分摊运费) ÷ 计重量`，6 位小数，**不再加权** ③ 写 `stock_ledgers.direction='IN'` + `stock_ledger_lines` ④ 按到货金额冲减应付 ⑤ 生成入库凭证（按 `purpose` 选科目）⑥ 更新 `arrived_amount` / `arrival_count` |
| 反审核（到货级） | 先按到货反审核：① 该批次已被下游裁剪消耗 → 拒绝（`40005`）② 按同一批 `stock_ledger_lines` 逐条反向冲回 ③ 红冲该次入库凭证 ④ 冲减该次应付 |
| 反审核（单据级） | **必须先冲完全部到货**；未冲完 → 拒绝（`50012`） |

### 7.6 工资结算周期（用户自定义起止区间）

> 决策依据 [ADR-0010](./adr/0010-工资结算周期自定义.md)。

```sql
CREATE TABLE payroll_periods (
    id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    period_code  varchar(32) NOT NULL,          -- 用户自定义标签 '2026-08' / '2026-07~08' / '夏季款'
    start_date   date NOT NULL,                 -- 起始日（含）
    end_date     date NOT NULL,                 -- 截止日（含）
    status       payroll_period_status NOT NULL DEFAULT 'OPEN',  -- OPEN / CLOSED
    source       varchar(16) NOT NULL DEFAULT 'MANUAL',          -- MANUAL / CUTTING_BOUNDARY
    closed_by    uuid,
    closed_at    timestamptz,
    close_reason text,
    ...公共字段,
    CONSTRAINT uq_payroll_periods_code  UNIQUE (period_code),
    CONSTRAINT uq_payroll_periods_range UNIQUE (start_date, end_date),
    CONSTRAINT ck_payroll_periods_range CHECK (end_date >= start_date)
);
```

**规则**：
- 周期是**用户自建的起止日期区间**，不是固定枚举
- 常见形态：整月、两月一次、半月、按裁剪打菲完成日自动截取
- `source = 'CUTTING_BOUNDARY'`：从裁剪单/打菲单的实际完成日期范围推导生成
- `payroll_settlements.period_id` 外键引用，**不用字符串存 period**
- 周期 `CLOSED` 后不允许再往里加结算单（`33003`）；重开需 `payroll:period:manage` + 必填原因；区间重叠被拒（`33004`）
- 结算取数：`piecework_logs.work_date BETWEEN start_date AND end_date`
- 跨车间可共用一个周期；结算单按 `UNIQUE (period_id, workshop_id)` 唯一

> **★ ADR-0021 口径落地**：`bundles.counted_at IS NOT NULL` 时禁止改 `hands` / `qty_per_hand`（`30004`）；行级徽标数据来自 `bundles` 聚合。
> **★ ADR-0022 口径落地**：`stock_id` **必填**（不允许自由输入缸号），`fabric_qty > 可用量` → `40006`。
> **迁移说明**：ADR-0017 把旧 `cutting_order_colors`（单据级）下沉为 `cutting_order_line_colors`（行内颜色级），迁移用 `ALTER TABLE cutting_order_colors RENAME TO cutting_order_line_colors;` + `doc_id → line_id` 重建外键；旧 `ratio_override` 列删除（ADR-0014 已取代）。

#### 7.7.3 三层结构与耗料/出数归属

```
cutting_orders（按日期 / 车间 / 款号）
└── cutting_order_lines             行 = 款号 + 布批(缸号+匹号+门幅) + 耗料 + 出数合计
    └── cutting_order_line_colors   颜色（一床可多个）+ 录入模式 + 比例快照
        └── cutting_order_size_lines  尺码 + hands + qty_per_hand + output_qty
```

| 归属 | 内容 | 原因 |
| --- | --- | --- |
| **耗料记在行** | `fabric_qty`、`waste_qty`、`fabric_weight_kg` | 耗料是**布的属性**，与裁几个颜色无关；同一缸布被多色共用时只录一次 |
| **出数记在尺码明细** | `output_qty` | 出数是**颜色的属性** |
| 余量归行 | `line.balance_qty = line.output_qty − Σ(颜色尺码 output_qty)` | 负数 → `30002` |

| 校验 | 规则 | 失败 |
| --- | --- | --- |
| 行耗料下限 | `line.fabric_qty ≥ Σ(该行各颜色 Σ(尺码 output_qty × BOM.单件用量)) + line.waste_qty` | `30002` |
| 行出数 | `line.output_qty = floor(可裁件数)`；= 各颜色出数合计 | 整件口径 |
| 颜色合法 | 必须是该款已定义颜色，尺码在该款尺码集合内 | `20007` |
| 比例 | 该颜色完全未配置比例时，带不出建议行 | `20006` |

**示例（一床多颜色，ADR-0017 §3）**：
```
行1 · 缸号 DY-2609-01 · 匹 B-2610-001 · 门幅 152 · 耗料 96.0 米
  ├─ WHT 本白 [MASTER] 每手 60 → L 1手 60 · XL 2手 120 · XXL 2手 120 · 3XL 1手 60 = 360 件
  └─ BLK 黑   [MASTER] 每手 50 → L 1手 50 · XL 2手 100 · XXL 2手 100          = 250 件
行1 小计：610 件（耗料 96.0 米）
行2 · 缸号 DY-2609-02 · 耗料 31.5 米
  └─ WHT 本白 [MANUAL] → XL 2手×60=120 · XL 1手×30=30 · XXL 2手×60=120     = 270 件
本单合计：880 件，耗料 127.5 米
```

#### 7.7.4 三种录入模式（ADR-0014，颜色级，挂在 `cutting_order_line_colors`）

| 模式 | `entry_mode`（`cutting_order_line_colors`） | 场景 | 界面 | 行级字段 |
| --- | --- | --- | --- | --- |
| **A 按比例带出** | `MASTER` | 常规，尺码比例固定 | 点「按比例带出」自动生成行，`hands` 取自比例，用户只填 `qty_per_hand` | `hands` 取比例、`qty_per_hand` 手填 |
| **B 统一件数** | `UNIFORM` | **所有尺码件数一样** | 点「统一件数」→ 填一个件数 → 所有尺码行同件数 | `qty` 全部相同，`hands` 反算 `= qty / qty_per_hand` |
| **C 自定义明细** | `MANUAL` | **裁床个别尺码数量不一致** | 可增/删/改任意行；`hands`、`qty_per_hand`、`qty` 三者任填其一 | 全部手填 |

**示例（业务方 2026-10-01 原话场景）**：
```
红色 L:XL:XXL:3XL = 1:2:2:1，每手 60 件  →  模式 A
  L    1 手 × 60 = 60 件
  XL   2 手 × 60 = 120 件
  XXL  2 手 × 60 = 120 件
  3XL  1 手 × 60 =  60 件            合计 6 手 = 360 件

后来又多个 XL 1手 30件               →  模式 C（在 A 基础上追加一行）
  L    1 手 × 60 =  60 件
  XL   2 手 × 60 = 120 件     ← 原比例
  XL   1 手 × 30 =  30 件     ← 新增行（每手件数不同）
  XXL  2 手 × 60 = 120 件
  3XL  1 手 × 60 =  60 件            合计 7 手 = 390 件
```

**关键规则**：
| # | 规则 |
| --- | --- |
| 1 | **比例只用于"带出建议"，不约束裁剪单行**。裁剪行可以任意偏离比例。 |
| 2 | `hands` 与 `qty_per_hand` 都是**行级**，允许同尺码多行且取值不同（如上面的 XL 两行） |
| 3 | `output_qty` 服务层算 `floor(hands × qty_per_hand)`；人工改 `output_qty` 时 `entry_mode` 自动转 `MANUAL` |
| 4 | 每行余量（`hands × qty_per_hand − qty`）并入单据级 `balance_qty`（09 §4.2 整件口径） |
| 5 | 耗料 = `Σ(各行 output_qty × 该尺码 BOM.单件用量) + 损耗`；**BOM 只算耗料，不反推件数** |
| 6 | 从 `MASTER` 切到 `UNIFORM` / `MANUAL` 要**二次确认**（会清掉当前行的 `hands`）；模式存 `cutting_order_colors.entry_mode` |
| 7 | 单据保存时把当时的比例快照写入 `cutting_order_line_colors.ratio_snapshot`（jsonb），便于事后解释"为什么这么裁" |
| 8 | 三种模式**可以在同一张单里混用**（如本行红色走 A、另一行黑色走 C）—— 模式是**行 × 颜色级**属性 |

```sql
CREATE TABLE operations (
```

**规则**：
- 工序由用户自由增删改，**不内置枚举**

- 停用工序不参与新建单据，历史数据照常可查

#### 7.8.2 款号工序配置（模板载体）

```sql
CREATE TABLE style_operations (
    id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    -- ⚠️ **REV-2026-10 修正**：原本写的是 `style_no REFERENCES styles(style_no)`，
    --    而实际建表是 `style_id REFERENCES styles(id)` + `style_no` 无外键的字符串冗余。
    --    原因见 `00-P0地基.设计.md` §10.1 的注：`uq_styles_no` 是**部分索引**
    --    （`WHERE deleted_at IS NULL`），PG 不允许外键引用部分唯一索引，所以款号
    --    根本不能作为被引用目标。照旧文案建表会直接失败，而读者不会怀疑文档。
    --    同一修正同样适用于 `style_colors` / `style_sizes`（见 §7.14.3）
    style_id      uuid NOT NULL REFERENCES styles(id),
    style_no      varchar(32) NOT NULL,                     -- 冗余：历史单据按它引用
    operation_no  varchar(16) NOT NULL REFERENCES operations(operation_no),
    sequence      integer NOT NULL,                        -- 工序顺序 1,2,3…
    bundle_qty    numeric(14,3) NOT NULL DEFAULT 1,       -- 该款该工序一扎几件
    is_piecework  boolean NOT NULL DEFAULT true,
    is_final_operation boolean NOT NULL DEFAULT false,      -- 是否最后一道工序（默认整烫）
    remark        text,
    ...公共字段,
    CONSTRAINT ck_style_operations_sequence_positive CHECK (sequence > 0),
    CONSTRAINT ck_style_operations_bundle_qty_positive CHECK (bundle_qty > 0),
    CONSTRAINT uq_style_operations UNIQUE (style_no, operation_no)
);
```

> ⚠️ **子表外键指向 `styles.id` 而不是 `styles(style_no)`**（docs/12 §5 L-029）：
> `uq_styles_no` 是 `WHERE deleted_at IS NULL` 的**部分索引**，PostgreSQL 的外键
> 只能引用普通唯一约束，引用不了部分索引（实测
> `there is no unique constraint matching given keys for referenced table "styles"`）。
> 保留部分唯一索引（款号软删后可复用）优先，子表改为存 `style_id`（uuid FK → `styles.id`）
> + `style_no`（业务键，查询与唯一约束用）。本节的 `style_no` 字面量按此理解。

**索引**：`idx_style_operations_style ON style_operations (style_no, sequence)`
——员工端「可绑定工序列表」按 ``WHERE style_no=? AND is_piecework ORDER BY sequence`` 走它。

**规则**：
- `is_final_operation` **至多一道**（业务确认所有款最后一道都是整烫，识别不到必须人工指定）
- `operation_no` 必须**存在且启用**；建配置时 service 内对工序字典行加锁，与「停用工序」串行化
- 停用工序后款号既有配置照常可查，只是默认不在新建/列表里展示

#### 7.8.3 工序单价历史（**ADR-0026 三档 + 时间维度，禁止 UPDATE 历史价**）

> **本节是 ADR-0026 的唯一权威**（2026-10-03 修订，取代原先的单档版本）。
> ADR-0020 要求「款号专用价 > 分类+工序专用价 > 工序通用价」三档，而单档 DDL 的
> `style_no NOT NULL` **存不下第三档**（工序通用价按定义没有款号）。

```sql
CREATE TABLE operation_rates (
    id                  uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    -- ★ 可空：空 = 该档不限定款号（档位 2 / 3）
    style_id            uuid REFERENCES styles(id),          -- 见 L-029：外键指主键
    style_no            varchar(32) REFERENCES styles(style_no),
    operation_no        varchar(16) NOT NULL REFERENCES operations(operation_no),
    -- ★ 可空：空 = 不限分类（档位 1 / 3）
    product_category_id uuid REFERENCES product_categories(id),
    effective_from      date NOT NULL,                          -- 生效起（含）
    effective_to        date,                                   -- 生效止（不含），NULL = 当前有效
    unit_price          numeric(12,6) NOT NULL,                 -- 工价 元/件，精度 6
    reason              text,
    ...公共字段,
    -- ★ 档位互斥：**两者不能同时有值**
    --
    -- ⚠️ 本约束 2026-10-03 已修正（docs/12 §5 L-030）。ADR-0026 §1 原文写的是
    --    CHECK (style_no IS NOT NULL OR product_category_id IS NOT NULL)
    --    （"至少指定款号或分类其中之一"），但它与本文下表的**档位 3 直接冲突** ——
    --    档位 3 的定义恰恰是 style_no 与 product_category_id 都为空，
    --    于是这条约束把第三档整个禁掉了（实测插入档位 3 报 ck_operation_rates_target 违例）。
    --    三档的真实形态是"恰好一个有值，或者都没有"，所以约束是"不能**同时**有值"。
    CONSTRAINT ck_operation_rates_target
        CHECK (NOT (style_no IS NOT NULL AND product_category_id IS NOT NULL)),
    CONSTRAINT ck_operation_rates_range
        CHECK (effective_to IS NULL OR effective_to > effective_from),
    CONSTRAINT ck_operation_rates_price CHECK (unit_price >= 0)
);

-- ★ 唯一索引：PG 默认认为 NULL 与 NULL 互不相等，会放过「重复的通用价」行，
--   必须用 NULLS NOT DISTINCT（PG 15+，本项目 PG 16，ADR-0002）
CREATE UNIQUE INDEX uq_operation_rates
    ON operation_rates (style_no, product_category_id, operation_no, effective_from)
    NULLS NOT DISTINCT;

-- 取价 / 区间重叠校验 / 变更历史，三者全部以 operation_no 起步走它
CREATE INDEX idx_operation_rates_lookup
    ON operation_rates (operation_no, style_no, product_category_id, effective_from DESC);

-- 计件员看"某工序当前价"概览（有查询场景才建，ADR-0026 §3）
CREATE INDEX idx_operation_rates_operation_current
    ON operation_rates (operation_no, effective_from DESC)
    WHERE effective_to IS NULL;
```

> `NULLS NOT DISTINCT` 是本节的**关键技术点**：没有它，"款号通用 + 分类 NULL +
> 同工序 + 同一生效日"可以插入任意多行，取价变成不确定 —— 而计件金额错就是工资错。

**三档定义与 `rate_source`**（ADR-0026 §2）：

| 档位 | `rate_source` | 匹配条件 | 业务含义 |
| --- | --- | --- | --- |
| 1（最高） | `STYLE` | `style_no = :style_no` 且 `product_category_id IS NULL` | 这款这个工序的专用价 |
| 2 | `CATEGORY` | `style_no IS NULL` 且 `product_category_id = :category_id` | 这个分类下这个工序的通用价（分类取款号档案值，单据不可改） |
| 3（最低） | `OPERATION` | `style_no IS NULL` 且 `product_category_id IS NULL` | 全厂这个工序的通用价 |

**取价 SQL（唯一口径，`:category_id` 来自 `JOIN styles.category_id`）**：

```sql
SELECT unit_price, style_no, product_category_id, effective_from, effective_to
FROM operation_rates
WHERE operation_no = :operation_no
  AND deleted_at IS NULL
  AND effective_from <= :work_date::date
  AND (effective_to IS NULL OR effective_to > :work_date::date)
  AND (   (style_no = :style_no        AND product_category_id IS NULL)
       OR (style_no IS NULL           AND product_category_id = :category_id)
       OR (style_no IS NULL           AND product_category_id IS NULL) )
ORDER BY
  CASE WHEN style_no = :style_no THEN 0
       WHEN product_category_id = :category_id THEN 1
       ELSE 2 END,                       -- 档位优先
  effective_from DESC                     -- 同档位取最新生效的那一行
LIMIT 1;
-- 未命中 → 20004（三档全未命中，或当日无生效单价）
```

⚠️ `ORDER BY` 的两段**不可交换**：先档位（`CASE`）、同档位内取最新生效日。
写成 `effective_from DESC, CASE ...` 会让"三个月前公布的款号价"盖掉"今天生效的分类价" ——
而款号价本来就该赢。

`:category_id` 为 NULL（款号档案未设分类的极端情况）时第 2 档自然不命中，只在 1、3 档中取。

**调价流程（禁止 UPDATE 价格）**：

1. 校验新区间与该**三元组** `(style_no, product_category_id, operation_no)` 下所有既有区间无交集
2. 旧行只改 `effective_to = 新价生效日`（`unit_price` 永不动）
3. 插入新行 `effective_from = 新价生效日` + 新 `unit_price`
4. 同事务写 `document_logs`（`doc_type='OperationRate'`, `action='UPDATE'`, `changed_fields` 记新旧价与生效日）
5. 历史计件流水的 `unit_price` 快照（INV-3）**完全不受影响**

**约束**：
- `effective_from` **可以是未来日期**（提前公告调价），但 `effective_from > work_date` 的价**不参与当日取价**
- 同一三元组内生效区间**不允许重叠**（重叠 → `20005`，`details` 回传冲突区间）；**至多一条** `effective_to IS NULL`
- 同一生效日已有行 → `20002`（追加式模型下"改今天的价"必须换一个生效日）
- 调价 `reason` 必填（`10006`）；首次设价可空
- `unit_price = 0` 允许（免费工序），但同样需要 `reason` 说明
- 区间行按 `effective_from` 排序 `SELECT ... FOR UPDATE` 加锁，唯一性最后由 `uq_operation_rates` 兜底

| 不计成本 | WIP 恒 `unit_cost IS NULL`；成衣成本在最后工序入库时一次性结转 |
| 手动完单入库 | `stock:in:manual` 权限 + 必填原因（`10006`）+ `document_logs` |
| 尾数 | 裁剪尾数不入 WIP，直接进 `balance_qty` 损耗 |

### 7.11 商品分类与按分类取价（REV-2026-10 新增，见 [ADR-0020](./adr/0020-商品分类与手数直接输入.md)）

> ⚠️ **2026-10-03：`operation_rates` 与 `style_operations` 的 DDL 与索引片段已作废**
> （[ADR-0026](./adr/0026-工序单价分类维度与款号可空建模.md) §5）。两个原因：
> ① `product_category_id` / `is_final_operation` **已经并入 §7.8.3 / §7.8.2 建表**，
>    在这里再写 `ALTER TABLE` 会与建表重复执行；
> ② 本节原有的 `CREATE INDEX idx_operation_rates_lookup ON operation_rates
>    (operation_id, style_no, product_category_id, effective_from)`
>    **引用了表里根本不存在的列 `operation_id`**（列名是 `operation_no`），
>    列序也与 §7.8.3 统一后的定义完全不同 —— 同一个项目里两个同名索引不可能同时成立。
> **取价口径与索引一律以 §7.8.3 为准**，本节只保留分类表本身的 DDL 与文字规则。

```sql
CREATE TABLE product_categories (        -- 内置 6 类
    id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    code varchar(32) NOT NULL UNIQUE,    -- SET / DRESS / TROUSERS / UNDERWEAR / VEST / THERMAL
    name varchar(32) NOT NULL,           -- 套装 / 单衣 / 单裤 / 棉毛 / 背心 / 打底裤
    sort int NOT NULL DEFAULT 0, is_active boolean NOT NULL DEFAULT true,
    ...公共字段
);
-- styles 增列（分类在款号档案上定死，裁剪单不冗余存分类，ADR-0020）
ALTER TABLE styles ADD COLUMN category_id uuid NOT NULL REFERENCES product_categories(id);
-- cutting_orders **不加** product_category_id；裁剪/计件一律 JOIN styles.category_id 取值
-- 货号可手工录入，唯一索引保证不冲突（冲突 → 10001）
CREATE UNIQUE INDEX uq_styles_no ON styles (style_no) WHERE deleted_at IS NULL;
```

**取价优先级**（文字口径，SQL 见 §7.8.3）：款号专用价 > 分类 + 工序专用价 > 工序通用价；
同优先级取当前生效区间里 `effective_from` 最新的一行，并回 `rate_source ∈ {STYLE, CATEGORY, OPERATION}`。

| 规则 | 说明 |
| --- | --- |
| 分类被引用 | 不可删除，只能停用（`base:category:manage`），与颜色/尺码一致 |
| 分类可改性 | **款号档案可改分类**（影响该款全部单据）；**单据上不可改**（裁剪单无 `product_category_id` 列），ADR-0020 |
| 件数派生 | `件数 = hands × qty_per_hand`，**不单独录入**；`hands` 必须是整数 |
| 比例降级 | `style_color_size_ratios.ratio` 仅建议，偏离 >20% 黄色提示，不拦截 |
| 取价留痕 | `piecework_logs` 增 `rate_source varchar(24)`（`STYLE` / `CATEGORY` / `OPERATION`），事后可追溯取价档位 |
| **档位 2 不参与模板复制** | 分类价属全厂口径，复制一款顺手改掉它等于静默改写全厂工资口径（ADR-0026 §4） |
| **单价页必须显示档位来源** | 三档各自是否已设价 + 当前生效价来源，并对被款号价遮蔽的档位打标记（ADR-0020「后果」列强制要求） |

### 7.12 采购台账与库存供应商视角（REV-2026-10 新增，见 [ADR-0022](./adr/0022-采购台账与库存供应商维度.md)）

| 视图 | 内容 | 消费页面 |
| --- | --- | --- |
| `v_purchase_supplier_summary` | 按 `supplier_id` + 收货日期区间：`SUM(weight_kg)` 总重量、`SUM(bolt_cnt)` 总匹数、`SUM(amount)` 总货值、`SUM(freight_amount)` 总运费、`SUM(dyeing_amount)` 总染费、`SUM(processing_amount)` 总加工费、应付（= `SUM(amount)`，不含费用）、已付（付款核销合计）、未付 | 采购台账汇总卡 |
| `v_purchase_arrival_detail` | 收货日期 · 供应商 · 面料名称 · 缸号 · 颜色 · 重量KG · 单价 · **金额=重量×单价** · 采购单号 · 到货单号 · 操作人 | 采购台账明细表 |
| `v_material_stock_by_supplier` | 供应商 · 面料 · 颜色 · 缸号 · 匹号 · 门幅 · 重量KG · 米数 · 可用量 · 已锁定 · 单价 · 金额 | 库存台账、裁剪选料级联 |

| 规则 | 说明 |
| --- | --- |
| `supplier_id` 不可手改 | 改供应商 = 退料重入库；`material_stocks.supplier_id` 由到货登记写入 |

#### 7.13.1 用户与角色

```sql
CREATE TABLE users (
    employee_no          varchar(32)  NOT NULL,           -- 工号，跨车间唯一；员工端登录账号
    name                 varchar(64)  NOT NULL,           -- 姓名（显示口径，界面一律用它而不是工号）
    phone                varchar(20),                     -- 手机号，员工端短信登录账号；可空
    password_hash        text,                             -- argon2id 哈希；员工端短信登录可空
    workshop_id          uuid REFERENCES workshops(id),   -- 所属车间；非车间人员为空
    group_no             varchar(32),                      -- 所属组别，对应 workshop_groups.group_no
    data_scope           varchar(16)  NOT NULL,           -- FACTORY / WORKSHOP / SELF
    is_active            boolean      NOT NULL DEFAULT true,
    must_change_password boolean      NOT NULL DEFAULT true,
    -- 幂等：工号与手机号各一个唯一索引（手机号可空，PG 的 NULL 不参与唯一判定，
    -- 所以「多人没有手机号」不会冲突）
);
CREATE UNIQUE INDEX uq_users_employee_no ON users (employee_no);
CREATE UNIQUE INDEX uq_users_phone       ON users (phone);
CREATE INDEX        idx_users_workshop_id_is_active ON users (workshop_id, is_active);

CREATE TABLE roles (
    code         varchar(32) NOT NULL,             -- 内置 10 个 + 用户自建
    name         varchar(64) NOT NULL,
    data_scope   varchar(16) NOT NULL,             -- 该角色授予的数据范围（用户自身 scope 可更严）
    is_system    boolean     NOT NULL DEFAULT false,  -- 内置角色不可删（restore_builtin 的前提）
    description  text
);
CREATE UNIQUE INDEX uq_roles_code ON roles (code);
```

> ⚠️ **`roles` 表没有 `is_active`**：T-AUTH-001 定的「停用角色」机制是**软删**
> （写 `deleted_at`），配合 AGENTS §2.1「禁止物理删除」。所以界面上「停用角色」
> 等于「删角色」，**恢复的办法是 `restore_builtin` 或手工改 `deleted_at`**，见
> `UserService.disable_role` 的注释。给 `roles` 加 `is_active` 会让「停用」有
> 两种实现而只有一种被测到。

#### 7.13.2 关联表（一行 = 一条关系，授权语义是「整体替换」）

```sql
CREATE TABLE user_roles (
    user_id uuid NOT NULL REFERENCES users(id),
    role_id uuid NOT NULL REFERENCES roles(id)

-- ⚠️ 复合主键而不是 `id`：同一对 (user, role) 不该出现两次。与 ADR-0029 的

CREATE UNIQUE INDEX pk_user_roles ON user_roles (user_id, role_id);

CREATE INDEX        idx_role_permissions_permission_id ON role_permissions (permission_id);

CREATE TABLE role_workshops (
    role_id     uuid NOT NULL REFERENCES roles(id),

-- ⚠️ 只有 `data_scope=WORKSHOP` 的角色才需要行；FACTORY 不受这张表约束
```

#### 7.13.4 登录日志与刷新令牌

```sql
-- ⚠️ append-only（04 §2 的例外）：应用账号对这张表**没有 UPDATE 也没有 DELETE**
--    （`REVOKE UPDATE, DELETE ON document_logs` 同款做法，0002 迁移里落地）。
--    登录日志被改过就失去意义 —— 它的全部价值在于「不能改」
CREATE TABLE auth_login_logs (
    employee_no varchar(32) NOT NULL,        -- 冗余：即使账号已删也要留住「谁试过登录」
    phone       varchar(20),                 -- 同上
    channel     varchar(16) NOT NULL,        -- admin / mobile（07 §1 的两个 AuthProvider）
    ip          inet,                        -- inet 而非 varchar：登录失败的暴力破解要按 IP 聚合
    user_agent  text,
    is_success  boolean NOT NULL,
    fail_reason varchar(64),                 -- 失败原因码；成功时为空
    user_id     uuid REFERENCES users(id)    -- 可空：账号不存在时没有 user
);
CREATE INDEX idx_auth_login_logs_employee_no ON auth_login_logs (employee_no, created_at DESC);
CREATE INDEX idx_auth_login_logs_created_at   ON auth_login_logs (created_at DESC);
-- ⚠️ **没有外键到 `users` 的级联**：账号被停用/软删后登录日志必须还在
--    （删账号 ≠ 抹掉登录历史）。这与 04 §6「审计表不可篡改」同一条原则

CREATE TABLE auth_refresh_tokens (
    user_id    uuid NOT NULL REFERENCES users(id),
    token_hash varchar(64) NOT NULL,          -- ⚠️ **只存哈希**，明文 token 不入库
    channel    varchar(16) NOT NULL,
    device_id  varchar(64),                   -- 员工端按设备去重（换设备重新登录）
    expires_at timestamptz NOT NULL,
    revoked_at timestamptz                    -- 非空 = 已吊销；**行保留**（吊销可追溯）
);
CREATE UNIQUE INDEX uq_auth_refresh_tokens_hash ON auth_refresh_tokens (token_hash);
-- ⚠️ 部分索引（`WHERE revoked_at IS NULL`）：refresh 的主路径是
--    「拿这行、未吊销、未过期」，已吊销的行不需要进索引 —— 单据越用越久，
--    这张表会一直涨，让未吊销的行留在索引里能把查询成本压住
CREATE INDEX idx_auth_refresh_tokens_user ON auth_refresh_tokens (user_id) WHERE (revoked_at IS NULL);
```

```sql
    next_no     numeric(32,0) NOT NULL DEFAULT 1
);
-- ⚠️ **两个部分唯一索引，不是一个三列唯一键**：PG 的 NULL 参与唯一判定时
--    「(NULL, 2026, 5)」可以无限重复插入 —— 用 `(customer_id, year) WHERE customer_id IS NOT NULL`
--    与 `(year) WHERE customer_id IS NULL` 分开，才真正挡住并发下的重复取号
CREATE UNIQUE INDEX uq_style_no_sequences_customer
    ON style_no_sequences (customer_id, year) WHERE (customer_id IS NOT NULL);
CREATE UNIQUE INDEX uq_style_no_sequences_factory
    ON style_no_sequences (year) WHERE (customer_id IS NULL);
CHECK (next_no >= 1);
```

> ⚠️ **取号必须 `SELECT ... FOR UPDATE`**（`core/numbering.py`）：这条约束只保证
> 「同一行不重复」，不保证两个并发事务读到不同的 `next_no`。并发取号有专门测试
> （`test_base_style_service.py`，20 并发不重复）。

### 7.9 操作日志（全模块强制）

> 章节号 REV-2026-10 再调整：新增 §7.4 字典表、§7.5 采购单与原材料批次、§7.7 款号尺码比例、§7.2.0 `material_stocks` 逐列定义；原 §7.4 工资结算周期 → §7.6；原 §7.5 工序与单价 → §7.8；操作日志 → §7.9。引用旧章节号的文档按新编号读。

```sql
CREATE TABLE document_logs (
    id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_type    varchar(32) NOT NULL,     -- CuttingOrder / BundlingOrder / ...
    doc_id      uuid NOT NULL,
    doc_no      varchar(32) NOT NULL,
    action      varchar(32) NOT NULL,     -- CREATE/UPDATE/SUBMIT/APPROVE/REJECT/REVERSE/CANCEL
    from_status varchar(32),
    to_status   varchar(32),
    operator_id uuid NOT NULL,
    operator_name varchar(64) NOT NULL,
    reason      text,
    changed_fields jsonb,                -- 仅 UPDATE 时记录字段级 diff
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX idx_document_logs_doc ON document_logs (doc_type, doc_id, created_at DESC);
```
**应用侧禁止 DELETE/UPDATE `document_logs`。** 部门 DBA 账号不给该表写权限（REVOKE）。

## 8. JSONB 使用边界

允许：`document_logs.changed_fields`、单据扩展 `extra_data`、报表导出参数。
不允许：把核心可查询字段塞 JSONB（款号、数量、金额、状态一律独立列）。
理由：JSONB 字段无法建约束、无法统计、后期迁移痛苦。
