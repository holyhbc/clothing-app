## 1. 路径与版本

| 规则 | 说明 |
| --- | --- |
| 前缀 | `/api/v1` |
| 资源名 | 小写复数、连字符：`piecework-logs`、`stock-transfers` |
| 单资源动作 | 用子资源，不用动词：`/orders/{id}/approvals` |
| 非常规动作 | 允许动词子路径：`/piecework-logs/{id}/reverse` |
| 版本升级 | 不兼容变更必须 `/api/v2`；旧版本至少保留一个发布周期 |
| 健康检查 | `/healthz`（存活）、`/readyz`（依赖就绪），**不带前缀不进版本** |

```
POST   /api/v1/auth/login
GET    /api/v1/piecework-logs
GET    /api/v1/piecework-logs/{log_id}
POST   /api/v1/self/piecework-bindings                # 员工绑定款号+工序（员工端一律走 /self/**）
GET    /api/v1/self/piecework-bindings                # 员工看自己绑定
GET    /api/v1/self/piecework-bindable-operations?style_no=   # 该款可绑工序列表（来自 style_operations）
DELETE /api/v1/self/piecework-bindings/{binding_id}
POST   /api/v1/piecework/count                        # 工位机扫码计件（高频，独立路径）
GET    /api/v1/self/piecework/counts                  # 员工看自己今日/本月件数（员工端只在 /self/** 下暴露）
POST   /api/v1/piecework/settlements/{id}/reverse     # 红冲
GET    /api/v1/cutting-orders/{id}/logs
```

## 2. 请求规范

| 项 | 约定 |
| --- | --- |
| Content-Type | `application/json`（文件上传用 `multipart/form-data`） |
| 请求体 | Pydantic Schema 校验，`extra="forbid"` 拒绝未知字段 |
| 分页参数 | `page`（1 起）、`page_size`（默认 20，上限 200） |
| 排序 | `sort=-work_date,employee_id`（`-` 表示降序），**白名单字段**校验 |
| 时间 | ISO8601 带时区：`2026-08-15T10:30:00+08:00`；日期 `2026-08-15` |
| 金额 | 传字符串或数字，Schema 用 `condecimal`，响应统一 **string** 避免精度丢失 |
| 批量 | 上限 500 行/请求，超出分批 |
| 空值省略 | 请求体中用 `null` 清空，字段不传表示不改（PATCH 语义） |

```python
class PieceworkCountIn(BaseModel):
    model_config = ConfigDict(extra="forbid")

    bundle_no: str = Field(min_length=8, max_length=64)
    employee_id: UUID | None = None    # 员工端从 token 取；工位机端必传
    scanned_at: datetime
    station_id: str | None = Field(default=None, max_length=32)
```

## 3. 响应规范

```json
{
  "code": 0,
  "message": "ok",
  "data": { "id": "01JB...", "amount": "12.5000" },
  "request_id": "01JB..."
}
```

**列表统一结构**：

```json
{
  "code": 0,
  "data": { "items": [], "total": 0, "page": 1, "page_size": 20 }
}
```

| 规则 | 说明 |
| --- | --- |
| 成功 `code` | 恒为 `0` |
| HTTP 状态码 | 与业务码配合：HTTP 只表达传输层语义（400/401/403/404/409/422/500） |
| 金额/数量 | **一律字符串**，防止 JS 浮点丢精度 |
| 时间 | 一律 ISO8601 带时区 |
| 枚举 | 传字符串值（`"APPROVED"`），前端用 `shared/enums` 映射中文 |
| 不返回 | `deleted_at`、`created_by` 等内部字段；`remark` 保留 |
| 批量字段 | 避免 SELECT *，用显式 Schema |

**响应包装实现**：

```python
# app/core/responses.py
from typing import Generic, TypeVar
from pydantic import BaseModel, Field

T = TypeVar("T")


class PageData(BaseModel, Generic[T]):
    items: list[T]
    total: int
    page: int
    page_size: int


class ApiResponse(BaseModel, Generic[T]):
    code: int = 0
    message: str = "ok"
    data: T | None = None
    request_id: str | None = None


def ok(data: object = None) -> dict:
    return {"code": 0, "message": "ok", "data": data}


def page_ok(items: list, total: int, page: int, page_size: int) -> dict:
    return ok(PageData(items=items, total=total, page=page, page_size=page_size))
```

## 4. 错误码规范

**分段规则**：`HTTP状态 × 业务域 × 序号`

| 段位 | 域 | 归属 |
| --- | --- | --- |
| `10xxx` | 通用/参数 | 通用 |
| `11xxx` | 认证 | auth |
| `12xxx` | 权限 | auth |
| `20xxx` | 基础资料 | base |
| `30xxx` | 裁剪 | cutting |
| `31xxx` | 打菲 | bundling |
| `32xxx` | 计件 | piecework |
| `33xxx` | 工资 | payroll |
| `40xxx` | 库存 | stock |
| `50xxx` | 销售/往来 | sales |

**错误响应**：

```json
{ "code": 32002, "message": "该员工未绑定此工序", "data": null,
  "details": { "operation_no": "03" }, "request_id": "01JB..." }
```

**实现**：

```python
# app/core/errors.py
from enum import IntEnum


class ErrorCode(IntEnum):
    OK = 0
    PARAM_INVALID = 10001
    OPTIMISTIC_LOCK_CONFLICT = 10003
    UNAUTHORIZED = 11001
    FORBIDDEN = 12001
    DATA_SCOPE_DENIED = 12002
    STYLE_EXISTS = 20002
    CUTTING_QTY_CONFLICT = 30002
    BUNDLE_NOT_FOUND = 31001
    PIECEWORK_NOT_BOUND = 32002
    PIECEWORK_SETTLED = 32003
    STOCK_INSUFFICIENT = 40001
    VOUCHER_UNBALANCED = 60001
    INTERNAL = 99999


class BusinessError(Exception):
    def __init__(self, code: ErrorCode, message: str, details: dict | None = None) -> None:
        super().__init__(message)
        self.code = code
        self.message = message
        self.details = details or {}
```

```python
# app/main.py
@app.exception_handler(BusinessError)
async def handle_business_error(request: Request, exc: BusinessError) -> JSONResponse:
    return JSONResponse(
        status_code=HTTP_STATUS_BY_CODE.get(exc.code, 400),
        content={"code": int(exc.code), "message": exc.message,
                 "data": None, "details": exc.details,
                 "request_id": request.state.request_id},
    )
```

## 5. 幂等规范（计件等高频写接口强制）

| 规则 | 说明 |
| --- | --- |
| 幂等键 | 客户端可传 `Idempotency-Key` 头；未传时服务端按业务唯一键推导 |
| 命中行为 | **返回首次结果 + HTTP 200**，不返回错误（扫码枪会重发） |
| 存储 | Redis（TTL 24h）+ 数据库唯一索引双保险 |
| 冲突 | 同键不同 body → `10002` 报错 |

**两件事禁止混淆**：

| 情形 | 结果 | 含义 |
| --- | --- | --- |
| 同幂等键 + 同 body（扫码枪连扫、网络重试） | HTTP 200 `code=0`，返回首次记录 | 幂等命中，**不是错误** |
| 同打菲号本工序已被**他人**计件 | HTTP 409 `32004` | 业务冲突，需人工介入 |

```python
@router.post("/piecework/count", response_model=ApiResponse[PieceworkCountOut],
             tags=["计件"], summary="扫码计件")
async def count_piecework(
    payload: PieceworkCountIn,
    ctx: AuthContext = Depends(require_permission("piecework:count")),
    idempotency: IdempotencyKey = Depends(),
) -> ApiResponse[PieceworkCountOut]:
    result = await PieceworkService(ctx.session).count_piecework(payload, ctx.user_id)
    return ApiResponse(data=PieceworkCountOut.model_validate(result))
```

## 6. 权限声明规范

**每个接口必须声明**，缺一不可：

```python
@router.get(
    "/piecework-logs",
    response_model=ApiResponse[PageData[PieceworkLogOut]],
    tags=["计件"],                                     # OpenAPI 标签（必填）
    summary="计件流水列表",
    description="数据范围按车间/组别/本人过滤；员工端自动限本人",
)
async def list_piecework_logs(
    query: PieceworkLogQuery = Depends(),
    ctx: AuthContext = Depends(require_permission("piecework:read", scope="piecework_logs")),
) -> ApiResponse[PageData[PieceworkLogOut]]:
    ...
```

**权限点命名**：`<资源>:<动作>`，动作为 `read` / `create` / `update` / `delete` / `approve` / `reverse` / `export` / `count`。
例外：员工端自助接口用 `self:*` 前缀，如 `self:piecework:read`。

**数据范围**：`scope` 参数对应 `AuthContext` 的允许范围集合，由 service 层强制注入过滤条件。

## 7. OpenAPI 与文档

- 所有接口必须有 `tags`、`summary`；复杂逻辑补 `description`（含业务规则）
- Pydantic Schema 的 `Field(description=..., examples=[...])` 要写全，**这是给未来 AI 的主要上下文来源**
- 分组 tags：`认证`、`基础资料`、`裁剪`、`打菲`、`计件`、`工资`、`库存`、`销售`、`往来`、`财务`、`系统`
- 自动文档：`/docs`（Swagger）、`/redoc`；生产环境通过 Nginx 只对内网开放
- 变更接口后必须重新导出 `openapi.json` 供前端生成类型（见 06 规范）

## 8. SSE 规范（实时提示）

```
GET /api/v1/events/stream        （SSE，token 走 query 或 cookie）
Content-Type: text/event-stream

event: piecework_counted
id: 01JB...
data: {"bundle_no":"BD-...","style_no":"HB-2026-0001","operation_no":"03","employee_name":"张三","qty":1}
```

| 规则 | 说明 |
| --- | --- |
| 鉴权 | 建立连接时鉴权一次；断开后客户端重连 |
| 心跳 | 每 25s 发 `:ping`，防 nginx 60s 超时 |
| 事件名 | `<资源>_<动作>` 蛇形 |
| **禁止** | 用 SSE 下发业务写操作结果（员工确认必须查接口拿真值） |
| 降级 | SSE 失败时前端降级为 30s 轮询 |

## 9. Excel 导入 / 导出规范（REV-2026-10 新增）

### 9.1 导出

| 项 | 规范 |
| --- | --- |
| 入口 | **每个列表页右上角都有「导出」按钮**，与「新建」相邻 |
| 格式 | `.xlsx`（UTF-8，金额为**数值型**不是字符串，便于财务再计算） |
| 首行 | 表头 + 冻结首行 + 自动筛选 |
| 内容 | 与当前**筛选条件与数据范围**一致（导出与列表共用同一 service 方法，07 §3.2 铁律） |
| 单次上限 | 10 万行，超出报 `11011`，提示缩小时间范围 |
| 实现 | `openpyxl` 只写模式 + 流式 `SpooledTemporaryFile`；**禁止把全量数据读进内存** |
| 异步 | 超过 5 万行改为后台任务（Redis Stream），返回任务号，前端轮询下载 |
| 脱敏 | 含成本/工资的导出需 `*:export` + `system:export:manage`；导出记录写 `document_logs`（谁导了什么范围） |
| 文件名 | `{资源}_{筛选摘要}_{YYYYMMDD_HHmm}.xlsx` |

### 9.2 导入（**三步式**，禁止"上传即入库"）

```
[1] 下载模板  →  [2] 上传文件（只校验，不入库）  →  [3] 确认导入（入库）
```

**导入流程与规则**：

| 步骤 | 接口 | 说明 |
| --- | --- | --- |
| 1. 下载模板 | `GET /api/v1/imports/{resource}/template` | 返回带**字段说明页**与**示例行**的 xlsx；未填列删除 |
| 2. 上传校验 | `POST /api/v1/imports/{resource}/validate`（multipart） | **不写库**。返回逐行校验结果 |
| 3. 确认导入 | `POST /api/v1/imports/{resource}/commit` | 带 `upload_id`，**单事务**入库 |

**校验响应格式**：

```json
{
  "code": 0,
  "data": {
    "upload_id": "01JB...",
    "total": 128,
    "valid": 120,
    "invalid": 8,
    "can_commit": false,
    "errors": [
      { "row": 7,  "field": "dye_lot_no", "message": "缸号不能为空" },
      { "row": 23, "field": "width_cm",  "message": "门幅必须是 > 0 的数字，当前值 '约1.5'" },
      { "row": 41, "field": "supplier",  "message": "供应商编码 SUP-0009 不存在或已停用" }
    ],
    "preview": { "items": [], "total": 120 }
  }
}
```

| 规则 | 说明 |
| --- | --- |
| 有错误时 `can_commit=false` | 前端必须显示错误行表格 + 「下载错误明细」，**不允许静默跳过错误行** |
| 错误明细可下载 | 生成带原始行号与错误说明的 xlsx，用户改完重传 |
| 行数上限 | 5000 行（`10009`） |
| 文件格式 | 仅 `.xlsx`（表头不匹配 → `11007`） |
| 幂等 | 同一 `upload_id` 重复 commit 返回首次结果（Redis 幂等键） |
| 事务 | commit 时**全部行一个事务**，任一行失败整体回滚 |
| 校验顺序 | 格式 → 必填 → 引用完整性（外键存在且启用）→ 业务规则（如区间重叠 `20005`、比例缺配 `20006`） |
| 审计 | commit 成功写 `document_logs`（`action='IMPORT'`，`changed_fields` 记行数与来源文件名） |
| 权限 | 需模块的 `*:import` **且** `system:import:manage` |

## 9.5 模糊查询与可搜索选择器规范（INV-9，REV-2026-10 新增）

**背景**：款号 / 客户 / 供应商 / 物料 / 工序 / 缸号 会随时间累积到数千条，原生 `<select>` 下拉必须肉眼滚动，既慢又容易选错。**所有"选择某主数据"的场景必须支持模糊查询。**

### 9.5.1 通用查询参数（所有 `GET /api/v1/**` 列表接口强制）

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `q` | string | **模糊关键字**：对「编码 + 名称 + 常用副标识」做 `ILIKE '%q%'`（**大小写不敏感、去首尾空格**）。多个关键字用空格分隔 → **AND** 关系 |
| `page` / `size` | int | 分页；`size` 默认 `20`、**上限 `100`**（候选下拉强制 `size ≤ 20`） |
| `sort_by` / `sort_order` | string | 白名单字段 + `asc`/`desc`，**禁止拼接 SQL** |
| `active_only` | bool | 默认 `true`：只返回启用数据（停用/删除的不进候选） |

**返回体**统一用 §3 的分页结构；候选下拉接口额外返回 `matched_field`（命中的是编码还是名称）与 `highlight`（前端高亮片段，可选）。

### 9.5.2 专用候选搜索接口（给选择器用）

| 用途 | 路径 | 说明 |
| --- | --- | --- |
| 款号 | `GET /api/v1/styles/options?q=` | 返回 `style_no` / `style_name` / `customer_name` / `product_category` / `last_used_at`；默认按 `last_used_at DESC`（常用优先） |
| 客户 | `GET /api/v1/customers/options?q=` | `code` / `name` / `contact` |
| 供应商 | `GET /api/v1/suppliers/options?q=` | `code` / `name` / `contact` |
| 物料 | `GET /api/v1/materials/options?q=` | `code` / `name` / `spec` |
| 工序 | `GET /api/v1/operations/options?q=` | `op_no` / `name` |
| 颜色 / 尺码 | `GET /api/v1/colors/options?q=`、`/sizes/options?q=` | 编码 + 名称 |
| 布批（缸号/匹号） | `GET /api/v1/material-stocks/options?q=&supplier_id=&material_id=` | **必须带 `available_qty > 0`**（ADR-0022）；返回 `dye_lot_no` / `bolt_no` / `width_cm` / `available_qty` |

规则：
- **不得**为选择器返回全量数据（超过 200 条就必须搜索）。
- 关键字**最小 1 个字符**即可搜（编码场景），名称场景可要求 ≥ 1 字符；`q` 为空时只返回**最近使用 / 默认排序的前 20 条**。
- 选择器一律**只显示停用项为已停用样式**，不可直接选中（需提示"已停用，是否启用"）。
- 已选项必须**回显为「编码 + 名称」**，禁止只显示编码。

### 9.5.3 前端交互（强制）

| 要求 | 口径 |
| --- | --- |
| 控件 | **可搜索下拉（Combo）**：输入框 + 候选列表；**禁止**超过 30 项的裸 `<select>` |
| 防抖 | 输入 **300ms** 防抖；`Enter` 直接选中高亮项；`↑/↓` 移动、`Esc` 关闭 |
| 空态 | 无匹配时显示「无匹配结果」+ 「新建 xxx」入口（若该主数据允许新建，如颜色/尺码/款号） |
| 失效项 | 已选值被停用/删除时，标签显示红色并提示 `20003`/`20005` |
| 移动端 | 员工端不使用复杂选择器，工序绑定走扫码 + 少量候选（≤ 20） |

### 9.5.4 性能与索引

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
-- 候选搜索走三元组 GIN 索引，禁止全表 ILIKE 扫描
CREATE INDEX idx_styles_trgm      ON styles          USING gin ((style_no || ' ' || style_name) gin_trgm_ops);
CREATE INDEX idx_customers_trgm   ON customers       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_suppliers_trgm   ON suppliers       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_materials_trgm   ON materials       USING gin ((code || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_operations_trgm  ON operations      USING gin ((op_no || ' ' || name) gin_trgm_ops);
CREATE INDEX idx_material_stocks_trgm ON material_stocks USING gin (dye_lot_no gin_trgm_ops);
```

- 关键词**必须走索引**（`EXPLAIN` 出现 `Bitmap Index Scan`），否则视为未通过评审。
- 结果集**硬上限 100 行**；超过先收窄条件，禁止"先取全量再前端过滤"。
- 选择器接口**必须禁止深分页**（`offset > 10000` 直接 `10001`）。
