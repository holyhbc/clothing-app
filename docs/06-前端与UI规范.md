# 06 前端与 UI 规范

> 目标：**好看且易用**。AI 生成的页面必须符合本文，否则视觉与交互会七零八落。
> 原则：PC 端**密度优先**（工厂用户看表格），员工端**大按钮优先**（戴手套/车间光线差）。

| 已审核 APPROVED | 绿 `--color-success` | 已审核 |
| 已驳回 REJECTED | 红 `--color-danger` | 已驳回 |
| 已作废 CANCELLED | 灰 `--color-info`（+ 删除线） | 已作废 |

前端映射集中在 `packages/shared/enums/status.ts`，禁止在页面里写 `switch`。

## 2. PC 端页面规范（Ant Design Vue 5）

### 2.1 布局

```
┌──────────────────────────────────────────────────────────────┐
│ Header 48px：Logo | 菜单折叠 | 面包屑 | 消息 | 用户          │
├──────────┬───────────────────────────────────────────────────┤
│ Sider    │ Content：PageHeader（标题+操作区）                 │
│ 200px    │            FilterCard（查询条件，可折叠）           │
│ 菜单     │            TableCard（表格 + 分页）                │
│ 按模块   │                                                    │
└──────────┴───────────────────────────────────────────────────┘
```

| 区域 | 规范 |
| --- | --- |
| 菜单 | 两级：模块 → 功能。默认收起二级（`inlineCollapsed=false`），超过 20 项用左侧折叠 |
| 内容区 | 24px 内边距，最大宽度 1680px 居中（超宽屏不要拉满，边距观感更稳） |
| 页面标题 | 20px/600，与操作按钮同一行右侧 |
| 操作区 | 主操作 1 个（`primary`），其余 `default`；危险操作（反审核/作废）放 `...` 下拉并二次确认 |

### 2.2 列表页标准结构（所有模块 List.vue 统一）

```
PageHeader: 标题 | [导出] [新建]
FilterCard:  查询条件表单（默认 3 个字段，"更多条件"展开）
TableCard:
  - 工具栏：已选 N 项时的批量操作（禁用状态显式）
  - 表格：默认 20 条/页，列宽固定不跳动，操作列固定右侧
  - 分页：右下角，显示总数
```

**表格列规范**：
- 金额列**右对齐**、等宽字体（`font-variant-numeric: tabular-nums`）
- 单号/款号/打菲号列**不换行**，超长省略 + Tooltip（`bundle_no` 要能完整复制）
- 状态列用 `StatusTag` 组件，不用纯文字
- 操作列：最多直接显示 3 个，其余进下拉；**破坏性操作不用红色文字按钮**（避免误点），放 `...` 菜单
- 空状态用 Ant Design `Empty`，文案给下一步动作（"还没有裁剪单，点右上角新建"）
- 加载中用表格内 `Skeleton` 或 `Spin`，**禁止整页闪烁**

### 2.3 详情页标准结构

```
面包屑 + 单号（可复制） + 状态 Tag
描述列表 Descriptions（横排 3 列，主信息在上）
  - 基本信息 / 款号信息 / 数量金额 / 审核信息
明细表格（可折叠，按 line_no 排序）
底部汇总（数量合计、金额合计，右对齐，等宽字体）
操作区（右上，sticky）：
  草稿：编辑 | 提交 | 删除
  待审核：审核 | 驳回 | 撤回
  已审核：反审核 | 打印 | 复制
变更历史（Drawer，展示 document_logs：时间/操作人/动作/从→到/原因）
```

### 2.4 表单规范

| 项 | 规范 |
| --- | --- |
| 布局 | 3 列（`labelCol 6`），字段少时 2 列；必填项 label 带红色 `*` |
| 校验 | `blur` 触发（不是 change，避免刚输入就报错）；提交时全量校验并滚动到第一个错误 |
| 数字 | 金额 `InputNumber` 精度 4，工价精度 6，数量精度 3；**禁止 `type="number"` 原生** |
| 下拉 | 有 100+ 项用远程搜索（如物料、客户），前缀搜索 + 防抖 300ms |
| 日期 | `RangePicker` 显示格式 `YYYY-MM-DD`，禁用手输 |
| 明细行 | 用可编辑表格，行内校验；支持"复制上一行"（裁剪/打菲高频操作） |
| 提交 | 提交后按钮 loading 禁用防重复；失败保留用户输入 |
| 只读 | 已审核单据所有字段 `disabled` 并提供"复制新建"入口 |

### 2.5 扫码交互（工位机页面，工厂核心体验）

```
┌─────────────────────────────────────────────┐
│  款号 HB-2026-0001   工序 03 拼前           │
│  员工 张三   今日 128 件 / ¥ 268.50         │
├─────────────────────────────────────────────┤
│                                             │
│   ┌─────────────────────────────┐           │
│   │      ⌨ 等待扫码…            │  ← 全局捕获，非输入框
│   │   BD-20260815-000045-0000123 │           │
│   └─────────────────────────────┘           │
│  成功计数 128    重复提示 3    今日合计 ¥268.50 │
└─────────────────────────────────────────────┘
```

**必须实现的交互细节**：
1. 页面加载后**立即 focus 到页面级监听**，用户不需要点任何地方就能扫
2. 扫码成功后：计数 +1、金额累加、**播放一声短提示音**、绿色边框闪烁 200ms
3. 重复扫码（该码本工序已完成）：黄色提示 + 显示已有记录，**不报错弹窗打断操作**（一个工人一连扫几十件，弹窗会拖慢产线）
4. 扫码失败：红色提示 + 短音，**清空缓冲准备下一次**
5. 数字大字显示（`--font-size-2xl` 以上，`tabular-nums`），远处可读
6. 网络异常：本地队列缓存（见 07 §7），界面明确显示"离线缓存 N 条"
7. 提供「暂停扫码」开关，防止过账时误扫

## 3. 员工端 H5 规范（Vant 4）

**用户**：车工、查勘。用手机、可能戴手套、光线差、网络差。
**目标**：3 秒内看到"我今天做了多少、多少钱"。

### 3.1 页面清单（只做这 5 个，不要多）

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 登录 | `/m/login` | 手机号 + 短信验证码（首次可由管理员预建账号） |
| 首页 | `/m` | 今日件数/金额大字卡 + 当前绑定工序 + 快捷入口 |
| 绑定工序 | `/m/bind` | 扫打菲二维码 → 自动填款号 → 选工序 → 确认 |
| 我的 | `/m/me` | 当期明细、我的绑定列表、历史工资单 |
| 工资 | `/m/payroll` | 按期展示结算件数与金额：已审核显示实际值；未审核显示预估值并标注"含未审核，以最终为准"（口径见 §3.2） |

### 3.2 移动端规范

| 项 | 值 |
| --- | --- |
| 设计宽度 | 375px 基准，`postcss-px-to-viewport` 关闭，用相对单位 + 安全区适配 |
| 触控目标 | 最小 **48×48px**，主要按钮高度 ≥ 50px |
| 字号 | 正文 ≥ 15px，关键数字 ≥ 24px |
| 安全区 | `env(safe-area-inset-bottom)` 适配 iPhone 底部横条 |
| 微信适配 | `<meta name="viewport" content="width=device-width,initial-scale=1,maximum-scale=1,user-scalable=no">` |
| 扫码 | 优先 `html5-qrcode` 调起摄像头；失败降级为手动输入 `bundle_no`（**必须保留**） |
| 首页加载 | 关键数字接口 P95 <300ms，加载骨架屏 |
| 手势 | 不用需要精确点按的小控件；下拉刷新 + 上拉加载 |

**金额显示规则（唯一口径，REV-2026-10 修订）**：员工端金额显示到分（`¥268.50`）。
已审核结算显示实际值并标"已审核"；未审核结算**显示预估值**并标"预估，含未审核，以最终为准"。
未审核数据**不是**隐藏而是标注 —— 因为工人需要看到当天进度，隐藏会引发投诉。

## 4. 标签打印规范（打菲二维码）

| 项 | 规范 |
| --- | --- |
| 标签尺寸 | 40mm × 40mm（不干胶），预留打印偏移 2mm |
| 内容 | 款号 / 颜色 / 尺码 / 打菲号 / 工序名 / 二维码 / 条码 |
| 二维码 | 内容纯文本 `bundle_no`，纠错等级 **M**，尺寸 ≥ 20mm（保证扫码距离） |
| 条码 | Code 128，字符集 B |
| 打印方式 | 优先浏览器打印（`@media print` + 尺寸标签页）；次选导出 PDF/CSV 给标签软件 |
| 批量 | 一次选中多扎 → 打印预览网格 → 支持部分重打（重打必须写日志） |
| 打印样式 | `@page { size: 40mm 40mm; margin: 0 }`，隐藏所有交互元素 |

**打印页必须**提供"打印张数"输入与序号（重打第几件），便于与实物核对。

## 5. 状态与错误反馈规范

| 场景 | 反馈方式 | 文案要求 |
| --- | --- | --- |
| 加载中 | Skeleton / Spin | — |
| 成功 | `Message.success` 2s 自动消失 | 动词，如"已审核" |
| 业务错误 | `Message.error` 常驻 + 可关闭 | **说清楚为什么 + 下一步**，如"库存不足，可用 30，需 50" |
| 表单错误 | 行内红字 | 字段级，精确到输入框下方 |
| 网络错误 | 全局提示 + 重试按钮 | "网络异常，请检查后重试" |
| 无权限 | 页面级空态 403 页 | "您没有访问此页面的权限" + 申请入口 |
| 危险确认 | `Modal.confirm` + **必填原因输入** | "反审核后已生成的计件将失效，请填写原因" |
| 空数据 | `Empty` + 下一步动作 | 见 2.2 |

**禁止**：`alert()` / `confirm()` 原生弹窗；纯技术错误信息直接抛给用户（如 "500 Internal Server Error" 必须换成业务文案 + request_id）。

## 6. 响应式与浏览器支持

| 端 | 断点 | 要求 |
| --- | --- | --- |
| PC 小屏 | <1366px | 表格横向滚动，筛选区折叠为两行 |
| PC 常规 | 1366-1920 | 主设计区间 |
| PC 大屏 | >1920 | 内容居中限宽 1680px |
| 平板 | 768-1366 | 侧栏自动折叠成图标 |
| 手机 | <768 | PC 端给"请用手机端"提示（员工端路由自动分流） |

支持：Chrome/Edge 最新两个大版本、Safari 最新两个大版本；不做 IE 兼容。

**工厂现场附加要求**：
- 允许浏览器 125%/150% 缩放不破版
- 关键页面（计件工位机、审核列表）在 **1920×1080 与 1366×768** 两种分辨率下验收
- 所有按钮有 `title` 或 Tooltip（工人可能不识字/记不住图标）

## 7. 前端类型生成流程（防止前后端不一致）

```bash
# 后端启动后导出
curl -s http://localhost:8000/openapi.json > frontend/packages/shared/api-schema.json

# 生成 TS 类型（禁止手写接口类型）
cd frontend && pnpm generate:api
```

**规则**：
- 接口类型只允许在 `api-schema.json` → `packages/shared/types/` 中生成
- 页面**禁止**手写接口 DTO；确有需要用 `Omit<>` / `Pick<>` 组合
- 枚举值来自后端，前端只做 `中文映射`，不重新定义取值

## 10. 可搜索选择器规范（INV-9，REV-2026-10 新增，强制）

**背景**：款号 / 客户 / 供应商 / 物料 / 工序 / 颜色 / 缸号 会随时间累积到数千条，裸 `<select>` 必须肉眼滚动，效率极低且容易选错。

| 要求 | 口径 |
| --- | --- |
| 组件 | **必须用 `<Combo>` 可搜索下拉**；**候选 > 30 项禁止裸 `<select>`** |
| 匹配 | 对「编码 + 名称 + 副标识」做**模糊匹配**（大小写不敏感）；命中片段高亮 |
| 交互 | 输入即搜（后端 300ms 防抖）；`↑/↓` 移动、**`Enter` 选中高亮项**、`Esc` 关闭、点击外部关闭 |
| 候选上限 | 空关键字返回最近使用 / 默认排序 **前 20 条**；超 20 条提示「请继续输入关键字」（对应 05 §9.5 硬上限） |
| 回显 | 已选项显示**「编码 + 名称」**，禁止只显示编码 |
| 空态 | 显示「无匹配结果」+ **「＋ 用 xxx 新建」入口**（该主数据允许新建时，如款号 / 颜色 / 尺码） |
| 失效项 | 选中项被停用时标红提示（`20003` / `20005`），**不可直接提交** |
| 状态 | 加载中显示骨架/转圈；请求失败显示「搜索失败，点此重试」，**不得静默清空** |
| 唯一性 | 款号 / 客户 / 供应商编码唯一，冲突返回 `10001` 并回显「已存在：{名称}」 |
| 移动端 | 员工端不做复杂选择器：工序绑定走**扫码**，候选 ≤ 20 |

实现基线：PC 端 `components/Combo.vue`（对应 [05 §9.5](./05-接口设计规范.md) 接口规范 + [04 §5.1](./04-数据库规范.md) 索引规范）。

**反例**（禁止）：
```
<select>  <!-- 300 个款号要滚动选 -->
<select>  <!-- 每次打开都拉全量 /options 接口 -->
```

**正例**：
```
<Combo v-model="form.styleNo"
       :options="styleOptions"        <!-- GET /styles/options?q= -->
       placeholder="输入货号或款名搜索…"
       create-text="＋ 用「{kw}」新建款号" />
```

## 8. UI 走查清单（新页面合入前）

- [ ] 无硬编码颜色/间距，全部走 token
- [ ] 金额右对齐 + 等宽数字；单号可复制
- [ ] 状态 Tag 用统一组件，色值一致
- [ ] 空状态/加载/错误/无权限 四态齐全
- [ ] 表格列宽稳定，分页显示总数
- [ ] 危险操作有二次确认 + 必填原因
- [ ] 表单 blur 校验，错误定位到字段
- [ ] 提交防重复（loading + disable）
- [ ] 权限点齐全：显隐 + 禁用 + 后端 403
- [ ] PC 端在 1366×768 不横向破版
- [ ] 员工端按钮 ≥48px，金额显示到分并标注审核状态
- [ ] 打印页尺寸正确，二维码实测可扫
- [ ] 键盘可完成全部操作（工位机不用鼠标）
