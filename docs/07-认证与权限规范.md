# 07 认证与权限规范

> 权限是本项目的合规底线：**工资数据、库存成本、单据审核**必须严格隔离。
> 实现原则：前端控制"看得见"，后端控制"能不能做"。**后端是唯一可信边界。**

---

## 1. 认证方式

### 1.1 PC 管理端

| 项 | 规范 |
| --- | --- |
| 登录 | `POST /api/v1/auth/login`，账号 + 密码（首次强制改密） |
| 密码哈希 | **argon2id**（`pwdlib[argon2]`），禁止 MD5/SHA1/裸存 |
| 密码策略 | 长度 ≥ 8，含字母与数字；90 天强制更换；连续 5 次失败锁定 15 分钟 |
| Access Token | JWT，`HS256`，有效期 **15 分钟**，存 `Authorization: Bearer` |
| Refresh Token | 有效期 7 天，存 **HttpOnly + Secure + SameSite=Lax Cookie**，存库可吊销 |
| Token 载荷 | `{ sub: user_id, role_ids: [], scopes: [], type: 'access' }`，**不放权限明细**（权限查库，避免权限变更不生效） |
| 登出 | 服务端吊销 refresh token + 前端清 localStorage |
| 2FA | 财务与总经理角色强制要求（后续里程碑） |

### 1.2 员工端 H5

| 项 | 规范 |
| --- | --- |
| 登录 | **手机号 + 短信验证码**（阶段一）；预留微信授权（ADR-0003） |
| Token 有效期 | 2 小时 |
| 设备绑定 | 记录 `device_id`（首次生成存 localStorage）；同一账号新设备登录可配置为拒绝或通知 |
| 会话续期 | refresh token 30 天 |
| 员工自助范围 | **只能访问 `/api/v1/self/**` 系列接口**，不暴露管理端接口 |

```python
        """用前端传来的临时 code 换取身份并验证。"""
        ...

    async def get_user_by_external(self, identity: ExternalIdentity) -> Employee | None:

        ...
```

**当前实现**：`SmsAuthProvider`（阶段一）。
**后续**：`WeComAuthProvider` / `WeChatMiniAuthProvider`，实现同接口 + `Employee.external_id_map` 一张映射表即可，业务代码零改动。

> 企业微信自建应用 / 公众号网页授权 / 小程序均需**企业主体认证**（企业 300 元/年，个体工商户优惠期 30 元，个人主体不支持认证）。因此阶段一走 H5 短信登录，认证通过后再切 `AuthProvider`，零风险渐进。

### 2.2.1 权限点的落点（加权限点时要改哪几个地方）

> ⚠️ **为什么需要这张表**：本表的「权限点」列是**声明**，而权限点真正生效要经过下面
> 五道关。少改一处不会报错，只会让那个权限「看起来配了、实际不生效」，或者
> 「界面上没有按钮但接口放行了」。**已踩过两次**（`cutting:import` 漏登记、
> ADR-0008 新增 8 个动作时漏了 `reject`/`withdraw`）。
>
> ⚠️ **顺序不能变**：先改 `permissions_registry.py`，再重生成前端常量，最后跑
> 迁移 —— 反过来做的话，前端会引用到一个 `permissions` 表里还没有的 code。

| 步骤 | 改哪 | 干什么 | 忘了会怎样 |
| --- | --- | --- | --- |
| 1 | [`permissions_registry.py`](../backend/app/common/permissions_registry.py) | 在 `PERMISSIONS` 里加 `Permission(code, name, module, action)`，并在需要时挂到 `ROLES` 的某个角色 | `seed_baseline` 写不进这张表，**新权限点不存在**（`10003`/`12001` 全都指向它） |
| 2 | 本文件 §2.2 的模块表 | 加进对应模块那一行的权限点列表 | 后端有、前端 `PERM` 常量里没有 → **界面永远显示不出**这个操作 |
| 3 | `frontend/scripts/generate-frontend-contract.mjs` 重跑 | 生成 `packages/shared/src/enums/permissions.ts`（含中文名 `PERMISSION_NAMES`） | 前端引用一个不存在的常量 → **TS 编译红**（这条是好事，比静默失败强） |
| 4 | 新迁移（`alembic/versions/00XX_*.py`） | `INSERT INTO permissions`（用 `ON CONFLICT (code) DO NOTHING`），撤销时**不要** `DELETE` | 已部署的环境拿不到新权限点；`seed_baseline` 虽能补，但**生产库不跑 seed** |
| 5 | `tests/modules/test_permission_registry.py` | 更新断言里的权限点总数 / 模块清单 | 闸门 3 红，报「文档与代码不一致」 |

> 「registry ↔ 迁移 ↔ 生成物」三方一致，**管不到本文件**）。所以改权限点时
> **必须**顺手改这里 —— 守卫抓不到的那一处，正是最容易漏的。

## 3. 后端权限实现

### 3.1 AuthContext 与依赖

```python
# app/core/permissions.py
from dataclasses import dataclass, field
from uuid import UUID

from fastapi import Depends
from sqlalchemy.ext.asyncio import AsyncSession

from app.common.enums import DataScope
from app.modules.auth.service import AuthService


@dataclass(frozen=True)
class AuthContext:
    user_id: UUID
    name: str
    employee_no: str
    workshop_id: UUID | None
    group_no: str | None
    permissions: frozenset[str]
    data_scope: DataScope
    allowed_workshop_ids: frozenset[UUID] = field(default_factory=frozenset)
    session: AsyncSession = None  # 实际不放 session，用 Depends(get_db) 单独注入

    def has(self, permission: str) -> bool:
        return "*" in self.permissions or permission in self.permissions


async def get_auth_context(
    session: AsyncSession = Depends(get_db),
    credentials: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> AuthContext:
    if credentials is None:
        raise BusinessError(ErrorCode.UNAUTHORIZED, "未登录")
    payload = await decode_token(credentials.credentials)
    if payload.get("type") != "access":
        raise BusinessError(ErrorCode.UNAUTHORIZED, "令牌类型错误")
    user = await AuthService(session).get_active_user(UUID(payload["sub"]))
    return user.to_auth_context()
```

```python
def require_permission(permission: str, scope: str | None = None) -> Callable[..., AuthContext]:
    """接口级权限声明。scope 为数据范围字段名（表名），由 service 强制注入过滤。"""
    async def dependency(ctx: AuthContext = Depends(get_auth_context)) -> AuthContext:
        if not ctx.has(permission):
            raise BusinessError(ErrorCode.FORBIDDEN, f"无权限执行该操作：{permission}")
        return ctx
    return dependency
```

### 3.2 数据范围强制过滤（**必须在此层，不许放 Router**）

```python
# app/core/scope.py
from sqlalchemy import Select
from typing import TypeVar

T = TypeVar("T")


def apply_data_scope(stmt: Select, model: type[T], ctx: AuthContext, *, user_column: str | None = None) -> Select:
    """按 AuthContext.data_scope 给查询加过滤。service 层第一行就要调。"""
    match ctx.data_scope:
        case DataScope.FACTORY:
            pass
        case DataScope.WORKSHOP:
            allowed = ctx.allowed_workshop_ids or ({ctx.workshop_id} if ctx.workshop_id else set())
            if not allowed:
                return stmt.where(False)   # 无车间 → 查不到任何数据
            stmt = stmt.where(model.workshop_id.in_(allowed))
        case DataScope.GROUP:
            stmt = stmt.where(model.workshop_id == ctx.workshop_id, model.group_no == ctx.group_no)
        case DataScope.SELF:
            if user_column is None:
                return stmt.where(False)
            stmt = stmt.where(getattr(model, user_column) == ctx.user_id)
        case _:
            return stmt.where(False)
    return stmt.where(model.deleted_at.is_(None))   # 软删过滤在此统一附加
```

**反例（禁止）**：
```python
# ❌ 让前端传 workshop_id 决定范围
@router.get("/piecework-logs")
async def list_logs(workshop_id: UUID | None = None, ...):
    return await service.list(workshop_id)   # 越权风险

# ❌ 只在 Router 里过滤，service 的其他调用绕过
# ❌ 用 if ctx.is_admin 硬编码角色名，不用权限点
```

**铁律**：
1. 每个列表/详情/导出 service 方法的第一行是 `stmt = apply_data_scope(stmt, Model, ctx, user_column="employee_id")`
2. 详情方法额外校验：`if not in_scope(doc, ctx): raise DATA_SCOPE_DENIED`（防越权按 ID 查）
3. 导出接口与列表**共用同一 service 方法**，禁止另写导出路径

### 3.3 写操作的额外校验

| 操作 | 额外校验 |
| --- | --- |
| 审核 | ① 操作人 ≠ 制单人（自己不能审自己的单，除非 `factory_manager`）；② 当前状态必须是 `SUBMITTED`；③ 反审核必填原因 |
| 反审核 | ① 当前状态 `APPROVED`；② 下游单据已生成时禁止（如工资已发放 → 只能红冲，见 `33001`）；③ 必填原因，写日志 |
| 作废 | 同反审核，作废与反审核是不同动作，作废不可恢复 |
| 修改基础资料单价 | 已有计件/库存引用时**只允许影响未来**，不得 UPDATE 历史 |
| 删除 | 只能软删；被引用时禁止（返回 `20003`） |

```ts
import type { Directive } from 'vue'
import { useAuthStore } from '@/stores/auth'

export const permission: Directive<HTMLElement, string | string[]> = {
  mounted(el, binding) {
    const auth = useAuthStore()
    const required = Array.isArray(binding.value) ? binding.value : [binding.value]
    if (!required.some((code) => auth.has(code))) {
      el.remove()
    }
  },
}
```

```vue
<a-button v-can="'cutting:approve'">审核</a-button>
<a-button v-can="['payroll:approve', 'payroll:pay']">工资发放</a-button>
```

**规则**：
- `v-can` 控制**显示**；控制**禁用**用 `:disabled="!auth.has('xxx')"` 并配 Tooltip 说明原因
- 路由守卫：菜单项按权限过滤；直接访问无权限路由跳 403 页
- **员工端无 `v-can` 概念**（只有 `self:*` 固定集合），接口端已锁死

## 5. 审计与合规

| 要求 | 实现 |
| --- | --- |
| 权限变更留痕 | 角色/权限/数据范围变更写 `document_logs`（`doc_type='Role'`） |
| 登录日志 | 成功/失败/登出写 `auth_login_logs`（IP、UA、时间） |
| 敏感操作日志 | 审核、反审核、作废、单价调整、凭证过账、成本查看全部记日志 |
| 成本可见性 | `stock:cost:view` 独立权限；仓管看不到成本单价，接口层过滤 `unit_cost` 字段 |
| 工资保密 | 员工端只能看自己；主管看本车间需 `payroll:read`；导出工资表需 `payroll:export` |
| 日志不可删 | `document_logs` 无 UPDATE/DELETE 权限（DB 层 REVOKE） |

## 6. 新增角色/权限的操作流程（AI 执行规范）

1. 在 `docs/modules/08-基础资料与往来.md` 或本文件 §2.2 登记权限点
2. 写 Alembic 迁移插入 `permissions` 记录（幂等：`ON CONFLICT DO NOTHING`）
3. 若新增角色 → 插入系统角色 + 绑定权限，**用 `is_system=true` 标记**
4. 补测试：接口权限拒绝用例（403）+ 数据范围越权用例（403/空列表）
5. 更新前端 `packages/shared/enums/permissions.ts` 权限点常量
6. 更新 `docs/12` 变更记录

**禁止**：把权限点写死在页面里而不在 `permissions` 表登记——否则无法审计"谁被授权了什么"。

## 7. 员工端离线与扫码容错

工厂网络差，计件必须能扛住：

| 机制 | 实现 |
| --- | --- |
| 本地队列 | 工位机页（PWA/IndexedDB）与员工端（localStorage）缓存待提交流水 |
| 重试 | 指数退避（1s/2s/4s/8s/30s），最多 8 次 |
| 幂等 | 重试携带同 `bundle_no`，服务端幂等返回既有记录（见 05 §5） |
| 冲突提示 | 同码被他人计件 → 明确提示"该件已由张三完成"，不静默丢弃 |
| 状态显示 | 页面顶部常驻条：`在线` / `离线（缓存 N 条待提交）` |
| 数据归属 | 离线缓存必须记 `device_id` + `scanned_at`，服务端以 `scanned_at` 为准归属日期 |
