# 09 领域术语与编码规则

> **动手写任何业务代码前必须读本文。** 服装行业术语不统一是 AI 写错业务的最大来源。
> 本文中「系统字段名」为强制统一命名，代码、数据库、接口、前端一律照用，不得自行发明同义词。

### 1.5b 裁剪排版口径（REV-2026-10 新增，见 [ADR-0013](./adr/0013-裁剪尺码比例与手数.md)）

| 项 | 口径 |
| --- | --- |
| 比例维度 | **款号 × 颜色 × 尺码** → 手数。同款不同颜色比例可不同 |
| 每手件数 | **尺码明细级输入**（整数），每次裁剪可不同；同一尺码可多行且每手件数不同（ADR-0014 + ADR-0020） |
| **录入模式** | **A 按比例带出**（`MASTER`）/ **B 统一件数**（`UNIFORM`，所有尺码件数一样）/ **C 自定义明细**（`MANUAL`，个别尺码不一致）；挂在**行内颜色级** `cutting_order_line_colors.entry_mode`（ADR-0017 下沉）；**比例只是建议值，手数才是权威输入** |
| 明细计算 | **件数 = `hands × qty_per_hand`（整数 × 整数，精确值，不取整不四舍五入）**；`hands` 必须为**正整数**（否则 `30006`）；仅人工指定件数时差额并入 `balance_qty`（ADR-0020 取代原 floor 口径） |
| 同尺码多行 | 允许（如 XL 2手×60件 + XL 1手×30件 = 150 件），**不写回比例主数据** |
| 耗料计算 | 该尺码耗料 = 该尺码件数 × BOM.单件用量 + 该尺码损耗 |
| 顺序 | **先比例算件数，再算耗料**；不是从 BOM 反推件数 |
| 单据覆盖 | 裁剪单可临时覆盖比例，必填原因（`10006`），不改主数据，写日志 |
| 门幅校验 | 审核裁剪单时校验所选批次的 `effective_width_cm` 是否满足该款铺布要求 |

**示例**（红色 L:XL:XXL:3XL = 1:2:2:1，本次每手 100 件）：

| 尺码 | ratio（手） | 计算 | 件数 |
| --- | --- | --- | --- |
| L | 1.0000 | floor(1 × 100) | 100 |
| XL | 2.0000 | floor(2 × 100) | 200 |
| XXL | 2.0000 | floor(2 × 100) | 200 |
| 3XL | 1.0000 | floor(1 × 100) | 100 |
| **合计** | **6.0000 手** | | **600 件** |

## 2. 编码规则（唯一强制）

### 2.1 单据号规则

格式：`{前缀}-{YYYYMMDD}-{6 位序号}`

| 单据 | 前缀 | 示例 |
| --- | --- | --- |
| 裁剪单 | `CT` | `CT-20260815-000123` |
| 打菲单 | `BD` | `BD-20260815-000045` |
| 完工入库单 | `FG` | `FG-20260816-000201` |
| 采购单 | `PO` | `PO-20260810-000012`（含缸号/颜色/门幅/重量/匹数/用途/备注） |
| 领料出库单 | `MI` | `MI-20260815-000088` |
| 调拨单 | `TR` | `TR-20260816-000007` |
| 盘点单 | `SC` | `SC-20260831-000003` |
| 销售订单 | `SO` | `SO-20260801-000021` |
| 发货单（发货即出库） | `SH` | `SH-20260820-000066` |
| 收款单 | `SK` | `SK-20260825-000015` |
| 付款单 | `PY` | `PY-20260825-000018` |
| 核销单 | `ST` | `ST-20260826-000009` |
| 客户对账单 | `SN` | `SN-202608-000031` |
| 计件结算单 | `PW` | `PW-20260831-000005` |
| 工资单 | `PR` | `PR-20260831-000005` |
| 记账凭证 | `VO` | `VO-2026-08-000123` |

> **REV-2026-10 前缀修订**：
> ① 原表把销售出库单与销售订单都定为 `SO`、把收款单与采购入库单都定为 `RC`，已修正。
> ② **取消「采购入库单」独立单号**：入库是采购单审核的同事务副作用，不产生独立单据（[ADR-0012](./adr/0012-采购原材料批次字段.md)）。库存模块的「采购入库」入口 = 采购单审核。
> **发货即出库是一张单**（`SH`），不另设「销售出库单」；审核即扣库存并生成应收与出库凭证。
> 对账单（`SN`）与凭证（`VO`）按月编号（`YYYY-MM`），其余按日编号（`YYYYMMDD`）。

**实现约束**：
- 序号在**数据库层**用序列或带唯一索引的计数器表生成，禁止 `count(*)+1`。
- 单据号一经生成永不变更、不复用。
- 生成后写入表即视为已占用。

### 2.2 款号规则

> ⚠️ **2026-10-03 修订**（业务方决策 Q-P0-04 / Q-P0-10）：款号**不再由后端生成**，改为**用户自定义**；
> 服务端仍按下面的格式给一个**建议号**，只作参考，用户输入一律优先。
> 「无客户时用什么前缀」规范里没有（实现取常量 `ST`，docs/12 §5 L-031）。

**建议号**格式：`{客户前缀(2-3 位大写字母)}-{年份}-{4 位序号}`，例如 `HB-2026-0001`

- 序号按 `(customer_id, 年份)` 分组递增；`customer_id` 为空（款号可无归属客户）落**全厂序列**
- 用户输入的款号**不做格式正则校验**，只做「唯一性 + 去首尾空白转大写 + 长度上限 32」
- 全厂唯一，大小写不敏感唯一（存库统一转大写）；唯一索引是**部分索引** `WHERE deleted_at IS NULL`，
  所以**软删后的款号可以重建同号**
- 已产生计件或库存的款号**不可删除**，只能停用（R2）

### 2.3 物料编码规则

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 面料 | `F-{类目码}-{6 位}` | `F-CT-000128` |
| 辅料 | `T-{类目码}-{6 位}` | `T-ZL-000456`（ZL=拉链） |
| 成衣 | `FG-{款号}-{色}-{码}` | `FG-HB-2026-0001-BLK-M` |

> ⚠️ **REV-2026-10 补：「类目码」的取值来源此前从未定义**（格式在这，码表不在）。
> 现定为字典表 **`material_categories`**，种子值 `CT` 纯棉布 / `TW` 混纺布 / `KN` 针织布 /
> `FL` 毛料 / `DM` 牛仔布 / `ZL` 拉链 / `NX` 纽扣 / `WD` 织带 / `TH` 缝纫线 /
> `LB` 唛头，用户可按自己的料号体系自行扩充。DDL 见
> [04 §7.15.1](./04-数据库规范.md)（T-BASE-003 D1）。
>
> ⚠️ **它是表而不是 `varchar` 列**：类目码已经进了物料编码，用自由文本的话
> 同一个类目会出现 `CT`/`ct`/`Ct` 三种写法，于是 `F-CT-000128` 与 `F-ct-000128`
> 被当成两件不同的布 —— **不报错**，只会让「按类目统计耗料」少一半。
>
> ⚠️ 与款号一样：**不做格式正则校验**（见 §2.2 的理由），只做唯一性 + 去空白转大写。

### 2.4 打菲二维码编码规则（INV-1 落地）

| 字段 | 值 |
| --- | --- |
| 二维码内容 | 纯文本 `bundle_no`，纠错等级 M，尺寸 ≥ 20mm（**不带数量**，数量查库得，ADR-0004 + ADR-0016） |
| 条码码制 | Code 128，内容与二维码一致，供扫码枪 |
| **`bundle_no` 格式** | `{打菲单号}-{尺码码}{手序号2位}-{件序号4位}`，如 `BD-20261018-000031-XL02-0001`（REV-2026-10 修订，含手序号） |
| **一码 = 一手** | 一手一个码；`hands` 手序号在同单同尺码内从 1 起；`UNIQUE(doc_id, color_code, size_code, hands)` |
| **一码一员工** | `counted_by` 只允许一人；第二个员工扫同码 → `32001` |
| **扫码得件数** | 扫码查 `bundles.bundle_qty` 得到该手件数，计件默认按整手；可手写更小的件数（部分生产），**超过则拒绝（`32006`）** |
| 标签新增内容 | **第 N 手 / 共 M 手** + **该手件数**（便于人工核对与分工辨识） |
| 生命周期 | 生成即固化；返工/换色/拼件必须新建码，旧码作废写 `voided_at` |
| 整件口径 | `bundle_qty` 必须为整数；尾数不生成码（`31003`） |

**手数 → 码数的拆分规则（裁剪 → 打菲）**：

```
裁剪尺码明细：XL  hands=2, qty_per_hand=60  →  output_qty = 120 件
  bundle_qty = floor(120 / 2) = 60 件/手
  ↓ 拆成 2 个码
  bundle 1: BD-…-XL01-0001  bundle_qty=60  ← 员工 王海涛
  bundle 2: BD-…-XL02-0001  bundle_qty=60  ← 员工 陈美玲
  余数（除不尽时）→ balance_qty，不生成码
```

**扫码枪输入约定（PC 工位机）**：
- 扫码枪为 USB 键盘 HID 设备，扫码后自动发送 `Enter`
- 前端必须用**全局输入捕获**（监听 `keydown` 累积字符 + `Enter` 触发），不能依赖焦点在输入框
- 扫码结果提交到工位计件接口，**必须带幂等键**（`idempotency_key = bundle_no + station + operation + 时间片`），重复提交返回上次结果而不是报错

## 3. 常见误解警示（AI 高频错误点）

| 错误理解 | 正确理解 |
| --- | --- |
| 打菲 = 打包装箱 | 打菲是配齐裁片捆成件，打箱是后续包装工序，属不同工序号 |
| 一扎 = 12 件 | 大多数车缝工序 1 扎 = 1 件；以**款号工序配置** `bundle_qty` 为准，不许硬编码 |
| 计件单价可以改历史 | 改基础资料只影响未来；历史用快照 `unit_price` |
| 库存成本可以手工改 | 只能通过盘点差异或红冲单据调整 |
| 反审核 = 删除 | 反审核产生反向流水，原始单据与流水都保留 |
| 员工能看到全车间计件 | 员工数据范围恒为 `SELF`，由后端强制，不可前端传参放大 |
| 微信扫一扫能读 Code128 条码 | 可以，但员工端是 H5，走 `bundle_no` 文本更稳；条码主要给工位机扫码枪 |
| 尾单 = 布头 | **两回事**。布头是仍可再裁的整段布（**入库**）；尾数是不足一件的余量（**不入库**，计入裁剪损耗） |
| 尾数也生成打菲码 | 尾数**不生成码、不计件、不入库**，向下取整到整件（见 §4.1） |

### 4.2 尾数处理口径（2026-10-01 业务方确认：尾单不入库）

**规则**：所有生产数量**向下取整到整件**，不足一件的余量按**裁剪损耗**处理，全链路不产生成衣。

| 环节 | 口径 |
| --- | --- |
| 裁剪 | `output_qty = hands × qty_per_hand`（整数精确值，ADR-0020）；仅人工指定出数时 `balance_qty = 差额`；`cut_waste_qty = 正常损耗 + balance_qty` |
| 打菲 | 一手一码，**码数 = 尺码明细 `hands`**（整数）；每码件数 = 该行 `qty_per_hand`；不生成尾数码（ADR-0016 + ADR-0020） |
| 计件 | `piecework_logs.qty` 只允许**正整数**件（数据库 `CHECK (qty > 0 AND qty = trunc(qty))`） |
| 完工入库 | 只入整件成衣；无尾数入库单据 |
| 销售 | 订单与发货数量必须为**正整数**件；尾批零星发货（末批只有几件）仍为整数件，只是标记 `is_balance_line` |
| 成本 | 尾数余料不计成本（已随损耗摊入裁剪成本），不生成台账 |

**布头 vs 尾数（必须区分）**：

| | 布头 `scrap_qty` | 尾数 `balance_qty` |
| --- | --- | --- |
| 是什么 | 裁剪后剩下**仍可再裁的整段布** | 产出**不足一件**的余量 |
| 能否再裁 | 能 | 不能 |
| 入库 | ✅ **入库**为布料批次（同缸号匹号，批次实际成本） | ❌ **不入库** |
| 归属 | `stock_ledgers.direction='IN'`，`source_doc_type='CuttingOrder'` | 计入 `cut_waste_qty` |

**不变式补充（INV-6 细化）**：
```
output_qty = floor(裁剪可出件数)
cut_waste_qty >= balance_qty
bundled_qty + cut_waste_qty + (wip_qty) <= output_qty + balance_qty
piecework_logs.qty ∈ 正整数
```
