# 10 测试规范

> 本项目是"钱和实物"系统，**测试不是质量加分项，是准入条件**。
> AI 写完功能必须同步写测试，且测试必须先失败再通过（否则测试无效）。

---

## 1. 测试分层与比例

| 层级 | 工具 | 覆盖对象 | 目标行覆盖 | 强制要求 |
| --- | --- | --- | --- | --- |
| 单元测试 | `pytest` | service / util / 状态机 / 计算逻辑 | ≥ 80%（核心 service ≥ 90%） | **每个新功能必带** |
| 集成测试 | `pytest` + 测试库 | 路由 + service + DB | 关键路径全覆盖 | 每个接口至少 1 条 |
| 并发测试 | `pytest` + 多任务 | 计件、库存扣减、结算 | — | **计件/工资/库存/凭证强制**（§5） |
| E2E | `Playwright` | 关键业务流程 | — | 每模块 1 条主流程 + 单据审批 |
| 前端单测 | `Vitest` | 组件、composable、工具函数 | 新组件 ≥ 1 | — |
| 对账测试 | `pytest` | 库存台账 vs 结余、凭证借贷平 | — | **每次发布前必跑** |

**禁止**：为了通过 CI 而写 `assert True`、跳过标记、降低覆盖率阈值。

```
│   └── test_reconciliation.py        # 库存/凭证对账
└── e2e/
```

| 规则 | 说明 |
| --- | --- |
| 命名 | `test_<被测单元>.py`，函数名 `test_<行为>_<预期>`，如 `test_approve_when_stock_insufficient_should_reject` |
| 隔离 | 每个测试独立事务，结束回滚；**用例之间零依赖，顺序随机仍通过** |
| 数据 | 用 `factories` 生成，**禁止在测试里手写 uuid/时间** |
| 断言 | 只断言业务结果，**不绑死内部实现**（不断言 SQL 语句、不断言私有方法调用） |
| 时间 | 固定 `work_date`，不依赖 `now()`；需要时注入 `frozen_time` |
| 数量 | `Decimal` 与整数比较要用 `Decimal("1")` 而非 `1.0` |

### 2.3 业务测试正例

```python
# backend/tests/modules/test_piecework_service.py
from decimal import Decimal

import pytest

from app.core.errors import BusinessError, ErrorCode
from app.modules.piecework.service import PieceworkService


async def test_count_piecework_should_write_log_with_rate_snapshot(
    db_session, piecework_bundle, factory_employee
) -> None:
    """计件落库时快照单价（INV-3），后续改基础资料不影响历史。"""
    service = PieceworkService(db_session)
    payload = _payload(bundle=piecework_bundle, employee=factory_employee)

    log = await service.count_piecework(payload, operator_id=factory_employee.id)

    assert log.qty == Decimal("1")
    assert log.unit_price == Decimal("0.3500")     # 快照值
    assert log.amount == Decimal("0.3500")

    # 改基础资料单价
    await service.update_rate(payload.style_no, payload.operation_no, Decimal("0.5000"))
    log.amount  # 仍是 0.3500 —— 由数据库里的快照保证，不重读


async def test_count_piecework_when_duplicated_should_be_idempotent(
    db_session, piecework_bundle, factory_employee
) -> None:
    """同一打菲号+工序+员工+日期重复扫码，返回既有记录（05 §5）。"""
    service = PieceworkService(db_session)
    payload = _payload(bundle=piecework_bundle, employee=factory_employee)

    first = await service.count_piecework(payload, operator_id=factory_employee.id)
    second = await service.count_piecework(payload, operator_id=factory_employee.id)

    assert second.id == first.id
    assert await _count_logs(db_session) == 1


async def test_count_piecework_when_employee_not_bound_should_raise(
    db_session, piecework_bundle, factory_employee
) -> None:
    with pytest.raises(BusinessError) as exc:
        await PieceworkService(db_session).count_piecework(
            _payload(bundle=piecework_bundle, employee=factory_employee), operator_id=factory_employee.id
        )
    assert exc.value.code == ErrorCode.PIECEWORK_NOT_BOUND
```

固定四个维度，缺一不可：

```python
# backend/tests/modules/test_permissions.py
async def test_list_logs_without_permission_should_return_403(client, auth_headers) -> None:
    resp = await client.get("/api/v1/piecework-logs", headers=auth_headers(role="employee"))
    assert resp.status_code == 403
    assert resp.json()["code"] == 12001


async def test_list_logs_out_of_data_scope_should_be_empty(client, auth_headers) -> None:
    """车间主管看不到别的车间（数据范围 12002）。"""
    resp = await client.get("/api/v1/piecework-logs", headers=auth_headers(role="workshop_supervisor"))
    assert resp.status_code == 200
    assert all(item["workshop_id"] == OTHER_WORKSHOP for item in resp.json()["data"]["items"])


async def test_list_logs_by_id_out_of_scope_should_return_403(client, auth_headers) -> None:
    """防越权按 ID 直查（最常见的越权漏洞）。"""
    resp = await client.get(f"/api/v1/piecework-logs/{other_workshop_log.id}",
                            headers=auth_headers(role="workshop_supervisor"))
    assert resp.status_code == 403
    assert resp.json()["code"] == 12002


async def test_export_requires_separate_permission(client, auth_headers) -> None:
    resp = await client.get("/api/v1/piecework-logs/export", headers=auth_headers(role="line_leader"))
    assert resp.status_code == 403
```

**每个新接口的矩阵测试模板**（必须覆盖）：
`[无 token] 401` / `[无权限] 403` / `[无数据范围] 403 或空` / `[合法] 200` / `[参数非法] 422`

## 4. E2E（Playwright）关键流程

| # | 流程 | 覆盖要点 |
| --- | --- | --- |
| E2E-01 | 登录 → 建款号 → 建工序单价 → 建裁剪单 → 提交 → 审核 | 单据全流程 + 库存扣减 |
| E2E-02 | 打菲单 → 审核 → 打印标签 → 扫码计件（模拟扫码枪键盘输入） | **模拟键盘事件**：`page.keyboard.type(code)` + `press('Enter')` |
| E2E-03 | 计件 → 结算 → 工资审核 → 发放 → 导出代发文件 | 金额一致 |
| E2E-04 | 反审核裁剪单 → 库存完全还原 | 闭环 |
| E2E-05 | 员工端：登录 → 扫二维码绑定 → 看今日件数 → 看已审核工资 | 员工数据范围 = SELF |
| E2E-06 | 审核页：普通员工看不到审核按钮，直接调接口 403 | 权限双层 |
| E2E-07 | 销售单 → 出库 → 应收 → 收款核销 → 凭证 | 借贷平衡 |

**E2E 要求**：
- 数据通过 API seed 准备（`tests/e2e/seed.py`），不通过 UI 造数据
- 每个 E2E 用独立库，CI 可并行
- 失败的截图/trace 自动存档（`--trace on`）

## 5. 并发测试（计件/工资/库存/凭证强制）

这是本项目**最容易出事故**的地方。必须用真实并发，不得用 `await asyncio.sleep` 模拟串行。

### 5.1 计件并发

```python
# backend/tests/modules/test_piecework_concurrency.py
import asyncio

from sqlalchemy import func, select


async def test_count_concurrently_20_times_should_write_one_log(
    db_session, piecework_bundle, factory_employee, make_piecework_service
) -> None:
    """同一打菲号 20 个并发请求：数据库唯一索引兜底，只允许 1 条流水。"""
    payload = _payload(bundle=piecework_bundle, employee=factory_employee)

    results = await asyncio.gather(
        *[make_piecework_service().count_piecework(payload, factory_employee.id) for _ in range(20)],
        return_exceptions=True,
    )

    succeeded = [r for r in results if not isinstance(r, Exception)]
    total = await db_session.scalar(select(func.count()).select_from(PieceworkLog))
    assert total == 1
    # 成功返回的必须是同一条记录（幂等），失败的是唯一键冲突且被业务层转成幂等命中
    assert all(r.id == succeeded[0].id for r in succeeded)
```

### 5.4 并发测试纪律

| 规则 | 说明 |
| --- | --- |
| 真并发 | `asyncio.gather` + 独立 session（每任务一个 session），**共享一个 session 测不出来** |
| 隔离性 | 每个用例用独立数据（不同 bundle_no），避免互相干扰 |
| 必须有兜底 | 通过 = 唯一约束生效 + 业务层正确处理冲突；**只靠业务层检查 = 未通过** |
| 断言明确 | 断言最终条数与失败类型，不接受"大概对" |

## 10. 常见错误（AI 高频）

| 错误 | 正确做法 |
| --- | --- |
| 测试通过但没测状态机副作用 | 必须测"审核→反审核 数据完全还原" |
| 用 `Mock` 掉数据库测业务 | 单测 mock 依赖，集成测真库；不能靠 mock 掩盖 SQL 错误 |
| 一个 `assert resp.status_code == 200` 测完 | 断言 `code` + `data` 关键字段 |
| 忘记测越权 | 权限矩阵 5 条是硬要求 |
| 并发测试用单 session | 每任务独立 session |
| 用 `time.sleep` 让测试变慢 | 用事件/钩子同步 |
| 快照测试（snapshot）大量使用 | 快照变化难 review，只对极少数稳定输出用 |
| 测试里写死日期导致跨月失败 | 固定 `date(2026, 8, 15)` |
