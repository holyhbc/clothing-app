# ADR-0007：收入确认与凭证阶段划分：阶段一按发货确认收入

---

## 背景

阶段一销售口径是"单货销售"：工厂给代工客户或贸易客户发成衣，发货单 `SH-YYYYMMDD-NNNNNN` 审核即出库、即生成应收、即需出凭证。凭证的借贷方向取决于**收入在什么时点确认**，这一步定错会连带影响应收生成时点、毛利分析口径和反审核链路。

- 现状：`modules/09` §5.1 已列 `SALES_DELIVERY` 两张凭证模板，但"按发货确认"这个口径未落 ADR。
- 痛点/风险：
  1. 服装代工/单货场景，货权在**交付时**转移，客户验收是形式动作；工厂管理层日常看的是"这个月发了多少货"，按发货确认与实际管理口径一致。
  2. 工厂大量客户不需要开票（境外小单、代工客户、个体客户），若按开票确认，收入会长期挂账、报表无意义。
  3. 客户不反馈就永远无法确认 → 按验收确认会让销售数据常年空白。
  4. 反审核若不生成红字反向凭证，已过账凭证会与业务单据脱钩（INV-5 被破坏）。
  5. 成本结转方向写错会直接把毛利算反，且要等到对账才发现。
- 硬约束：本金本位币 RMB，不做多币（`00` §3.2）；不做"已发货未开票"与分期确认；凭证借贷必须相等（INV-5）。

---

## 决策

**我们决定：阶段一按发货确认收入——发货单 `SH` 审核时，一次性确认主营业务收入、结转主营业务成本、生成应收，不做"已发货未开票"与分期确认。**

凭证模板 `sales:ship`（`source_type='SALES_DELIVERY'`）借贷方向（唯一口径，科目取自 `modules/09` §3.2）：

| 分录 | 借（DEBIT） | 贷（CREDIT） | 金额口径 |
| --- | --- | --- | --- |
| ① 发出货物确认收入 | `1122` 应收账款 | `6001` 主营业务收入 | 贷 = 出库金额 |
| ② 结转主营业务成本 | `6401` 主营业务成本 | `1407` 库存商品-产成品 | 借 = 出库成本（批次成本快照，INV-4） |

相邻链路的凭证方向（同样锁定，AI 不得自行改）：

| 场景 | 借 | 贷 |
| --- | --- | --- |
| 裁剪耗料 | `1406` 库存商品-在产品 | `1405` 库存商品-面料 |
| 完工入库 | `1407` 库存商品-产成品 | `1406` 库存商品-在产品 |
| 计提计件工资 | `5051` 制造费用-计件工资 | `2211` 应付职工薪酬 |
| 发放工资 | `2211` 应付职工薪酬 | `1002` 银行存款 |
| 收客户款 | `1002` 银行存款 | `1122` 应收账款 |

```text
反审核链路：SH 反审核前先处理凭证
  已过账 → 必须先红字反向凭证（借贷方向整体镜像，金额取负）再反审核单据
  未过账 → 软删该 DRAFT 凭证
  任一情况下都写 document_logs（谁、何时、原因）
```

`voucher_templates` 用「借贷成对 + 金额相等」结构，保证 `total_debit == total_credit` 天然成立；尾差用 `6602.01` / `6051.02` 兜平。

---

## 理由

| # | 理由 |
| --- | --- |
| 1 | 单货销售货权在交付时转移，按发货确认符合业务实质，也符合工厂管理层"看发货量"的管理口径。 |
| 2 | 发货即应收，账龄分析从发货日开始算，与客户实际付款周期对齐；按开票确认会让大量无票客户的应收永远不生成。 |
| 3 | 成本按批次成本快照一次性结转（INV-4），毛利 = 出库金额 - 批次成本，当月即可算出"哪个款赚钱"，直接支撑 `00` §2 最后一条痛点。 |
| 4 | 反审核需要红字反向凭证，方向整体镜像即可，不引入分期后就不存在"部分确认后反审"的复杂状态。 |
| 5 | 计提计件工资走 `5051` 制造费用，完工时进在产品、出库时进成本，成本链条与实际生产流向一致，不产生"凭空成本"。 |
| 6 | 分期确认（发货未验收）在阶段一不产生实际价值：服装代工的验收是形式动作，等到验收只会让数据更晚可用。 |
| 7 | 借贷成对结构 + `numeric(18,4)` 精确金额，让 `v_voucher_balance` 视图能作为发布前的自动对账闸门。 |

## 备选方案与否决原因

| 方案 | 是否考虑 | 否决原因 |
| --- | --- | --- |
| 按开票确认收入 | ✅ | 工厂大量客户（代工、境外个体、个体工商户）不需要开票，收入会长期挂账、不生成凭证，月度报表无意义；且与"发货量"管理口径脱节。 |
| 按客户验收确认收入 | ✅ | 客户不主动反馈就永远无法确认，销售数据常年空白；验收状态需额外跟单维护，成本高收益低。 |
| 分期确认（发货 70% + 验收 30%） | ✅ | 服装单货场景无合同约定比例，属于自造业务规则（AGENTS.md §2.3 禁止）；需要额外维护待确认余额、确认单、比例配置，复杂度远超收益。 |
| 发出商品挂"已发货未开票"科目 | ✅ | 需新增科目与待确认台账，阶段一每月单量下就是纯负担；且与 `00` §3.2「不做已发货未开票」冲突。 |
| 收付实现制（收到钱才确认收入） | ✅ | 与应收账龄、账期管理完全脱节，客户欠款无法反映在报表上，不可接受。 |

## 影响

| 项 | 说明 |
| --- | --- |
| 正面 | 收入/成本/应收三点一线，当月毛利可算；凭证方向固定、AI 不会生成错向分录；反审核链路清晰。 |
| 负面/代价 | 无法表达"已发货未验收"的风险敞口；出口多币种场景不适用（阶段一不支持）。 |
| 风险 | 成本结转用错库存栈（`material_stocks` 而非 `finished_goods_stocks`）→ 毛利失真；已过账凭证被直接软删 → `v_voucher_balance` 与单据脱钩。由对账测试 + `fv:09` 模板驱动生成测试兜底。 |
| 迁移路径 | 无存量。初始化迁移幂等插入科目集 + `voucher_templates` + 当期 `accounting_periods`（`status='OPEN'`）。 |
| 回滚方式 | 改口径属决策变更，**必须新写 ADR 并把本篇标记 `Superseded`**；数据层通过新增模板行 + 老模板 `is_active=false` 切换，不改历史凭证。 |
| 对规范的影响 | `modules/09` §3.2/§5.1、`modules/07-销售.md`（`SH` 审核触发链）、`08-单据状态机规范.md`（反审核下游联动）。权限点：`sales:ship`、`finance:voucher:post`、`finance:voucher:reverse`（均已登记，无需新增）。 |
| 对测试的影响 | 必测：① 一笔销售生成 3 张（收入/成本/…）凭证且 `v_voucher_balance` 0 行；② 成本结转取批次快照而非当前成本；③ 已过账时反审核生成红字反向凭证且借贷仍平衡；④ 关账期间生成凭证被拒（`FOR SHARE` 竞态）。 |

## 未来扩展（阶段二及以后）

- **多货模式**（销货 / 回购）：确认时点可能拆分，需在模板层加"分批确认"参数，届时新增 ADR。
- **出口多币种**：`amount` 侧挂 `currency` 与 `exchange_rate numeric(18,8)`，收入确认与汇兑损益分离。
- **退货与返工**：退货走红字反向凭证 + 返工入库，成本按原批次结转。
- 明确**不做**：不做收入分期确认、不做"已发货未开票"台账（阶段一无实际价值）。

| 指标 | 目标值 | 观测方式 |
