# ADR-0012：采购原材料的批次字段与用途口径

---

## 背景

### 现状（业务方原话整理）

> 采购原材料例如布，单据会包含：供应商、日期、缸号、颜色、重量、匹数（多少条布）；
> 一般一张单子会包含缸号、总重量、数量多少条布；
> 要能加备注——"万一返修退回厂里"。

> 布的度量：**有重量，还要有个门幅需要输入填写**。

### 痛点

| # | 痛点 | 后果 |
| --- | --- | --- |
| 1 | 之前规范只有"库存模块的采购入库单"，**没有采购单本身** | 采购员没地方录供应商的单，只能先手工记在本子上 |
| 2 | 库存批次只有 `dye_lot_no + bolt_no + qty + unit_cost`，**没有门幅、没有重量** | 门幅是裁剪能不能用的关键参数（有效门幅 = 门幅 − 布边 − 对格损耗），缺了无法校验；重量也无法核账 |
| 3 | 返修布（客户/加工厂把布退回来重做）没有独立标记 | 返修布成本混入正常布料，导致款式毛利失真 |
| 4 | 一张采购单含多个缸号时，无法按缸号对账与追溯 | 面料商按缸号结算时对不上 |

### 硬约束

- 批次实际成本（[ADR-0011](./0011-面料批次实际成本.md)）已确定：入库时定成本，之后不可改
- 裁剪按缸选批（选批规则见 [04 §7.2.2](./../docs/04-数据库规范.md)）
- 整件口径（[09 §4.2](./../docs/09-领域术语与编码规则.md)）不适用于布料（布料按米/重量计量，不取整到件）

---

## 决策

**我们决定：新增独立采购模块，采购单行以「缸号 + 颜色 + 门幅 + 重量 + 匹数 + 用途」为核心；布料计量采用「重量 + 门幅」双主量，匹数与米数作为辅助；返修布用 `purpose` 字段标记并走单独成本口径。**

### 1. 双模块拆分

| 模块 | 职责 |
| --- | --- |
| **采购模块**（新） | 采购单：录供应商、缸号、颜色、门幅、重量、匹数、单价、备注 → 审核生成应付 |
| **库存模块** | 接收审核通过的采购单 → 生成物料批次（缸号+匹号）→ 台账 → 成本结转 |

采购单审核 = **同事务**完成"建批次 + 写台账 + 生成应付 + 生成凭证"，不跨模块异步。

### 2. 布料计量（照业务方回答）

| 字段 | 类型 | 必填 | 角色 |
| --- | --- | --- | --- |
| `weight_kg` | `numeric(14,3)` | ✅ | **主计量**（染色后按重量计价与核账） |
| `width_cm` | `numeric(8,2)` | ✅ | **裁剪关键参数**（有效门幅校验） |
| `bolt_count` | `numeric(14,3)` | ✅ | 匹数（条数），决定批次拆几行 |
| `length_per_bolt_m` | `numeric(14,3)` | ⬜ | 每匹米数 |
| `total_length_m` | `numeric(14,3)` | ⬜ | 总米数；未填则按 `匹数 × 每匹米数` 计算 |

**三者不强制一致**：染厂缩水、布头剪除会造成差异，超过 5% 时给**警告但不阻断**（阻断会让采购员做不了真实业务）。

### 3. 用途口径（`purchase_purpose`）

| 值 | 含义 | 成本科目 | 毛利报表 |
| --- | --- | --- | --- |
| `NORMAL` | 正常采购 | `1405 库存商品-面料` | 混入主料成本 |
| `REWORK_RECEIPT` | 返修补退回厂 | `5403 制造费用-返修补布费` | **单独列示** |
| `RETURN` | 客供料退回 | 冲减 `1406 在产品` | 单独列示 |
| `SAMPLE` | 样布 | `6602 管理费用-样品费` | 不进产品成本 |

`purpose = REWORK_RECEIPT` 时 **`rework_note` 必填**（写明哪款哪单返修回来的），否则 `10006`。

返修布**照常入库、照常可被裁剪领用**，但因为批次实际成本独立成立，所以返修布的成本天然可与正常布料分开统计——这正是 [ADR-0011](./0011-面料批次实际成本.md) 带来的额外好处。

### 4. 采购单状态与反审核

沿用通用单据状态机（[08 §1.1](./../docs/08-单据状态机规范.md)）。

反审核的额外约束：**若该缸批次已被下游裁剪消耗 → 拒绝（`40005`）**，必须先冲销下游裁剪单。原因：批次成本已被结转到在产品与成衣成本，冲不回来。

## 理由

| # | 理由 |
| --- | --- |
| 1 | **门幅必须入库**。裁剪铺布时有效门幅 = `width_cm − 左右布边 − 对格损耗`。没有门幅，系统无法校验"这批布够不够裁这个款"，也无法在裁剪时提示用错缸。 |
| 2 | **重量是主计量**。染厂交货与结算大量按 kg，重量是核账的第一依据；米数只是参考。 |
| 3 | **不强制三者一致**。真实业务里重量/米数/匹数经常对不上（缩水、剪损），强制一致会让系统在实际使用中被绕过。给警告比阻断有用。 |
| 4 | **返修布单独成本口径**。业务方明确要"万一返修退回厂里"能追溯。用 `purpose` 字段而非独立仓库，是因为返修布也会进正常裁剪流程，独立仓库会让库存割裂。 |
| 5 | **同单多缸号**。一张采购单含多个缸是常态，所以缸号在**行**级而不是头级；头级是供应商，单据时，库存是批次。三个粒度对齐。 |
| 6 | **采购与库存拆分但同步过账**。职责清晰（采购管订单、库存管实物），但审核时同事务完成，避免出现"单据审核了但库存没变"的中间态。 |

## 备选方案与否决原因

| 方案 | 是否考虑 | 否决原因 |
| --- | --- | --- |
| 不做采购模块，采购员直接录库存入库单 | ✅ | 采购员要手填单价、供应商信息重复；且应付账款缺来源单据，财务无法核销 |
| 门幅放在物料主数据（一个物料一个门幅） | ✅ | 同款布不同批的门幅会有差异（缩水/织造偏差），**必须能按批次覆盖**，故主数据有默认、采购行可覆盖 |
| 只记匹数不记重量 | ✅ | 染厂按 kg 结算，缺重量无法核账 |
| 重量/门幅/匹数三者强制一致 | ✅ | 真实数据经常不一致，强制会阻断正常业务 |
| 返修布进独立仓库 | ✅ | 库存割裂，裁剪选批时要跨仓合并，复杂度陡增；`purpose` 字段成本天然可分 |
| 返修布不存库只做台账 | ✅ | 业务方选择"标记用途 + 单独成本口径"，且返修布要能再裁 |
| 用 `purpose` 拆成多个物料档案（"返修布"当独立物料） | ✅ | 同一缸布的用途可能随批次变化（正常采购的部分后来变返修），绑在物料上会错 |

## 影响

| 项 | 说明 |
| --- | --- |
| 正面 | 采购员有单可录；门幅入库后裁剪可做有效门幅校验；返修布成本独立可查；按缸对账可行 |
| 负面/代价 | `materials` 与 `material_stocks` 各增 2-3 列；采购审核要跨采购+库存+往来+凭证四个模块（但同事务）；前端采购单录入字段多，需要分步表单 |
| 风险 | ① 采购员不填门幅 → 裁剪时无法校验 → 门幅设为必填 + 提交时校验 ② 重量与米数不一致 → 只警告，报表以重量为准 ③ 返修布 `rework_note` 不填 → 必填校验 |
| 迁移路径 | 新建 `purchase_orders` / `purchase_order_lines`；`materials` 增 `width_cm` / `weight_kg_per_m`；`material_stocks` 增 `width_cm` / `weight_kg` / `purpose`（分两次 ALTER：先可空 → 回填 → 加约束） |
| 回滚方式 | 新表可删；增列可逆；已生成的批次数据需备份恢复 |
| 对规范的影响 | 04 §7.4 新增采购两表 DDL + 审核副作用；04 §7.2 库存表增列；05 §4 新增 `40005` / `11007` / `11008`；07 §2.2 新增采购 10 个权限点；09 §1.1 新增采购与门幅术语 |
| 对测试的影响 | **必测**：① 同单多缸号各生成独立批次 ② 返修布必填 `rework_note`（`10006`）③ 重量/米数差异 >5% 只警告不阻断 ④ 反审核已被裁剪消耗的批次被拒（`40005`）⑤ 返修布批次成本独立统计不混正常布料 ⑥ 审核同事务完成库存+应付+凭证，任一失败整体回滚 |

## 验证方式

| 指标 | 目标值 | 观测方式 |
| --- | --- | --- |
| 采购单字段完整率 | 100%（门幅/重量/缸号无空） | 提交校验拦截率统计 |
| 按缸对账通过率 | 100% | 采购台账按 `dye_lot_no` 分组核对 |
| 返修布成本可分 | 是 | 款式毛利报表能单独列出返修补布费 |
| 采购录入耗时 | 单缸单行 ≤ 2 分钟 | 手工计时 |
