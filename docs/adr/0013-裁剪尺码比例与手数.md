# ADR-0013：裁剪按「款号 × 颜色」的尺码比例自动算明细

| 项 | 内容 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-10-01 |
| 决策人 | 业务方 + AI |
| 影响范围 | 数据库 / 裁剪模块 / 基础资料 / 库存 |
| 关联 | [04-数据库规范 §7.6](./../docs/04-数据库规范.md)、[modules/02-裁剪](./../docs/modules/02-裁剪.md) |

---

## 背景

### 现状（业务方原话）

> 裁剪一般会根据款的尺码比例进行裁剪。比如该款红色尺码是 L XL XXL 3XL，裁剪比例是 1 2 2 1，
> 那么就是 6 手，如果每手 50 件，那么该款红色这次裁剪明细数量 4 个尺码分别对应是 50、100、100、50，
> 总数量是 300 件。

### 追问确认结果

| 问题 | 业务方回答 |
| --- | --- |
| "每手 50 件"的 50 是怎么定的？ | **每次裁剪输入，不同数据** |
| 尺码比例按什么维度设？ | **款号 × 颜色**（同款不同颜色比例可不同） |

### 痛点

| # | 痛点 | 后果 |
| --- | --- | --- |
| 1 | 之前规范里裁剪明细只说"按 BOM 反算应出件数"，**没有尺码比例概念** | AI 生成的裁剪单只能平均分摊或让用户手填每行件数，与实际排版习惯不符 |
| 2 | 比例如果按款号设 | 同款红色 1:2:2:1、黑色 2:2:1:1 时无法表达 |
| 3 | "每手件数"如果做成款号配置 | 每次裁剪不同（旺季赶工每手 40 件、改工艺后 60 件）就必须改基础资料 |

### 硬约束

- 整件口径已定（[09 §4.2](./../docs/09-领域术语与编码规则.md)）：不足一件的余量计入 `balance_qty`，不入库不计件
- 尺码必须来自款号的颜色-尺码配置（不能配款号里没有的尺码）

---

## 决策

**我们决定：尺码比例按「款号 × 颜色」预置（单位 = 手数，可小数）；`每手件数` 在裁剪单上逐行输入；明细件数由 `floor(ratio × qty_per_hand)` 自动计算，余量并入 `balance_qty`。**

### 1. 比例主数据（04 §7.6）

```sql
style_color_size_ratios (style_no, color_code, size_code, ratio)
UNIQUE (style_no, color_code, size_code)
CHECK (ratio > 0)
```

### 2. 两层职责分离

| 层 | 内容 | 变更频率 |
| --- | --- | --- |
| **主数据**（比例） | 款号 × 颜色 × 尺码 = 几手。业务方给销售/客户定好的排版构成 | 低（一款一次） |
| **单据输入**（每手件数 `qty_per_hand`） | 本次裁剪每手多少件 | **高（每次裁剪不同）** |

业务方明确"每手数量每次裁剪输入"，所以 **`qty_per_hand` 放在裁剪单行，不做基础资料配置**。

### 3. 计算规则

```
裁剪单行（款号 + 颜色）：
  qty_per_hand = 100（本行输入，每次可不同）
  ┌──────────────────────────────────────────────────┐
  │ 该款该颜色的尺码比例（来自 style_color_size_ratios）│
  │   L=1.0000  XL=2.0000  XXL=2.0000  3XL=1.0000      │
  └──────────────────────────────────────────────────┘
  明细：
    L    floor(1.0000 × 100) = 100 件，1.0000 手
    XL   floor(2.0000 × 100) = 200 件，2.0000 手
    XXL  floor(2.0000 × 100) = 200 件，2.0000 手
    3XL  floor(1.0000 × 100) = 100 件，1.0000 手
  合计：6.0000 手 = 600 件
```

**取整口径**：每个尺码**独立向下取整**（`floor`），不四舍五入。
理由：多裁一件就是多耗料，整件口径要求精确；三项余量合计进 `balance_qty`。

### 4. 校验

| 校验 | 失败码 |
| --- | --- |
| 该 (款号, 颜色) 下有尺码缺比例 | `20006` |
| 比例里出现款号颜色组内不存在的尺码 | `20007` |
| `qty_per_hand <= 0` | `10001` |
| 比例合计 ≤ 0（不可能，`ratio > 0` 保证） | — |

### 5. 单据可覆盖

裁剪单允许**临时覆盖比例**（本次特殊排版，如某色多裁备货），但：
- 必须在行上填 `ratio_override` + **必填原因**（`10006`）
- **不改主数据**，写 `document_logs`（`changed_fields` 记原比例与覆盖比例）
- 覆盖只影响本单，不影响后续裁剪

### 6. 与 BOM 单件用量的关系

```
该尺码耗料量 = 该尺码件数 × 该尺码单件用量(BOM.usage) + 该尺码损耗量
```

**先有件数（比例算出），才有耗料**。这与之前"按 BOM 反算应出件数"的顺序相反——**比例优先，BOM 只算耗料**。

---

## 理由

| # | 理由 |
| --- | --- |
| 1 | **比例是客户的排版要求，不是 BOM 推导结果**。BOM 回答"一件要多少布"，比例回答"这个颜色要做多少件各尺码"。两者独立。 |
| 2 | **按颜色设比例是业务方明确要求**。同款不同颜色销售构成不同是常态。 |
| 3 | **每手件数做单据字段**。业务方明确"每次裁剪输入，不同数据"。做成基础资料会导致每次裁剪都要改配置，是错误的建模。 |
| 4 | **`floor` 而不是 `round`**。多裁要真多耗料；`round` 会让合计与实际不符，与整件口径冲突。 |
| 5 | **允许单据覆盖比例**。现实中总有临时加量，不覆盖就只能先改基础资料再改回来，容易留错数据。 |
| 6 | **比例存主数据 + 单据可覆盖**双层，兼顾复用与灵活，且覆盖有日志可追溯。 |

---

## 备选方案与否决原因

| 方案 | 是否考虑 | 否决原因 |
| --- | --- | --- |
| 比例存成字符串（`"1:2:2:1"`） | ✅ | 无法按尺码查询、无法校验缺配、无法做"某尺码占比多少"的报表 |
| 比例按款号设（不分颜色） | ✅ | 业务方明确不同颜色比例可不同 |
| 每手件数做成款号配置 | ✅ | 业务方明确"每次裁剪输入，不同数据" |
| 裁剪时手工填每行件数，不做比例 | ✅ | 业务方明确要比例；手工填易错且无法复用 |
| 按**件数**比例而不是**手数**比例 | ✅ | 业务方描述用的是"6 手 / 每手 50 件"，手数是排版单位；件数比例需要先知道总件数才能定比例，逻辑倒置 |
| `ratio` 用整数手数 | ✅ | 允许 1.5 手（实操中存在），故用 `numeric(14,4)` |
| 覆盖比例直接改主数据 | ✅ | 会污染其他单据；且无法追溯"当时为什么这么裁" |
| 四舍五入代替向下取整 | ✅ | 多裁即多耗料，会导致耗料与出数对不上 |

## 影响

| 项 | 说明 |
| --- | --- |
| 正面 | 裁剪单录入从"填 N 行件数"变成"填 1 个每手件数"；比例复用；报表可分析各尺码构成 |
| 负面/代价 | 多了比例维护界面；裁剪单要能从 BOM 反查比例并在缺配时明确拦截 |
| 风险 | ① 比例漏配 → 裁剪提交失败，服务层给 `20006` 引导补配 ② 用户误以为比例是件数 → 界面必须同时显示"手数"与"件数"两列 ③ 覆盖比例不留原因 → 必填校验 |
| 迁移路径 | 新建 `style_color_size_ratios`；`cutting_order_lines` 增 `qty_per_hand`、`ratio_override`、`ratio_override_reason`、`ratio_source` 四个字段（可空起步，审核后必填） |
| 回滚方式 | 表与列可删；已生成的裁剪单保留当时的 `ratio_source` 快照 |
| 对规范的影响 | 04 §7.6 新增比例表 DDL + 计算规则；05 §4 新增 `20006` / `20007`；02-裁剪模块的"按 BOM 反算应出件数"全部改为"按比例算出"; 08 §2.1 审核副作用第③项改写 |
| 对测试的影响 | **必测**：① 1:2:2:1 × 50 手 → 50/100/100/50 = 300 件 ② ratio 含小数（1.5 手 × 33 = 49.5 → floor 49，余 0.5 进 balance_qty）③ 缺配尺码报 `20006` ④ 配了款号没有的尺码报 `20007` ⑤ `qty_per_hand=0` 被拒 ⑥ 单据覆盖比例不改主数据 + 写日志 ⑦ 同款不同颜色比例独立 ⑧ 耗料 = Σ(件数 × BOM.usage) |

## 验证方式

| 指标 | 目标值 | 观测方式 |
| --- | --- | --- |
| 裁剪录入耗时 | 从 5 分钟降到 1 分钟内 | 手工计时（填 1 个每手件数 vs 填 4 行件数） |
| 比例算错 | 0 起 | 裁剪单出数与车间实际件数核对 |
| 比例缺失拦截 | 100% | `20006` 触发次数 = 缺配次数 |
| 报表可用性 | 各尺码占比可出 | 按尺码分组统计出数占比 |
