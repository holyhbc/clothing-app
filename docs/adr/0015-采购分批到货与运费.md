# ADR-0015：采购分批到货录入与单据级运费

| 项 | 内容 |

| 状态 | Accepted（**修订 ADR-0012 的「一张 PO 一次到齐」「入库=采购单审核」两条条款**；ADR-0012 其余内容仍有效） |

## 背景

### 业务方 2026-10-01 补充

| # | 原话 | 含义 |
| --- | --- | --- |
| 1 | **采购分批到货录入** | 一张 PO 分多次到货，逐次录入 |
| 2 | **没有外裁** | 不存在委外加工，不需要委外模块 |
| 3 | **运费根据每次采购收到的单据输入** | 运费在采购单上按实际单据录入，不做复杂规则 |
| 4 | **布的门幅根据采购过来的单子输入** | 门幅以采购单为准 |

### ADR-0012 原本的决策（以及为什么不够用）

ADR-0012 定的是：**入库 = 采购单审核的同事务副作用，一张 PO 一次到齐。**

| 问题 | 后果 |
| --- | --- |
| 一张 PO 必须一次到齐 | 现实里面料商经常分 2-3 次送；一次到齐会让采购员等齐了才敢录，账实严重滞后 |
| 缸号绑死在采购行 | 分批染色很常见：同一 PO 第二次到货可能是**另一个缸号**，采购行缸号不够用 |
| 没有运费字段 | 运费无处录，批次成本偏低，毛利虚高 |
| 入库与订单确认混为一谈 | 订单确认 = 承诺收货；实物到货 = 入库。混在一起会导致"已确认订单但货没到就占了库存" |

### 硬约束（不变的部分）

- 批次实际成本入库时一次确定（[ADR-0011](./0011-面料批次实际成本.md)）
- 门幅必填、重量为主计量（[ADR-0012](./0012-采购原材料批次字段.md)）
- 返修布 `purpose = REWORK_RECEIPT` 单独成本口径（ADR-0012）
- 整件口径（[09 §4.2](./../docs/09-领域术语与编码规则.md)）

---

## 决策

**我们决定：采购拆成「订单确认」与「到货登记」两个动作；新增 `purchase_arrivals` / `purchase_arrival_lines` 两张表支持分批到货；运费是采购单头的独立输入字段，按到货金额比例分摊进批次成本。**

### 1. 职责拆分（关键修订）

| 动作 | 干什么 | 入库？ | 生成应付？ | 生成凭证？ |
| --- | --- | --- | --- | --- |
| 采购单 `approve` | **确认订单**（锁定价、锁数量、锁缸号） | ❌ **不入库** | ✅ 应付承诺（`PENDING_ARRIVAL`） | ❌ |
| **到货登记**（新） | **记录实物到达** | ✅ **入库唯一入口** | 按到货金额冲减应付 | ✅ 入库凭证 |

**为什么要拆**：订单是"承诺"，到货是"事实"。混在一起会导致库存账出现"没有货却有余额"。

### 2. 分批到货表

```sql
purchase_arrivals        -- 到货批次头：第几次到、日期、金额、分摊运费
purchase_arrival_lines   -- 到货明细：挂在「采购行」上，可带新缸号
```

| 规则 | 说明 |
| --- | --- |
| 展示编号 | `PO 单号 / 第 N 次`，如 `PO-20261018-000012 / 第 2 次` |
| **缸号可在到货行覆盖** | 同一 PO 第二次到货可能是另一个缸（分批染色），`dye_lot_no` 以**到货行**为准，采购行的缸号只作默认 |
| 累计校验 | `Σ到货行 bolt_count ≤ 采购行 bolt_count`；超了报 `50011` |
| 每匹成本 | 到货行金额 = `该行重量 × 采购行单价 + 该行分摊运费`，单位成本 6 位小数 |
| 单次到货原子 | 建批次 + 台账 + 明细 + 冲减应付 + 凭证，**一个事务**，任一失败整体回滚 |
| 反审核粒度 | **先按到货反审核**（冲回该次批次与凭证），全部冲回后才允许反审核采购单；未冲完 → `50012` |
| 未到货不建批次 | 采购行没到货就完全没有库存批次 |

### 3. 运费（单据级输入）

| 项 | 规则 |
| --- | --- |
| 录入位置 | `purchase_orders.freight_amount` + `freight_no`（运单号），**单据级**，业务方按收到的单据填 |
| 分摊基准 | **货值金额比例**：`行分摊运费 = freight_amount × (行 amount ÷ Σ行 amount)`，6 位小数 |
| 分批到货 | 第 N 次到货分摊 `freight_amount × (本次到货金额 ÷ total_amount)` |
| 尾差 | 最后一行补差额，保证 `Σ行分摊运费 == freight_amount` |
| 进成本 | 并入批次单位成本（ADR-0011：批次实际成本含运费） |
| 凭证 | `借` 批次成本合计、`贷 2202 应付账款 = total_amount + freight_amount` |
| 为 0 | 表示供方包邮；不分配、不入成本 |
| 修改限制 | 只能 DRAFT / REJECTED 改；已到货后要改必须先冲销到货批次 |

### 4. 门幅以采购单为准

| 项 | 规则 |
| --- | --- |
| 权威值 | **批次上的 `width_cm`** = 采购到货行填的值 |
| 物料默认值 | `materials.width_cm` 只作新建单据时的**预填值**，可被采购行覆盖 |
| 到货行可覆盖 | 同一 PO 不同批次门幅实测有差异时，到货行填实测门幅（覆盖采购行） |
| 必填 | 门幅在到货行**必填**，为空 → 提交被拒（`10001`） |

### 5. 无委外加工

业务方明确**没有外裁**：
- **不建**委外发出 / 委外收回模块
- [modules/10-采购](./../docs/modules/10-采购.md) Q-PO-07 关闭
- 若未来出现委外，需新增独立模块（采购单不能代替委外单）

## 理由

| # | 理由 |
| --- | --- |
| 1 | **分批到货是常态**。面料商分 2-3 次送很常见；"一次到齐"会让账实滞后，甚至催着采购员提前录入造成虚假库存。 |
| 2 | **缸号在到货时才是最终确定的**。采购下单时的缸号可能只是预期；染厂中途换缸是常事。到货行能覆盖缸号才能对上账。 |
| 3 | **订单 ≠ 到货**。混在一起会让"应付"和"库存"同时挂账，业务上说不通。 |
| 4 | **运费必须进批次成本**。业务方"按收到的单据输入"意味着运费是**单据级已知数**，不需要复杂规则表；按金额比例分摊是最简单且可核对的方案。 |
| 5 | **门幅以实物为准**。实测门幅与标称有差（缩水、织造偏差），批次必须记实测值。 |
| 6 | **不做委外**是业务现实，遵循"不发明业务规则"原则 —— 少一个模块就少一套未来要维护的复杂度。 |

## 备选方案与否决原因

| 方案 | 是否考虑 | 否决原因 |
| --- | --- | --- |
| 一次到齐（ADR-0012 原方案） | ✅ | 与业务现实不符；缸号无法在到货时修正 |
| 分批到货但仍挂在采购行（不加到货表） | ✅ | 缸号覆盖不了；无法记录"第几次到"；反审核粒度不清 |
| 到货行缸号只读（必须与采购行一致） | ✅ | 分批染色必然出现新缸号，会导致对不上账 |
| 运费按重量分摊 | ✅ | 业务方口径是"按货值"；按重量分摊会让高单价料多分运费，财务不好核 |
| 运费按行录入 | ✅ | 业务方说"按收到的单据输入"，单据级一处录入最省事；行级录入会让采购员算分摊 |
| 运费不进成本（走期间费用） | ✅ | 布料运费本质是物料成本，进批次成本才能让毛利真实 |
| 委外模块 | ✅ | **业务方明确没有**，不做 |
| 到货登记独立单据（`AR` 单号） | ✅ | 增加单据层级与对账复杂度；到货本质是 PO 的履约进度，挂在 PO 下更清晰 |

## 影响

| 项 | 说明 |
| --- | --- |
| 正面 | 账实及时；缸号可修正；运费进成本使毛利真实；应付与库存各自有据 |
| 负面/代价 | 新增 2 张表；采购页面多一个"到货登记"动作；应付有"承诺 vs 已到"两态需要财务理解 |
| 风险 | ① 采购员在到货时忘填门幅 → 必填校验 ② 累计到货超量 → `50011` + 唯一约束 ③ 运费分摊尾差 → 最后一行补差 ④ 有人用采购单审核当入库 → UI 明确"审核不产生库存"，加引导 ⑤ 反审核顺序错 → `50012` 明确提示 |
| 迁移路径 | 新建 `purchase_arrivals` / `purchase_arrival_lines`；`purchase_orders` 增 `freight_amount`/`freight_no`/`arrival_expected_date`/`arrival_count`/`arrived_amount`（分两次 ALTER）；`ap_ledgers` 增 `arrival_status` 字段。阶段一均无数据 |
| 回滚方式 | 表可删；增列可逆 |
| 对规范的影响 | 04 §7.5.2.1（运费）、§7.5.2.2（分批到货）、§7.5.3（审核副作用改为到货入库）；05 §4 新增 `50011`/`50012`；07 §2.2 采购行补 `purchase:arrival`；08 §2.5 采购单状态机补到货动作；09 §2.1 单号表确认无 `AR`；09 §4 关闭 Q-PO-03/Q-PO-07 |
| 对测试的影响 | **必测**：① 一张 PO 分 3 次到货，各建独立批次 ② 累计超量报 `50011` ③ 到货行覆盖缸号成功 ④ 运费按金额比例分摊且尾差归最后一行 ⑤ 运费进批次单位成本 ⑥ 采购单审核**不产生库存批次** ⑦ 到货登记单事务回滚 ⑧ 到货反审核后批次与凭证完全还原 ⑨ 未冲完到货时反审核单据报 `50012` ⑩ `arrival_count`/`arrived_amount` 正确累加 |

## 验证方式

| 指标 | 目标值 | 观测方式 |
| --- | --- | --- |
| 账实同步 | 货到 24h 内入库 | 到货登记时间 vs 库存批次时间 |
| 缸号一致率 | 100% | 按缸对账（与 ADR-0011 对账视图） |
| 运费分摊误差 | 0（尾差 ≤ 0.0001） | `Σ行分摊运费 == freight_amount` 校验脚本 |
| 批次成本含运费 | 是 | 抽样批次 `unit_cost` 反算含运费 |
