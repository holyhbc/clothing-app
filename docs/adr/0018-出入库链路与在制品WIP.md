# ADR-0018 出入库链路与在制品 WIP

| 项 | 值 |
| --- | --- |
| 状态 | Accepted（2026-10-02 补充：最后一道工序 = 整烫） |
| 日期 | 2026-10-01 |
| 决策人 | 业务负责人 |
| 影响模块 | 裁剪 / 打菲 / 计件 / 库存 / 采购 / 销售 / 工资 |

## 背景

仓库里同时存在「布料」和「衣服」两类东西，业务上最常见的错误是把两者混在一个库存表里，导致裁剪领料扣了成衣库存、销售发了还没缝的半成品。

原有设计只有 `material_stocks`（面料）+ `finished_goods_stocks`（成衣），中间「裁完还没缝完」这段没有任何台账，损耗归属和可销售数量都对不上。

## 决策

### 三段式链路（各自独立台账，互不串账）

| 段 | 台账 | 对象 | 进入方式 | 离开方式 |
| --- | --- | --- | --- | --- |
| **① 原材料** | `material_stocks` + `stock_ledger_lines` | 面料/辅料（供应商+缸号+匹号） | **到货登记**（`purchase_arrivals`，ADR-0015） | 裁剪领料出库（按布批扣减）、布头回库 |
| **② 在制品 WIP** | `wip_stocks` + `wip_ledger_lines`（新增） | 裁片（款号+色+码） | **裁剪单审核通过时自动入库** | 工序流转（不产生成本差异）、尾数计入损耗 |
| **③ 成衣** | `finished_goods_stocks` | 成衣（款号+色+码+扎段） | **最后一道工序扫码完成自动入库** | 销售出库、盘点 |

### 成衣入库时机

- **主路径（自动）**：该码在**最后一道工序 = 整烫（烫衣服）**扫码计件完成，即从 WIP 转入 `finished_goods_stocks`，同一事务内写两段台账。
  - 业务已确认（2026-10-02）：**所有款号的最后一道工序都是烫衣服**，因此 `style_operations.is_final_operation` 的默认值 = 工序名含「整烫 / 烫衣」的工序。
- **兜底路径（手动）**：允许**手动完单入库**（`stock:in:manual` 权限），用于漏扫、返修后补入库、整单批量入库。手动入库必须填原因（`10006`）并写 `document_logs`。
- **不允许**裁剪完成就直接当成衣入库（会造成"没缝的衣服算库存"，超卖且损耗无处体现）。

### WIP 不计成本

WIP 只记数量与来源，不结转工价成本；成衣成本在**最后一道工序入库时**一次性结转 = 面料实际成本（按布批）+ 全部已计件工价，避免工序流转时反复重算成本。

### 新增错误码

| 码 | HTTP | 含义 |
| --- | --- | --- |
| `40006` | 409 | 布批可用库存不足（裁剪领料 > 可用量） |
| `40007` | 409 | 成衣入库数量与在制品结存不符 |

### 新增权限点

`stock:wip:read`（在制品台账）、`stock:in:manual`（手动完单入库）。

## 后果

**正面**：布料/裁片/成衣三段独立，库存对得上账；销售只能卖已入库的成衣；裁剪损耗归属在 WIP 段清晰可见；漏扫有手动兜底。

**代价**：多两张台账表；成衣入库时机依赖「最后一道工序 = 整烫」这一配置，**默认按工序名自动识别**（含「整烫 / 烫衣」），款号保存时校验必须能识别到一道；识别不到则在工序页标红提示由人工指定。

**风险与对策**：`is_final_operation` 配错 → 工序与单价页对最后工序（整烫）打醒目徽标 + 款号保存时「未识别到最后工序」告警；工位机在整烫扫码时提示「本工序完成即成衣入库」。若某款确实没有整烫工序，**必须人工指定**最后工序，不允许留空。
