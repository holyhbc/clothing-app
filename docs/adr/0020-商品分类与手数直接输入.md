# ADR-0020 商品分类与「手数直接输入」取价

| 项 | 值 |
| --- | --- |
| 状态 | Accepted（修订 ADR-0013/0014 的权威值口径；2026-10-02 补充：分类单据不可改） |
| 日期 | 2026-10-01 |
| 决策人 | 业务负责人 |
| 影响模块 | 裁剪 / 打菲 / 计件 / 库存 / 采购 / 销售 / 工资 |

## 背景

两个问题：

1. 裁剪工资要**按商品分类**分别计算（套装、单衣、单裤、棉毛、背心、打底裤），但 `styles` 表没有分类字段，单价也没有分类维度。
2. 手数怎么来的说法前后不一致：ADR-0013/0014 写的是"按比例带出、比例是权威值"，业务实际用法是**直接输入手数，件数 = 手数 × 每手件数**。

## 决策

### 1. 商品分类

- 新增字典表 `product_categories`，内置 6 类：套装 / 单衣 / 单裤 / 棉毛 / 背心 / 打底裤。
- `styles.category_id` 非空，建款号时必选；分类被款号引用后不可删除，只能停用（与颜色/尺码一致，见 04 §7.4）。
- **★ 分类在款号档案上定死，裁剪单不可改**（业务已确认 2026-10-02）：`cutting_orders` **不冗余存分类**，裁剪与计件一律 `JOIN styles.category_id` 取值；界面只读展示。这样同款任何批次的分类永远一致，工资报表不会因单据改分类而错乱。
- 款号货号 `style_no` **允许手工输入**，但 `UNIQUE` 索引保证不与已有冲突，冲突返回 `10001` 并提示已有款号。

### 2. 手数是权威输入，比例降级为提示

| 字段 | 权威性 | 说明 |
| --- | --- | --- |
| `hands`（手数，整数） | **权威，用户直接输入** | 例：XL 填 2 |
| `qty_per_hand`（每手件数） | 权威，单据输入 | 例：60 |
| 件数 | **派生** | `件数 = hands × qty_per_hand`，前端实时算，不单独录入 |
| `style_color_size_ratios.ratio` | **仅建议值** | 带出手数后与输入值偏离 >20% 时给黄色提示"与建议比例偏离较大"，不拦截 |

**取消** ADR-0013 中"明细 = floor(比例 × 每手件数)"的算法；**取消** ADR-0014 的 `MASTER` 模式作为权威录入路径，三种模式降级为「手数带出方式」：`MASTER` 带出建议手数（可改）、`UNIFORM` 所有尺码同一手数、`MANUAL` 逐格手数。**手数在任何模式下都必须由用户确认或输入**。

### 3. 按分类取裁剪工价

- `operation_rates` 增**可空** `product_category_id`：为空 = 通用价；非空 = 该分类专用价。
- 取价优先级：`款号专用价` > `分类 + 工序专用价` > `工序通用价`，分类取款号档案值（单据不可改），取当前生效区间（`effective_from ≤ 生产日 < effective_to`）。
- 一个尺码比例可跨颜色，多色不同件数靠 `cutting_order_line_colors` 承载（ADR-0017 不变）。

### 新增权限点

`base:category:manage`（商品分类维护）。

## 后果

**正面**：分类有了，工资能按分类算；手数口径与业务一致，取消"floor"这类反直觉算法；比例仍在但只当参考。

**代价**：`operation_rates` 从"工序×款号"变成"工序×款号/分类"两级，需要在单价维护页做优先级提示；同一工序可能存在 3 档价，用户要理解优先级——**单价页必须显示"当前生效价来源"**。

**风险**：分类单价配错会导致计件金额错。对策：计件流水落库时把**实际取到的单价与来源**（`rate_source`）写入流水，事后可追溯是哪档价算的。
