# ADR-0021 裁剪单修改 → 打菲码联动规则

| 项 | 值 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-10-01 |
| 决策人 | 业务负责人 |
| 影响模块 | 裁剪 / 打菲 / 计件 / 库存 / 采购 / 销售 / 工资 |

## 背景

裁剪单允许修改（生产现场返工、比例调整很常见），但打菲已经按手生成了二维码，员工也已经在扫码计件。如果改单时直接把码改掉，会出现"码上计件数量与裁剪明细对不上"，工资必然算错，且无法追溯。

## 决策

按裁剪单状态分四档，**已计件的手永远不可变**：

| 裁剪单状态 | 改耗料/布批/备注 | 改尺码手数 | 已有码的处理 |
| --- | --- | --- | --- |
| `DRAFT` / `SUBMITTED` | 允许 | 允许 | 不影响码（还没打菲） |
| `APPROVED`，**未打菲** | 允许 | 允许，需重新审核 | 无码 |
| `APPROVED`，**已打菲未扫码** | 允许（需重新审核） | 允许（需重新审核） | **未打印**的码软删并重建（`deleted_at`）；**已打印未计件**的码置 `VOIDED`，需作废重打（`31007`） |
| **已扫码计件**（任一码 `counted_at IS NOT NULL`） | 禁止 | **禁止**（`30004`） | — |

### 唯一合法的修正路径（红冲链）

```
红冲反计件（piecework:reverse，生成 REVERSAL 流水，工资自动回退）
  → 裁剪单反审核（cutting:reverse）→ 修改手数
  → 重新审核 → 重新打菲（新单据号，旧打菲单 CANCELLED，码 VOIDED）
  → 员工重新扫码
```

每一步写 `document_logs`，`piecework_logs` 保持 append-only（ADR-0005 不变）。

### 校验时机

- 裁剪单保存/审核时：若 `hands` 变小导致码数 < 已生成码数 → `31004`；手序号重复 → `31005`。
- 已生成码被改数量 → `31006`。
- 已打印码需重建 → `31007`（409，提示"请先作废该码再重新打菲"）。

### 新增错误码

| 码 | HTTP | 含义 |
| --- | --- | --- |
| `30004` | 409 | 裁剪明细已有计件，需先红冲反计件才能修改 |
| `30005` | 409 | 裁剪单已审核，修改后需重新审核 |
| `31007` | 409 | 码已打印，不可静默重建，需作废后重打 |

### 新增权限点

无新增。作废复用 `bundling:code:void`，红冲复用 `piecework:reverse`。

## 后果

**正面**：工资不会算错；任何改动都有红冲链和日志可追溯；打菲码不会被静默改掉。

**代价**：现场返工要走 5 步红冲，操作成本高。**必须在界面上做引导**：裁剪单行直接显示"已计件 🔒 / 已打印 / 未动"三个徽标，并把"红冲反计件"做成单据上的直达按钮，避免用户找不到入口。

**风险**：员工漏扫导致 WIP 长期挂账。对策：打菲页与生产追踪页提供"未计件码清单"（`idx_bundles_counted_pending`），超期未扫码由车间主管处理（手动完单入库或作废）。
