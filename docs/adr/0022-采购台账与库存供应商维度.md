# ADR-0022 采购台账（供应商维度）与库存供应商视角

| 项 | 值 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-10-01 |
| 决策人 | 业务负责人 |
| 影响模块 | 裁剪 / 打菲 / 计件 / 库存 / 采购 / 销售 / 工资 |

## 背景

业务负责人要求"按供应商看清账"：总布料数量、总货值、总运费、应付/已付/未付，并能按时间查明细（收货日期、供应商、面料名称、缸号、颜色、重量、单价、金额=重量×单价）。

现有库存表 `material_stocks` 没有 `supplier_id`，库存页面看不出这批布是哪家供应商的；采购模块也没有按供应商汇总的台账。

## 决策

### 1. 库存带供应商来源

`material_stocks` 增 `supplier_id uuid REFERENCES suppliers(id)`，由到货登记写入，**不可手工改**（改供应商 = 退料重入库）。

库存情况列表默认列：**供应商 · 面料名称 · 颜色 · 缸号 · 匹号 · 门幅 · 重量KG · 米数 · 可用量 · 已锁定 · 单价 · 金额**；支持按供应商、面料、颜色、时间区间筛选与导出。

### 2. 裁剪选料 = 供应商 → 面料 → 颜色 → 缸号/匹号 → 数量

裁剪单的布批行用**级联选择**：先选供应商，再选面料、颜色，最后列出该供应商名下**可用库存 > 0** 的缸号/匹号及重量；输入领用重量时：

- 校验可用量：`领用 > 可用量` → `40006`
- 审核裁剪单时生成领料出库 + `stock_ledger_lines` 批次耗用明细
- 领用重量 < 整匹重量时，余量走**布头回库**（`stock_type='MATERIAL'`、`direction='IN'`、`purpose='REMNANT'`），不产生损耗

### 3. 采购台账页（新增）

| 区块 | 内容 | 筛选 |
| --- | --- | --- |
| **供应商汇总卡** | 总重量KG · 总匹数 · 总货值 · **总运费（只记录，ADR-0019）** · 应付 · 已付 · 未付 | 供应商 + 收货日期区间 |
| **到货明细表** | 收货日期 · 供应商 · 面料名称 · 缸号 · 颜色 · 重量KG · 单价 · **金额=重量×单价** · 采购单号 · 到货单号 · 操作人 | 收货日期区间 + 供应商 + 面料 + 缸号/颜色关键字 |

- 应付 = 到货金额合计（`purchase_arrivals.amount`）；已付 = 付款单对该供应商的核销合计；未付 = 应付 − 已付。
- 支持导出（复用 `purchase:export`）；只读页无任何写操作。

### 新增视图

| 视图 | 用途 |
| --- | --- |
| `v_purchase_supplier_summary` | 供应商维度汇总（重量/匹数/货值/运费/应付/已付/未付） |
| `v_purchase_arrival_detail` | 到货明细（重量×单价=金额） |
| `v_material_stock_by_supplier` | 库存按供应商维度 |

### 新增权限点

`purchase:ledger:read`（采购台账只读页）。

## 后果

**正面**：按供应商对账、查库存一条线；裁剪选料能直接看到"这缸布还剩多少"；应付/已付/未付口径明确。

**代价**：三张视图 + `supplier_id` 需要在到货、库存、裁剪领料三处打通；到货登记必须强制选供应商（供应商从采购单头带出，只读）。

**风险**：历史数据若已有库存行没有 `supplier_id`，需要数据订正脚本（记为发布前置检查项）。
