# ADR-0023 生产单据页面重排（5 页 → 2 页 + 1 追踪页）与溯源链

| 项 | 值 |
| --- | --- |
| 状态 | Accepted |
| 日期 | 2026-10-01 |
| 决策人 | 业务负责人 |
| 影响模块 | 裁剪 / 打菲 / 计件 / 库存 / 采购 / 销售 / 工资 |

## 背景

原型评审反馈：裁剪单、裁剪明细录入、裁剪按布匹、打菲单、打菲按手 5 个页面职责重叠，**相互之间看不出关联**，用户不知道数据怎么串起来。

根因是**按"操作步骤"切页面**（录明细 → 按布匹 → 打菲 → 按手），而不是按**单据层级**切。而业务真实心智模型是父子单据链：裁剪单 → 打菲单 → 码。

## 决策

### 1. 页面重排：5 页合并为 2 页 + 1 追踪页

| 页面 | 路由 | 职责（合并了什么） |
| --- | --- | --- |
| **裁剪单** | `#/pc/cutting` | 唯一生产主单。表头（货号 / **商品分类** / 颜色多选 / 车间 / 日期）；表体**矩阵**：行 = 布批（供应商·缸号·匹号·门幅·领用重量），列 = 颜色 × 尺码，格 = **手数**（件数自动算）。矩阵顶部切换三种手数带出方式。**原「裁剪明细录入」「裁剪按布批」两页并入这里** |
| **打菲** | `#/pc/bundling` | 从裁剪单明细**一键生成**打菲单；单内按**手**列出码（`bundle_no` + 手号 + 件数 + 打印/计件状态），直接打印标签。**原「打菲按手」页并入这里** |
| **生产追踪** | `#/pc/trace` | 新增。按款号/单号把「裁剪 → 12 手 → 12 码 → 谁扫的 → 计件 → 工资」串成一条时间线，回答"这件衣服现在在哪、谁做的、值多少钱" |

菜单由 5 项变 3 项。

### 2. 溯源链（解决"看不出关联"）

每个生产行都带溯源链，任一端可跳父单：

```
码 bundle_no
  ← 打菲单 BD-20261018-000031
  ← 裁剪单 CD-20261018-000012
  ← 款号 HB-2026-0018（分类：单衣）
  ← 布批 缸号 K2026-0818 / 匹号 03（供应商 XX 布行）
```

- 列表页加「来源」列，显示父单号（可点击跳转）。
- 详情页顶部显示面包屑：`款号 > 裁剪单 > 打菲单 > 码`。
- 所有跳转只读，允许从任意一层看到全部上游与下游。

### 3. 查询与报表

- **裁剪查询**：时间 + 货号 + **条码编号（bundle_no 或手号）** + 操作人 + 分类 + 车间；全部列表支持导出（`cutting:export`）。
- **裁剪汇总报表**：按日期/款号/分类/车间/组别 → 手数、件数、耗料重量、尾数损耗、领料成本。
- **裁剪工资报表**：按分类/工序/员工/周期 → 取 ADR-0020 的分类单价，导出 Excel。

### 新增权限点

`cutting:trace:read`（生产追踪页）。

## 后果

**正面**：菜单从 5 变 3，父子关系一眼可见；溯源链让"这批货哪来的"可追溯；报表口径与计件口径一致（同一取价函数）。

**代价**：裁剪单页面变重（矩阵编辑 + 布批行 + 三种模式切换），需要良好的表格交互（合并表头、冻结列、手数快速录入）；单文件行数会上升，需要拆分组件。

**风险**：矩阵在行数多时性能与易用性下降。对策：布批行默认折叠只显示一行摘要，展开才编辑矩阵；手数支持键盘上下/回车快速跳格。
