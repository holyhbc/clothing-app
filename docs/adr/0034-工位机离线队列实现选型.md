## 背景

- 现状：T-PIECE-007 已交付工位机扫码页（在线主链路），顶部有「在线 / 离线」提示条但**不落队列**；断网时扫码直接失败。
- 痛点 / 风险：工厂网络差。断网丢一条扫码 = 工人这一手产出没记上（少拿钱），且该码停在 `counted_at IS NULL`。规范 [07 §7](../07-认证与权限规范.md) 早已要求工位机页（PWA/IndexedDB）缓存待提交流水、指数退避重试、冲突不静默丢弃。
- 硬约束：
  - [07 §7](../07-认证与权限规范.md) 指定工位机页用 **IndexedDB**；localStorage 被指定为**员工端**口径。
  - [05 §5](../05-接口设计规范.md) 幂等的实际机制是 `Idempotency-Key`（重试必须携带同一键）。
  - 仓库前端当前**没有任何 IndexedDB 相关依赖**（`admin` 包仅有 ant-design-vue / bwip-js / dayjs / pinia / qrcode / vue / vue-router）。
  - [ADR-0028](./0028-PC端UI库锁定AntDesignVue4.md) 教训：选依赖前版本号必须先在 npm 上核实存在。

## 决策

**我们决定：工位机离线队列用 `idb` v8（IndexedDB 的 Promise 封装）；离线回放遇 `32001` 时把该条标记为「冲突」保留在队列并常驻计数，由人工决定删除或保留。**

具体约定：

```
依赖   : "idb": "^8.0.4"（admin 包 dependencies；已核实 npm 上存在）
库     : garment-erp-piecework-offline v1 / store: pending_counts / keyPath: id
状态   : pending / syncing / conflict / failed
幂等   : Idempotency-Key 入队时生成、重试间不变（05 §5）
退避   : 1s/2s/4s/8s/30s，最多 8 次，超限 → failed（保留）
冲突   : 32001 → status='conflict'，保留 + 常驻计数 + 可展开，不静默丢弃
清理   : conflict 由人工删除或保留；failed 可人工重试或删除
```

## 理由

| # | 理由 |
| --- | --- |
| 1 | [07 §7](../07-认证与权限规范.md) 已把工位机页的存储锁定为 **IndexedDB**，`idb` 只是它的 Promise 封装，**不改变存储选型**，只是让事务生命周期可控 |
| 2 | 裸 `indexedDB` 的事务在 `await` 之后自动失活（`TransactionInactiveError`），而队列逻辑天然是「读 → 等网络 → 写结果」，最容易踩中；`idb` 用约 1KB 换掉这一类只在断网时才暴露的缺陷 |
| 3 | 「冲突不静默丢弃」的可执行解释只能是**保留在队列**：一次性 toast 一闪即逝、无人可追溯；保留条目才能让工人 / 组长看到「已由张三计件」并决定删除或保留 |
| 4 | `idb` 有成熟的测试替代 `fake-indexeddb`，离线队列可进组件测试（jsdom 无真实 IndexedDB），符合 [10-测试规范](../10-测试规范.md) 的要求 |

## 备选方案与否决原因

| 方案 | 是否考虑 | 否决原因 |
| --- | --- | --- |
| 裸 `indexedDB` 封装 | ✅ | 零依赖，但事务生命周期易错（`await` 后失活）、样板代码多；省 1KB 换来一类断网才暴露的缺陷 |
| `localStorage` | ✅ | 员工端口径（[07 §7](../07-认证与权限规范.md)）；容量约 5MB、同步 API 阻塞主线程，工位机高频扫码 + 持久队列不适用 |
| `localForage` | ✅ | 体积更大、且默认会在 IndexedDB / localStorage 间自动降级；降级到 localStorage 正是本决策要避开的 |
| Web Worker + IndexedDB | ✅ | 增加 worker 通信与构建复杂度；当前队列量级 10²，收益不抵成本 |
| PWA service worker / 离线壳 | ✅ | 本卡非目标（只做数据队列）；SW 带来缓存失效、版本升级一整套问题，另有独立评估价值 |

## 影响

| 项 | 说明 |
| --- | --- |
| 正面 | 断网扫码不丢；冲突可追溯、可人工处置；离线路径有测试；大字卡仍以服务端为准 |
| 负面 / 代价 | 新增 1 个前端运行时依赖；测试需 `fake-indexeddb` devDependency；工位机页复杂度上升 |
| 风险 | IndexedDB 在隐私模式 / 配额受限下不可用 → 明确提示「离线不可用」，不假装缓存成功 |
| 迁移路径 | 无数据库迁移（队列只存在于浏览器）；已扫未提交记录随发版不受影响 |
| 回滚方式 | 回退镜像 tag；IndexedDB 残留队列数据无害（旧版本不打开该库） |
| 对规范的影响 | [01 §1](../01-技术选型与架构.md) 加一行 + [§6](../01-技术选型与架构.md) 加 0034 索引；[04-计件 §12](../modules/04-计件.md) 登记 Q-PW18 闭环；[06 §2.5](../06-前端与UI规范.md) 第 6 条最小对齐。**不改**错误码 / 权限点 / 枚举 / 单据号 / 数据库结构 |
| 对测试的影响 | 新增：退避序列、幂等键冻结、`syncing` 崩溃恢复、`32001`→`conflict` 保留、8 次上限、单循环并发 |

## 验证方式

| 指标 | 目标值 | 观测方式 |
| --- | --- | --- |
| 断网扫码落库率 | 100% | 组件测试 + 手工断网 |
| 重试不重复计数 | 0 条重复流水 | 服务端 `idempotent=true`；`piecework_logs` 计数 |
| 冲突静默丢弃数 | 0 | 展开面板冲突计数 |
| 队列跨会话持久 | 刷新后仍在 | 组件测试重新 `openDB` |
