# 02 裁剪模块

> 裁剪单是面料消耗与件数结转的唯一源头：审核即扣面料库存 + 出耗料台账 + 写结转记录，同一事务内完成；反审核成对反向冲销。
> 关联规范：[docs/00 业务蓝图](../00-项目概述与业务蓝图.md)（INV-6）、[docs/04 数据库规范](../04-数据库规范.md) **§7.7（§7.7.2 行=布批 / §7.7.3 三层结构与耗料归属 / §7.7.4 三种录入模式）**、§7.0/§7.0.1（打菲按手）、§7.4（字典表/门幅）、[docs/05 接口设计规范](../05-接口设计规范.md) §4/§9、[docs/07 认证与权限](../07-认证与权限规范.md) §2.2、[docs/08 单据状态机规范](../08-单据状态机规范.md) §2.1、[docs/09 领域术语](../09-领域术语与编码规则.md) §1.2/§1.5b/§2.4/§4.1/§4.2。ADR：[0012](../adr/0012-采购原材料批次字段.md)、[0013](../adr/0013-裁剪尺码比例与手数.md)、[0014](../adr/0014-裁剪明细三种录入模式.md)、**[0016](../adr/0016-打菲按手与扫码得件数.md)**、**[0017](../adr/0017-裁剪按布批与行内多颜色.md)**。
>
> **REV-2026-10（第四批，ADR-0017）层级结构定稿 —— 本轮最重要变更**：
> 裁剪单改为**三层结构**：
> ```
> cutting_orders                        裁剪单（日期 / 车间 / 款号）
> └── cutting_order_lines               ★ 行 = 款号 + 布批（缸号 + 匹号 + 门幅 + 耗料）
>     └── cutting_order_line_colors     ★ 颜色（一床可多个）+ 录入模式 + 比例快照
>         └── cutting_order_size_lines  尺码明细：hands + qty_per_hand + output_qty
> ```
> **耗料记在行（布的属性，与颜色无关）；出数记在尺码明细（颜色的属性）**；一床可裁多个颜色，**每个颜色的比例与手数独立计算**。详见 §2 C32~C36、§3、§5.1、§11 TC-47~TC-53。
> ❌ **上一轮的两层结构（行 = 款号 + 色组，色组挂单头）整体作废**：`cutting_order_colors` → 更名下沉为 `cutting_order_line_colors`（`doc_id` → `line_id`）；原 `cutting_order_lines`（含 `hands`/`qty_per_hand`/`size_code`）→ 更名下沉为 `cutting_order_size_lines`；`cutting_order_lines` 由**新的布批行**占用。
> ✅ **仍然有效的**：ADR-0014 的**三种录入模式**（`MASTER`/`UNIFORM`/`MANUAL`，`entry_mode` 现挂**颜色层**）、比例只作建议值、`floor` 取整、同尺码可多行、`ratio_snapshot` 快照、改行不写回主数据；ADR-0013 的比例主数据 `style_color_size_ratios`（款号 × 颜色 × 尺码 → 手数）；09 §4.2 整件口径。
> > **REV-2026-10（第三批，ADR-0014）明细录入口径**：**比例降级为「建议值」，尺码明细行是「权威数据」**。`hands` 与 `qty_per_hand` 都是**尺码明细级**、同一尺码**可多行且每手件数不同**。
> > **REV-2026-10（第二批，ADR-0013）排版口径**：裁剪明细**先算出件数，再按 BOM 算耗料**。
> > ❌ **旧口径「按 BOM 反算应出件数」已作废**（BOM 回答"一件要多少布"，不回答"这个颜色要做多少件各尺码"），全篇已改写，见 §2 C7/C8/C13/C18~C31、§5。

## 1. 模块职责与边界

| 项 | 内容 |
| --- | --- |
| 职责 | 建裁剪单（款号 + **布批（缸号 + 匹号 + 门幅）** + **行内多颜色** + 尺码明细）；**按颜色选录入模式（三种）并录尺码明细 `hands` / `qty_per_hand` / 出数**；把比例当建议值带出手数；**按铺布实耗录入行耗料**；审核时扣面料、生成耗料出库台账、生成 `cutting_outputs` 结转记录；裁剪损耗与布头入库；**有效门幅校验** |
| 拥有 | `cutting_orders`、**`cutting_order_lines`（布批行）**、**`cutting_order_line_colors`（行内颜色）**、**`cutting_order_size_lines`（尺码明细）**、`cutting_outputs`、`cutting_scrap_records` |
| 上游 | 基础资料（`styles` / `style_colors` / `style_sizes` / **`style_color_size_ratios`（建议值，只读）** / `materials` / `bom_items` / `workshops` / `warehouses`） |
| 下游 | 库存模块（扣料、台账、布头入库）；打菲模块（**必须行级引用 `cutting_order_size_lines.id` 作为 `bundles.cutting_size_line_id`**，§3.8）；完工入库（读结转）；财务（面料成本结转凭证，阶段二） |
| 不负责 | 排料（`marker`）计算逻辑（见 §12 Q-C02）；辅料领用（属库存领料出库单 `MI`）；工位计件 |

**术语对照**（09 §1.2 / §1.3 / §1.5b，全部为强制系统字段名）：

| 中文 | 字段 | 本模块层级 |
| --- | --- | --- |
| 缸号 / 匹号 / 门幅 / 耗料 / 布头 / 尾数 | `dye_lot_no` / `bolt_no` / `width_cm` / `fabric_qty` / `scrap_qty` / `balance_qty` | **行（布）** |
| 颜色 / 录入模式 / 比例快照 | `color_code` / `entry_mode` / `ratio_snapshot` | **行下颜色** |
| 手数 / 每手件数 / 出数 | `hands` / `qty_per_hand` / `output_qty` | **尺码明细** |
| 尺码比例（手数，建议值） | `ratio` | 主数据（`style_color_size_ratios`） |
| 层数 / 裁损 / 利用率 / 有效门幅 | `ply_count` / `cut_waste_qty` / `utilization_rate` / `effective_width_cm` | 单据头 |

> **REV-2026-10 整件口径（09 §4.2）**：本模块一切数量**向下取整到整件**；不足一件的余量是 `balance_qty`（尾数），**不入库、不出码、不计件**，并入 `cut_waste_qty`。**布头 `scrap_qty` 与尾数 `balance_qty` 是两回事**，见 C19。
>
> **REV-2026-10 明细口径（09 §1.5b）**：`output_qty` 的来源是**尺码明细行 `hands` × `qty_per_hand` 向下取整**；**比例 `ratio` 只用于"带出手数建议"，不约束行**；BOM 只在**件数确定之后**算耗料。

## 2. 业务规则

| # | 规则 | 说明 |
| --- | --- | --- |
| C1 | 单据号 | `CT-{YYYYMMDD}-{6 位序号}`（09 §2.1），数据库层序列生成，生成即占用、永不复用 |
| C2 | 车间接单 | `workshop_id` 必填（04 §7.3），是数据范围过滤依据（INV-8） |
| **C3** | **行粒度 = 款号 + 布批（ADR-0017）** | **一行 = 一匹布裁这个款**：`style_no` + `dye_lot_no` + `bolt_no` + `width_cm` + `fabric_qty`（耗料）。**行内可挂多个颜色**（C32）；颜色下才是尺码明细。❌ 旧口径「行 = 匹 × 缸号 × 尺码」作废（那是两层结构遗留，耗料被按尺码重复录入） |
| C4 | 层数与出数 | `ply_count ≥ 1`；`ply_count > 1` 时 `output_qty` 为多层合计后的**总件数**（不是单层件数），UI 必须显式标注"含 N 层" |
| C5 | 数量校验 | 行级 `output_qty ≥ Σ(颜色尺码 output_qty)`（C34）；`fabric_qty > 0`；`output_qty > 0`；`waste_qty ≥ 0`；`balance_qty ≥ 0`。**`cut_waste_qty` 已包含 `balance_qty`（C13），余量不得再单独扣一次** |
| C6 | 头行一致 | 表头 `fabric_qty` = Σ行 `fabric_qty`；`output_qty` = Σ行 `output_qty` = Σ颜色 Σ尺码明细 `output_qty`；`cut_waste_qty` = Σ行之和；`balance_qty` = Σ行之和。差异由 service 重算并覆盖入参，不信任前端 |
| C7 | 耗料量 | 审核时实际耗用 = **Σ行 `fabric_qty`**（每行按其布批独立登记，同缸同匹只录一次）；**不是** BOM 推算值。BOM 只提供**单件用量 `usage_qty` 与耗损率 `waste_rate`**，用于**校验耗料**（见 C8），**不再用于反算件数** |
| C8 | **耗料基准校验（BOM 只算耗料，不算件数；REV-2026-10 改写）** | 件数由**尺码明细算出**（C20~C22）之后，理论耗料 = `Σ(Σ颜色 Σ尺码 output_qty × usage_qty × (1 + waste_rate/100))`，与**逐行**登记 `fabric_qty` 比对；偏差超阈值时 `submit` 阶段告警并要求 `remark` 说明，超硬阈值拒绝提交。**禁止用 BOM 反算「应出件数」**（ADR-0013 理由 ①） |
| C9 | 数量不变式（INV-6） | `bundled_qty + reserved_qty + cut_waste_qty ≤ output_qty + balance_qty`（尾数计入损耗，故右侧含 `balance_qty`），违反 → `30002` |
| C10 | 结转口径 | `cutting_outputs` 按 **（款号, 色组, 尺码）** 记可打菲余量（尺码级汇总）；`bundled_qty` 由打菲审核累加，`reserved_qty` 由提交待审核的打菲单预占。**打菲侧必须再按 `cutting_order_size_lines.id` 行级引用**，否则同尺码跨布批无法区分归属（C31） |
| C11 | 布头处理 | 裁剪剩余**仍可再裁的整段布**（`scrap_qty`，数米以上）在审核时入库为 `stock_type='MATERIAL'`、`direction='IN'`、`source_doc_type='CuttingOrder'`、`batch_no = 缸号+匹号`，单价取**该缸号批次实际成本**（ADR-0011）；**布头可再裁**，所以入库而非直接报废。**与 C19 尾数严格区分，不可合并** |
| C12 | 报废布头 | 无法再利用的碎布（超短、瑕疵）走 `remark` 登记的废料记录 `cutting_scrap_records`，不入可用库存，只进成本 |
| C13 | **件数 = 手数 × 每手件数（精确，不取整；REV-2026-10 改写，ADR-0020）** | ★ **手数 `hands` 是权威输入（正整数，用户直接输入）**，件数由乘法得出：`尺码 output_qty = hands × qty_per_hand`。**取消** ADR-0013 的「按比例反算 + floor」。`hands` 非正整数 → `30006`。**只有人工直接指定出数时**（`MANUAL` 且改的是件数而非手数）才产生尾数：`|人工出数 − hands × qty_per_hand| > 0` 时差额进 `balance_qty`（C21）；尾数仍**不出码、不计件、不入库**（09 §4.2、INV-6） |
| C14 | 改单受限 | `DRAFT`/`REJECTED` 可改；`SUBMITTED`/`APPROVED` 只读；已扣料后想改数量必须先 `reverse` |
| C15 | 不可自审 | `created_by == operator` 拒绝（08 §4） |
| C16 | 库存口径 | 审核校验 `available_qty = stock_qty - locked_qty`，**不是** `stock_qty` |
| C17 | **布头 ≠ 尾数（本模块强制区分，09 §3 明令）** | `scrap_qty` = 裁完**仍可再裁的整段布**（数米以上）→ **入库**为布料批次（同缸号匹号，批次实际成本 ADR-0011）；`balance_qty` = 产出**不足一件**的余量 → **不入库**（无 `stock_ledgers` 行、无批次行），只并入 `cut_waste_qty`。录入界面、列表、报表**必须分列展示，禁止合并成一个"剩余"字段** |
| C18 | **比例是「建议值」，尺码明细是「权威数据」**（ADR-0014，ADR-0017 保留） | 比例主数据落在 `style_color_size_ratios`（款号 × 颜色 × 尺码 → **手数**，见 [04 §7.7.1](../04-数据库规范.md)、§3.3），**只用于「带出手数建议」**，**不约束裁剪单行**。裁剪明细可以任意偏离比例而**不需要任何理由**。比例主数据归 [01-基础资料](./01-基础资料.md) 维护，本模块只读 |
| C19 | **比例缺配不再硬拦截（ADR-0014 修订）** | ① 该 `(style_no, color_code)` **完全没有**任何比例行 → `20006`（连建议都没有，属漏配，仍硬拦）；② **部分**尺码缺配 → **不拦**，返回 `details.missing_size_codes` 仅作提示，用户可切 `MANUAL` 手录；③ 比例里出现款号颜色组内**没有**的尺码 → `20007`（主数据脏数据，仍硬拦） |
| C20 | **手数是权威输入（ADR-0020 修订）** | ★ `hands` **必须是正整数**（DB `CHECK (hands > 0 AND hands = trunc(hands))`，否则 `30006`），不再允许 1.5 手；`Σratio` 仍是建议值，与实际 `hands` 偏离 **> 20%** 给黄色提示**不拦截**。实际手数 = 本单各尺码明细 `hands` 之和（按颜色各自汇总） |
| C21 | **整数乘法，不取整不四舍五入（ADR-0020 修订）** | `output_qty = hands × qty_per_hand`（整数 × 整数 = 整数，**精确值，不需要也不允许 floor/round**）。**禁止**前端把件数四舍五入后回写手数。人工改出数时的差额处理见 C13 |
| C22 | **`hands` 与 `qty_per_hand` 都是尺码明细级**（ADR-0014；ADR-0020 追加整数约束） | 两个字段都在 `cutting_order_size_lines`，**同一尺码可多行且两字段取值不同**（如 `XL 2手×60件` 与 `XL 1手×30件`）。`<= 0` → `10001`；**`hands` 非整数 → `30006`** |
| C23 | ~~单据可覆盖比例~~ → **已由 ADR-0014 取代** | 「行级可改 `hands`」就是"偏离比例"的正常表达方式，**不再需要** `ratio_override` + 必填原因的覆盖机制。替代品：① 尺码明细 `hands` 可改（C22）；② 颜色层 `ratio_snapshot`（jsonb）快照当时比例；③ 改行写 `document_logs`。原「`OVERRIDE` 缺原因 → `10006`」校验取消 |
| C24 | **有效门幅校验（提交前预警，不满足阻止提交）** | `submit` 时校验所选批次的 `effective_width_cm`（= `material_stocks.width_cm` − 左右布边 − 对格损耗）是否满足该款铺布要求：**不满足 → 阻止提交**；接近临界（余量 < 5%）给**预警不阻断**。`approve` 时再校验一次（防并发改批次）。铺布对格方式与布边 cm 取值待业务方确认（§12 Q-C08） |
| C25 | **界面必须同时显示「手数」与「件数」两列** | 明细矩阵格**分两行展示**：上行「手数」可编辑（整数），下行「件数 = 手数 × 每手件数」**只读自动算**。前端禁止只显示一个「数量」列，禁止让用户直接录件数（除非切 `MANUAL` 人工指定） |
| C26 | **三种录入模式，模式是「颜色级」属性**（ADR-0014 + ADR-0017） | `entry_mode ∈ {MASTER, UNIFORM, MANUAL}`，存在**行下颜色表 `cutting_order_line_colors`**，**不存单据头、不存尺码明细**。**同一行里不同颜色用不同模式完全允许**（WHT `MASTER` + BLK `MANUAL`，§5.1 实例）——业务方的差异是"这个颜色特殊"。⚠️ ADR-0017 修订前挂在 `cutting_order_colors`（单据级），**现已下沉为行内颜色级**（04 §7.7.4 第 8 条随之修订） |
| C27 | **模式切换要二次确认（切模式会清空 `hands`）** | 从 `MASTER` 切到 `UNIFORM` / `MANUAL` 会清掉**该行该颜色**当前尺码明细的 `hands` → 前端必须弹**二次确认**并明示「已有 N 行手数将被清空」；只影响该行该颜色 |
| C28 | **人工改 `qty`（出数）自动转 `MANUAL`** | 尺码明细的出数一旦被**人工指定**（与服务端 `floor(hands × qty_per_hand)` 的计算值不同），**所在颜色** `entry_mode` 自动置 `MANUAL` 并写 `document_logs`。`MASTER` / `UNIFORM` 下改 `hands` 或 `qty_per_hand` **不**转模式 |
| C29 | **改行绝不写回比例主数据（零污染，本模块铁律）** | `MANUAL` 追加 / 删除 / 修改尺码明细**只改本单的 `cutting_order_size_lines`**，**严禁 `INSERT/UPDATE/DELETE style_color_size_ratios`**。验证口径：用完模式 C 后检查比例主数据零变更 |
| C30 | **同一尺码可多行**（ADR-0014） | 明细唯一约束为 `UNIQUE (line_color_id, size_line_no)`，**允许同尺码多行**。每行独立算 `output_qty` / `balance_qty` / 耗料；`cutting_outputs` 按**尺码汇总**，**下游必须行级引用**（C31） |
| C31 | **下游引用必须行级 `cutting_size_line_id`，不能只靠 `size_code`** | 打菲码 `bundles.cutting_size_line_id` → `cutting_order_size_lines.id`（**件数权威来源**，ADR-0016 + ADR-0017 §4）；`bundling_order_lines.cutting_size_line_id` 冗余引用；`piecework_logs.bundle_id` → `bundles.id`。❌ 上一轮的 `cutting_line_id`（指向旧的两层 `cutting_order_lines`）**作废**：新结构下"行"是布批，"尺码明细"才是件数载体，二者不可混 |
| **C32** | **一床可裁多个颜色（ADR-0017 核心）** | 一个 `cutting_order_lines`（一匹布）下可挂 **N 个 `cutting_order_line_colors`**。铺布时不同颜色的布可拼在同一裁床上按各自比例裁，**省布 5~10%**（拼接对花）。**每个颜色的尺码比例、每手件数、手数、录入模式、出数全部独立**（唯一约束 `UNIQUE (line_id, color_code)`） |
| **C33** | **行耗料下限校验（ADR-0017）** | `行 fabric_qty ≥ Σ(该行各颜色 Σ(尺码 output_qty × BOM.单件用量 × (1+waste_rate/100))) + 行 waste_qty`。**不满足 → `30002`**。理由：耗料由铺布实耗**正向录入**（不是从出数反推），两者独立，用校验约束一致性，避免循环计算 |
| **C34** | **行余量 = 行出数 − Σ颜色出数（ADR-0017）** | `行 balance_qty = 行 output_qty − Σ(颜色 Σ尺码 output_qty)`。行 `output_qty` 取 `floor(可裁件数)`（09 §4.2 整件口径）；**结果为负 → 报错 `30002`（耗料不足）**；为正即行级余量，并入 `cut_waste_qty`。**余量归行、不归颜色**（余量无法区分是哪一色多出来的） |
| **C35** | **耗料记行、出数记尺码明细 —— 原因必须写清（ADR-0017 理由 ①）** | ① **耗料是布的属性**：一匹布（缸号 `DY-2609-01`）裁什么与布本身有关，与裁几个颜色无关；同缸布被两色共用时耗料**只录一次**，不会重复录也不会分摊出错。② **出数是颜色的属性**：件数由该色的尺码比例与每手件数决定，与其他颜色无关。③ 二者解耦后**不再循环**：耗料正向录入、出数正向计算，靠 C33/C34 的 CHECK 兜一致性。④ 与库存批次天然对齐（批次 = 缸号 + 匹号，ADR-0012），行 ↔ 批次一一对应 |
| **C36** | **同缸布可被多行占用（ADR-0017 风险 ①）** | 同一 `(dye_lot_no, bolt_no)` 允许出现在**多张裁剪单的多行**（先裁一部分布，剩下的再裁一单）。审核时按**每行各自** `fabric_qty` 扣减同一批次；**累加扣减不得超该批 `available_qty`**，超 → `40001` |

| C37 | **商品分类取自款号档案，★ 单据不可改**（ADR-0020，业务确认 2026-10-02） | 裁剪单**不存分类列**，分类一律 `JOIN styles.category_id` 取值，界面**只读展示**（灰底不可编辑）。分类变更只能在款号档案上做，影响该款全部单据。取价优先级：`款号专用价` > `分类+工序专用价` > `工序通用价`，实际取到的档位写入 `piecework_logs.rate_source`。款号无分类 → 建款号时 `10001`，不允许建档 |
| C38 | **选料必须级联到布批（供应商 → 缸号/匹号），超出可用即拒**（REV-2026-10，[ADR-0022](../adr/0022-采购台账与库存供应商维度.md)） | 布批行不允许自由输入缸号：必须从 `v_material_stock_by_supplier` 选**该供应商名下 `available_qty > 0` 的 `(dye_lot_no, bolt_no)`**，并显示门幅与可用重量。`fabric_qty > available_qty` → `40006`。**同缸布可跨单行占用，但累计不得超批次可用量**（C36） |
| C39 | **裁剪审核即裁片入 WIP**（REV-2026-10，[ADR-0018](../adr/0018-出入库链路与在制品WIP.md)） | 审核第 ⑧ 步写 `wip_stocks` + `wip_ledger_lines(IN)`，`source_doc_id` = 裁剪单。**尾数不入 WIP**；WIP 不计成本（`unit_cost` 恒 NULL）。反审核同步冲回。**裁剪侧不生成成衣库存**，成衣入库由最后一道工序触发 |
| C40 | **改单 → 打菲码联动：已计件的手冻结**（REV-2026-10，[ADR-0021](../adr/0021-裁剪改单与打菲联动.md)） | ① `DRAFT`/`SUBMITTED` 随便改；② `APPROVED` 改任何业务字段都**回到 `SUBMITTED` 需重新审核**（`30005`）；③ 任一码 `counted_at IS NOT NULL` → **拒绝修改**（`30004`），必须先红冲反计件；④ 已打菲未计件：未打印码软删重建、已打印码置 `VOIDED`（提示 `31007`）。详见 [08 §2.1.1](../08-单据状态机规范.md) |
| C41 | **溯源链双向可达**（REV-2026-10，[ADR-0023](../adr/0023-生产单据页面重排与溯源链.md)） | 每个尺码明细行、每个码都必须能反查「款号 → 裁剪单 → 布批（缸号/匹号）→ 供应商」，正向也能查「打菲单 → 码 → 计件流水 → 工资」。实现约束：`bundles.cutting_size_line_id` 必须落库（不得只在内存关联）。列表页「来源」列可点击跳父单 |

## 3. 数据模型

所有表含 04 §2 公共字段。`cutting_orders` 另含 04 §7.3 单据公共列。

### 3.0 三层结构总览（照抄 [04 §7.7.2 / §7.7.3](../04-数据库规范.md)，本模块不得改写 DDL）

```sql
-- ★ 第 1 层：行 = 一匹布裁这个款（耗料记在行，布的属性，与颜色无关）
CREATE TABLE cutting_order_lines (
    id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_id            uuid NOT NULL REFERENCES cutting_orders(id) ON DELETE RESTRICT,
    line_no           integer NOT NULL,
    style_no          varchar(32) NOT NULL,
    -- 布批（缸号 + 匹号）
    dye_lot_no        varchar(64) NOT NULL,
    bolt_no           varchar(32) NOT NULL,
    color_plan        varchar(64),                   -- 铺布排版说明（可选）
    width_cm          numeric(8,2),                  -- 铺布用门幅（默认取批次实测值）
    fabric_qty        numeric(14,3) NOT NULL,        -- **耗料（米）** ← 行级，布的属性
    fabric_weight_kg  numeric(14,3),                 -- 用掉的重量
    waste_qty         numeric(14,3) NOT NULL DEFAULT 0,  -- 布头（可再裁，入库）+ 布损
    output_qty        numeric(14,3) NOT NULL DEFAULT 0,  -- 行出数合计 = Σ(颜色 Σ(尺码 output_qty))
    balance_qty       numeric(14,3) NOT NULL DEFAULT 0,  -- 行余量（不足件，09 §4.2）
    ...公共字段,
    CONSTRAINT uq_cutting_order_lines UNIQUE (doc_id, line_no),
    CONSTRAINT ck_cutting_lines_fabric CHECK (fabric_qty > 0)
);
CREATE INDEX idx_cutting_order_lines_lot ON cutting_order_lines (dye_lot_no, bolt_no)
       WHERE deleted_at IS NULL;

-- ★ 第 2 层：行下颜色：一床可多个颜色（ADR-0017）
CREATE TABLE cutting_order_line_colors (
    id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    line_id           uuid NOT NULL REFERENCES cutting_order_lines(id) ON DELETE RESTRICT,
    color_code        varchar(32) NOT NULL,
    entry_mode        cutting_entry_mode NOT NULL DEFAULT 'MASTER',
    qty_per_hand      numeric(14,4),                  -- 模式 A/B 的默认每手件数
    uniform_qty       numeric(14,3),                  -- 模式 B 的统一件数
    ratio_snapshot    jsonb,                          -- 下单时的比例快照
    ...公共字段,
    CONSTRAINT uq_cutting_line_colors UNIQUE (line_id, color_code)
);

-- ★ 第 3 层：尺码明细：hands + qty_per_hand 均为明细级，同尺码可多行（ADR-0014 + ADR-0016）
CREATE TABLE cutting_order_size_lines (
    id                uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    line_color_id     uuid NOT NULL REFERENCES cutting_order_line_colors(id) ON DELETE RESTRICT,
    size_line_no      integer NOT NULL,
    size_code         varchar(32) NOT NULL,
    hands             numeric(14,4) NOT NULL,         -- 本行裁几手
    qty_per_hand      numeric(14,4) NOT NULL,         -- 本行每手几件（**明细级**，同尺码多行可不同）
    output_qty        numeric(14,3) NOT NULL,         -- = floor(hands × qty_per_hand)，可人工覆盖
    hands_seq         integer,                        -- 手序号预留（打菲拆分用）
    remark            text,                          -- 「新增行」等说明
    ...公共字段,
    CONSTRAINT uq_cutting_size_lines UNIQUE (line_color_id, size_line_no)
);

CREATE TYPE cutting_entry_mode AS ENUM ('MASTER', 'UNIFORM', 'MANUAL');
```

**为什么是三层而不是把颜色平铺**（ADR-0017 备选方案表）：平铺会丢失"**每个颜色一套录入模式与一套比例**"的语义，比例校验无法按色聚合；引入"床"实体又多一层间接且"一床可能多布批"，行 = 布批已够。

### 3.3 `cutting_order_line_colors`（★ 行内颜色，ADR-0017 第 2 层）

> **ADR-0017 修订**：原 `cutting_order_colors`（`doc_id` + `color_code` 唯一、单据级色组）**已作废**。新表 `UNIQUE (line_id, color_code)`，挂在**布批行**下 —— 因为"这个颜色用哪种录入模式、这套比例"是**这匹布上这个颜色**的属性，换一匹布就可能换模式。04 §7.7.4 第 8 条「模式是行 × 颜色级属性」随之修订。

| `hands_total` | `numeric(14,4)` | ✅ | 该颜色各尺码明细 `hands` 之和（service 重算，不信任前端） |

| `entry_mode_changed_at` / `entry_mode_changed_by` | `timestamptz` / `uuid` | ❌ | 模式切换留痕（配合 C27 与 `document_logs`） |
| 公共字段 | 见 04 §2 | — | 同上 |

约束：`uq_cutting_line_colors (line_id, color_code)`、`CHECK (entry_mode IN ('MASTER','UNIFORM','MANUAL'))`、`CHECK (hands_total >= 0)`。

| 规则 | 说明 |
| --- | --- |
| 一行可几个颜色 | **N 个**（ADR-0017 核心，C32）。上限走配置，阶段一不设硬上限 |
| 跨行同色 | 允许：行1 有 BLK、行2 也有 BLK（两匹布都裁黑色），但**各自比例/手数独立** |
| 模式切换 | `POST /cutting-orders/{id}/entry-mode`（`line_id` + `color_code` + `mode` + `confirm`）；从 `MASTER` 切走清该颜色各尺码明细 `hands`，**必须二次确认**（C27）；写 `document_logs` |
| 与尺码明细的关系 | 尺码明细通过 `line_color_id` 归属；权威出数在尺码明细，颜色层只做汇总与模式承载 |
| 颜色合法性 | 必须是该款 `style_colors` 内启用的颜色，且尺码在该款尺码集合内，否则 `20007` |

### 3.4 `cutting_order_size_lines`（★ 尺码明细，ADR-0017 第 3 层）

| **`output_qty`** | `numeric(14,3)` | ✅ | 服务端算 `floor(hands × qty_per_hand)`（C21），**允许人工覆盖**（覆盖即该颜色转 `MANUAL`，C28）。**恒为整数** |
| `hands_seq` | `integer` | ❌ | 手序号预留（打菲按手拆分用，ADR-0016）。阶段一由 service 在审核时按 `hands` 展开回填 |
| `balance_qty` | `numeric(14,3)` | ✅ | 本明细尾数 `= hands × qty_per_hand − output_qty`，**归集到行 `balance_qty`**（C34）；不入库、不出码、不计件 |
| `usage_qty` | `numeric(14,3)` | ✅ | **单件用量快照**（09 §1.2），保存时从 BOM 读入。**只用于算耗料，不用于反算件数**（C8） |
| `waste_rate` | `numeric(6,4)` | ✅ | 耗损率快照 |
| `remark` | `text` | ❌ | 「新增行」「加急」等说明 |
| 公共字段 | 见 04 §2 | — | 同上 |

> `usage_qty` / `waste_rate` 在明细上做**快照**而非审核时实时查 BOM：反审核与审计要能还原"当时按什么算的"，与 INV-3 同理。
> ⚠️ **必填时机**：`hands` / `qty_per_hand` 可空起步，**`approve` 后必填**（缺失 → `10002` 要求补录），避免上线即锁死存量草稿单。

**唯一约束（ADR-0017）**：

| 项 | 口径 |
| --- | --- |
| 布批行 | `UNIQUE (doc_id, line_no)`（04 已建） |
| 行内颜色 | `UNIQUE (line_id, color_code)` —— **同一匹布 + 同一颜色只能一行** |
| 尺码明细 | `UNIQUE (line_color_id, size_line_no)` —— `line_no` 在**同颜色内**唯一即可；**允许 `(line_color_id, size_code)` 重复** |
| 报表与结转 | `cutting_outputs` 按 **（款号, 色组, 尺码）** 汇总；打菲必须**尺码明细行级引用** `cutting_size_line_id`（C31） |

### 3.5 `style_color_size_ratios`（款号尺码比例主数据，**引用 04 §7.7.1，本模块只读**）

> 归属 [01-基础资料](./01-基础资料.md) §3（本模块**不拥有**该表，只在 `submit`/`approve` 读取）。**权威口径在 [04 §7.7.1](../04-数据库规范.md)**，此处不重复定义、不允许本模块自行加列。

| 读取场景 | 本模块用法 | 失败码 |
| --- | --- | --- |
| 建单带出建议（模式 A） | 选定 `style_no` + `color_code` 后 `GET /suggest-lines` 带出该颜色全部尺码的建议 `hands`（= `ratio`）；带出后写入 `cutting_order_size_lines.hands` 与 `cutting_order_line_colors.ratio_snapshot` | **完全无该颜色比例** → **`20006`**；**部分缺配** → 不报错，返回 `missing_size_codes` **仅提示**（C19） |
| 提交/审核校验 | ① 该颜色**一条比例都没有** → `20006`；② 比例表出现款号颜色组内**没有**的尺码 → **`20007`**（主数据脏数据，硬拦）；③ **部分缺配不拦** | `20006` / `20007` |
| 计算明细 | 该明细 `output_qty = floor(hands × qty_per_hand)`；`hands` 可改，与 `ratio` 无关 | `hands <= 0` 由 DB `CHECK` 挡住 |
| 手数合计 | `Σratio` = **建议**手数合计（不要求整数）；**实际手数以本单各尺码明细 `hands` 之和为准**（C20） | — |
| 改行 / 追加行 | **只写 `cutting_order_size_lines`，严禁写本表**（C29） | — |

- **比例主数据由谁维护**：颜色 / 尺码 / 尺码比例的 CRUD 归 [01-基础资料](./01-基础资料.md) §6（`base:read` / `base:update`）；本模块 §6 只暴露 `GET /suggest-lines` 供建单带出建议。
- **比例快照**：单据保存时把当时的比例写入 `cutting_order_line_colors.ratio_snapshot`（jsonb）；**主数据后续改动不影响已提交/已审核单据**。

### 3.6 `cutting_outputs`（裁剪结转，08 §2.1 命名的 `cutting_output`）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `style_no` | `varchar(32)` | ✅ | ✅（+`color_group`+`size_code`） | 款号 |
| `color_group` | `varchar(32)` | ✅ | ↑ | 色组 |
| `size_code` | `varchar(16)` | ✅ | ↑ | 尺码（C10） |
| `workshop_id` | `uuid` | ✅ | — | 车间 |
| `output_qty` | `numeric(14,3)` | ✅ | — | 裁剪累计出数（审核累加，反审核减）。恒为整数累计值 |
| `balance_qty` | `numeric(14,3)` | ✅ | — | 累计尾数（09 §4.2）。**不入库、不出码、不计件**，已含在 `cut_waste_qty` 中 |
| `bundled_qty` | `numeric(14,3)` | ✅ | — | 打菲累计占用，打菲审核累加 |

- CHECK：`output_qty >= 0`、`bundled_qty >= 0`、`reserved_qty >= 0`、`balance_qty >= 0 AND balance_qty < 1`（逐次审核尾数恒不足一件，累计可 ≥ 1）。
- CHECK：`cut_waste_qty >= balance_qty`。
- 每次增减写 `document_logs`（`doc_type='CuttingOutput'`, `action='CREATE'|'REVERSE'|'BUNDLE_UPDATE'`）。

## 4. 单据与状态机

迁移表严格对齐 08 §2.1 与 §1.1（动作名 `submit`/`approve`/`reject`/`withdraw`/`reverse`/`cancel`）。

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用（与状态变更同事务，08 R4） |
| --- | --- | --- | --- | --- | --- |
| `create` | — | `DRAFT` | `cutting:create` | 款号存在且启用；车间存在；面料 `material_type='FABRIC'` | 生成 `doc_no`；重算头行合计（C6） |
| `update` | `DRAFT` / `REJECTED` | 同 | `cutting:update` | `version` 乐观锁；`line_no` 可改，数量不可负 | 写日志 + `changed_fields` diff |
| `submit` | `DRAFT` / `REJECTED` | `SUBMITTED` | `cutting:submit` | 明细非空；每行 `fabric_qty > 0`；`ply_count ≥ 1`；C5 数量校验（含 C33 耗料下限、C34 余量非负）；**C19 比例校验**（完全无比例 → `20006`，比例含款号没有的尺码 → `20007`）；`hands > 0` 且 `qty_per_hand > 0`（否则 `10001`）；C28 人工改过出数的颜色已转 `MANUAL`；C8 耗用偏差（超阈值需 `remark`）；**C24 有效门幅校验**；`available_qty ≥ Σ行 fabric_qty`（不足 `40001`） | 预占 `cutting_outputs.reserved_qty`（按**尺码汇总**）；写 `cutting_orders.ratio_snapshot` 与各颜色 `ratio_snapshot` |
| **`approve`** | `SUBMITTED` | `APPROVED` | `cutting:approve` | 制单人 ≠ 审核人（`10005`）；重算 `available_qty`（防并发吃掉库存）；再校验 C19 + C24（防并发改批次/比例主数据）；再校验 INV-6 | **见下方「审核副作用七步（ADR-0017 重排）」** |
| `reject` | `SUBMITTED` | `REJECTED` | `cutting:reject` | **必填 `reason`** | 释放 `reserved_qty`；写日志 |
| `withdraw` | `SUBMITTED` | `DRAFT` | `cutting:update` | 撤回人 = `created_by` | 释放 `reserved_qty`；写日志 |
| `reverse` | `APPROVED` | `SUBMITTED` | `cutting:reverse` | **必填 `reason`**；`output_qty + balance_qty − 本次冲销量 − cut_waste_qty ≥ 已打菲数`，否则 `30002`；布头已被下游领用则拒绝 | **① 按布批行逐行 `+fabric_qty` 加回 `material_stocks.stock_qty`；② 写反向 `stock_ledgers`（`direction='IN'`）；③ `cutting_outputs.output_qty` / `balance_qty` / `cut_waste_qty` 减；④ 布头反向出库（已被领用 → 拒绝 `40001`）；⑤ 写日志。原始记录与原始台账全部保留** |

### 4.1 `approve` 副作用七步（**ADR-0017 重排，顺序不可调换**）

```
①  按缸选批扣料
    逐行按 (warehouse_id, fabric_id, dye_lot_no, bolt_no) 条件 UPDATE：
       UPDATE material_stocks
          SET stock_qty = stock_qty - :row.fabric_qty
        WHERE id = :stock_id AND (stock_qty - locked_qty) >= :row.fabric_qty
       rowcount = 0 → 40001（返回该布批当前可用量）
    ⚠️ 同一 (dye_lot_no, bolt_no) 被多行占用时逐行累加扣（C36），
       全程条件 UPDATE，绝不"先 select 后 update"

②  写批次明细
    stock_ledgers（source_doc_type='CuttingOrder', direction='OUT', stock_type='MATERIAL',
                   qty = −行 fabric_qty）+ stock_ledger_lines（记 dye_lot_no + bolt_no）

③  逐行重算行出数
    行 output_qty = Σ(该行各颜色 Σ(该颜色各尺码明细 floor(hands × qty_per_hand)))
    尺码明细 output_qty 被人工指定过 → 取人工值
    逐尺码明细 balance_qty = hands × qty_per_hand − output_qty
    ❌ 不用 BOM 反算件数；❌ 不用 Σfloor(ratio × qty_per_hand)（比例只是建议值）

④  耗料校验（ADR-0017 新增，行级下限）
    Σ(Σ颜色 Σ尺码 output_qty × usage_qty × (1 + waste_rate/100)) + 行 waste_qty ≤ 行 fabric_qty
    不满足 → 30002（C33）
    行 balance_qty = 行 output_qty − Σ颜色出数 < 0 → 30002（C34，耗料不足）

⑤  有效门幅校验
    material_stocks.width_cm（取实测值）− 布边 − 对格损耗 ≥ 该款铺布要求
    不满足 → 阻止并提示当前门幅与所需门幅（C24，防 submit 后被改批次）

⑥  结转
    cutting_outputs.output_qty / balance_qty 按（款号, 色组, 尺码）汇总累加
    cutting_outputs.reserved_qty 清零
    cut_waste_qty = 正常损耗 + Σ行 balance_qty（校验 ≥ balance_qty）
    cutting_order_size_lines.hands_seq 按 hands 展开回填（打菲按手拆分用，ADR-0016）

⑦  布头入库
    cutting_scrap_records（line_id = 布批行，scrap_type='REUSABLE'）
    → stock_ledgers direction='IN' + stock_ledger_lines，dye_lot_no/bolt_no 沿用被裁批次
    → unit_cost = 该缸批次实际成本（ADR-0011）
    ❌ 尾数 balance_qty 不入库、不写台账（C17 / 09 §4.2）
```

**审核/反审核副作用对称表**（08 §3.3 强制）：

| 副作用 | `approve` | `reverse` |
| --- | --- | --- |
| `material_stocks.stock_qty` | **逐行** `−行 fabric_qty` | 逐行 `+行 fabric_qty` |
| `stock_ledgers` | 写 OUT 流水（`qty` 负）+ `stock_ledger_lines` 批次明细 | 写 IN 反向流水（`qty` 正），**新增行不删旧行** |
| 布批行 `output_qty` | **按 ③ 重算**（= Σ颜色 Σ尺码明细） | 减回本次出数 |
| 布批行 `balance_qty` | **按 ③/C34 归集** | 减回 |
| 尺码明细 `output_qty` / `balance_qty` | 落整件口径后固化 | 还原为审核前快照 |
| `cutting_outputs.output_qty` / `balance_qty` | 累加 | 减回 |
| `cutting_outputs.reserved_qty` | 清零 | 重新预占 |
| 布头库存 `scrap_qty` | 入库（`REUSABLE`，C11/C17） | 反向出库 |
| **尾数 `balance_qty` 库存** | **无任何入库台账**（C17，09 §4.2） | **无（本就未入库，无需冲销）** |
| `material_stocks` 缸号批次成本 | 不改（成本入库即定，ADR-0011） | 不改 |
| `document_logs` | 追加 APPROVE（记逐行扣料与逐尺码取整结果） | 追加 REVERSE + 原因 |

- **非法迁移**：`APPROVED→submit`、`SUBMITTED→approve` 以外的直接跳、`CANCELLED→*` 一律 `30001`。
- **状态字段只允许 service 的 `_apply_status` 写**（08 R7）；Repository 不得出现 `status` 参数。

## 5. 核心流程

> **顺序铁律（09 §1.5b / ADR-0014 / ADR-0017）**：**先由尺码明细定件数，再算耗料**；**耗料由铺布实耗正向录入，出数由比例正向算出**，二者用校验（C33/C34）约束一致性。
> **REV-2026-10 第四批**：录入顺序改为「**行（布批）→ 颜色 → 尺码明细**」三层展开，**行必须先建**（因为颜色挂在行下）。

1. **选款号 + 车间 + 仓库 + 日期**；`color_group` 选色组（订单色组）。
2. **建行（布批行）**：录入员按铺布实耗逐行登记 —— `缸号` + `匹号` + `门幅`（默认取批次实测值）+ `耗料 fabric_qty` + `布头/布损 waste_qty` + `铺布说明 color_plan`（可选）。**同一匹布只建一行**；同一缸号的不同匹、或同缸的多段布，各建一行（C36 允许同缸布出现在多行）。
3. **建行内颜色（可多个）**：该匹布要裁哪些颜色？逐个在 `PUT /lines/{line_id}/colors` 里加，**每个颜色各自选录入模式**（C26/C32）。默认 `MASTER`。
4. **选录入模式（颜色级）**，界面给三个按钮：
   - 「**按比例带出**」→ `MASTER`：点一次出该颜色全部尺码明细行（`hands` = 比例），用户只填 `qty_per_hand`；
   - 「**统一件数**」→ `UNIFORM`：填一个件数，所有尺码出数相同；
   - 「**自定义明细**」→ `MANUAL`：可增 / 删 / 改任意尺码明细行。
   - ⚠️ **切换模式二次确认**（C27）：从 `MASTER` 切走会清空**该行该颜色**各尺码明细的 `hands`，弹窗明示「已有 N 行手数将被清空」。
5. **录尺码明细**：`hands` / `qty_per_hand` / `output_qty` 三者任填其一（模式 A/B 走前两个，模式 C 任一）；**同一尺码可多行且每手件数不同**（如 `XL 2手×60件` + `XL 1手×30件`）。**追加 / 修改 / 删除一律只写本单 `cutting_order_size_lines`，严禁动 `style_color_size_ratios`**（C29）。
6. **人工改 `qty`（出数）→ 自动转 `MANUAL`**（C28）：只要某尺码明细出数被人工指定，该颜色 `entry_mode` 自动置 `MANUAL` 并写 `document_logs`。
7. **比例缺配怎么办**（C19）：点「按比例带出」时若该颜色**完全没有**比例 → `20006`（**硬拦**）；若**部分**尺码缺配 → **不拦**，返回 `missing_size_codes` 提示，可切 `MANUAL` 手录。保存时把当时的比例写入 `cutting_order_line_colors.ratio_snapshot`。
8. **行出数上限与余量**：`行 output_qty = floor(可裁件数)`（按铺布实耗估），必须 `≥ Σ(颜色 Σ尺码出数)`；差额即 `行 balance_qty`（C34）。**系统不做反算**，只做校验并在保存时回显差额。
9. **耗料下限试算**（C33）：`Σ(尺码出数 × usage_qty × (1+waste_rate/100)) + waste_qty ≤ 行 fabric_qty`，前端实时显示"理论需布 X m / 实登记 Y m"，`Y < X` → `30002` 阻断提交。
10. **门幅校验**（C24）：按行上的批次 `effective_width_cm` 与该款铺布需求比较——**不满足 → 阻止提交**；余量 < 5% → 预警不阻断。`approve` 再校验一次。
11. 保存为 `DRAFT`：表头与各行、各颜色合计由**后端重算**（C6），**不信任前端**。
12. `submit`：校验数量、`hands` / `qty_per_hand > 0`、比例校验（`20006`/`20007`）、**行耗料下限（C33）**、**行余量非负（C34）**、门幅、耗用偏差、可用库存 → 预占 `cutting_outputs.reserved_qty`（按尺码汇总）。
13. 主管 `approve`（本人建的单不能自审，`10005`）：按 §4.1 **七步**执行。

### 5.2 三种录入模式并排示例（同 §5.1 的 WHT（行1）演示 ADR-0014）

款号红色，L:XL:XXL:3XL 比例 = **1:2:2:1**（主数据，共 6 手）。三个示例用同一款同一色：

#### 模式 A（`MASTER` 按比例带出）
```
点「按比例带出」→ 出 4 行（hands 取自比例）→ 只填 qty_per_hand = 60
┌──────┬──────────┬──────────┬──────────┐
│ 尺码 │ hands(手)│ 每手件数 │ 出数(件) │
├──────┼──────────┼──────────┼──────────┤
│ L    │ 1.0000   │ 60       │ 60       │  floor(1×60)
│ XL   │ 2.0000   │ 60       │ 120      │  floor(2×60)
│ XXL  │ 2.0000   │ 60       │ 120      │  floor(2×60)
│ 3XL  │ 1.0000   │ 60       │ 60       │  floor(1×60)
├──────┼──────────┼──────────┼──────────┤
│ 合计 │ 6.0000 手│          │ 360 件   │
└──────┴──────────┴──────────┴──────────┘
比例主数据 0 变更
```

#### 模式 B（`UNIFORM` 统一件数）
```
点「统一件数」→ 填 1 个件数 = 100 → 所有尺码出数相同
┌──────┬──────────┬──────────┬──────────┐
│ L    │ 1.0000   │ 100      │ 100      │  ← 比例不影响
│ XL   │ 2.0000   │ 100      │ 100      │
│ XXL  │ 2.0000   │ 100      │ 100      │
│ 3XL  │ 1.0000   │ 100      │ 100      │
├──────┼──────────┼──────────┼──────────┤
│ 合计 │ 6.0000 手│          │ 400 件   │
└──────┴──────────┴──────────┴──────────┘
★ 比例不为 1:1:1:1 时也能做出等量（ADR-0013 表达不了的场景）
```

#### 模式 C（`MANUAL` 自定义明细）—— 在模式 A 基础上追加一行
```
模式 A 已录好 4 行 → 追加一行「XL 1 手 × 30 件」（同尺码第二行、每手件数不同）
┌──────┬──────┬──────────┬──────────┬──────────┐
│ line │ 尺码 │ hands(手)│ 每手件数 │ 出数(件) │
├──────┼──────┼──────────┼──────────┼──────────┤

│  3   │ XL   │ 1.0000   │ 30       │ 30       │ ← ★ 新增行
│  4   │ XXL  │ 2.0000   │ 60       │ 120      │
│  5   │ 3XL  │ 1.0000   │ 60       │ 60       │
├──────┼──────┼──────────┼──────────┼──────────┤

★ 新增的 line 3 只存在于这张裁剪单里
  → style_color_size_ratios 中 XL 仍为 2.0000（主数据零污染）
  → 下次裁剪仍按 2 手带出建议

```

**同一行内混用模式**（C26/C32，颜色级）：

| 布批行 | 颜色 | `entry_mode` | 尺码明细 | 说明 |
| --- | --- | --- | --- | --- |
| 行1 `DY-2609-01` | WHT | `MASTER` | 4 行（60/120/120/60）= 360 | 按比例带出，只填每手件数 |
| 行1 `DY-2609-01` | BLK | `MASTER` | 3 行（50/100/100）= 250 | 同款不同色，比例独立 |
| 行1 `DY-2609-01` | GRY | `UNIFORM` | 4 行（全 100）= 400 | 所有尺码件数一样 |
| 行2 `DY-2609-02` | WHT | **`MANUAL`** | 3 行（120/30/120）= 270 | **同一款同一色，换一匹布换模式** |

**取整带小数手数**（`hands` 允许小数，`numeric(14,4)`）：某色 L = 1.5 手、`qty_per_hand = 33`
→ `floor(1.5 × 33) = floor(49.5) = 49` 件，**余 0.5 件进 `balance_qty`**（`0.500`），归集到**行** `balance_qty`（C34），并入 `cut_waste_qty`，**不入库、不出码、不计件**。

**耗料**：件数定完之后才算 —— `耗料 = Σ(各尺码明细 output_qty × usage_qty × (1 + waste_rate/100))`，**按布批行归集**用于 C33 校验。❌ 不是反过来用耗料推件数。

| POST | `/api/v1/imports/cutting-orders` | ⚠️ **待登记 `cutting:import`** + `system:import:manage` | `data_scope` | **三步式（05 §9.2）**：`/template` 下载模板 → `/validate`（multipart，**只校验不入库**，≤5000 行）→ `/commit`（带 `upload_id`，单事务） | `/validate` 返回 `upload_id` / `total` / `valid` / `invalid` / `can_commit` / `errors[]` / `preview`；`/commit` 返回写入单号列表 + `document_log_id` | `11007` `11008` `10009` `10001` `20006` `20007` `12001` |

**三层字段说明（接口入参 / 出参共用）**：

**① 布批行（`PUT /lines`）**

| 字段 | 类型 | 谁算 | 说明 |
| --- | --- | --- | --- |
| `line_no` | `integer` | 前端 | 1 起；`UNIQUE (doc_id, line_no)` |
| `dye_lot_no` | `varchar(64)` | 前端 | **缸号**；必须在本厂可用库存中 |
| `bolt_no` | `varchar(32)` | 前端 | **匹号**；与缸号共同定位批次 |
| `width_cm` | `numeric(8,2)` | 前端（默认批次实测值） | 铺布用门幅 |
| **`fabric_qty`** | `numeric(14,3)` | **用户按铺布实耗录** | **行耗料（米）**，`> 0`；受 C33 下限约束；**不接受前端反算值** |
| `waste_qty` | `numeric(14,3)` | 用户 | 布头 + 布损，参与 C33 下限 |
| `output_qty` | `numeric(14,3)` | **服务端算** | `Σ(颜色 Σ尺码出数)`；前端传了必须 `≥` 该值 |
| `balance_qty` | `numeric(14,3)` | **服务端算** | `output_qty − Σ(颜色尺码出数)`；**为负 → `30002`**（C34） |

**② 行内颜色（`PUT /lines/{line_id}/colors`）**

| 字段 | 类型 | 谁算 | 说明 |
| --- | --- | --- | --- |
| `color_code` | `varchar(32)` | 前端 | 该匹布要裁的颜色；`UNIQUE (line_id, color_code)`；**一行可 N 个** |
| `entry_mode` | `MASTER/UNIFORM/MANUAL` | 前端（默认 `MASTER`） | 颜色级录入模式（C26） |
| `qty_per_hand` / `uniform_qty` | `numeric(14,4)` / `numeric(14,3)` | 前端 | 模式 A/B 的默认值；尺码明细行的值才是权威 |
| `ratio_snapshot` | `jsonb` | **服务端写** | 保存时的比例快照；**不接受前端传入** |

**③ 尺码明细（`PUT /size-lines`）**

| 字段 | 类型 | 谁算 | 说明 |
| --- | --- | --- | --- |
| `line_id` / `color_code` | `varchar` | 前端 | 定位所属行与颜色 |
| `size_line_no` | `integer` | 前端 | **同颜色内唯一**即可；`UNIQUE (line_color_id, size_line_no)` |
| `size_code` | `varchar(32)` | 前端 | 尺码码；**同一 `(line_id, color_code, size_code)` 可重复多行** |
| `hands` | `numeric(14,4)` | 用户 / 比例带出（**可改**） | **本明细行手数**，权威；`<= 0` → `10001` |
| `qty_per_hand` | `numeric(14,4)` | 用户 | **本明细行每手件数**，权威；同尺码多行可不同 |
| `output_qty` | `numeric(14,3)` | **服务端算**，可人工覆盖 | `floor(hands × qty_per_hand)`；前端传不同值 → 所在颜色转 `MANUAL`（C28） |
| `balance_qty` | `numeric(14,3)` | **服务端算** | `hands × qty_per_hand − output_qty`；**不接受前端传入** |

- 路径用子资源表示动作（05 §1），反审核用 `reversals` 子资源而非动词路径。
- OpenAPI：`tags="裁剪"`、`summary` 必填，`cutting-orders/{id}/approvals` 的 `description` 必须写明 **§4.1 的七步副作用**（08 R4）。
- 响应金额/数量一律字符串（05 §3）。
- ❌ **上一轮接口 `PUT /api/v1/cutting-orders/{id}/entries` 作废**（那是两层结构的"扁平明细批量保存"），由 `PUT /lines` + `PUT /lines/{line_id}/colors` + `PUT /size-lines` 三接口取代；权限点不变（`cutting:update`）。
- **导出（05 §9.1）**：本模块导出入口 `/api/v1/cutting-orders/exports`、`/api/v1/cutting-orders/statistics/exports`、`/api/v1/style-color-size-ratios/exports`；**与列表共用同一 service 方法**（07 §3.2 铁律 3），超 10 万行报 `11011`。
- **导入（05 §9.2/§9.3）**：三步式，**禁止上传即入库**。**模板列（REV-2026-10 第四批定稿，一行一个尺码明细）**：

  | 列名 | 含义 | 必填 |
  | --- | --- | --- |
  | `款号` | `style_no` | ✅ |
  | `缸号` | `dye_lot_no` | ✅ |
  | `匹号` | `bolt_no` | ✅ |
  | `门幅` | `width_cm` | ❌（留空取批次实测值） |
  | `耗料` | `fabric_qty`（行级） | ✅ |
  | `颜色` | `color_code` | ✅ |
  | `尺码` | `size_code` | ✅ |
  | `手数` | `hands` | ✅ |
  | `每手件数` | `qty_per_hand` | ✅ |

  **同缸同匹的多行自动归并为一个布批行**（耗料只出现一次，取该组第一行的值）；同 `(缸号, 匹号, 颜色, 尺码)` 的多行 = **多个尺码明细行**（C30，`size_line_no` 按出现顺序编号）；`entry_mode` **不在模板列里**——统一按 `MASTER` 导入，导入后用户可在界面切 `UNIFORM`/`MANUAL`（**避免模式混用时模板无法表达**，见 §12 Q-C12）；导入路径同样**不得写比例主数据**（C29）。
- ⚠️ **待登记权限点（本模块不自造）**：`cutting:import` 出现在 [05 §9.3](../05-接口设计规范.md) 支持导入清单里，但**尚未在 [07 §2.2](../07-认证与权限规范.md) 权限点总表登记**。**本模块不擅自启用**。
- ✅ **已闭环（无需新权限点）**：`PUT /lines`、`PUT /lines/{line_id}/colors`、`PUT /size-lines`、`POST /entry-mode` 都用已登记的 `cutting:update`；`GET /suggest-lines`、`GET /batches` 用已登记的 `cutting:read`。

## 7. 并发与幂等

| 风险场景 | 方案 |
| --- | --- |
| 并发审核同一裁剪单 | 乐观锁 `WHERE id=? AND version=? AND status='SUBMITTED'` + `rowcount=0` → `10003`；并发第二请求不会重复扣料 |
| 并发审核不同单扣同一批面料 | `material_stocks` 条件 UPDATE `SET stock_qty = stock_qty - :qty WHERE id=:id AND (stock_qty - locked_qty) >= :qty`，`rowcount=0` → `40001` 并返回当前可用量；**不用"先 select 后 update"**（10 §5.2 要求） |
| **★ 同缸布被多行占用时的扣减（ADR-0017 风险 ①，C36）** | 同一 `(dye_lot_no, bolt_no)` 可出现在**同单多行 / 多单多行**（先裁一部分、剩下的再裁一单）。审核时**按固定顺序（`doc_id` → `line_no`）逐行**做条件 UPDATE，每行扣自己的 `fabric_qty`；**任一行 `rowcount=0` 立即整事务回滚并报 `40001`**（返回该布批可用量与已扣量），**不允许出现"扣了一半"**。加锁顺序统一为「`cutting_orders` → `material_stocks` → `stock_ledgers` → `cutting_outputs`」，与打菲/计件全模块一致防死锁。校验口径：单批累计扣减 `Σ(所有行 fabric_qty) ≤ stock_qty − locked_qty` |
| **★ 行耗料与出数一致性校验的并发（C33/C34）** | 校验必须**在同一审核事务内、用已加行锁的数据**做：先锁 `cutting_orders`（乐观锁）→ 逐行条件 UPDATE 扣料 → 再 `SELECT ... FROM cutting_order_size_lines` 读明细（此时同单已被版本锁挡住修改）→ 算 C33 / C34。**绝不把校验放到扣料之前的事务外**，否则会出现"校验通过后被人改了尺码明细"。提交侧同样：`submit` 与 `approve` 各校验一次，`approve` 用的是**已落库的行与明细**，不读前端回传值 |
| 提交后反审核（跨状态竞争） | 同一行锁 + 状态条件 UPDATE，二者只有一个成功；失败方报 `10003` |
| 打菲审核与裁剪反审核同时改 `cutting_outputs` | `cutting_outputs` 行级 `SELECT ... FOR UPDATE`，按固定顺序取锁 |
| `reserved_qty` 超卖 | 分配时条件 UPDATE `available >= :qty`；预占总量恒 ≤ `output_qty + balance_qty - bundled_qty - cut_waste_qty`（INV-6 细化，09 §4.2） |
| 比例主数据被并发修改 vs 裁剪单提交/审核 | 带出建议时读到的比例在**同一事务内**写入尺码明细 `hands` 并落到颜色 `ratio_snapshot`；**件数此后只由明细决定**，他人并发改 `style_color_size_ratios` **完全不影响本单**。`approve` 二次校验只拦两件事：该颜色**完全**无比例（`20006`）、比例含款号没有的尺码（`20007`）；**部分缺配不拦**（C19） |
| 改单 vs 他人并发改比例主数据 | 二者写**不同的表**，无写冲突；**改行永不 UPDATE 主数据**（C29）。同一裁剪单被两人同时改 → 靠单据 `version` 乐观锁（三个 PUT 接口都必须传 `version`），后到者 `10003` |
| **★ 切模式 vs 他人正在编辑尺码明细（C27）** | `POST /entry-mode` 与 `PUT /size-lines` 都**必须带 `version`**，并发只有一个成功（后到者 `10003`）；`entry-mode` 事务内对 `cutting_order_line_colors` 行 `SELECT ... FOR UPDATE`，按 `doc_id` → 行 → 颜色 → 明细的**固定顺序**取锁。**切模式清 `hands` 与他人刚保存的行有竞争时以 `version` 判定**，绝不出现"清了一半行" |
| **★ 同尺码多行并发插入（C30）** | `UNIQUE (line_color_id, size_line_no)` + `size_line_no` 由服务端在**锁住该颜色行**的前提下分配（防两个请求拿到同一个号）；唯一索引冲突转 `10003` 并提示刷新。**允许**同尺码重复，故并发插两行同尺码**不会**被误拦 |
| **★ 并发删行 vs 并发改行（C32 三层级联）** | 删布批行必须**同事务**级联软删其 `line_colors` 与 `size_lines`；锁顺序 `lines` → `line_colors` → `size_lines`。若他人正在改该行的尺码明细，靠单据 `version` 判定（`10003`），**不允许出现"行还在但尺码明细被清空"的中间态** |
| 并发审核时 `floor` 结果漂移 | `floor` 在**同一审核事务内**用**已落库的尺码明细 `hands` / `qty_per_hand`** 计算（**不依赖比例主数据的当前值**）；事务提交前 `SELECT ... FOR UPDATE` 挡住并发打菲；`document_logs` 记逐尺码 `output_qty`/`balance_qty` 取整结果，可复算 |
| 重复提交 `submit` | 状态机拒绝第二次（`30001`）；接口支持 `Idempotency-Key`（05 §5） |
| 网络重试审核 | 同上，命中幂等键返回首次结果而非重复扣料 |
| 台账与结存不一致 | 每次审核/反审核后跑 `v_stock_reconciliation` 断言为空（04 §7.2）；CI 与发布后各跑一次 |

## 8. 索引与查询场景

| 裁剪单列表：车间 + 日期倒序 | `WHERE workshop_id=? AND deleted_at IS NULL ORDER BY doc_date DESC, doc_no DESC` | `idx_cutting_orders_workshop_doc_date`（部分索引） |
| 款号 + 日期查历史裁剪 | `WHERE style_no=? AND doc_date BETWEEN ? AND ?` | `idx_cutting_orders_style_no_doc_date` |
| 待审核列表（主管工作台） | `WHERE workshop_id=? AND status='SUBMITTED' AND deleted_at IS NULL` | `idx_cutting_orders_status_workshop`（`status` 在前） |
| 打菲取可打菲余量 | `SELECT ... WHERE style_no=? AND color_group=? AND size_code=?` | `uq_cutting_outputs_style_color_size` |
| 报表：按款号聚合出数/损耗 | `GROUP BY style_no, color_group` + 日期区间 | `idx_cutting_orders_style_no_doc_date` |
| **单据详情（三层展开）** | 行 → 颜色 → 尺码明细逐层取 | `uq_cutting_order_lines (doc_id, line_no)` / `uq_cutting_line_colors (line_id, color_code)` / `uq_cutting_size_lines (line_color_id, size_line_no)`（04 已建，唯一索引即查询索引） |
| **审核时按布批定位批次** | `WHERE material_id=? AND dye_lot_no=? AND bolt_no=? AND warehouse_id=? AND deleted_at IS NULL` | `uq_material_stocks_dim`（仓库+物料+缸号+匹号+色） |
| **同缸布被多行占用查询** | `WHERE dye_lot_no=? AND bolt_no=? AND deleted_at IS NULL` | `idx_cutting_order_lines_lot (dye_lot_no, bolt_no) WHERE deleted_at IS NULL`（04 §7.7.2 已建） |
| **按缸号追溯裁剪历史** | `WHERE dye_lot_no=? ORDER BY doc_date DESC` | `idx_cutting_order_lines_lot` |

| **按颜色汇总出数（报表 / `cutting_outputs`）** | `GROUP BY line_id, color_code` 求 `Σsize_lines.output_qty` | `uq_cutting_line_colors (line_id, color_code)` 唯一前缀 + `uq_cutting_size_lines (line_color_id, size_line_no)` |

| 操作日志时间线 | `WHERE doc_type='CuttingOrder' AND doc_id=? ORDER BY created_at DESC` | `idx_document_logs_doc`（04 §7.9；章节号 REV-2026-10 已由原 §7.4 调整为 §7.9） |

## 9. 错误码

| 码 | HTTP | 含义 | 本模块触发场景 | 处理 |
| --- | --- | --- | --- | --- |
| `10001` | 422 | 参数校验失败 | `hands<=0`、`qty_per_hand<=0`、`fabric_qty<=0`、尺码码非法 | 行内红字提示 |
| `10002` | 400 | 缺少必填业务参数 | `reject`/`reverse`/`cancel` 未填原因；`entry-mode` 切模式未传 `confirm`；`approve` 后缺 `hands`/`qty_per_hand` | 弹出必填提示 |
| `10003` | 409 | 乐观锁冲突 | 并发审核/反审核/改单同一单 | 刷新后重试 |
| `10005` | 409 | 不允许自审 | 制单人 = 审核人（08 §4） | 换他人审核 |
| `10006` | 422 | 该动作必须填写原因 | `reject` / `reverse` / `cancel` 未填原因（**不再用于比例覆盖**，C23） | 弹出原因输入框 |
| `12001` | 403 | 无操作权限 | 缺 `cutting:approve` 等 | 隐藏入口 |
| `12002` | 403 | 无数据权限 | 车间主管查他车间（INV-8） | 提示无权访问 |
| `20006` | 422 | 该款该颜色缺某些尺码的比例 | 只在「该 `(style_no, color_code)` **完全没有**任何比例行」时触发（带建议 / `submit` / `approve`，C19）；`details` 回传该颜色 | 引导「去补比例」跳 `PUT /style-color-size-ratios`。**部分缺配不再报错**，改在 `GET /suggest-lines` 回 `missing_size_codes` |
| `20007` | 422 | 尺码比例与款号颜色组内的尺码集合不一致 | ① 比例里出现 `style_sizes` 中不存在的尺码；② **行内颜色不是该款已定义的颜色**（ADR-0017 校验清单第 ⑤ 条） | 提示多余/缺失尺码或非法颜色 |
| `11007` | 422 | 导入文件格式/表头错误 | `/imports/cutting-orders` 上传非 xlsx 或表头不匹配模板 | 下载模板重填 |
| `11008` | 422 | 导入数据校验失败 | 逐行校验不通过，响应带行号与字段级错误 | 下载错误明细改后重传 |
| `10009` | 413 | 导入行数超过上限 | 单文件 > 5000 行 | 拆文件 |
| `11011` | 422 | 导出条件为空或范围过大 | 导出 > 10 万行 | 缩小时间范围 |
| `30001` | 409 | 裁剪单状态不允许该操作 | 非 `DRAFT` 改单、非 `SUBMITTED` 审核、终态再迁移 | 刷新看状态 |
| **`30002`** | 409 | 裁剪数量 < 已打菲数量 + 损耗 | **REV-2026-10 第四批收窄为四处**：① **行耗料下限不满足**（C33，`Σ理论耗料 + waste_qty > fabric_qty`）；② **行余量为负**（C34，耗料不足）；③ 反审核时 INV-6 破（`bundled_qty + reserved_qty + cut_waste_qty > output_qty + balance_qty`）；④ 提交时耗用偏差超硬阈值 | 阻止提交 / 先反审核打菲单；`details` 回 `line_no` 与差额 |
| `30003` | 422 | 数量必须为整件 | 用户把尾数当件数填（`output_qty` 传小数） | 提示向下取整 |

### 11.5.1 页面收敛：4 页 → 1 页 + 追踪页

评审反馈"5 个生产页面看不出关联"，根因是**按操作步骤切页面**而非按**单据层级**切。收敛为：

| --- | --- | --- |
| 裁剪单 | **保留为唯一生产主单** `#/pc/cutting` | 表体 = 布批行矩阵：行 = 布批，列 = 颜色 × 尺码，格 = 手数（件数自动算）；矩阵顶部切换三种手数带出方式（C26） |

| 裁剪按布批 | **合并** | 并入裁剪单矩阵（布批行 = 矩阵行） |
