# 03 打菲模块

> 打菲是本项目一码一手（**REV-2026-10 / ADR-0016**）的固化点：打菲单审核时按「尺码 + 手序号」批量生成 `bundles`，**每一手一个码 = 一个员工的责任单元**；码终生不变；计件、完工入库全部以 `bundle_no` 为唯一追溯键。
> 关联规范：[docs/04 数据库规范](../04-数据库规范.md) **§7.0（`bundles` 表）/ §7.0.1（`bundle_no` 格式）/ §7.0.2（扫码计件规则）**、[docs/05 接口设计规范](../05-接口设计规范.md) §4、[docs/07 认证与权限](../07-认证与权限规范.md) §2.2、[docs/08 单据状态机规范](../08-单据状态机规范.md) §2.2、[docs/09 领域术语](../09-领域术语与编码规则.md) §1.4/§2.4/§4.2。ADR：[0004 打菲二维码编码方案](../adr/0004-打菲二维码编码方案.md)（**`bundle_no` 格式已被 0016 修订**，「二维码 = 纯 `bundle_no`」仍有效）、[0013](../adr/0013-裁剪尺码比例与手数.md)、**[0016](../adr/0016-打菲按手与扫码得件数.md)**、**[0017](../adr/0017-裁剪按布批与行内多颜色.md)**。
>
> **REV-2026-10（第四批，ADR-0016）按手 —— 本篇最重要变更**：
> ① **打菲单位是「手」不是「件」**：一码 = 一手 = 一个员工的责任单元；❌ 一码一件作废。
> ② **`bundle_no` 内嵌手序号**：`BD-{打菲单号}-{尺码码}{手序号2位}-{件序号4位}`，例 **`BD-20261018-000031-XL02-0001`**；❌ 旧的 `{打菲单号}-{7 位单内序号}` 作废。
> ③ **`bundle_qty` = 该手件数** = 裁剪尺码明细的 `qty_per_hand`（**直接取，不 floor**；**Q-B15 2026-10-06 闭环**，依据 ADR-0020 + [08 §2.2](../08-单据状态机规范.md)）。**扫码即知**（数量**不写进码**，查库得，沿用 ADR-0004）。
> ④ **打菲手数不得超打裁剪手数**，否则 `31004`（少打允许，B21；单尺码 >99 手 → `10001`）；手序号重复 `31005`；已计件码不可改手数 `31006`。
> ⑤ **一码一员工**：`counted_by` 只允许一人，第二个员工扫同码 → `32001`。
> ⑥ **标签必须印「第 N 手 / 共 M 手」+ 该手件数**。
> ⑦ **必须引用裁剪尺码明细行** `bundles.cutting_size_line_id`（ADR-0016 + ADR-0017 §4）—— 不再按缸号行引用。
> 详见 §2 B2~B3、B19~B26、§3.3、§5.1~§5.5、§11 TC-20~TC-28。
> ❌ **作废的旧口径**：`bundle_count`（扎数/整数）→ 由 `hands`（手数）取代；`is_counted` 布尔列 → 由 `counted_qty` / `counted_by` / `counted_at` 取代；`seq_no` 单内 7 位序号 → 由 `hands` 手序号 + 件序号取代；「1 码 = `style_operations.bundle_qty` 件」→ 由 `bundle_qty = 裁剪尺码明细的 qty_per_hand` 取代（**名称冲突见 §12 Q-B11**）。

## 1. 模块职责与边界

| 项 | 内容 |
| --- | --- |
| 职责 | 建打菲单（款号 + 工序 + 色组 + 尺码 + **手数** + 来源裁剪单）；审核时按「尺码 + 手序号」**一码一手**批量生成 `bundles`（`bundle_qty` = 该手件数）；**预演拆分**（不落库）；标签打印数据（印「第 N 手 / 共 M 手」+ 该手件数）与批量导出；单码作废 |
| 拥有 | `bundling_orders`、`bundling_order_lines`、`bundles`、`bundle_label_prints` |
| 上游 | 基础资料（`styles` / `style_colors` / `style_sizes` / `operations` / `workshops`）；裁剪模块（`cutting_outputs` 可用量 + **`cutting_order_size_lines` 的 `hands` / `output_qty`**） |
| 下游 | 计件模块（验码：存在 / 未作废 / **已计件**；并**写 `bundles.counted_qty` / `counted_by` / `counted_at`**）；完工入库（成衣栈，`bundle_no` 段）；报表（一码一手追溯、"未计件手清单"） |
| 不负责 | 排料与裁剪损耗（裁剪模块）；计件金额与单价（计件模块）；成衣库存数量（库存模块） |

**术语对照**（09 §1.4，强制系统字段名）：`bundling` 打菲、**`hands` 手序号 / 手数**、**`bundle_qty` 该手件数**、`bundle_no` 打菲号、`operation_no` 工序号、`routing` 工序路线、`group_no` 组别、`workstation_no` 工位。

> **REV-2026-10 整件口径（09 §4.2）**：**只对整件出码**；**尾数（`balance_qty`，裁剪产出不足一件的余量）不生成码** —— 它在裁剪审核时已并入 `cut_waste_qty`，本模块看不到也无需处理，因此 `bundles` 表里不可能出现尾数码（与 ADR-0016 §"余数归损耗"一致）。
> **REV-2026-10 按手口径（ADR-0016）**：**码数 = 手数**（不是件数、不是"扎数"）。`hands=6` 就是 6 个码，不是 6×`bundle_qty` 个码。

## 2. 业务规则

| # | 规则 | 说明 |
| --- | --- | --- |
| B1 | 单据号 | `BD-{YYYYMMDD}-{6 位序号}`（09 §2.1），序列生成，永不复用 |
| **B2** | **打菲号格式（ADR-0016 修订，取代旧 `{单号}-{7 位单内序号}`）** | `bundle_no = {打菲单号}-{尺码码}{手序号2位}-{件序号4位}`，例 **`BD-20261018-000031-XL02-0001`**（XL 的**第 2 手**，件序号 `0001`）；`BD-20261018-000031-L01-0001`（L 第 1 手）。**手序号在同单 + 同尺码内从 1 递增**；**件序号一码一手时恒为 `0001`**，第 4 段仅预留"一手拆多码"扩展（是否需要见 §12 Q-B10）。DB 兜底 `CHECK (bundle_no ~ '^BD-[0-9]{8}-[0-9]{6}-[A-Z0-9]{2}[0-9]{2}-[0-9]{4}$')` |
| **B3** | **一码 = 一手 = 一个责任单元（ADR-0016 修订，取代"一码一件"）** | 每个 `bundle_no` 对应**一手**（该手件数为 `bundle_qty`）；一手**只允许一个员工计一次**（B24）。`bundle_no` 一经生成终生不变、不复用、不改写。❌ 旧"一码一件（INV-1 每件一码）"作废；**INV-1 的"每件可追溯"由"码 → `bundle_qty` → 件"保留** |
| B4 | 一手件数来源 | **`bundle_qty = 裁剪该尺码明细行的 `qty_per_hand`**（**直接取，不 floor**；B20 / **Q-B15 2026-10-06 闭环**，ADR-0020）。`style_operations.bundle_qty`（"一扎几件"）与 `operations.default_bundle_qty` **只作录入参考与默认值**，**不作权威**（**名称冲突见 §12 Q-B11**）；**严禁硬编码 1 或 12**（09 §3 明令） |
| B5 | 二维码内容 | 纯文本 `bundle_no`，**不加前缀、不加 JSON、不加校验位、**`bundle_no` **不带数量**（ADR-0004 + ADR-0016 理由 ④） |
| B6 | 条码 | Code 128 字符集 B，编码内容与二维码**完全相同**（同为 `bundle_no`），供工位机扫码枪 |
| B7 | 打菲数量约束 | `Σ(本单各码 bundle_qty) ≤ 来源裁剪单对应（款号+色组+尺码）的可用量`，否则 `30002` 口径（INV-6） |
| B8 | 来源裁剪单 | `source_cutting_order_id` 必填且必须 `status='APPROVED'`；**允许一对多**（一张裁剪单可出多张打菲单） |
| B9 | 工序一致性 | 打菲单必须带 `operation_no`；不同工序必须开不同打菲单（码与工序强绑定，计件按工序分别扫码）。**一码一手不改变这一点**：同一手在不同工序要打不同的码 |
| B10 | 作废规则 | 单码作废写 `voided_at` + `void_reason`（**必填原因**），`status='VOIDED'`；`VOIDED` 为该码终态 |
| B11 | 已计件不可作废 | `counted_at` 非空（存在未红冲的 `piecework_logs`）的码**禁止作废**，报 `32003` 口径；须先在计件模块红冲 + 补录 |
| B12 | 已反审核码不可恢复 | 打菲单反审核时本单全部码置 `voided_at`（**不可恢复**），重新打菲必须新开单据生成新码（09 §2.4 生命周期） |
| B13 | 码不随单据改号 | 打菲单 `doc_no` 永不变更（09 §2.1），因此 `bundle_no` 前缀稳定，可物理反查单据 |
| B14 | 标签打印 | 规格见 §5.4（照抄 06 §4）：40mm×40mm 不干胶，二维码纠错 M、尺寸 ≥ 20mm，Code128 字符集 B；**必须印「第 N 手 / 共 M 手」+ 该手件数**（B25） |
| B15 | 重打留痕 | 每次打印写 `bundle_label_prints`（含 `printed_qty`、`is_reprint`、`hands_seq` 快照）；重打写 `document_logs` |
| B16 | 码与库存 | 打菲**不减**面料、不增成衣库存；成衣库存由完工入库生成（打菲=在制品） |
| B17 | 软删 | `bundles` 与单据表均带 `deleted_at`；**作废不是软删**，是业务终态（`status='VOIDED'` + `voided_at`） |
| B18 | **只对整件出码（整件口径，09 §4.2；2026-10-06 对齐 Q-B15）** | ① 每手件数 = 裁剪尺码明细行的 `qty_per_hand`（**直接取，不 floor**），必须是**正整数**，非整数入参一律 `31003` / `10001` 拒绝，不静默取整；② 件数 = `hands × qty_per_hand`（整数精确值）；**余数仅在裁剪侧人工指定出数时产生**并已归裁剪侧 `balance_qty`（09 §4.2），**本模块不出余数码**；③ 因此 `bundles` 中不存在尾数码，计件无从扫到（[04-计件](./04-计件.md) BR-PW-19）；④ **`hands = 0` 的行不允许提交**（`10001`），零手行对生产无意义 |
| **B19** | **每手必须有编号（ADR-0016 背景 2）** | 业务方原话：「XL 2 手打两张就重复 —— 如果多个员工生产就不知道谁做工」。因此 `bundle_no` **必须内嵌手序号**，标签**必须印「第 N 手 / 共 M 手」**；`hands` 是 `bundles` 的必填列，`UNIQUE(doc_id, color_code, size_code, hands)` 从库层面保证不重复 |
| **B20** | **每手件数算法（2026-10-06 对齐 Q-B15）** | `bundle_qty = cutting_order_size_lines.qty_per_hand`（**直接取，不 floor**）；码数 = `cutting_order_size_lines.hands`。例：`hands=2, qty_per_hand=60` → `output_qty = 120`，**2 个码，各 60 件**；`hands=3, qty_per_hand=33` → `output_qty = 99`，**3 个码，各 33 件**。**不存在「100÷3 除不尽」的形态** —— `output_qty` 已是 `hands × qty_per_hand` 的精确整数（ADR-0020）；仅当裁剪侧**人工指定**出数时才产生差额并归 `balance_qty`。同一尺码多条尺码明细行时**逐行拆**（ADR-0017 §4） |
| **B21** | **打菲手数不得超打（≤ 裁剪手数）** | 提交/审核时按 (色码,尺码) 校验：`本单 Σhands ≤ 裁剪该色该尺码（所引用行）Σhands`。**超打 → `31004`**（08 §2.2 第 ③ 条），响应回传两侧手数。**少打允许**（主管控制节奏 / 分批打是常态）。**单尺码单行手数上限 99**（打菲号手序号只有 2 位且与 1~3 位尺码码无分隔符，>99 会生成能过 DB CHECK 却解析错尺码的静默损坏码 → `10001`）。⚠️ 2026-10-06 业务确认：原「码数必须等于裁剪手数（少打也多打都拦）」与「少打几手是常态」矛盾，收敛为**防超打** |
| **B22** | **手序号重复 → `31005`** | 同一 `doc_id` + `color_code` + `size_code` + `hands` 已存在 → `31005`，`details` 回传已存在的手号。**兜底靠 `uq_bundles_hand` 唯一索引**，不靠"查后插" |
| **B23** | **已计件的码不可改手数 → `31006`** | 审核后若要改某尺码的 `hands`（增手/减手），凡该 (单, 色, 码) 下**存在 `counted_at` 非空的码** → 拒绝 `31006`，提示**先红冲该手流水**。同场景下**允许**把该 (单, 色, 码) 下**未计件**的码的 `bundle_qty` 同步为新的每手件数（04 §7.0.2「改每手件数」行） |
| **B24** | **一码一员工（ADR-0016 决策 3）** | `counted_by` **只允许一个员工**；**第二个员工扫同一码 → `32001`**，响应回传原计件人姓名与时间。理由：业务方原话「多个员工生产就不知道谁做工」，责任单元就是手。⚠️ 与计件侧的 `32004` 语义重叠，**本文统一用 ADR-0016 指定的 `32001`**（见 §12 Q-B12） |
| **B25** | **标签新增内容** | ① **第 N 手 / 共 M 手**（多员工分工时肉眼可辨）；② **件数（该手）**（与扫码结果一致，避免扫码核对）；③ 款号 / 颜色 / 尺码 / `bundle_no` 等宽字体完整显示 + Code128 + 二维码 |
| **B26** | **必须引用裁剪尺码明细行（ADR-0016 + ADR-0017）** | `bundles.cutting_size_line_id` → `cutting_order_size_lines.id`（**件数权威来源**，04 §7.0 DDL 为 `NOT NULL`）。❌ 不再按缸号行引用（ADR-0017 后"行 = 布批"，布批不是件数载体）。**一个手来自一个布批行的某条尺码明细行**（ADR-0017 §4） |

| B20 | **打菲页 = 裁剪明细的下游，页面合并不新增单据**（REV-2026-10，[ADR-0023](../adr/0023-生产单据页面重排与溯源链.md)） | 原「打菲单列表页」与「打菲按手页」**合并为一个打菲页** `#/pc/bundling`：从裁剪明细一键生成打菲单，单内按**手**列码（手号 / `bundle_no` / 件数 / 打印状态 / 计件状态），直接打印标签。**页面变少，单据模型不变** |
| B21 | **码必须能反查裁剪单**（REV-2026-10，C41） | 每个码展示溯源链 `码 ← BD-打菲单 ← CT-裁剪单 ← HB-款号 ← 缸号/匹号（供应商）`；`bundles.cutting_size_line_id` 必须落库。**不允许**只在内存里关联 |
| B22 | **改单联动：已计件的码冻结**（REV-2026-10，[ADR-0021](../adr/0021-裁剪改单与打菲联动.md)） | ① 上游裁剪单已审核 → 打菲单引用它的尺码明细行；② 上游改手数时，**未打印的码软删重建、已打印未计件的码置 `VOIDED`**（提示 `31007` 需作废重打）；③ **任一码已计件 → 上游禁止修改**（`30004`），必须先红冲反计件；④ 打菲单自身反审核时若存在计件流水 → 拒绝（同 `32003` 口径） |
| B23 | **件数直接取裁剪明细的 `qty_per_hand`**（REV-2026-10，ADR-0020 连带；**Q-B15 2026-10-06 闭环后与第一组 B4/B18/B20 收敛于本口径**） | 每手件数**不再**用 `floor(output_qty / hands)` 反算（那是 ADR-0013 的旧口径，会在手数非整数时出错）。直接取该尺码明细行的 `qty_per_hand`；码数 = 该行 `hands` |

## 3. 数据模型

> ⚠️ **REV-2026-10：DDL 以 [04 §7](../04-数据库规范.md) 为准**。本节 §3.1/§3.2 的字段表**已于 T-BASE-004 搬进 `04 §7.16`** —— 此前 `bundles`（04 §7.0）与 `cutting_order_size_lines`（04 §7.1）都外键引用本节这两张表，而 `04 §7` 里却没有它们，两份文档都像是权威的（docs/12 L-070）。**本节保留字段表是为了读语义**，建表请照 `04 §7.16`。两侧的列由守卫 `test_bundling_tables_match_module_field_tables` 保持**双向一致**。

> ⚠️ 搬运时改了一处**自相矛盾**：`hands_total` 原写 `CHECK (> 0)`，而它是审核前就有的列、草稿态必然为 0 —— `DEFAULT 0` 与该 CHECK 直接矛盾，照抄会让**任何新建的草稿单都插不进去**。已改为 `>= 0`，> 0 的校验留在 service 的 `approve`（那里顺便能断言跨表不变量）。

所有表含 04 §2 公共字段；`bundling_orders` 另含 04 §7.3 单据公共列。

| `approved_by` / `approved_at` | `uuid` / `timestamptz` | ❌ | — | 审核人与时间 |
| `rejected_reason` / `cancelled_reason` | `text` | ❌ | — | 必填原因落库 |

- CHECK：`output_qty > 0`、`hands_total > 0`。
- CHECK：`output_qty = trunc(output_qty)`（整件口径，09 §4.2 显式兜底，防迁移误改为小数列）。
- CHECK：`hands_total = count(bundles WHERE doc_id = :id)` **不能建 CHECK（跨表）**，由 service 在审核事务内断言（B21、§7）。

> ❌ **作废列**：`source_bundle_seq_from` / `source_bundle_seq_to`（件号区间，ADR-0016 后码内不再有全局件序号，无区间概念）。

### 3.2 `bundling_order_lines`（打菲明细，按尺码）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `doc_id` | `uuid` FK→`bundling_orders` `ON DELETE RESTRICT` | ✅ | — | 04 §7.3 |
| `line_no` | `integer` | ✅ | ✅（与 `doc_id`） | 1 起 |
| `color_code` | `varchar(16)` | ✅ | — | 色码（与表头一致；`bundles` 一码一色） |
| `size_code` | `varchar(16)` | ✅ | — | 尺码码。**同一 `(doc_id, size_code)` 允许多行**（同尺码可来自裁剪的多个布批 / 多条尺码明细行，ADR-0017 §4） |
| `operation_no` | `varchar(16)` | ✅ | — | 工序号（行级冗余，便于报表；与表头一致） |
| **`cutting_size_line_id`** | `uuid` FK→`cutting_order_size_lines` `ON DELETE RESTRICT` | ✅ | — | **★ 引用裁剪的尺码明细行**（ADR-0016 + ADR-0017 §4）。**件数与手数的权威来源**；`size_code` / `color_code` 为冗余快照 |
| **`hands`** | `integer` | ✅ | — | **★ 本行手数，整数**（[ADR-0020](../adr/0020-商品分类与手数直接输入.md) §2，2026-10-06 对齐）。审核时生成 `hands` 个码（一码一手）；`CHECK (hands > 0)`，`<= 0` → `10001`。❌ 旧口径「可小数（如 1.5 手），审核时 `round(hands)` 个码」**作废**；❌ 旧列 `bundle_count`（扎数）**作废** |
| `planned_qty` | `numeric(14,3)` | ✅ | — | 本行计划件数 = `Σ(该行各码 bundle_qty)` = `hands × qty_per_hand`（整数 × 整数，**精确值，不 floor / 不 round**，ADR-0020）。每手件数的**权威来源** = 裁剪尺码明细的 `qty_per_hand`（**Q-B15 2026-10-06 已闭环**）。审核后由 service 重算 |
| `available_qty_before` | `numeric(14,3)` | ✅ | — | 提交时从 `cutting_outputs` 读到的可用量快照（**整件**，尾数已在裁剪侧并入损耗） |
| `group_no` | `varchar(32)` | ❌ | — | 派给的车间组别，供下游派工 |
| `workstation_no` | `varchar(32)` | ❌ | — | 工位号（09 §1.4） |

- CHECK：`hands > 0`（**不为 0**，零手行无意义，`hands = 0` → `10001`）。
- CHECK：`planned_qty = trunc(planned_qty)`（整件约束，09 §4.2 / B18）。
- 索引建议：`idx_bundling_order_lines_doc_size (doc_id, size_code)`；`idx_bundling_order_lines_cutting (cutting_size_line_id)`。

### 3.3 ★ `bundles`（打菲件表，**一码一手**，照抄 [04 §7.0](../04-数据库规范.md)，本模块不得改写）

> **打菲单位是「手」不是「件」**（ADR-0016）。每一手 = 一个码 = 一个责任单元（一个员工）。
> `bundle_no` 内嵌**尺码码 + 手序号**；`bundle_qty` 存该手件数，扫码即知（**码里不带数量**，ADR-0004 不变）。

```sql
CREATE TABLE bundles (
    id                    uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    doc_id                uuid NOT NULL REFERENCES bundling_orders(id) ON DELETE RESTRICT,
    line_id               uuid NOT NULL REFERENCES bundling_order_lines(id) ON DELETE RESTRICT,
    bundle_no             varchar(64) NOT NULL,
    hands                 integer NOT NULL,           -- **手序号**（同单同尺码内从 1 起）
    style_no              varchar(32) NOT NULL,
    color_code            varchar(32) NOT NULL,
    size_code             varchar(32) NOT NULL,
    operation_no          varchar(16) NOT NULL,
    cutting_size_line_id  uuid NOT NULL,              -- 引用裁剪的尺码明细行（件数权威来源）
    bundle_qty            numeric(14,3) NOT NULL,      -- **该手件数** = 裁剪尺码明细的 qty_per_hand（ADR-0020，不取整；Q-B15 2026-10-06）
    counted_qty           numeric(14,3) NOT NULL DEFAULT 0,  -- 已计件数量（≤ bundle_qty）
    counted_by            uuid,                       -- **一码一员工**
    counted_at            timestamptz,
    status                bundle_status NOT NULL DEFAULT 'ACTIVE',  -- ACTIVE / VOIDED
    voided_at             timestamptz,
    void_reason           text,
    qr_content            varchar(64) NOT NULL,       -- = bundle_no（ADR-0004：二维码纯文本）
    ...公共字段,
    CONSTRAINT uq_bundles_no   UNIQUE (bundle_no),
    -- Q-B18 2026-10-06：尺码码 1~3 位（S/XL/XXL/3XL），手序号固定 2 位
    CONSTRAINT ck_bundles_no   CHECK (bundle_no ~ '^BD-[0-9]{8}-[0-9]{6}-[A-Z0-9]{1,3}[0-9]{2}-[0-9]{4}$'),
    CONSTRAINT uq_bundles_hand UNIQUE (doc_id, color_code, size_code, hands),
    CONSTRAINT ck_bundles_qty  CHECK (bundle_qty > 0 AND bundle_qty = trunc(bundle_qty)),
    CONSTRAINT ck_bundles_cnt  CHECK (counted_qty >= 0 AND counted_qty <= bundle_qty),
    CONSTRAINT ck_bundles_one  CHECK (counted_qty = 0 OR counted_by IS NOT NULL)
);
CREATE INDEX idx_bundles_counted_pending ON bundles (doc_id, color_code, size_code)
       WHERE deleted_at IS NULL AND status = 'ACTIVE' AND counted_at IS NULL;
CREATE TYPE bundle_status AS ENUM ('ACTIVE', 'VOIDED');
```

**逐列说明（本模块依赖的关键列）**：

| 列 | 含义与本模块用法 |
| --- | --- |
| **`hands`** `integer NOT NULL` | **★ 手序号**（同单 + 同色 + 同尺码内从 1 开始）。**B19 的落地**：XL 2 手 → `XL01` / `XL02` 两个码，`hands = 1` / `2`。`UNIQUE(doc_id, color_code, size_code, hands)` 保证不出现两个"第 2 手"（ADR-0016 §1） |
| **`bundle_qty`** `numeric(14,3)` | **★ 该手件数** = 裁剪尺码明细的 `qty_per_hand`（**直接取，不 floor**；B20 / Q-B15 2026-10-06）。`CHECK` 保证**是正整数**（整件口径，09 §4.2）；**扫码即知这手数量**（ADR-0016 决策 4） |
| **`cutting_size_line_id`** `uuid NOT NULL` | **★ 引用裁剪尺码明细行**（件数权威来源）。ADR-0017 §4 的下游衔接点；**打菲单必须按尺码明细行逐行拆分**，不得按布批行归并 |
| **`counted_qty`** | **★ 已计件数量**，`0 ≤ counted_qty ≤ bundle_qty`（DB CHECK 兜底）。⚠️ **部分生产**场景下 `counted_qty < bundle_qty`（`qty = 28 / 60`），**不是"未计件"**；判定"未计件"看 `counted_at IS NULL` |
| **`counted_by`** | **★ 一码一员工**（B24）。第二个员工计同一码被计件模块拦为 `32001` |
| **`counted_at`** | **★ 计件时间**。`counted_at IS NULL` = **未计件**（派生状态判定依据，取代旧的 `is_counted` 布尔列）；非空即"已计件" |
| `status` | `ACTIVE` / `VOIDED`（B10）。`VOIDED` 是业务终态，**不是软删** |
| `qr_content` | **恒等于 `bundle_no`**（B5）；CHECK 相等，防只改一处 |
| `style_no` / `color_code` / `size_code` / `operation_no` | **冗余**（列表、报表、标签免 JOIN；`bundles` 是大表，字段冗余优先，§3.5） |
| `line_id` | 所属打菲明细行 |
| 公共字段 | 04 §2：`created_at/by`、`updated_at/by`、`deleted_at`、`version`、`remark` |

**派生状态（不落库为状态列）**：

| 派生状态 | 判定条件 | 业务含义 |
| --- | --- | --- |
| 未计件 | `status='ACTIVE' AND counted_at IS NULL` | 可被计件；命中 `idx_bundles_counted_pending` |
| 已计件·足额 | `counted_at IS NOT NULL AND counted_qty = bundle_qty` | 整手做完；**不可改手数**（B23 → `31006`）；不可作废（B11 → `32003`） |
| **已计件·部分（部分生产）** | `0 < counted_qty < bundle_qty AND counted_at IS NOT NULL` | 这手只做了一部分（ADR-0016）；**剩余量不改码**；如需补做走**红冲 + 补录**（[04-计件](./04-计件.md) BR-PW-07）。⚠️ 是否需要报表提醒与裁剪侧口径，见 §12 Q-B09 / [02-裁剪](./02-裁剪.md) Q-C13 |
| 已作废 | `status='VOIDED'` | 终态（B10/B12） |

**索引**（04 §7.0 已给）：`uq_bundles_no`、`uq_bundles_hand`、`idx_bundles_counted_pending`；**建议新增** `idx_bundles_line_id (line_id)`、`idx_bundles_style_size_status (style_no, size_code, status) WHERE deleted_at IS NULL`、`idx_bundles_cutting (cutting_size_line_id)`。

> ❌ **作废列**（上一轮旧口径）：`seq_no`（单内 7 位序号）、`is_counted`（布尔）、`barcode`（内容恒等于 `bundle_no`，并入 `qr_content` + CHECK）、`color_group`、`workshop_id`/`group_no`（可从 `bundling_orders` 关联取；确需冗余时另议）。
> **`bundles` 是大表**：一年 3 个款式 × 3 万件 ≈ 6 手/款 → 全厂年增数十万行量级（码数 = 手数，远小于按件出码）；索引必须精简，字段冗余优先。

### 3.4 `bundle_label_prints`（标签打印记录）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `bundle_no` | `varchar(64)` | ✅ | — | 码 |
| `doc_id` | `uuid` | ✅ | — | 打菲单 |

### 3.5 关键关系

```
bundling_orders 1─< bundling_order_lines 1─< bundles 1─< bundle_label_prints
bundling_orders >─ cutting_orders（source_cutting_order_id，一对多）
bundling_orders ─▶ cutting_outputs（审核累加 bundled_qty，释放 reserved_qty）
bundling_orders 1─< document_logs

★ 新增关系（ADR-0016 + ADR-0017）
bundling_order_lines.cutting_size_line_id ──> cutting_order_size_lines.id   （手数与件数权威来源）
bundles.cutting_size_line_id ───────────────> cutting_order_size_lines.id    （冗余，标签与扫码回查免 JOIN）
bundles.counted_by ─────────────────────────> users.id                       （一码一员工；红冲时清空由计件模块负责）

# 计件方向（跨模块，不建 FK）
bundles ──(bundle_no / id)──> piecework_logs.bundle_id    计件模块写 bundles.counted_qty/by/at
```

- `bundles` **不建** 到 `bundling_orders` 的复合外键：唯一索引 + 同事务保证，避免批量插入时每行 FK 检查拖慢。
- **跨模块不做 FK**（计件 → `bundles`）：打菲单可能整体反审核，FK 会阻止合法操作；改由 service 显式校验 + `31001`/`31002`/`32001` 兜底（[04-计件](./04-计件.md) §7.1）。

## 4. 单据与状态机

迁移对齐 08 §2.2 与 §1.1（动作名 `submit`/`approve`/`reject`/`withdraw`/`reverse`/`cancel`）。

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用（与状态变更同事务，08 R4） |
| --- | --- | --- | --- | --- | --- |
| `create` | — | `DRAFT` | `bundling:create` | 款号 + 工序存在且启用；来源裁剪单 `APPROVED`；明细非空；**每行 `hands > 0`**（零手 → `10001`）；**每行 `cutting_size_line_id` 必填且其 `size_code` 与本行一致** | 生成 `doc_no`；`hands_total` / `output_qty` 后端重算 |
| `update` | `DRAFT` / `REJECTED` | 同 | `bundling:update` | `version` 乐观锁；**改 `hands` 前先查该 (单, 色, 码) 下是否已有 `counted_at` 非空的码 → 有则 `31006`**（B23） | 写日志 + diff |
| **`submit`** | `DRAFT` / `REJECTED` | `SUBMITTED` | `bundling:submit` | ① **款号 + 工序存在**；② **所属裁剪单已 `APPROVED`**；③ **每行 `bundle_qty > 0`**（08 §2.2 提交校验第 ② 条）→ `hands > 0` 时等价成立；④ **`Σ planned_qty ≤ 可用量`**，不足 → `30002`；⑤ **防超打预检**：`Σ hands`（`integer`，ADR-0020）不得超过裁剪侧 `Σhands` → 超打 `31004`；单尺码单行 >99 手 → `10001`（B21）；⑥ 手序号预检：展开后的 `(color_code, size_code, hands)` 是否与库内已存在的 ACTIVE 码冲突 → `31005`；⑦ `cutting_size_line_id` 存在且尺码匹配（否则 `10001`） | **预占** `cutting_outputs.reserved_qty`；快照 `available_qty_before` |
| **`approve`** | `SUBMITTED` | `APPROVED` | `bundling:approve` | 制单人 ≠ 审核人；重算可用量；**08 §2.2 第 ①~⑤ 条全跑一遍**（见下方「审核六步」） | **① 按手生成 `bundles`（一码一手）；② 每手件数 = 裁剪尺码明细的 `qty_per_hand`（**直接取，不 floor**；Q-B15）；③ 打菲手数不得超打裁剪手数，否则 `31004`；少打允许（B21）；④ 手序号重复 → `31005`；⑤ `UNIQUE(doc_id, color_code, size_code, hands)` 兜底；⑥ 更新裁剪结转** |
| `reject` | `SUBMITTED` | `REJECTED` | `bundling:reject` | **必填 `reason`** | 释放 `reserved_qty`；写日志 |
| `withdraw` | `SUBMITTED` | `DRAFT` | **`bundling:withdraw`** | 撤回人 = `created_by` | 释放 `reserved_qty`；写日志 |
| `reverse` | `APPROVED` | `SUBMITTED` | `bundling:reverse` | **必填 `reason`**；**已有计件流水存在 → 拒绝**（`32003` 口径，08 §2.2 第 ① 条）；已作废码不可恢复 | **① 本单全部 `bundles` 置 `status='VOIDED'` + `voided_at=now()` + `void_reason=反审核原因`（终态，不删行）；② `cutting_outputs.bundled_qty` 减回、`reserved_qty` 重新预占；③ 写日志。原记录与原码全部保留** |
| `cancel` | `DRAFT` / `REJECTED` | `CANCELLED` | `bundling:cancel` | **必填 `cancelled_reason`** | 无码无库存副作用；写日志 |

### 4.1 `approve` 审核六步（照抄 08 §2.2，**顺序不可调换**）

```
① 按手生成 bundle_no（一码一手，手序号内嵌）
   逐条裁剪尺码明细行 cutting_size_line_id：
     for hands_seq in 1..line.hands:            ← hands 为 integer（ADR-0020），不需 round
        bundle_no = {doc_no}-{尺码码}{hands_seq:02d}-0001
        bundle_qty = line.qty_per_hand           ← 直接取，不 floor（Q-B15）
        cutting_size_line_id = line.id
     批量 INSERT（INSERT ... SELECT + generate_series，§5.3）

② 每手件数 = 裁剪尺码明细的 qty_per_hand（直接取，不 floor；Q-B15 2026-10-06）
   件数 = hands × qty_per_hand（整数精确值）
   余数（仅裁剪侧人工指定出数时产生）→ 已在裁剪侧记入 balance_qty
   ❌ 本模块不出余数码、不计件、不入库（09 §4.2）

③ 打菲手数不得超打裁剪手数，否则 31004（少打允许，B21）
   比对口径：count(bundles WHERE doc_id=?) == Σ明细 hands
   少打或多打都拦；details 回「应有手数 / 当前手数」

④ 手序号重复 → 31005
   uq_bundles_hand 冲突即业务错误，不靠"查后插"

⑤ UNIQUE(doc_id, color_code, size_code, hands) 兜底
   DB 唯一索引是最终防线（ADR-0016 风险 ①）

⑥ 更新裁剪结转
   cutting_outputs.bundled_qty += 本单件数；reserved_qty 清零
```

**审核 / 反审核副作用对称表**（08 §3.3）：

| 副作用 | `approve` | `reverse` |
| --- | --- | --- |
| `bundles` 行数 | `0 → Σ 明细 hands`（= **码数 = 手数**，批量 INSERT） | 行**保留**，全部置 `VOIDED`（B12，不可恢复） |
| `bundles.bundle_qty` | 裁剪尺码明细的 `qty_per_hand`（直接取，不 floor） | 不改（码作废但内容保留可追溯） |
| `bundles.hands` | `1..hands` 连续 | 不改 |
| `cutting_outputs.reserved_qty` | 释放（清零） | 重新预占 |
| `cutting_outputs.bundled_qty` | 累加本单件数 | 减回本单件数 |
| `document_logs` | 追加 `APPROVE`（记码数 = 手数断言结果） | 追加 `REVERSE` + 原因 |
| `bundle_label_prints` | 不变 | 已打印记录**保留**（实物标签已存在，作废只体现在码状态） |

- **非法迁移**：`APPROVED→submit`、`CANCELLED→*`、已 `VOIDED` 码再作废（非幂等请求）→ `30001` 口径。
- 状态字段只允许 service 的 `_apply_status` 写（08 R7）。

> ✅ **权限点（07 §2.2 已闭环）**：打菲行已含 `bundling:reject` / `withdraw` / `reverse` / `cancel` / `export` / `print` / `code:void`；`withdraw` 用**独立权限点 `bundling:withdraw`**（07 §2.2 已登记，不必新增）—— 撤单与改单不是一回事，车间主管能撤自己submitted的单不代表他有权改别人的单。**⚠️ 08 §1.1 的通用表原写 `<mod>:update`，已按本模块的特例回填（见 08 §1.1 注）。本轮新增的 `hands` / `split` / 单码详情接口全部复用已登记的 `bundling:read` / `bundling:approve`**，**不需要新权限点**。

**单码作废（独立动作，不改单据状态）**

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `void_code` | `ACTIVE` | `VOIDED` | `bundling:code:void` | **必填 `void_reason`**；`counted_at IS NOT NULL` → 拒绝 `32003` 口径；`status` 已 `VOIDED` → 幂等返回首次结果 | `status='VOIDED'` + `voided_at` + `void_reason` + `voided_by`；`cutting_outputs` 可用量加回该码件数；写日志（**不删行**） |

## 5. 核心流程

### 5.1 打菲主流程

1. 主管查可打菲数：`GET /bundling-orders/{id}/available-outputs` 或 `v_cutting_output_available`（按款号 + 色组 + 尺码）。
2. 建打菲单：选来源裁剪单（只列 `APPROVED`）、工序（默认带出款号工序）、色码（**一码一色**）、各尺码**手数 `hands`**。
   - 录入参考值 `bundle_qty`（"一扎几件"）默认取 `operations.default_bundle_qty`，**但审核后不作权威**（B4、§12 Q-B11）。
   - **每行必须带 `cutting_size_line_id`**（B26）—— 前端从"该尺码可打菲来源"列表里选，列出 `hands` / `output_qty` / 每手件数预览 / 所属布批（缸号 + 匹号）。
3. **拆分预演**（不落库）：`POST /bundling-orders/{id}/split` → 返回**将生成的码与件数**清单（`bundle_no`、`hands`、`bundle_qty`），并给出 `余数（仅裁剪侧人工指定出数时非 0）= 裁剪 output_qty − 手数 × qty_per_hand`。用户可据此先核对再提交（§5.5）。
4. `submit`：预占裁剪可用量；跑 08 §2.2 的提交校验（含防超打预检、单尺码 ≤99 手、手序号冲突预检）。
5. `approve`（**制单人 ≠ 审核人**）：按 §4.1 **六步**执行。
6. 打印标签：按手批量打印（**每张印「第 N 手 / 共 M 手」+ 该手件数**）→ 写 `bundle_label_prints`（含 `hands_seq`）；重打同样留痕。
7. 挂筒 → 转车间；员工扫码绑定工序 → 工位机扫码计件（扫一次码 = 完成**一手**，[04-计件](./04-计件.md) §5.1）。

### 5.2 `bundle_no` 生成与唯一约束（照抄 04 §7.0.1 / 09 §2.4）

| 项 | 规则 |
| --- | --- |
| 格式 | `{打菲单号}-{尺码码 1~3 位}{手序号 2 位}-{件序号 4 位}` → `BD-20261018-000031-XL02-0001`、`…-XXL01-0001`、`…-3XL01-0001`（09 §2.4、ADR-0016 §1；**尺码码长度 Q-B18 2026-10-06 闭环**） |
| 手序号来源 | **同一打菲单 + 同一颜色 + 同一尺码内从 1 递增**。由 service 在审核事务内按 `generate_series(1, hands)` 展开（`hands` 为 `integer`） |
| 件序号 | **一码一手时恒为 `0001`**；第 4 段**预留"一手拆多码"扩展**（是否需要见 §12 Q-B10）—— **未确认前不生成 `> 0001` 的码** |
| **唯一约束（双保险）** | `uq_bundles_no UNIQUE (bundle_no)`（全局）+ **`uq_bundles_hand UNIQUE (doc_id, color_code, size_code, hands)`**（手序号级）—— 后者从库层面保证"XL 2 手"不会重复成两个第 2 手（ADR-0016 §1） |
| 不变式 | 一旦写入永不改、不删、不复用；反审核产生的 `VOIDED` 行**也占着手号**，新建单据不复用（新单有新 `doc_no` 前缀，天然不冲突） |
| 格式校验 | `CHECK (bundle_no ~ '^BD-[0-9]{8}-[0-9]{6}-[A-Z0-9]{1,3}[0-9]{2}-[0-9]{4}$')`（**尺码码 1~3 位、手序号固定 2 位**；Q-B18 2026-10-06 闭环，已落 DB CHECK） |
| 码内容 | `qr_content = bundle_no`（CHECK 相等，防只改一处）；Code128 同内容（B6） |
| **数量不入码** | 业务方明确「数量不带在码里，查库得到」（ADR-0016 决策 ④）；好处是改每手件数**不用作废旧码** |

### 5.3 ★ 拆分算法与批量生成（**一码一手**）

**问题**：一张裁剪单一色 `XL` 若有 **2000 手**（大手数排版），需生成 **2000 个码**。逐条 INSERT = 2000 次往返，审核耗时不可接受。

**拆分算法（审核时逐条尺码明细行执行）**：

```
输入：某条 cutting_order_size_lines 行 → hands = 2（整数）, qty_per_hand = 60
  bundle_qty = qty_per_hand = 60           ← B20 / Q-B15（直接取，不 floor）
  码数 = hands = 2                          ← B21（码数 = 手数）
  output_qty = hands × qty_per_hand = 120   （精确整数）
  展开：
    bundle 1: bundle_no = BD-…-XL01-0001  hands=1  bundle_qty=60   ← 员工 王海涛
    bundle 2: bundle_no = BD-…-XL02-0001  hands=2  bundle_qty=60   ← 员工 陈美玲
  余数 = 0                                  → 不进 balance_qty

输入：hands = 3, qty_per_hand = 33
  bundle_qty = 33
  码数 = 3
  output_qty = 3 × 33 = 99
  展开：XL01-0001(33) / XL02-0001(33) / XL03-0001(33) = 99 件
  ❌ 不存在「100÷3 除不尽」的形态：ADR-0020 后 output_qty 恒等于 hands × qty_per_hand；
     余数只来自裁剪侧**人工指定**出数（output_qty_manual），且已在裁剪侧记入 balance_qty，
     本模块不生成余数码、不计件、不入库（09 §4.2）

输入：裁剪侧人工指定出数（output_qty_manual = true）
  此时裁剪侧可能产生 balance_qty（差额），但**打菲侧每手件数仍取该行的 qty_per_hand**；
  本模块不承接裁剪余额、不生成余数码。打菲件数仍受 B7「可用量」约束（超出 → 30002）。

输入：同一尺码来自裁剪的多条尺码明细行（ADR-0017 §4）
  行A: color=WHT size=XL hands=2 qty_per_hand=60 → bundle_qty=60 → XL01-0001 / XL02-0001
  行B: color=WHT size=XL hands=1 qty_per_hand=30 → bundle_qty=30 → 手序号续编 XL03-0001
  ⚠️ 手序号连续编还是逐行从 1 编 → **[02-裁剪](./02-裁剪.md) Q-C11 待业务方确认**；
     当前实现按「同一打菲单内同尺码手号连续唯一」执行（合规于 uq_bundles_hand）
```

**批量生成性能（2000 手）**：

| 方案 | 说明 | 结论 |
| --- | --- | --- |
| ✅ `INSERT ... SELECT` + `generate_series` | `FROM generate_series(1, :hands) g` 展开为行，与本单 `doc_no` + 尺码码拼成 `bundle_no`，一次语句插入全部 | **采用**。语句数 = 明细行数（通常 < 50），**非手数** |
| ✅ 批量 `insert()` | ORM `session.execute(insert(Model), [dict, ...])` 一次多 VALUES | 可用，但 2000 行 × 20 列 SQL 过长；PG 单语句参数上限约 65535，本场景安全 |
| ❌ 逐条 INSERT | 2000 次 `INSERT` | **禁止**：审核事务内 2000 次往返，2C VPS 上秒级耗时，行锁持有时间暴增 |
| ❌ 逐条 Python 循环构造 ORM 对象 | 2000 个 ORM 实例 + flush | 禁止：ORM 实例化开销大，内存峰值高 |

**断言（审核事务内，任一不满足整事务回滚）**：

```
1. count(bundles WHERE doc_id = :id) == Σ 明细 hands                  ← B21 码数 = 手数（hands 为 integer）
2. Σ(bundles.bundle_qty) + balance_qty == cutting_output 本次可用件数  ← 余数归位
3. 每个 (color_code, size_code) 内 hands 恰为 1..N 无缺号            ← B22
4. Σ(bundles.bundle_qty) ≤ cutting_outputs.available_qty             ← INV-6
```

**整件口径在批量生成中的落点（B18 / 09 §4.2）**：

| 项 | 规则 |
| --- | --- |
| 每手件数直接取 | `bundle_qty = cutting_order_size_lines.qty_per_hand`（直接取，**不 floor**，Q-B15 / ADR-0020）；`bundle_qty` DB `CHECK (bundle_qty = trunc(bundle_qty))` 兜底 |
| 余数不出码 | 余数**不出码、不进 `bundles`**；回写本单 `balance_qty` 并与裁剪侧口径一致 |
| 重算结果必须回写 | `hands_total` / `output_qty` / `balance_qty` **同步回写单据**并写 `document_logs`，否则"申请 2000 手、实得 1998 个码"无人知晓 |
| 非整数入参 | 接口收到非整数 `hands` / `qty_per_hand`（两者均为 `integer`，ADR-0020）或 `<= 0` → `10001` / `31003`，**不静默取整** |
| 大单单量上限 | 单张打菲单 `hands_total ≤ 20000`（防一次插 20 万行锁表），超限拆单；上限值走基础资料/配置，**不硬编码在 service** |

- 批量插入后依赖 `uq_bundles_no` 与 `uq_bundles_hand` 兜底重复；**冲突转业务错误（`31005`）**，不靠"查后插"。
- 幂等：审核接口带 `Idempotency-Key`（05 §5），重复提交返回首次结果而非重复生成。
- 生成后同事务内跑上面 4 条断言；任一不过整事务回滚（08 R4）。

### 5.4 标签打印规格（照抄 06 §4 + ADR-0016 §5）

| 项 | 规范 |
| --- | --- |
| 标签尺寸 | 40mm × 40mm（不干胶），预留打印偏移 2mm |
| 内容 | 款号 / 颜色 / 尺码 / **第 N 手 / 共 M 手** / **件数（该手）** / 打菲号 / 工序名 / 二维码 / 条码 |
| **★ 手序号与件数（B25，ADR-0016 必印）** | 印「第 N 手 / 共 M 手」—— 多员工分工时肉眼可辨（B19）；印**该手件数** —— 与扫码结果一致，避免扫码核对 |
| 二维码 | 内容纯文本 `bundle_no`，纠错等级 **M**，尺寸 ≥ 20mm（保证扫码距离） |
| 条码 | Code 128，字符集 B，编码内容同 `bundle_no` |
| 打印方式 | 优先浏览器打印（`@media print` + 尺寸标签页）；次选导出 PDF/CSV 给标签软件 |
| 批量 | 一次选中**若干手**（可按 `hands` 区间）→ 打印预览网格 → 支持部分重打（重打必须写日志） |
| 打印样式 | `@page { size: 40mm 40mm; margin: 0 }`，隐藏所有交互元素 |
| 打印页 | 必须提供"打印张数"输入与序号（重打第几手），便于与实物核对；入参**必须带 `hands_seq`** |

### 5.5 拆分预演（`POST /split`，**只读不落库**）

```
输入：{ lines: [{size_code, hands, cutting_size_line_id}] }
输出：{
  "previews": [
    { "size_code": "XL", "hands": 2, "cutting_size_line_id": "…",
      "bundle_qty": 60,
      "bundles": [
        { "bundle_no": "BD-20261018-000031-XL01-0001", "hands": 1, "bundle_qty": 60 },
        { "bundle_no": "BD-20261018-000031-XL02-0001", "hands": 2, "bundle_qty": 60 }
      ],
      "remainder_qty": 0 } ],
  "hands_total": 2, "planned_qty": 120, "balance_qty": 0,
  "conflicts": []          ← 手序号与库内已有 ACTIVE 码冲突时列出（提交后会报 31005）
}
```

| 项 | 规则 |
| --- | --- |
| 权限点 | `bundling:read`（**只读预演，不写库**，不需要 `bundling:approve`） |
| 数据范围 | `data_scope` 强制过滤（07 §3.2），越权 `12002` |
| 与审核的关系 | 审核时**重算一遍**并做 4 条断言（§5.3）—— **预演结果不作为审核依据**，避免 TOCTOU |
| 用途 | ① 主管提交前核对"会打几个码、每手几件、余数多少"；② 现场发现余数异常时提前发现；③ 车间核对"这批 XL 到底打几张标签" |

> **REV-2026-10 第五批（2026-10-07，T-BUND-006 落地回填）** —— 以下 6 处原契约与实现对不上，
> 已按实现收敛（原契约在这 6 点上要么含糊、要么把前端该做的事塞给后端）：
>
> 1. **`format` 是 `data\|csv` 而非 `html\|csv`** —— 「打印模板」是前端的活（`@media print`）。
>    后端出 html 等于把打印模板复制一份到后端、改一次要改两处，且模板永远追不上设计稿。
> 2. **两个标签接口都要 `30001`** —— 两者都要求单已 `APPROVED`（没码就没标签；
>    反审核后码全 `VOIDED`）。原契约没列 `30001`，会让人拿到空数组后误判「这单没有手」。
> 3. **响应是 `print_ids` 列表而非 `print_id` 单值** —— 一手一行留痕，多手时不存在「那一个 id」。
> 4. **「重打必带 `print_seq`」**（原契约未写）—— 没有批次号就无法去重，「重打」退化成「又打了一次正常打印」。
>    缺 `print_seq` → `10002`。
> 5. **`register_print` 入参补 `size_code`** —— 手号**每尺码各自编号**（Q-B13），
>    多尺码单上的「第 3 手」不带尺码指不到具体哪一手。
> 6. **`print_seq` 重复 → `10008`（非法操作）而非 `10003`（并发冲突）** —— 这不是「别人刚改了单」，
>    是「这个批次号用过了」。用户的正确动作是换 `print_seq` 或带同一 `Idempotency-Key` 重试；
>    `10003` 的文案会把人引去「刷新单据」，那是错的引导。
>
> **另记**：`04 §7.16` 的 `print_seq` **没有唯一索引**，本卡明令不加迁移，幂等靠三层
> （`FOR UPDATE` 锁表头 → 同事务查 `print_seq` 是否已用 → Router 的 `Idempotency-Key` 短路）。
> 库层兜底要另开迁移改 `04 §7.16`（已登记 `docs/12` L-100）。
| GET | `/api/v1/bundling-orders/{id}/statistics` | `bundling:read` | 按 `data_scope` | `date_from` `date_to` `style_no` | 按款号/尺码聚合**手数**、件数、已计手数、未计件手数 | `10001` `12002` |
| GET | `/api/v1/bundling-orders/exports` | `bundling:read` | 按 `data_scope` | 同列表条件 | CSV（复用列表 service，07 §3.2 铁律 3） | `12001` `12002` |

- **`POST .../bundles/generations` 作废**（上一轮的"按 `seq_no` 区间补生成"接口）：ADR-0016 后码在**审核事务内按手一次性全量生成**（§4.1 第 ① 步），不存在"审核后分段补生成"；分段场景改为 **`GET /hands` + 标签打印按手号区间筛选**。若确实需要重跑生成，走 `POST /approvals` 的幂等重入。
- **整件口径（09 §4.2 / B18）**：`bundle_qty` **必须是整数**（DB `CHECK` + 04 §7.0），**余数不出码**；响应里的 `hands_total`（码数）与 `bundling_orders.hands_total` 恒等。
- **拆分预演 `split` 只读**：不写库、不预占、不写日志；因此用**已登记的 `bundling:read`**，**不新增权限点**。
- 标签导出与批量打印登记是两个接口：**导出拿数据、打印登记拿痕迹**，不要合成一个（06 §4 要求重打留日志）。
- OpenAPI：`tags="打菲"`、`summary` 必填；`approvals` 的 `description` 必须写明 §4.1 六步与"码数 = 手数"断言；批量生成部分必须写明"用 `INSERT ... SELECT` + `generate_series`、禁止逐条"。
- 响应金额/数量一律字符串（05 §3）。

## 7. 并发与幂等

| 风险场景 | 方案 |
| --- | --- |
| **★ 批量生成码的手序号竞争（ADR-0016 风险 ①）** | 三层防线：① **状态机 + 乐观锁**：`WHERE id=? AND version=? AND status='SUBMITTED'`，`rowcount=0` → `10003`，并发第二请求**进不来**；② **手序号由服务端在审核事务内按 `generate_series(1, hands)` 统一展开**（`hands` 为 `integer`），**不接受前端传入 `hands` 值**，故不存在"两个请求各要第 2 手"的分配竞态；③ **`uq_bundles_hand UNIQUE (doc_id, color_code, size_code, hands)` 兜底**，冲突转 `31005`（带已存在手号），**绝不"查后插"**。`uq_bundles_no` 兜底 `bundle_no` 唯一 |
| **★ 同码重复计件（`32001`，一码一员工）** | 计件事务内 `SELECT ... FROM bundles WHERE bundle_no = :bn **FOR UPDATE**` 锁该码行 → 判 `counted_at` 非空则抛 `32001`（带原计件人姓名与时间）→ 否则回写 `counted_qty` / `counted_by` / `counted_at`。**本模块（打菲）侧的反向动作**（作废、反审核、改手数）**同样要先 `FOR UPDATE` 锁该码行**再判 `counted_at`，与计件侧串行；后到者按最新状态判断 |
| **★ 改手数 vs 正在计件（B23 `31006`）** | `PATCH /bundling-orders/{id}` 改 `hands` 前：① 先 `SELECT ... FROM bundles WHERE doc_id=? AND status='ACTIVE' FOR UPDATE` 锁本单全部 ACTIVE 码；② 检查是否存在 `counted_at IS NOT NULL` → 有则 `31006`；③ 无则允许**同步未计件码的 `bundle_qty`** 为新的每手件数，并写 `document_logs`（记改前改后）。**已计件的码永远不动 `bundle_qty`**（否则 `ck_bundles_cnt (counted_qty <= bundle_qty)` 会炸） |
| 批量生成性能（2000 手） | `INSERT ... SELECT ... FROM generate_series()`，**禁止逐条 INSERT / 禁止 ORM 循环**；生成后跑 §5.3 的 4 条断言；单事务内完成，禁止把批量拆成多次请求 |
| **取整导致码数变化（整件口径）** | `output_qty ÷ hands` 除不尽时**余数不出码**（B18）。审核事务内：① 算 `bundle_qty` 与 `balance_qty` → 回写 `bundling_orders.hands_total` / `output_qty` / `balance_qty` 与 `bundling_order_lines.planned_qty`；② 再 `generate_series` 展开插入；③ 跑断言。**任一步失败整事务回滚**，不得出现"单据写 2000 手、码只有 1998 个"的半成品；取整结果写 `document_logs`（`changed_fields` 记取整前后值）。并发取整漂移由审核的乐观锁 + `cutting_outputs` 行锁挡住 |
| 批量生成并发重复 | 同上乐观锁；即使双击两次，也只有一个事务进入生成；另一请求命中幂等键返回已生成结果（05 §5） |
| 并发打菲与裁剪反审核 | 同一行 `cutting_outputs` 行级 `SELECT ... FOR UPDATE`；统一加锁顺序（先 `cutting_outputs` → `bundling_orders` → `bundles`）防死锁 |
| 并发打菲超可打菲数 | `reserved_qty` 分配用条件 UPDATE `available >= :qty`；`rowcount=0` → `30002`，恒不超发（INV-6） |
| 单码作废重复点击 | `Idempotency-Key = bundle_no + 'void'`；第二次命中返回首次结果（`200`）而非报错（05 §5） |
| 标签打印重复登记 | 同上幂等键 + `bundle_label_prints` 只追加，重打次数如实累加（B15） |
| 大事务锁表 | `bundles` 批量插入只锁本单新行，不更新全表；`cutting_outputs` 按行锁；禁止表级 `LOCK TABLE` |

## 8. 索引与查询场景

| 场景（业务动作） | SQL 条件 | 命中索引 |
| --- | --- | --- |

| **按手列表（`GET /hands`）** | `WHERE doc_id=? AND (:color_code IS NULL OR color_code=?) AND (:size_code IS NULL OR size_code=?) AND deleted_at IS NULL ORDER BY size_code, hands` | `idx_bundles_line_id (line_id)` + `uq_bundles_hand (doc_id, color_code, size_code, hands)` 最左列 `doc_id` |
| **★ 未计件手清单（ADR-0016 验证方式）** | `WHERE status='ACTIVE' AND counted_at IS NULL AND deleted_at IS NULL AND doc_id=?` | **`idx_bundles_counted_pending`**（04 §7.0 部分索引） |
| **★ 手序号重复定位（`31005`）** | `WHERE doc_id=? AND color_code=? AND size_code=? AND hands=? AND status='ACTIVE'` | `uq_bundles_hand`（唯一索引即查询索引） |

| 码列表：款号 + 尺码 + 状态 | `WHERE style_no=? AND size_code=? AND status='ACTIVE' AND deleted_at IS NULL` | `idx_bundles_style_size_status`（建议新增，部分索引） |
| **按裁剪尺码明细行回查码（追溯链）** | `WHERE cutting_size_line_id=?` | `idx_bundles_cutting`（建议新增） |

## 9. 错误码

| 码 | HTTP | 含义 | 本模块触发场景 | 处理 |
| --- | --- | --- | --- | --- |
| `31003` / `10001` | 422 | 非整件参数 → `31003`；其他参数失败 → `10001` | `hands <= 0`、`qty_per_hand <= 0`、`hands_total` 为 0、**码数 ≠ 裁剪手数**、尺码码非法（`bundle_no` CHECK） | 行内红字提示 |
| `10002` | 400 | 缺少必填业务参数 | `reject`/`reverse`/`cancel`/`void_code` 未填原因 | 弹出原因输入框 |
| `10003` | 409 | 乐观锁冲突 | 并发审核 / 重复提交审核 | 刷新后重试 |
| `12001` | 403 | 无操作权限 | 缺 `bundling:approve` / `bundling:print` / `bundling:code:void` | 隐藏入口 |
| `12002` | 403 | 无数据权限 | 车间主管查他车间码 | 提示无权访问 |
| `20001` | 404 | 基础资料不存在 | 款号 / 工序 / 车间已停用；`cutting_size_line_id` 指向的尺码明细行不存在 | 刷新下拉 |
| `30001` | 409 | 裁剪单状态不允许该操作 | 非 `SUBMITTED` 审核、终态再迁移、非 `DRAFT` 编辑 | 刷新看状态 |
| `30002` | 409 | 裁剪数量 < 已打菲数量 + 损耗 | 打菲件数超裁剪可用量（INV-6，B7） | 提示剩余可打菲数 |
| `31001` | 404 | 打菲号不存在 | 码格式对但查无此码（扫码输错/别厂码） | 重新扫码 |
| `31002` | 409 | 该打菲号已作废 | `status='VOIDED'`，重复作废 | 重新扫码 / 显示作废原因 |
| **`31004`** | 409 | **打菲码数与裁剪手数不一致（少打或多打）** | `submit` 预检或 `approve` 断言时 `count(bundles) ≠ Σround(明细 hands)`（B21、08 §2.2 第 ③ 条） | 提示**应有手数与当前手数**；核对是改 `hands` 还是改尺码明细来源 |
| **`31005`** | 409 | **手序号重复（同单同色同尺码同手号已存在）** | 展开时与 `uq_bundles_hand` 冲突；或 `split` 预演的 `conflicts[]`（B22） | 提示已存在的手号；查是否上一单/上一次审核已占用 |
| **`31006`** | 409 | **已计件的码不可改手数** | `PATCH` 改 `hands` 时该 (单, 色, 码) 下存在 `counted_at` 非空的码（B23） | **先红冲该手流水**，或新开单据追加手 |
| **`32001`** | 409 | **计件流水冲突：同一打菲号本工序已被他人计件** | 作废/反审核时被计件侧占用；或统计到该码 `counted_by` 非空（B24） | 提示"XL 第 2 手，陈美玲 09:44 已计 60 件"；**不允许改手数或作废** |
| `32003` | 409 | 计件已结算，不可修改 | **作废已计件码**（B11）、**反审核已有计件的码**（08 §2.2） | 提示"先在计件模块红冲 + 补录" |
| `10004` | 429 | 请求过于频繁 | 高频批量打印登记 | 退避重试 |

> 全部取自 [05 §4](../05-接口设计规范.md) 清单，**未新增**。打菲域 `31xxx`（`31001`~`31006`），跨域引用 `30xxx`（裁剪，INV-6 口径）与 `32xxx`（计件，`32001` / `32003`）。
> ⚠️ **`31001` / `31002` 是本模块向计件侧提供的验码错误码**（码不存在 / 已作废），由 [04-计件](./04-计件.md) 触发；本模块自身 `GET /bundles/{bundle_no}` 查无此码时也用 `31001`。
