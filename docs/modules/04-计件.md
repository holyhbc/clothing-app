# 04 计件（扫码计件）

> 计件流水是全系统**唯一的计件事实来源**：一次扫码一条 append-only 流水，单价按计件日期命中 `operation_rates` 生效区间取一次并**落库即快照**（INV-3），已结算只能红冲 + 补录两笔新流水修正（INV-2）。

> **REV-2026-10（第四批，ADR-0016）扫码口径 —— 本篇最重要变更**：
> ① **扫一次码 → 默认 `qty = bundles.bundle_qty`（该手件数）**，❌ **不再是"扫码 +1 件"**。工位机反馈形如 `✓ 打边 第 1 手 · 60 件 · +¥25.20`。
> ② **允许手写更小的数量（部分生产）**，校验 `0 < qty ≤ bundle_qty`；剩余量**不改码**。
> ③ **超产拒绝 `32006`**；要超产必须**追加手**（新裁剪 + 新打菲），不能靠改数量。
> ④ **一码一员工**：第二个员工扫同一码 → **`32001`**（提示原计件人与时间）。
> ⑤ `piecework_logs.qty` **仍是整数件**（`ck_piecework_logs_whole` 保留）；新增 `piecework_logs.bundle_id` 引用 `bundles`。
> ⑥ **幂等键语义变化**：从"同码可重复扫返回原记录"改为"**一码一次**；第二人扫 → `32001` 明确报冲突"（不再是静默幂等）。
> ⑦ **计数单位从「件」改为「手」为主计数**，旁边并列「件」（ADR-0016 §6）。
> 详见 §2 BR-PW-26~BR-PW-31、§3.1、§5.1、§6.1、§7.1、§11 TC-39~TC-44。
> **REV-2026-10（第三批，ADR-0009）取价口径**：单价按 `(style_no, operation_no, work_date)` 命中生效区间取一次并快照。
> **REV-2026-10（第二批，09 §4.2）整件口径**：`qty` 只允许正整数；裁剪尾数**不出码、不计件**。

## 1. 模块职责与边界

### 1.1 职责与边界

**职责**：① 采集计件流水（工位机扫码枪 / 员工端 H5 / 手工补录，统一写 `piecework_logs`）；② **锁码校验 + 写回 `bundles.counted_qty` / `counted_by` / `counted_at`（一码一员工，ADR-0016）**；③ 维护员工工序绑定 `piecework_bindings`；④ **按 `work_date` 命中 `operation_rates` 生效区间取价**，落库即快照单价（INV-3）；⑤ 提供纠错通道（红冲 + 补录，禁 `UPDATE qty/amount`，INV-2）；⑥ SSE 实时可见；⑦ 向 [05-工资](./05-工资.md) 提供未结算流水、向 [06-库存](./06-库存.md) 提供成衣计提工价。

**依赖契约**：

| 依赖方向 | 契约 | 失败处理 |
| --- | --- | --- |
| 打菲模块 → 本模块 | 传入 `bundle_no`；本模块 `SELECT … FOR UPDATE` 锁 `bundles` 行后反查 `style_no` / `operation_no` / `color_code` / `size_code` / **`hands`（手序号）/ `bundle_qty`（该手件数）** / `cutting_size_line_id` | 查不到 → `31001`；`status='VOIDED'` → `31002`；`counted_at` 非空 → **`32001`**（带原计件人姓名与时间）。**裁剪尾数无码**：尾数不生成 `bundle_no`，不存在"扫到尾数"的可能（09 §4.2、BR-PW-19） |
| 本模块 → 打菲模块 | **同事务内回写** `bundles.counted_qty` / `counted_by` / `counted_at`；红冲 + 补录时同步清空/重写（§4.3） | DB CHECK `ck_bundles_cnt (0 ≤ counted_qty ≤ bundle_qty)` 兜底 |
| 基础资料 → 本模块 | `style_operations` 提供该款**可选工序列表**（`operation_no`/`sequence`/`bundle_qty`/`is_piecework`）；`operation_rates` 提供 (style_no, operation_no, work_date) → `unit_price` | 款号/工序不存在 → `20001`；**当日无生效单价 → `20004`** |
| 本模块 → 工资模块 | 未结算流水查询（`payroll_id IS NULL`） | 工资侧只读，不得反写计件金额 |
| 本模块 → 库存模块 | 成衣单位成本 = 物料耗用成本 + 计提工价 | 本模块只提供工价金额，不做成本结转 |

> 本模块对 `operations` / `style_operations` / `operation_rates` **只读**，任何写入都在 [01-基础资料](./01-基础资料.md)（权限点 `base:operation:manage` / `piecework:rate:manage` / `base:rate_template:manage`）。

**明确不做的**：

| 不属于本模块 | 归属 | 理由 |
| --- | --- | --- |
| 生成 `bundle_no`、打菲单审核、码作废、按手拆分 | [03-打菲](./03-打菲.md) | 一码一手（INV-1 + ADR-0016）在打菲审核时固化 |
| 计件结算单、工资单、发放、凭证 | [05-工资](./05-工资.md) | 本模块只提供未结算流水，不做任何汇总 |
| 款号 / 工序 / 工序单价 CRUD、员工调岗 | M1 基础资料 / M10 权限 | 本模块只读；`group_no` 来自 `users` |
| 扫码枪驱动、标签打印 | 终端 / 打印模块 | 扫码枪是 HID 键盘，前端只做键盘事件捕获 |
| PDA / 小程序计件 | 本期不做 | 写入同一张 `piecework_logs` 表（00 §5.3 可插拔点） |

## 2. 业务规则

| # | 规则 | 详细口径 | 强制手段 |
| --- | --- | --- | --- |
| BR-PW-01 | **一码一工序一次计件** | 同一 `bundle_no` + 同一 `operation_no` + 同一 `employee_id` + 同一 `work_date` + 同一 `log_type` 只允许 1 条 | `uq_piecework_logs_idem` 唯一索引 |
| BR-PW-02 | 同码不同工序允许 | 一件成衣经过 03→04→05 多个工序，每个工序各自计件，金额分开算（⚠️ ADR-0016 后同码只在**本工序**内"一次"，不同工序各打各的码与手，见 BR-PW-29） | 唯一键含 `operation_no` |
| **BR-PW-03** | **同码不同员工冲突 → `32001`**（ADR-0016，Q-PW13） | 同一 `bundle_no` **该手已被他人计件** → 拒绝，**明确提示"XL 第 2 手，陈美玲 09:44 已计 60 件"**（带 `details.counted_by_name` + `details.counted_at`）。判定依据是 **`bundles.counted_at IS NOT NULL`**（不是"查 `piecework_logs` 有没有别人的行"） | 事务内 `SELECT … FROM bundles WHERE bundle_no=:bn FOR UPDATE` → 判 `counted_at` → 抛 `32001` |
| BR-PW-04 | 绑定当天有效 | `piecework_bindings.work_date` = 当天；次日必须重扫绑定 | 查绑定时校验 `work_date = scanned_at 的日期` |
| BR-PW-05 | 单价快照 | `unit_price` 在落库瞬间按 `work_date` 命中 `operation_rates` 生效区间取值并写入，之后**永不重读** | INV-3；测试断言改基础资料后历史不变 |
| BR-PW-06 | 流水不可变 | 禁止 `UPDATE qty / amount / unit_price / bundle_no / bundle_id / employee_id / work_date`；只允许改 `remark / updated_*` | 编码规范 + `piecework` service 无对应方法 |
| BR-PW-07 | 红冲补录 | 错误计件（含**部分生产做少了**要改成做全）→ 写 1 条 `REVERSAL`（负数）+ 1 条 `SUPPLEMENT`（正确值），两笔新流水；`reversal_of_id` 均指向被冲的原流水。**同时回写 `bundles`**（§4.3） | ADR-0005；索引 `idx_piecework_logs_reversal_of_id` |
| BR-PW-09 | 结算标记独立 | 是否已结算用独立字段 `payroll_id` 判定，**不改 `log_type`** | 04 §7.1 要点 |
| BR-PW-10 | 已结算不可改 | `payroll_id IS NOT NULL` 的流水禁止红冲/补录 | `32003` |
| BR-PW-11 | 归属日期以 `scanned_at` 为准 | 离线缓存重传时以客户端 `scanned_at` 归属 `work_date`，不按服务端接收时间 | 07 §7 |
| **BR-PW-12** | **件数由「该手件数」决定（ADR-0016 修订，取代"由款号配置决定"）** | **默认 `qty = bundles.bundle_qty`（该手件数，扫码查库即得）**，**不再取 `style_operations.bundle_qty`**（那是"一扎几件"的录入参考，**同名不同义，见 §12 Q-PW13**）。❌ **不再是"扫码 +1 件"**；❌ **不再硬编码 1 或 12**（09 §3 明令） | `bundles.bundle_qty` 为唯一权威来源（04 §7.0）；`COUNT = bundles.counted_qty` |
| BR-PW-13 | 无效码拒绝 | `bundle_no` 格式不符 / 查无此码 / 码已 `voided_at` → 拒绝 | `31001` / `31002` |
| BR-PW-14 | 员工端接口收敛 | 员工 token 只能访问 `/api/v1/self/**`，其余计件接口一律 403 | 路由分组中间件强制 |
| BR-PW-15 | 员工数据范围恒为 SELF | 员工不可看他人计件，前端传参不能放大范围 | INV-8 + 07 §3.2 `apply_data_scope` |
| **BR-PW-16** | **幂等命中不报错（仅限"同一幂等键的重试"）** | 同一 `Idempotency-Key`（或同业务唯一键 + 同 `employee_id`）的**网络重试** → 返回首次结果 + HTTP 200 + `code=0` + `idempotent=true`。⚠️ **但"另一个员工扫同一码"不再是幂等命中，而是业务冲突 `32001`**（BR-PW-03、BR-PW-26）—— 静默返回他人的记录会让工人以为自己也做了这手 | 05 §5 + `bundles.counted_by` 判定 |
| BR-PW-17 | 手工补录留痕 | `log_type=MANUAL` 需 `piecework:manual` 权限且 `remark` 必填（写明原因） | 07 §5 敏感操作日志 |
| BR-PW-18 | 只软删不物理删 | 流水只允许软删（管理端纠错入口），且软删需 `piecework:reverse` + 原因 | 04 §6.1 / INV-7 |
| BR-PW-19 | **尾数不计件（整件口径，Q-PW04 ✅ 已决策）** | `piecework_logs.qty` **只允许正整数件**（DB `ck_piecework_logs_whole CHECK (qty = trunc(qty))`，04 §7.1）。裁剪尾数 `balance_qty`（不足一件的余量）**不出打菲码，因此无码可扫，本模块不可能产生尾数流水**；手工补录 `MANUAL` / `SUPPLEMENT` 传小数同样拒绝（`32005`）。**错误信息必须写"本系统按整件计，尾数不计件（09 §4.2）"** | 09 §4.2、04 §7.1；[02-裁剪](./02-裁剪.md) C13、[03-打菲](./03-打菲.md) B18 |
| BR-PW-19b | **返工件计件仍待定（Q-PW03）** | 返工件（`rework_qty`）如何计件**当前无口径** | 见 §12 Q-PW03；**未确认前不得实现任何返工分支**，代码留 `TODO(业务待确认: Q-PW03)` |
| BR-PW-20 | **单价按工序定，不分技能等级** | 单价维度 = `款号 × 工序 × 生效区间`；同一款同一工序人人同价 | ADR-0009；09 §4 Q-01 ✅ |
| BR-PW-21 | **按计件日期取价，不是按结算日期取价** | `effective_from <= work_date AND (effective_to IS NULL OR effective_to > work_date)` | 04 §7.8.3 取价 SQL；ADR-0009 理由 3 |
| BR-PW-22 | **调价不影响已落库流水** | 调价只改 `operation_rates`，**不触碰 `piecework_logs`** | INV-3 |
| BR-PW-23 | **未设单价拒绝计件** | 当日命中不到任何生效区间 → 拒绝，返回 `20004`，提示缺哪个款号哪个工序；**禁止硬编码 0 或取"最近一档价"兜底** | 04 §7.8.3 |
| **BR-PW-24** | **一码一次（原"同日同款同工序重复扫码幂等返回"已收窄）** | ① **同一员工 + 同一 `Idempotency-Key` 的重试** → 返回首次结果 + `idempotent=true`（网络抖动、断网重传、用户连点）；② **同一员工 + 不同幂等键 + 同码同日同工序** → 视为重复提交，**返回首次结果 + `idempotent=true`**（不重复计数，避免工人连扫丢单）；③ **另一个员工 + 同码** → **`32001` 业务冲突，明确报出原计件人与时间**（❌ 不再静默幂等）。同幂等键不同 body → `10002` | `bundles.counted_by` / `counted_at` 判定 + `uq_piecework_logs_idem` 兜底 |
| BR-PW-25 | 员工可选工序来自款号配置 | 员工端"可绑定工序"只读 `style_operations`（`is_piecework=true` 且未停用）；`style_no` 由扫码带出不由前端填 | 04 §7.8.2；09 §4.1「员工绑定」 |
| **BR-PW-26** | **★ 扫一次码默认计「该手件数」（ADR-0016 决策 4）** | 扫码 → 事务内锁码 → `default_qty = bundles.bundle_qty`；**不传 `qty` 时 `qty = default_qty`**。响应回 `bundle_qty`（该手件数）与 `hands`（第 N 手），工位机显示 `✓ 打边 第 1 手 · 60 件 · +¥25.20`。**件数不写进码，查库得**（ADR-0004 沿用；改每手件数不用作废旧码） | `bundles.bundle_qty` 为权威；`amount = qty × unit_price` |
| **BR-PW-27** | **★ 允许部分生产（手写更小的数量）** | `qty` **可选**，传了必须 `0 < qty < bundle_qty`（等于也合法）。业务方原话：「有时候这手可能就生产一部分数量，可以支持手写数量，但是数量必须小于等于裁剪单该手的件数」。`qty` 必须是**整数件**（`32005`）。落库后 `bundles.counted_qty = qty < bundle_qty` → 派生状态「**已计件·部分**」。**剩余量不改码**；如需补做走**红冲 + 补录**（BR-PW-07）或**追加新手**（新裁剪 + 新打菲） | `ck_bundles_cnt (0 ≤ counted_qty ≤ bundle_qty)` + service 层前置校验 |
| **BR-PW-28** | **★ 超产拒绝 `32006`** | `qty > bundle_qty` → **拒绝 `32006`**，响应回 `bundle_qty` 与 `counted_qty`。**理由**（ADR-0016 理由 ⑥）：否则会出现"一只手做了 88 件"的账实不符，**裁剪结转闭环（INV-6）被打穿**。**要超产必须追加手**（新裁剪单 + 新打菲单），**不能靠改数量** | 04 §7.0.2 + 05 §4 `32006`；⚠️ ADR-0016 §4 与 04 §7.0.2 伪代码注释写的是 `31004`，见 §12 Q-PW14 |
| **BR-PW-29** | **★ 一码一员工（责任单元 = 手）** | `bundles.counted_by` **只允许一个员工**；第二个员工扫同一码 → **`32001`**（提示"XL 第 2 手，陈美玲 09:44 已计 60 件"）。业务方原话：「多个员工生产就不知道谁做工」——**ADR-0016 决策 ③：责任单元就是手**。⚠️ 同一件成衣的**不同工序**仍各计各的（B9 码与工序强绑定 → 不同工序是不同码，不构成冲突） | `bundles.counted_at IS NOT NULL` 判定 + `FOR UPDATE` 串行化 |
| **BR-PW-30** | **★ `piecework_logs.bundle_id` 引用 `bundles`** | 新增 `bundle_id uuid`（04 §7.1 已含该列，REV-2026-10）→ `REFERENCES bundles(id) ON DELETE RESTRICT`。**不再只靠 `bundle_no` 字符串关联**。❌ 上一轮写的 `piecework_logs.cutting_line_id` **作废**（ADR-0017 后裁剪的"件数权威"是 `cutting_order_size_lines.id`，已由 `bundles.cutting_size_line_id` 承载，计件侧**无需再引一行**） | 04 §7.1 + 03-打菲 §3.3 |
| **BR-PW-31** | **★ 计数单位改「手」，并列「件」** | 工位机与员工端的**主计数是「手」**（`COUNT(hands)`），旁边并列「件」（`SUM(qty)`）。响应同时给 `today_hands` 与 `today_qty` | ADR-0016 §6；§5.1 步骤 7、§6.2 `/self/piecework/today` |
| **BR-PW-32** | **★ 已计件的码不可改手数（跨模块约束）** | 打菲侧改 `hands` 时若该码 `counted_at` 非空 → `31006`（由 03-打菲 触发）。本模块的义务：**`bundles.bundle_qty` 永远不被本模块改动**；计件只写 `counted_qty` / `counted_by` / `counted_at` | 04 §7.0.2「改每手件数」行；[03-打菲](./03-打菲.md) B23 |

### 2.1 `log_type` 语义

| log_type | 含义 | qty / amount 符号 | 需要权限 | 能否被结算 |
| --- | --- | --- | --- | --- |
| `SCAN` | 扫码正常计件（工位机或员工端） | 正 | `piecework:count` | 能 |
| `MANUAL` | 管理端手工补录（漏扫码、纸质登记补录） | 正 | `piecework:manual` | 能 |
| `REVERSAL` | 红冲，冲回一条已存在的流水 | **负** | `piecework:reverse` | 能（净额参与） |
| `SUPPLEMENT` | 补录，红冲后重新录入的正确流水 | 正 | `piecework:manual` | 能 |

> 净额口径：某员工某工序当期应计金额 = `SUM(amount)`（REVERSAL 负数自然抵减），不按 `log_type` 分支计算。

## 3. 数据模型

### 3.1 `piecework_logs`（计件流水，append-only，照抄 [04 §7.1](../04-数据库规范.md)）

```sql
CREATE TABLE piecework_logs (
    id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
    bundle_no       varchar(64)  NOT NULL,
    style_no        varchar(32)  NOT NULL,
    operation_no    varchar(16)  NOT NULL,
    employee_id     uuid         NOT NULL,
    workshop_id     uuid         NOT NULL,
    group_no        varchar(32),
    work_date       date         NOT NULL,
    bundle_id       uuid,                            -- ★ 引用 bundles（REV-2026-10 / ADR-0016 / ADR-0017）
    qty             numeric(14,3) NOT NULL DEFAULT 1, -- ★ 该手件数（可小于 bundles.bundle_qty，ADR-0016）
    unit_price      numeric(12,6) NOT NULL,          -- INV-3 快照
    amount          numeric(18,4) NOT NULL,
    log_type        piecework_log_type NOT NULL,     -- SCAN / MANUAL / REVERSAL / SUPPLEMENT
    payroll_id      uuid,                            -- 结算后可回写（04 §7.1 要点）
    reversal_of_id  uuid,                            -- 红冲指向原流水
    source_station  varchar(32),
    created_at      timestamptz NOT NULL DEFAULT now(),
    created_by      uuid NOT NULL,
    updated_at      timestamptz NOT NULL DEFAULT now(),
    updated_by      uuid NOT NULL,
    deleted_at      timestamptz,
    version         integer NOT NULL DEFAULT 1,
    remark          text,
    CONSTRAINT uq_piecework_logs_idem UNIQUE
      (bundle_no, operation_no, employee_id, work_date, log_type),
    -- 符号规则（REV-2026-10 修订）：只有红冲行为负，其余为正
    CONSTRAINT ck_piecework_logs_sign CHECK (
      (log_type = 'REVERSAL' AND qty < 0 AND amount < 0)
      OR (log_type <> 'REVERSAL' AND qty > 0 AND amount > 0)
    ),
    -- 整件口径：尾数不入库，计件只按整件（09 §4.2）
    CONSTRAINT ck_piecework_logs_whole CHECK (qty = trunc(qty))
);
```

**照抄自 04 §7.1 的要点**（不改动含义）：

| 要点 | 内容 |
| --- | --- |
| **`bundle_id`（REV-2026-10 第四批，BR-PW-30）** | **★ 引用 `bundles.id`**，取代"仅靠 `bundle_no` 字符串关联"。理由：① `bundle_no` 是可变字符串格式（ADR-0004 → ADR-0016 已改过一次），FK 不会被格式变更打断；② 可直接 `JOIN bundles` 取 `hands` / `bundle_qty` / `cutting_size_line_id` / `counted_by` 做报表与追溯，不必再反查码表；③ `bundles` 侧 `counted_qty` 的对账以 `bundle_id` 为键更直接。⚠️ `bundle_id` **可空**：兼容 HR 手工补录与历史数据（`NULL` 时按 `bundle_no` 兼容读取并回 `bundle_ref: 'BUNDLE_NO_LEGACY'`）；**`SCAN` 流水必须非空**（扫码必然对应一个码） |
| **`qty` 语义变化（REV-2026-10 第四批）** | `qty` 从"该码的固定件数"变为"**本次实际完成的件数**"：`0 < qty ≤ bundles.bundle_qty`。① **不传 `qty` 时 = `bundles.bundle_qty`（整手）**；② 传了就是**部分生产**（`qty < bundle_qty`）；③ `qty > bundle_qty` → **`32006` 拒绝**（BR-PW-28）；④ `DEFAULT 1` 保留但**仅作兜底**：扫码路径必须显式写 `bundles.bundle_qty`，**不允许走到默认值 1**（那等于退回"扫码 +1 件"的旧口径，测试必须断言 `bundle_qty=60` 时 `qty=60`） |
| **整件口径不变（09 §4.2）** | `ck_piecework_logs_whole CHECK (qty = trunc(qty))` **保留**：部分生产只允许**整数件**（60 件的手可以记 28，但**不能记 28.5**）。叠加 `ck_piecework_logs_sign` 后：非红冲行 `qty` 必为**正整数**，红冲行必为**负整数** |
| 单价来源 | `unit_price` 来自 `operation_rates` 按 `work_date` 命中生效区间（§5.6），**落库时快照**写死（INV-3） |
| 幂等键 | `UNIQUE (bundle_no, operation_no, employee_id, work_date, log_type)` —— 兜底"同员工重试"；⚠️ **不含"码是否已被他人计过"**，一码一员工靠 `bundles.counted_at` + `FOR UPDATE` 保证（BR-PW-29、§7.1 C3） |
| 符号规则 | `log_type='REVERSAL'` 的行 `qty` 与 `amount` 为负，其余为正 |
| 禁改字段 | 禁止 `UPDATE qty/amount/bundle_id/bundle_no`；只有 `remark/updated_*` 可改 |
| 结算标记 | 用单独字段 `payroll_id`，不用改 `log_type` |

全字段清单（带 `*` 的是**本模块落地补充列**，需 `ALTER TABLE ADD COLUMN`）：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `bundle_no` | `varchar(64)` | 是 | 打菲号 `{打菲单号}-{尺码码}{手序号2位}-{件序号4位}`（09 §2.4、ADR-0016），二维码与 Code128 内容一致 |
| **`bundle_id`** | `uuid` | **`SCAN` 必填**，其余可空 | **★ `REFERENCES bundles(id) ON DELETE RESTRICT`**（BR-PW-30）；可空兼容历史与 HR 补录 |
| `style_no` | `varchar(32)` | 是 | 款号，如 `HB-2026-0001` |
| `operation_no` | `varchar(16)` | 是 | 工序号，如 `03` |
| `employee_id` | `uuid` | 是 | 员工（`users.id`），数据范围 SELF 过滤列 |
| `workshop_id` | `uuid` | 是 | 车间，数据范围过滤依据 |
| `group_no` | `varchar(32)` | 否 | 组别，GROUP 数据范围过滤列 |
| `work_date` | `date` | 是 | 计件归属日，取 `scanned_at` 的 `Asia/Shanghai` 日期 |
| **`qty`** | `numeric(14,3)` | 是 | **★ 本次完成件数（整数件）**：不传 = `bundles.bundle_qty`（整手）；部分生产 = 更小的正整数；`> bundle_qty` → `32006`；**恒为整数**（`ck_piecework_logs_whole`），尾数不计件（BR-PW-19）。REVERSAL 为负 |
| `unit_price` | `numeric(12,6)` | 是 | 单价快照（INV-3），由 `operation_rates` 按 `work_date` 命中区间取一次后写死 |
| `amount` | `numeric(18,4)` | 是 | `amount = qty × unit_price`，服务端算，前端传的忽略 |

| `source_station` | `varchar(32)` | 否 | 工位机号；员工端为空 |
| `payroll_id` | `uuid` | 否 | 指向 `piecework_settlements.id`，`NULL` = 未结算 |

| `idempotency_key*` | `varchar(128)` | 否 | 客户端显式传入时留存；未传时服务端按业务唯一键推导（BR-PW-24） |
| 公共字段 | 见 04 §2 | — | `created_at/by`、`updated_at/by`、`deleted_at`、`version`、`remark` |

**索引建议**：`idx_piecework_logs_bundle_id (bundle_id) WHERE deleted_at IS NULL`（★ 新增，BR-PW-30 的追溯主路径）；`idx_piecework_logs_employee_work_date`、`idx_piecework_logs_bundle_no`、`idx_piecework_logs_reversal_of_id`、`idx_piecework_logs_unsettled`（部分索引 `WHERE payroll_id IS NULL AND deleted_at IS NULL`）、`idx_piecework_logs_station`。

| 项 | 04 现状 | 结论 |
| --- | --- | --- |
| `ck_piecework_logs_sign` | 04 §7.1 已改为仅 `REVERSAL` 为负 | ✅ 已闭环（旧的 `ck_piecework_logs_qty CHECK (qty > 0)` 会拒掉红冲行，**不得**再用） |

### 3.2 `piecework_bindings`（员工工序绑定，照抄 [07 §2.1](../07-认证与权限规范.md)）

```sql
-- 员工扫码绑定（INV：员工↔款号↔工序）
piecework_bindings (
  id uuid PK, user_id uuid NOT NULL,
  style_no varchar(32) NOT NULL,
  operation_no varchar(16) NOT NULL,
  bundle_no varchar(64) NOT NULL,     -- 扫码来源，便于追溯
  workshop_id uuid NOT NULL,
  work_date date NOT NULL,            -- 绑定当天有效，次日需重扫
  is_active boolean NOT NULL DEFAULT true,
  UNIQUE (user_id, style_no, operation_no, work_date)
)
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `user_id` | `uuid` | 是 | 员工；`REFERENCES users(id)` |
| `style_no` | `varchar(32)` | 是 | 绑定时从扫码的 `bundle_no` 反查带出，**不由前端自由填写**（防伪造） |
| `operation_no` | `varchar(16)` | 是 | 必须存在于该款号 `style_operations` 且 `is_piecework=true`，否则拒绝（BR-PW-25） |
| `bundle_no` | `varchar(64)` | 是 | 触发本次绑定的打菲号；⚠️ **仅作触发来源追溯，不承担件数语义**（ADR-0016 后一件 = 一手，绑定不绑件数） |
| `workshop_id` | `uuid` | 是 | 数据范围过滤依据 |
| `work_date` | `date` | 是 | **绑定当天有效**，次日失效（BR-PW-04） |
| `is_active` | `boolean` | 是 | 主动解绑置 `false`（不物理删，INV-7） |

**行为要点**：重复绑定命中唯一键 → 幂等返回既有绑定；扫 `bundle_no` 自动带出款号（前端只提交 `bundle_no` + `operation_no`）；跨款号切换时旧绑定**不删除**；解绑走 `DELETE /api/v1/self/piecework-bindings/{binding_id}` → 置 `is_active=false` + `deleted_at` + 写 `document_logs`；绑定列表恒按 `user_id = ctx.user_id` 过滤（BR-PW-15）。

### 3.3 实体关系

```
users 1:N → piecework_bindings（候选工序来自 style_operations，取价源 operation_rates，均只读）
users 1:N → piecework_logs
bundles 1:1（逻辑）→ piecework_logs        ← ★ bundle_id（ADR-0016 / ADR-0017）
  bundles（03-打菲拥有）持 hands / bundle_qty / counted_qty / counted_by / counted_at
         ↑ 本模块在计件事务内 FOR UPDATE 锁行后写 counted_*
bundles.cutting_size_line_id → cutting_order_size_lines.id（裁剪尺码明细，件数权威来源，间接可追溯）
piecework_logs 自引用（reversal_of_id）
piecework_logs.payroll_id N:1 → piecework_settlements（05-工资 审核时回写）
```

| 关系 | 基数 | 外键约束 | 说明 |
| --- | --- | --- | --- |
| **`piecework_logs.bundle_id` → `bundles.id`** | N:1 | **必建 FK**（`SCAN` 行） | **★ BR-PW-30**；取代"仅靠 `bundle_no` 逻辑关联"。可空兼容历史 |
| `piecework_logs.employee_id` → `users.id` | N:1 | 必建 FK | 反查姓名用于 SSE 与 `32001` 冲突提示 |
| `piecework_logs.reversal_of_id` → `piecework_logs.id` | N:1 自引用 | 必建 FK + 索引 | 防环：红冲的原流水不能再被红冲 |
| `piecework_logs.payroll_id` → `piecework_settlements.id` | N:1 | 必建 FK（可空） | 05-工资 审核时回写 |
| `piecework_bindings.user_id` → `users.id` | N:1 | 必建 FK | 07 §2.1 已定 |
| `piecework_bindings` → `style_operations` | 逻辑引用 | 不建 FK | service 层校验，失败 → `20001` |
| `piecework_logs` → `operation_rates` | 逻辑引用 | 不建 FK | 落库前取价；命中不到 → `20004` |
| ❌ `piecework_logs.cutting_line_id` | — | **作废** | ADR-0017 后裁剪侧"行"是布批，件数权威在 `cutting_order_size_lines.id`（已由 `bundles.cutting_size_line_id` 承载），**计件侧无需再引一行**；[02-裁剪](./02-裁剪.md) C31 已同步 |

## 4. 单据与状态机

### 4.1 为什么计件流水没有状态机

`piecework_logs` 是**事实流水**不是单据：没有草稿、没有审核人、没有版本流转。08 §1.1 的动作集合只适用于 `status` 字段存在的单据表。按 08 §1.2 R7，流水表上**不写 `status`**。

流水的"状态"由**派生字段**判定（不落库为状态列）：

| 派生状态 | 判定条件 | 业务含义 |
| --- | --- | --- |
| 有效·未结算 | `payroll_id IS NULL` 且非红冲 | 可被工资结算单汇总 |
| 有效·已结算 | `payroll_id IS NOT NULL` | 锁定，禁改（BR-PW-10） |
| 已冲销 | 存在指向本行的 `REVERSAL` 流水 | 金额已被抵减，本行不再单独计薪 |
| 已作废 | `deleted_at IS NOT NULL` | 软删，仅审计可见 |

**`bundles` 侧的派生状态（ADR-0016）**：见 [03-打菲](./03-打菲.md) §3.3 —— `counted_at IS NULL` = 未计件；`counted_qty = bundle_qty` = 已计件·足额；`0 < counted_qty < bundle_qty` = **已计件·部分（部分生产）**。

### 4.2 迁移表（`piecework_bindings` 与计件纠错动作）

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `create`（绑定） | — | `is_active=true` | `self:piecework:bind` / `piecework:manual` | 码有效（`31001`/`31002`）；款号启用；操作在该款 `style_operations` 内且 `is_piecework=true`（否则 `20001`，BR-PW-25） | 写绑定；写 `document_logs` |
| `withdraw`（解绑） | `is_active=true` | `is_active=false` | `self:piecework:bind` | 本人绑定 | 置 `deleted_at`；已产生的流水**不受影响** |
| **`count`（计件，★ 重写）** | — | 新增流水 + `bundles.counted_*` 回写 | `piecework:count` | **校验链（顺序不可调换，§5.1）**：① 锁 `bundles` 行（`FOR UPDATE`）；② 码存在 `31001`；③ 未作废 `31002`；④ **`counted_at IS NULL`，否则 `32001`**（带原计件人 + 时间）；⑤ 绑定当天有效（`32002`）；⑥ 当日有生效单价（否则 `20004`）；⑦ **`qty` 解析**：不传 = `bundle_qty`；传了校验 `0 < qty ≤ bundle_qty`（`qty > bundle_qty` → **`32006`**；小数 → `32005`；`<= 0` → `10001`）；⑧ 同员工同码同日同工序已存在 → 幂等返回首次结果 | 插入流水（`bundle_id` + `qty` + `unit_price` 快照 + `amount`）+ **回写 `bundles.counted_qty` / `counted_by` / `counted_at`** + 发 `piecework_counted` + `document_logs` |
| `reverse`（红冲） | 有效·未结算 | 新增 `REVERSAL` 流水 | `piecework:reverse` | 原流水存在且 `payroll_id IS NULL`（否则 `32003`）；原因必填 | 插入负数流水；`reversal_of_id` 指向原流水；**清空 `bundles.counted_*`**（§4.3）；写日志 |
| `supplement`（补录） | 已被红冲 | 新增 `SUPPLEMENT` 流水 | `piecework:manual` | 被补录的原流水已红冲；`log_type=SUPPLEMENT` 唯一键不冲突；**补录后 `qty` 仍须 `≤ bundle_qty`**（`32006`） | 插入正确流水；`reversal_of_id` 指向原流水；**重写 `bundles.counted_*`**（§4.3） |

### 4.3 反向对称性（08 §3.3）与 `bundles` 回写规则

| 动作 | 正向做 | 反向必须做 |
| --- | --- | --- |
| 计件 / 补录 / 手工补录 | 插入 `SCAN` / `SUPPLEMENT` / `MANUAL` 流水 + `bundles.counted_qty/by/at` 回写 | 插入 `REVERSAL` 负数流水指向原行（**永不删原行**）+ **清空 `bundles.counted_*`**（该手回到"未计件"） |
| 结算（05-工资） | 回写 `payroll_id` | 清除 `payroll_id` |
| 打菲码作废（03-打菲） | 置 `voided_at` | 码不可恢复（本模块**只读校验**，见 `31002`） |

**`bundles` 回写规则（ADR-0016，跨模块写，必须成对）**：

| 计件动作 | `bundles.counted_qty` | `bundles.counted_by` | `bundles.counted_at` |
| --- | --- | --- | --- |
| `count`（整手，`qty = bundle_qty`） | `= qty` | `= ctx.user_id` | `= now()`（业务时区） |
| `count`（部分生产，`qty < bundle_qty`） | `= qty`（**小于 `bundle_qty`**） | `= ctx.user_id` | `= now()` |
| `reverse` | `= 0` | `= NULL` | `= NULL`（**该手回到未计件，可被他人重扫**） |
| `supplement` | `= 补录 qty` | `= 补录人` | `= now()` |

⚠️ **回写与流水插入必须同事务**：任一失败整事务回滚，**不允许"有流水但码未标记"或"码已标记但无流水"**（后者会导致这手永远扫不了，前者会导致重复计件）。DB `ck_bundles_cnt` 与 `ck_bundles_one` 兜底。
⚠️ **`bundles.bundle_qty` 本模块永不修改**（BR-PW-32）：改每手件数是打菲侧的权限，且已计件的码不可改（`31006`）。

| 非法动作 | 拒绝 | 错误码 |
| --- | --- | --- |
| 对 `payroll_id IS NOT NULL` 的流水红冲 / 对已红冲流水再红冲 | 拒绝 | `32003` |
| 未绑定工序或绑定非当天就计件 | 拒绝 | `32002` |
| **该款该工序当日无生效单价就计件** | 拒绝（提示"款号 X 工序 Y 未设单价"） | `20004` |
| **绑定该款号未配置的工序** | 拒绝 | `20001` |
| **★ 第二个员工扫已被他人计件的码** | 拒绝（提示"XL 第 2 手，陈美玲 09:44 已计 60 件"） | **`32001`** |
| **★ 计件数量超过该手件数（超产）** | 拒绝（提示"该手 60 件，请追加手"） | **`32006`** |
| **★ `qty` 非整数** | 拒绝（提示"本系统按整件计，尾数不计件（09 §4.2）"） | `32005` |
| 员工 token 调管理端计件路径 | 拒绝 | `12001` |
| 车间主管对越权车间流水红冲 | 拒绝 | `12002` |
| 红冲未填 `reason` / 补录未传 `remark` | 拒绝 | `10002` |

## 5. 核心流程

### 5.1 ★ 链路 A：PC 工位机 + 扫码枪（HID 键盘）—— **扫码得件数 + 部分生产**

```
前端（全局 keydown 捕获，不依赖输入框焦点）：扫码 → Enter → 本地校验 bundle_no 格式 → 提交
POST /api/v1/piecework/count
  Headers: Idempotency-Key = bundle_no + workstation_no + operation_no + 时间片
  Body:    { bundle_no, employee_id, scanned_at, station_id?, **qty?**(可选) }

service 事务（顺序不可调换）
 ① SELECT … FROM bundles WHERE bundle_no = :bn FOR UPDATE         ← ★ 锁码（一码一员工的串行化基础）
      └─ 不存在            → 31001
      └─ status = VOIDED   → 31002
      └─ counted_at 非空   → 32001（details.counted_by_name / counted_at / qty）
 ② 校验款号/工序匹配（bundles.style_no ↔ style_operations）→ 20001
 ③ 校验操作员当日绑定（piecework_bindings, work_date = 今天）→ 32002
 ④ 按 work_date 取价（operation_rates）→ 命中不到 20004
 ⑤ ★ 取件数（BR-PW-26/27/28）
      default_qty = bundle.bundle_qty            ← 扫码即知这手数量
      qty = 请求里的 qty（可选），默认 = default_qty
      校验 0 < qty ≤ bundle.bundle_qty
         qty >  bundle_qty → 32006（超产，须追加手）
         qty ≠ trunc(qty) → 32005（整件口径）
         qty <= 0         → 10001
      ⚠️ 严禁回落 DEFAULT 1（那等于"扫码 +1 件"的旧口径）
 ⑥ 金额 amount = qty × unit_price（Decimal）
 ⑦ 同员工同码同日同工序已有流水 → 幂等返回首次结果（idempotent=true），不重复计数
 ⑧ INSERT piecework_logs（bundle_id = bundle.id, qty, unit_price 快照, amount, log_type=SCAN）
 ⑨ UPDATE bundles SET counted_qty = :qty, counted_by = :uid, counted_at = now()
      （同事务；DB ck_bundles_cnt / ck_bundles_one 兜底）
 ⑩ 唯一索引冲突（并发重复）→ 回查既有流水 → 按幂等返回（同一员工）或 32001（他人）
 ⑪ 写 document_logs + 发 Redis Stream 事件 → SSE 广播 piecework_counted
```

### 5.2 链路 B：员工端 H5 扫码 + 绑定工序（重点链路）

1. 员工手机号 + 短信验证码登录 `/m/login`，token 有效期 2 小时（07 §1.2）。
2. 进入 `/m/bind`（06 §3.2）：优先 `html5-qrcode` 调起摄像头扫打菲二维码；**失败降级为手动输入 `bundle_no`（必须保留）**。
3. **员工扫打菲二维码（`bundle_no`）**：前端把 `bundle_no` 传给 `GET /api/v1/self/piecework-bindable-operations`（该接口支持 `bundle_no` 或 `style_no` **二选一**）。后端反查 `bundles`，带出 **`style_no` + `operation_no`（打菲单已定工序）** 与色组 / 尺码 / **手序号 / 该手件数**（用于界面展示，员工选工序时能看到"这手 60 件"）。
4. **前端调 `GET /api/v1/self/piecework-bindable-operations?style_no=`**：后端从 `style_operations` 列出该款号的全部工序，每行含 `operation_no`、`operation_name`、`sequence`、`bundle_qty`（⚠️ 这里的 `bundle_qty` 是"一扎几件"配置参考，**不是码的件数**，见 §12 Q-PW13）、`is_piecework`，按 `sequence` 升序。
5. **员工选择自己做的工序**（Vant 4 单选卡片）→ `POST /api/v1/self/piecework-bindings`，请求体只带 `bundle_no` + `operation_no`。
6. 绑定落库：唯一键命中重复 → **幂等返回既有绑定**；绑定**当天有效**，次日需重扫（BR-PW-04）。
7. 首页 `/m`：`GET /api/v1/self/piecework/today` 拿**大字卡（字号 ≥ 24px，`tabular-nums`）**；点「开始计件」扫下一手的码 → `POST /api/v1/self/piecework/count`（`employee_id` 从 token 取，前端不许传）。
8. 网络差时进本地队列（localStorage），携带 `device_id` + `scanned_at`；恢复后重传，服务端以 `scanned_at` 归属 `work_date`。金额显示到分（`¥268.50`），未审核部分标注"含未审核，以最终为准"（06 §3.2）。

**★「我今天做了多少手」的展示口径（BR-PW-31，ADR-0016 §6）**：

| 展示项 | 取值 | 说明 |
| --- | --- | --- |
| **主卡（头号大字）** | **今日手数 `today_hands`** | `COUNT(*) FROM piecework_logs WHERE employee_id = :uid AND work_date = :today AND log_type <> 'REVERSAL' AND deleted_at IS NULL`；**一码一手 = 一次计件 = 一手**，所以手数 = 计件流水条数 |
| 副指标 | 今日件数 `today_qty` | `SUM(qty)`；**手数与件数并列显示**（如「12 手 · 706 件」），因为部分生产会让两者不相等 |
| 金额 | `today_amount` | `SUM(amount)`；红冲为负自然抵减 |
| 明细行 | 每行「第 N 手 · N/M 件」 | `bundle_no` + `hands` / `bundle_qty` + `qty`；**部分生产行要能看出"只做了 28/60"** |
| 本月累计 | `month_hands` / `month_qty` / `month_amount` | 同样的三个口径 |
| ⚠️ 反例 | ❌ 只显示"今天做了 706 件" | 业务方的计量单位是**手**；只显示件数会让工人无法核对"我今天做了几手活"，也无法发现部分生产 |

**链路要点**：

| 要点 | 说明 |
| --- | --- |
| 工序列表自动来 | `style_operations` 是款号的工序模板，员工选的是"这套款里我做的第几道工序" |
| 不抄错工序号 | 工序号由配置统一维护，员工端只做选择，杜绝"03 敲成 04"这类脏数据 |
| 绑定只认配置 | 绑定接口校验 `operation_no` 必须在该款 `style_operations` 内且 `is_piecework=true`（BR-PW-25） |
| 跨款切换 | 扫新款号即换绑定，旧绑定不删，历史流水靠 `style_no` 区分 |
| **件来自码** | 员工**不需要数件数**；扫一下就是这手的件数（BR-PW-26），只有做少了才手写（BR-PW-27） |

### 5.3 流程 C：红冲 + 补录（INV-2 落地）

1. 发现错误（例：员工把 03 工序的码扫到 04 工序下；或**部分生产报多了数**要改成实际数）。
2. 计件流水列表筛选该 `bundle_no`，定位错误流水 `L1`。
3. `POST /api/v1/piecework-logs/{log_id}/reverse`，`reason` 必填 → 生成 `L2`（`log_type=REVERSAL`，`qty=-L1.qty`，`amount=-L1.amount`，`reversal_of_id=L1.id`）；**同事务清空 `bundles.counted_*`**（§4.3，该手回到未计件）。
4. `POST /api/v1/piecework-logs`（`log_type=SUPPLEMENT`）录入正确流水 `L3`，`reversal_of_id=L1.id`，单价按**补录当日**命中 `operation_rates` 取价快照；**`qty` 仍须 `≤ bundles.bundle_qty`（`32006`）**；同事务重写 `bundles.counted_*`。
5. 结算口径：净额 `L1 + L2 + L3`。
6. 全程无 `UPDATE`：审计可用 `SELECT * FROM piecework_logs WHERE bundle_no=… ORDER BY created_at` 完整复现。

**为什么禁止 UPDATE**：① 计件是"某人在某时做了某件"的客观事实；② 月底与工人对账要能展示完整轨迹；③ 流水只 INSERT，唯一索引即可保证幂等；④ 无 UPDATE 就没有"改 A 覆盖 B"的丢失更新。

### 5.4 流程 D：手工补录（MANUAL）

1. 计件员对漏扫码（纸单登记、员工离网）做补录。
2. `POST /api/v1/piecework-logs`，`log_type=MANUAL`，`remark` **必填**（写明"纸质单 X-12 补录"）。
3. 仍走完整校验链：码有效 + 绑定存在（或 `piecework:manual` 可越过当日绑定校验，见 Q-PW03）+ **他人未计该码（`32001`）** + 当日有生效单价（否则 `20004`） + **`qty` 必须是正整数**（`32005`）+ **`qty ≤ bundle_qty`**（`32006`）。⚠️ 返工件补录口径仍未确认（Q-PW03），`MANUAL` 补录**只允许用于漏扫码**，代码留 `TODO(业务待确认: Q-PW03)`。
4. 同事务回写 `bundles.counted_*`；单价按 `work_date` 取价快照；`document_logs` 记 `action='CREATE'` + `changed_fields` 标注 `log_type`。

### 5.5 流程 E：结算回写与单价变更

1. 05-工资 审核 `piecework_settlements` 时在同一事务内回写 `piecework_logs.payroll_id`；本模块**只提供** `payroll_id IS NULL` 的查询。
2. 05-工资 反审核时清空 `payroll_id`，流水重新可结算。
3. 单价变更影响面（INV-3 + BR-PW-22）：调价只影响 `work_date` 落在新区间的**未来**流水；已落库 `unit_price` **不变**；已结算工资 **不变**；历史纠正走红冲 + 补录。

### 5.6 流程 F：取价口径（ADR-0009，04 §7.8.3 唯一口径）

**取价 SQL**（与 [04 §7.8.3](../04-数据库规范.md) 逐字一致，`work_date` 取 `scanned_at` 的 `Asia/Shanghai` 日期）：

```sql
SELECT unit_price FROM operation_rates
WHERE style_no = :style_no AND operation_no = :operation_no
  AND effective_from <= :work_date::date
  AND (effective_to IS NULL OR effective_to > :work_date::date)
ORDER BY effective_from DESC
LIMIT 1;
```

**取价与落库规则**：

| # | 规则 | 强制手段 |
| --- | --- | --- |
| 1 | 取价只发生在**流水落库那一刻** | 单条 SQL + `LIMIT 1`；命中不到 → `20004` |
| 2 | 命中到的 `unit_price` **快照落库**，之后永不回读 | INV-3 |
| 3 | 区间半开：`effective_from <= work_date < effective_to` | 04 §7.8.3 |
| 4 | 区间不重叠，服务端校验 + 唯一索引双保险 | 调价在基础资料模块 |
| 5 | **未来生效价不参与当日取价** | SQL 的 `effective_from <= work_date` 天然满足 |
| 6 | 未设价**禁止兜底**：不许取 0、不许取最近一档价、不许取工序默认值 | BR-PW-23 |
| 7 | 单价只按工序定，**不分技能等级** | BR-PW-20 |
| 8 | 调价与计件并发时，以计件事务读到的区间为准 | §7.2 C5 |

**可解释性验收（ADR-0009）**：任取一条历史流水，用它的 `work_date` + `style_no` + `operation_no` 跑上面 SQL，**必须能查回同一个 `unit_price`**。

| GET | `/self/piecework/logs` | `self:piecework:read` | `SELF` | `work_date` 区间、`style_no`、`operation_no`、`log_type`、`page` | 分页流水（`bundle_no` 完整不截断；**含 `hands` / `bundle_qty` / `qty`**） | `10001` |
| GET | `/self/payroll/sheets` | `self:payroll:read` | `SELF` | `period` | 已审核结算的 `period` 列表 | `11001` |
| GET | `/self/payroll/current` | `self:payroll:read` | `SELF` | `period` 可选 | `period`、`is_approved`、`rows[]`（工序/**手数**/件数/单价/金额）、`total_hands`、`total_qty`、`total_gross`、`deductions`、`net_pay`、`estimate_flag` | `11001` |

**员工端与 PC 端接口的关系**：员工端**不复用** `/piecework/count`（07 §1.2 员工自助范围只能访问 `/self/**`）；服务端两个路径调用同一个 `PieceworkService.count_piecework`，保证规则完全一致（含锁码、默认整手、部分生产、超产拒绝、一码一员工）。

### 6.3 幂等要求（★ REV-2026-10 第四批：语义收窄）

| 接口 | 幂等键 | 命中行为 |
| --- | --- | --- |
| `POST /piecework/count` | 显式 `Idempotency-Key`（`bundle_no + workstation_no + operation_no + 时间片`）；未传时服务端按 `(bundle_no, operation_no, employee_id, work_date, SCAN)` 推导 | **① 同员工同键重试** → 返回首次结果 + HTTP 200 + `code=0` + `idempotent=true`；**② 同员工不同键同码** → 同样返回首次结果（不重复计数）；**③ 另一个员工扫同码** → **`32001` 业务冲突 + `details.counted_by_name` / `counted_at`**，❌ **不再静默幂等** |
| `POST /self/piecework/count` | 同上，`station` 用 `device_id` | 同上 |
| `POST /piecework-logs`（MANUAL/SUPPLEMENT） | `Idempotency-Key`（前端生成 UUID） | 同上；Redis TTL 24h + 唯一索引双保险（05 §5） |
| `POST /piecework-logs/{id}/reverse` | 天然幂等：同 `reversal_of_id` 已有 `REVERSAL` → 返回既有红冲流水 | HTTP 200 |
| `POST /self/piecework-bindings` | 业务唯一键 `(user_id, style_no, operation_no, work_date)` | 返回既有绑定 |

**同键不同 body** → `10002`（05 §5）。工位机时钟不准导致时间片不同时，依赖 `bundles.counted_at` + 数据库唯一索引兜底，**不依赖 Redis**。

> ⚠️ **与 05 §5 / 07 §7 的口径差异（需规范维护者回写）**：
> 05 §5「重复提交返回上次结果而不是报错」与 07 §7「重试携带同 `bundle_no`，服务端幂等返回既有记录」**成立**，本文未推翻（BR-PW-16 ①）。
> 但 09 §2.4「扫码结果提交到工位计件接口，必须带幂等键（`bundle_no + station + operation + 时间片`），重复提交返回上次结果而不是报错」**若被理解为"任何重复提交都幂等"，则与 ADR-0016 的"一码一次 + 第二人报 `32001`"冲突**。本文口径：**同一幂等键的重试幂等；不同员工的重复提交一律 `32001`**。

## 7. 并发与幂等

### 7.1 四类强制并发场景（对应 [10 §5.1](../10-测试规范.md)；REV-2026-10 第四批按 ADR-0016 重写 C3）

| # | 场景 | 期望 | 兜底手段 |
| --- | --- | --- | --- |
| C1 | **同码同员工 20 并发** | 只落 **1 条**流水；返回的 `log_id` 全部相同；其余按幂等 200 + `idempotent=true`；`bundles.counted_qty` 只被写一次 | `uq_piecework_logs_idem` + `UniqueViolation` → 回查转幂等；**`bundles` 行锁串行化** |
| C2 | **同码不同工序并发** | ADR-0016 后**同一 `bundle_no` 只属于一个工序**（码与工序强绑定）→ 该场景实际不会发生；**若历史数据存在同码跨工序**，仍按旧口径：各落 1 条 | 唯一键含 `operation_no` |
| **C3** | **★ 同码不同员工并发（ADR-0016：一人一扫）** | **先到者成功**，后到者得 **`32001`** + `details.counted_by_name` / `counted_at`；**不产生负数或重复流水**；`bundles.counted_qty` 只被写一次 | **① 事务开始 `SELECT … FROM bundles WHERE bundle_no = :bn FOR UPDATE` 锁码行；② 锁内判 `counted_at IS NULL`，非空抛 `32001`；③ 插入流水 + 回写 `counted_*`。**唯一索引挡不住 C3**（`employee_id` 是唯一键组成部分，两人各自都能插入）→ **必须靠 `FOR UPDATE` 锁码**，只靠业务层检查 = 10 §5.4 判**未通过** |
| C4 | **离线重传并发**（客户端缓存 20 条一次性补传） | 逐条按 `bundle_no` 幂等；已存在的返回 `idempotent=true`；`work_date` 以 `scanned_at` 为准 | 唯一索引 + 事务内逐条处理；批量上限 500 行/请求（05 §2） |

**★ C3 的实现要点（最容易写错）**：`uq_piecework_logs_idem` 含 `employee_id`，两名员工扫同码**不会撞唯一键**。必须 ① `SELECT … FOR UPDATE` 锁 `bundles` 行；② 锁内查 `bundles.counted_at`，非空即抛 `32001`（带原员工姓名与时间）；③ 再插入 + 回写。`FOR UPDATE` 是数据库级串行化，测试必须真并发（每任务独立 session）。

**★ 部分生产与他人同时扫（ADR-0016 风险 ③ 的并发版）**：

| 场景 | 期望 | 兜底 |
| --- | --- | --- |
| A 手写 `qty = 28` 提交（部分生产），B 同时扫同一码 | **只有一个成功**。若 A 先：B 得 `32001`（提示"A 09:44 已计 28/60 件"）；若 B 先（整手 60 件）：A 的请求因 `counted_at` 非空得 `32001` | 同一把 `bundles` 行锁（`FOR UPDATE`），天然串行 |
| A 手写 `qty = 28`，B 想手写 `qty = 60` | 同上，**不允许"两个部分生产叠加成 60"** —— `counted_qty` 只被写一次（BR-PW-27）；叠加需走红冲 + 补录 | `ck_bundles_cnt (counted_qty ≤ bundle_qty)` + 锁 |
| A 扫码的同时打菲侧改 `hands` | 计件侧只写 `counted_*`，**永不写 `bundles.bundle_qty`**（BR-PW-32）；打菲侧改 `hands` 前先 `FOR UPDATE` 锁码并判 `counted_at`（已计件 → `31006`） | 同一把 `bundles` 行锁 |

### 7.2 C5：调价与计件并发（ADR-0009）

| # | 场景 | 期望 | 兜底手段 |
| --- | --- | --- | --- |
| C5 | **调价事务与计件并发**：基础资料模块正在关旧区间 + 开新区间，同时本模块 20 条扫码计件 | ① 每条流水的 `unit_price` 必等于"该 `work_date` 命中的一档价"；② 已落库流水金额**永不因调价改变**；③ 不会出现"半条金额" | 调价只写 `operation_rates`，计件只写 `piecework_logs` + `bundles`，**无写冲突**；取价为单条 `SELECT … LIMIT 1` |

> C5 的断言口径：结果金额集合只可能是「全部旧价」或「新旧混合」，**且每条都能用它自己的 `work_date` 反查回同一 `unit_price`**（§5.6）。禁止为了让并发测试通过而给流水加锁等待调价。

### 7.3 其他并发风险

| 风险 | 方案 |
| --- | --- |
| 同一员工同时在工位机与手机计件 | 同一业务唯一键 + 同一 `bundles` 行锁 → 幂等返回首次结果，不重复计数 |
| 红冲与结算审核同时发生 | 结算侧 `SELECT … FOR UPDATE` 锁结算单；红冲侧校验 `payroll_id IS NULL`，竞争由行锁 + `32003` 收敛 |
| **红冲与他人扫同一码并发** | 红冲也要 `FOR UPDATE` 锁 `bundles` 行：若红冲先提交（`counted_*` 清空），他人扫**可成功**计这手；若他人先提交，红冲校验"该码 `counted_qty` 是否等于本流水 `qty`"，不等则拒绝并提示先红冲对应流水 |
| `work_date` 跨天（23:59 扫码、00:01 落库） | `work_date` 取 `scanned_at` 的业务时区日期，**不取 `now()`** |
| 员工重复绑定同工序 | `uq_piecework_bindings_user_style_op_date` 兜底 → 幂等返回既有绑定 |
| 员工端并发拉可绑定工序 + 主管改款号工序配置 | 可绑定工序列表只读 `style_operations`，读到的是**同一请求内的一致快照**；工序被停用后新绑定被拒（`20001`），已绑定不受影响 |
| 前端连点 / 扫码枪抖动 | `Idempotency-Key` + 前端提交期间禁用按钮（06 §2.4） |
| SSE 连接数过多 | 车间看板用 1 条连接聚合多工位；员工端只在首页打开时连接 |

## 9. 错误码

| 码 | HTTP | 含义 | 本模块触发场景 | 客户端处理 |
| --- | --- | --- | --- | --- |
| `32005` | 422 | 数量必须为整件（尾数不计件、不入库，见 09 §4.2） | **`qty` 非正整数**（如 `0.5`、`1.2`）——错误信息写「**本系统按整件计，尾数不计件（09 §4.2）**」（BR-PW-19、BR-PW-27） | 提示改输入 |
| `10001` | 422 | 参数校验失败 | `bundle_no` 长度/格式不合、缺必填字段、`qty <= 0` | 提示改输入 |
| `10002` | 400 | 缺少必填业务参数 | 红冲未填 `reason`；手工补录未填 `remark`；同幂等键不同 body | 弹必填提示 |
| `10003` | 409 | 乐观锁冲突 | 解绑/红冲时 `version` 不符 | 刷新后重试 |
| `10004` | 429 | 请求过于频繁 | 同一工位 1 秒内 > 30 次扫码 | 退避重试 |
| `11001` | 401 | 未登录或 token 过期 | 员工端 token 过期（2h） | 跳 `/m/login` |
| `12001` | 403 | 无操作权限 | 员工 token 调 `/piecework/count`；仓管调计件 | 隐藏入口 |
| `12002` | 403 | 无数据权限 | 主管按 ID 查他车间流水 | 提示无权访问 |
| `20001` | 404 | 基础资料不存在 | 款号/工序不存在或已停用；绑定了该款号 `style_operations` 里没有的工序 | 找基础资料配工序 |
| `20004` | 404 | 该款号该工序未设置单价（或当日无生效单价） | 按 `work_date` 查 `operation_rates` 命中不到任何生效区间 | `details` 回传 `style_no` + `operation_no`；**不允许前端兜底取 0 或旧价** |
| `31001` | 404 | 打菲号不存在 | 扫到库中无此 `bundle_no` | 重新扫码（红字 + 短音） |
| `31002` | 409 | 该打菲号已作废 | `bundles.status='VOIDED'` | 重新扫码，提示"该码已作废" |
| **`32001`** | 409 | **计件流水冲突：同一打菲号本工序已被他人计件（ADR-0016：一码一员工）** | **★ 主触发点**：`bundles.counted_at IS NOT NULL` 且 `counted_by ≠ 当前员工` → 第二人扫同码。**⚠️ 语义已从"仅作只读查重引用"改为正式业务错误**（ADR-0016 显式指定）；**同一员工重试仍走幂等 200，不返回 32001**（BR-PW-16/24） | `details` 回传 **`counted_by_name` + `counted_at` + `counted_qty` + `bundle_qty` + `hands`**；界面提示「XL 第 2 手，陈美玲 09:44 已计 60 件」，**不弹窗打断**（06 §2.5 第 3 条） |
| `32002` | 403 | 该员工未绑定此工序 | 首次扫该款号该工序；或绑定是昨天的 | 引导去 `/m/bind` 重新绑定 |
| `32003` | 409 | 计件已结算，不可修改 | 红冲 `payroll_id IS NOT NULL` 的流水；对已红冲流水再红冲 | 提示"已结算，请联系计件员" |
| **`32004`** | 409 | 同一打菲号同一工序不能由多人重复计件 | ⏳ **本轮不使用**（语义与 `32001` 重叠，ADR-0016 指定用 `32001`）；**待架构在 05 §4 定论是否废弃**（§12 Q-PW13） | 暂不返回 |
| **`32006`** | 409 | **计件数量超过该手件数（超产，ADR-0016）** | **★ `qty > bundles.bundle_qty`**（BR-PW-28）。`details` 回 `bundle_qty` + `counted_qty` | 提示「该手只有 60 件」；**超产需追加手**（新裁剪 + 新打菲），**不允许改数绕过** |
| `99999` | 500 | 服务器内部错误 | 未预期异常 | 上报 `request_id` |

> ✅ 已闭环：`32001` 语义在 [05 §4](../05-接口设计规范.md) 为「计件流水冲突：同一打菲号本工序已被他人计件」。**REV-2026-10 第四批起，`32001` 成为"第二人扫同码"的正式错误码**（ADR-0016 显式指定），`details` 必须带原计件人与时间。**幂等命中（同员工重试）永不返回 `32001`**，响应体给 `idempotent=true`（BR-PW-16 ①）。
> ✅ 已闭环：`20004`（未设单价）从 `20001` 拆出。
> ⚠️ **`32004` 暂挂**：05 §4 同时登记了 `32004` =「同一打菲号同一工序不能由多人重复计件」，与 `32001` **几乎同义**。本模块按 ADR-0016 统一用 `32001`，**`32004` 不再使用也不删除**，见 §12 Q-PW13。

- 权限点来源：`piecework:read` `piecework:count` `piecework:manual` `piecework:reverse` `piecework:rate:manage`（07 §2.2 计件行）；员工端固定集合 `self:profile:read` `self:piecework:read` `self:piecework:bind` `self:payroll:read`（07 §2.2 员工自助行）。**本表不引用未登记的权限点**。
- **★ 本轮新增响应字段（`bundle_qty` / `hands` / `hands_seq` / `color_name` / `size_name` / `today_hands`）不需要新权限点** —— 它们只是既有 `count` / `read` 接口的出参扩展。
- `GET /api/v1/self/piecework-bindable-operations` 用 `self:piecework:read`——它是"看数"不是写入。
- 工序与单价的**写权限全在基础资料模块**，本模块只读；本模块**不因取价而需要任何额外权限**。
- 双校验：每个接口 `require_permission(权限点, scope="piecework_logs")` + `apply_data_scope`（INV-8）；详情与红冲必须 `in_scope()` 二次校验，越权 `12002`。
- 导出一致性：`/piecework-logs/export` 与列表**共用同一 service 方法**（07 §3.2 铁律 3）。
- 不自审：计件无审核动作；红冲人不得是原流水创建人（`super_admin` 例外需 `force=true` 并写日志，08 §4）。
- 员工端隔离：员工 token 命中 `/api/v1/self/**` 之外的所有路由 → `12001`（路由分组中间件强制）。
- 前端：`v-can="'piecework:count'"` 控制显隐，`:disabled="!auth.has(...)"` 控制禁用 + Tooltip；员工端无 `v-can`。
