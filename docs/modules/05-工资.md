# 05 工资（计件结算与发放）

> 计件流水是事实，工资是结论：**结算周期是用户自建的起止日期区间**（`payroll_periods`，见 [ADR-0010](../adr/0010-工资结算周期自定义.md)），本模块按「周期区间 + 车间」把未结算流水汇成结算单，结算单汇总成工资单，工资单审核计提、发放付款，全程单价与金额快照，**已发放只能红冲不能反审核**。

## 1. 模块职责与边界

### 1.1 职责

① **工资结算周期** `payroll_periods`（REV-2026-10 新增，见 [ADR-0010](../adr/0010-工资结算周期自定义.md) / [04 §7.4](../04-数据库规范.md)）：用户自建的**起止日期区间**，标签 `period_code` 自由、唯一性靠 `UNIQUE (start_date, end_date)`；② **计件结算单** `piecework_settlements`：按 `period_id` + 车间汇总**未结算**流水，快照单价与金额，审核后回写流水 `payroll_id`；③ **工资单** `payroll_sheets` / `payroll_details`：每人每工序一行（`qty` / `unit_price` / `gross_amount` / 扣款 / `net_pay`）；④ **计提与发放凭证**（08 §2.4 口径）；⑤ **工资条与银行代发文件** CSV 导出（UTF-8 BOM）；⑥ **三方对账**：流水 → 结算单 → 工资单 数量金额逐层一致；⑦ **实时提示**：结算/发放后 SSE 推 `payroll_settled`。

### 1.2 边界

| 不属于本模块 | 归属 | 理由 |
| --- | --- | --- |
| 计件流水采集、红冲补录、单价快照 | [04-计件](./04-计件.md) | 本模块只读 `piecework_logs`（`payroll_id IS NULL`） |
| 会计科目体系、凭证模板、科目余额 | M9 财务凭证 | 本模块只按模板生成凭证，不建科目 |
| 银行网银对接、代发回盘 | 本期不做 | 只出文件给银行 U 盾 / 网银（00 §3.2） |
| 银行代扣（水电、罚款、社保） | 待决 | 见 §12 Q-PL01，口径未定前只留字段不实现 |
| 员工银行卡资料维护、工资条打印排版 | M1 基础资料 / 打印模块 | 导出时读 `users` 银行字段；阶段一走 CSV 导出 |

## 2. 业务规则

| # | 规则 | 详细口径 | 强制手段 |
| --- | --- | --- | --- |
| BR-PR-01 | 结算粒度 | 一张结算单 = 一个**周期区间** `period_id` × 一个 `workshop_id`（组别降为**行级**维度，见 §3.3 `group_no` 与 §12 Q-PL08） | `uq_piecework_settlements_period_workshop` |
| BR-PR-02 | 结算只取未结算流水 | 汇总条件 `payroll_id IS NULL AND deleted_at IS NULL` + `work_date BETWEEN :start_date AND :end_date` + `workshop_id` | 部分索引 `idx_piecework_logs_unsettled` + `idx_piecework_logs_work_date_workshop_id_style_no` |
| BR-PR-03 | 单价快照 | 结算单行与工资单行都存 `unit_price`，审核后不可改（INV-3 延伸） | 审核后所有字段 `disabled`（06 §2.4） |
| BR-PR-04 | 审核即占用 | 审核结算单 = 回写每条流水的 `payroll_id` + 标记已结算，同一事务 | 08 §1.2 R4 |
| BR-PR-05 | 工资单粒度 | 每人每（款号 × 工序）一行：件数 `qty`、工价 `unit_price`、`gross_amount` | `uq_payroll_details_sheet_employee_operation_style` |
| BR-PR-06 | 实发口径 | `net_pay = gross_amount - total_deduction`，`total_deduction = Σ(deduction_amount)` | service 计算 + 测试断言 |
| BR-PR-07 | 审核生计提凭证 | 借：应付职工薪酬（负债增加）/ 贷：制造费用-计件（成本增加） | 08 §2.4；INV-5 借贷平衡 |
| BR-PR-08 | 发放生付款凭证 | 借：应付职工薪酬 / 贷：银行存款；并生成代发文件、记 `paid_at` | 08 §2.4 |
| BR-PR-09 | 已发放不可反审核 | `status = PAID` 时 `reverse` 直接拒绝 | `33001`，只能走红字冲销 |
| BR-PR-10 | 不自审 | `created_by == operator` → 拒绝（`super_admin` 需 `force=true` 并写日志） | 08 §4 / 07 §3.3 |
| BR-PR-11 | 反审核必填原因 | `reverse` / `reject` / `cancel` 均需 `reason` | 08 §1.1 |
| BR-PR-12 | 工资保密 | 员工只见自己；主管看本车间需 `payroll:read`；导出需 `payroll:export` | 07 §5 |
| BR-PR-13 | 结算后计件锁定 | 结算单 APPROVED 后对应流水红冲被拒 | `32003`（04-计件 BR-PW-10） |
| BR-PR-14 | 结算期间不重复 | 同一 `period_id` + `workshop_id` 并发结算只允许一张 | 唯一索引 + `33002` |
| BR-PR-15 | 软删 + 禁 float | 单据与行表只软删，`document_logs` 不可删（REVOKE）；金额全 `numeric(18,4)` + `Decimal`，单价 `numeric(12,6)` | INV-7 / 04 §4/§7.4 / 03 §1.1 |
| **BR-PR-16** | **周期是用户自建日期区间** | `payroll_periods` 存 `start_date` / `end_date`（**均含**）+ `period_code` 标签。标签随便写（`'2026-08'` / `'7-8月'` / `'夏季款'`），**唯一性由 `UNIQUE (start_date, end_date)` 保证**，不由标签保证 | 04 §7.4 两个唯一约束（`uq_payroll_periods_code` / `uq_payroll_periods_range`）+ ADR-0010 §2 |
| **BR-PR-17** | **四种建周期方式** | ① 自定义区间 ② 一键「生成整月」 ③ 一键「生成两月」 ④ **按裁剪打菲完成日自动截取**（`source='CUTTING_BOUNDARY'`，取该款裁剪单最早完成日 ~ 最晚打菲完成日，标签自动填 `裁剪{起}-{止}`） | `source` 字段 + `POST /payroll-periods/generate` 的 `mode=month\|bimonth\|cutting_boundary` |
| **BR-PR-18** | **建周期必须核对取数口径** | 建周期与生成周期接口都要返回「区间内**未结算流水条数与金额合计**」，前端必须展示给用户核对。防止边界设错（如漏 8 月最后 3 天）导致漏算 | `generate` 接口响应含 `unsettled_log_count` / `unsettled_amount`；UI 必显（06 §2） |
| **BR-PR-19** | **周期关闭后冻结** | 周期 `status='CLOSED'` 后**不可**往里加结算单（`33003`）；`reopen` 需 `payroll:period:manage` + **必填原因**（`10006`）+ 写 `document_logs`；区间与既有周期重叠 → `33004` | §4.3 周期状态机 + 05 §4 错误码 + 07 §2.2 权限点 |
| **BR-PR-20** | **取数口径唯一** | 按周期区间 + 车间 + `payroll_id IS NULL` 取未结算流水（SQL 见 §3.1.1）；**禁止**按标签解析、按月份硬编码（`'2026-07~08'` 这类标签一律不入 SQL 条件） | 04 §7.4 规则 + §8 S2 索引 |
| **BR-PR-21** | **周期不可删，只可停用/关闭** | 周期一旦被结算单引用禁止删除；`end_date < start_date` 被 `CHECK` 拒绝；`period_code` 重复被 `uq_payroll_periods_code` 拒绝 | 04 §7.4 `ck_payroll_periods_range` / INV-7 |
| **BR-PR-22** | **整件计件口径（REV-2026-10：尾单不入库）** | 09 §4.2：尾数 `balance_qty`（裁剪产出**不足一件**的余量）**不生成打菲码、不计件、不入库**，已随裁剪损耗 `cut_waste_qty` 摊入成本。因此计件流水 `piecework_logs.qty` **只允许正整数件**（DB `ck_piecework_logs_whole CHECK (qty = trunc(qty))` + `ck_piecework_logs_sign`），本模块汇总（§2.1 `SUM(qty)`）**天然不含尾数**，**不需要任何额外过滤或尾数剔除逻辑** | 04 §7.1 两个 `CHECK` + 09 §4.2；本模块无尾数写路径 |

### 2.1 结算取数 SQL（唯一口径，04 §7.4 + ADR-0010 §5）

```sql
SELECT employee_id, group_no, style_no, operation_no,
       SUM(qty) AS qty, SUM(amount) AS amount, COUNT(*) AS log_count
FROM piecework_logs
WHERE work_date BETWEEN :start_date AND :end_date   -- 区间首尾日都含
  AND workshop_id = :workshop_id
  AND payroll_id IS NULL                              -- 只算未结算的（INV-2：不重复结算）
  AND deleted_at IS NULL
GROUP BY employee_id, group_no, style_no, operation_no;
```

- 区间从 `payroll_periods` 读，**不从请求参数收日期**（防止前端传错区间绕过周期校验）；`period_start_date` / `period_end_date` 只是冗余快照列，用于列表展示与反查流水。
- 结算单审核后回写 `piecework_logs.payroll_id`，`WHERE payroll_id IS NULL` 是条件 UPDATE 的必要部分（P3 兜底）。
- **整件口径（BR-PR-22）**：SQL 的输入 `qty` 已被 DB 约束限制为整数件，故 `SUM(qty)` 结果必为整数；红冲行取负后仍是整数。**不存在「尾数需要 round 掉」的场景**，SQL 里**禁止**出现 `trunc(qty)` / `ceil(qty)` / `CASE WHEN qty <> trunc(qty)` 这类尾数处理。

## 3. 数据模型

### 3.1 `payroll_periods`（工资结算周期，REV-2026-10 新增，照抄 [04 §7.4](../04-数据库规范.md)）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `period_code` | `varchar(32)` | 是 | **唯一** `uq_payroll_periods_code` | 用户自定义标签，**随便写**：`'2026-08'` / `'2026-07~08'` / `'8月全月'` / `'裁剪0820-0905'`。标签只给人看，SQL 取数不解析标签（BR-PR-20） |
| `start_date` / `end_date` | `date` | 是 | **联合唯一** `uq_payroll_periods_range` | 起始日 / 截止日，**均含**（`BETWEEN` 闭区间）。唯一性靠区间而非标签 |
| `status` | `payroll_period_status` | 是 | 否 | `OPEN` / `CLOSED`（04 §7.4）。`CLOSED` 后不可加结算单（`33003`） |
| `source` | `varchar(16)` | 是 | 否 | `MANUAL`（自定义/整月/两月）/ `CUTTING_BOUNDARY`（按裁剪打菲完成日自动截取，BR-PR-17） |
| `closed_by` / `closed_at` / `close_reason` | `uuid` / `timestamptz` / `text` | 否 | 否 | 关闭人与时刻；`close_reason` 关闭时必填、重开时必填（`10006`）。重开后 `status='OPEN'`、保留 `closed_*` 作为上次关闭痕迹，另由 `document_logs` 记重开 |
| `id` + 公共字段 | 见 04 §2 | 是 | — | `uuid` PK + 审计/软删/乐观锁/`remark`（周期表也必须有 `version`，重开走条件 UPDATE） |
| 约束 | — | — | — | `CONSTRAINT uq_payroll_periods_code UNIQUE (period_code)`；`CONSTRAINT uq_payroll_periods_range UNIQUE (start_date, end_date)`；`CONSTRAINT ck_payroll_periods_range CHECK (end_date >= start_date)` |

> 周期**不带 `workshop_id`**：周期是全厂口径，车间只是结算维度（ADR-0010 备选方案表第 4 行）。同一区间跨车间共用一个周期，结算单仍按「周期 + 车间」唯一。
> 周期不是单据（无 `doc_no` / `doc_date`），但有**极简状态机**（§4.3），迁移同样走 service 方法 + `document_logs`（08 R1/R2/R3）。

### 3.1.1 取数与索引口径

- 周期取数 SQL 见 §2.1；`piecework_logs` 侧索引 `idx_piecework_logs_work_date_workshop_id_style_no` 支撑（§8 S2）。
- `piecework_settlements.period_id` 外键引用 `payroll_periods(id)`，**不再用字符串存周期**（04 §7.4 规则末条）。
- 周期区间重叠：库层面只保证 `(start_date, end_date)` 不完全相同；**部分重叠**由 service 校验并报 `33004`（04 未采用 PG `daterange` 排除约束，见 ADR-0010 备选方案表第 5 行）。

| 公共字段 | 见 04 §2 | 是 | — | — |
| 约束 | — | — | — | `CONSTRAINT uq_payroll_details_sheet_employee_operation_style UNIQUE (doc_id, employee_id, style_no, operation_no)`；`CHECK (net_amount = gross_amount - deduction_amount)` |

### 3.6 `bank_payment_files`（代发文件记录）

`payroll_sheet_id`（**唯一**，一工资单一次导出，重复导出幂等返回）、`file_name`、`row_count`、`total_amount`、`content_hash`（SHA-256 防篡改）、`exported_by` / `exported_at`（07 §5 敏感操作必记）+ 04 §2 公共字段。

### 3.7 实体关系

`payroll_periods`（`UNIQUE(start_date, end_date)`）1:N → `piecework_settlements`（`period_id + workshop_id` 唯一）1:N → `piecework_settlement_lines` N:1 ← `piecework_logs`（`payroll_id IS NULL`）；`piecework_settlements` 1:1 → `payroll_sheets` 1:N → `payroll_details`，工资单 1:1 → `bank_payment_files`；工资单 → 凭证（`accrual_voucher_no` / `payment_voucher_no`，`VO-` 单号，跨模块逻辑引用）。

| 关系 | 基数 | 外键约束 | 说明 |
| --- | --- | --- | --- |
| `piecework_settlement_lines.piecework_log_id` → `piecework_logs.id` | N:1 | 必建 + **唯一索引** | 唯一性是"不重复计入"的最后一道兜底（P3） |
| `piecework_settlements.period_id` → `payroll_periods.id` | N:1 | 必建 FK + 索引 | REV-2026-10：周期由字符串改外键（BR-PR-16） |
| `payroll_periods` 两个唯一约束 | — | 唯一索引 | `uq_payroll_periods_code`（标签）+ `uq_payroll_periods_range`（区间） |
| `piecework_settlements` 周期+车间 | — | 唯一索引 | BR-PR-01 / BR-PR-14；组别为行级维度（Q-PL08） |
| `payroll_sheets.settlement_id` → `piecework_settlements.id` | 1:1 | 必建 + 唯一 | 阶段一一对应；多结算单合并见 Q-PL06 |
| `payroll_details.doc_id` → `payroll_sheets.id` | N:1 | 必建 | 04 §7.3 行表约定 |
| 工资单 → 凭证 | 逻辑引用 | 不建 FK | 凭证可被红冲，FK 会阻止；靠凭证号字段 + 同事务保证一致性 |

### 4.3 结算周期状态机（REV-2026-10 新增，极简，**不走 `DocumentStatus`**）

周期不是单据，用独立枚举 `payroll_period_status`（04 §7.4）：`OPEN` / `CLOSED`。
动作名沿用 [08 §1](../08-单据状态机规范.md)「会计期间动作」`open` / `close` / `reopen`（08 §1.1 通用动作表不覆盖非单据实体）。

```
[OPEN] ──── close（payroll:period:manage）────▶ [CLOSED]
[CLOSED] ─── reopen（payroll:period:manage，必填原因）────▶ [OPEN]
```

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `open`（新建时即 `OPEN`，本动作仅用于新建后显式置开） | — | OPEN | `payroll:period:manage` | 周期存在且未被删除 | 写 `document_logs`（`doc_type='PayrollPeriod'`, `action='OPEN'`） |
| `close` | OPEN | CLOSED | `payroll:period:manage` | **必填原因**（`10006`）；区间内无 `DRAFT` / `SUBMITTED` 的结算单（有则提示先处理） | 置 `closed_by` / `closed_at` / `close_reason`；此后加单报 `33003` |
| `reopen` | CLOSED | OPEN | **`payroll:period:manage`**（REV-2026-10，`payroll:reverse` 不再用于周期重开） | **必填原因**（`10006`） | 置 `status='OPEN'`；写 `document_logs`（`from_status='CLOSED'` / `to_status='OPEN'` / `reason`）；**已结算工资数据不变**（结算单是快照） |

- 周期迁移同样遵守 08 §1.2 铁律：唯一入口 `service.payroll_period.<action>()`、写 `document_logs`、`WHERE id=? AND version=? AND status=?` 条件 UPDATE、`rowcount=0` 报 `10003`。
- 周期**没有** `delete` 动作；被结算单引用后永久保留（INV-7）。

### 4.4 非法动作与反向对称（08 §3.3）

审核/反审核副作用必须成对：结算审核 ↔ 释放 `payroll_id`；工资审核 ↔ 红冲计提凭证；发放 ↔ **禁止反审核**（`33001`），只走红字冲销；`CANCELLED` 终态不可再迁移（08 R6）。

| 非法动作 | 错误码 |
| --- | --- |
| 对 `PAID` 工资单 `reverse`；结算反审核时下游工资已 `APPROVED`/`PAID` | `33001` |
| 同一「周期 + 车间」重复结算；`create` 时仍有未结算流水 | `33002` |
| 对已结算流水红冲（`payroll_id IS NOT NULL`） | `32003` |
| 制单人自审（08 §4；错误码见 05 §4） | `10005` |
| 向 `CLOSED` 周期加结算单（`create` / `submit` / 工资单 `create`） | `33003` |
| 新建周期区间与既有周期重叠（含部分重叠）；`period_code` 重复 | `33004` |
| 无 `payroll:period:manage` 调周期 `close` / `reopen` | `12001` |
| 缺银行资料就发放；`reverse/reject/cancel/close/reopen` 未填原因；乐观锁不匹配；终态后再迁移 | `10002` / `10003` |

## 5. 核心流程

### 5.1 结算周期（PP）创建与关闭（REV-2026-10 新增）

1. **建周期**：计件员点「自定义」/「生成整月」/「生成两月」/「按裁剪打菲截取」→ `POST /payroll-periods/generate`（`payroll:period:manage`）→ 服务端算区间并返回**区间内未结算流水条数与金额合计**（`unsettled_log_count` / `unsettled_amount`，BR-PR-18）→ 前端展示给用户核对 → 用户确认后 `POST /payroll-periods` 落库。
   - `mode=month`：入参 `anchor_month=2026-08` → `2026-08-01 ~ 2026-08-31`，标签 `2026-08`。
   - `mode=bimonth`：入参 `anchor_month=2026-07` → `2026-07-01 ~ 2026-08-31`，标签 `2026-07~08`。
   - `mode=cutting_boundary`：入参 `style_no` → 取该款裁剪单最早完成日 ~ 打菲单最晚完成日，标签 `裁剪{起}-{止}`，`source='CUTTING_BOUNDARY'`。
   - 区间与既有周期重叠 → `33004`；`(start_date,end_date)` 完全重复 → `uq_payroll_periods_range` 兜底（§7 P6）。
2. **核对**：结算完成后对账「周期内未结算流水条数 = 0」（ADR-0010 验证方式），非 0 说明区间设漏。
3. **关闭**：区间结算完 → `POST /payroll-periods/{id}/close`（`payroll:period:manage` + 必填原因）→ 此后加单报 `33003`。
4. **重开**：发现边界设错 → `POST /payroll-periods/{id}/reopen`（`payroll:period:manage` + 必填原因）→ 写 `document_logs`；**已结算的结算单不受影响**（快照）。

### 5.2 结算（PW）

1. 计件员选 `period_id`（周期）+ 车间 → `POST /payroll/settlements`（`payroll:settle`）。周期 `CLOSED` 直接 `33003`。
2. service 事务内：校验周期 `OPEN` + 查「周期 + 车间」是否已有单据（防重复）→ **按周期区间取未结算流水**（§2.1 SQL：`work_date BETWEEN start_date AND end_date AND workshop_id=? AND payroll_id IS NULL`，走 `idx_piecework_logs_work_date_workshop_id_style_no` + `idx_piecework_logs_unsettled`）→ 汇总件数金额 → 写单头 + 行（每条流水一行，含行级 `group_no`，快照 `unit_price`）；单号 `PW-20260831-000005` 由数据库序列生成。
3. `submit` → 主管 `approve`（制单人 ≠ 审核人）→ **同一事务内**回写每条流水的 `payroll_id`；反审核则同事务清空 `payroll_id`，流水立即可重新结算（对账视图必须回零）。

### 5.3 生成工资单（PR）

1. `POST /payroll/sheets`，传 `settlement_id`（`status` 必须 `APPROVED`）。
2. 按 `(employee_id, style_no, operation_no)` 分组汇总结算行（`qty = Σqty`，`unit_price` 取结算行明细值，**不重读基础资料**），写 `payroll_details` 并从 `users` 快照银行与身份证字段。
3. `submit` → 主管/厂长 `approve` → 生成计提凭证。

### 5.4 计提（08 §2.4）

`approve` 同一事务内调用财务模块凭证引擎：`借 应付职工薪酬 = total_gross` / `贷 制造费用-计件 = total_gross`；借贷必须相等，否则 `60001`（DB 约束 + service 双检，INV-5）；回写 `accrual_voucher_no` 并写 `document_logs`（`action='APPROVE'`，含金额与凭证号）。

### 5.5 发放（08 §2.4 `pay`）

1. 前置：所有 `payroll_details` 的 `bank_account` 非空，否则 `10002`。
2. 生成代发文件 `bank_payment_files` + CSV（列定义见 §6.4）。
3. 同一事务内生成付款凭证：`借 应付职工薪酬` / `贷 银行存款`，记 `paid_at`、`status = PAID`。
4. SSE 推 `payroll_settled`（车间主管 + 本人），员工端 `/m/payroll` 立即可见；已 `PAID` 后**禁止 `reverse`**（`33001`），只能由财务做红字冲销（阶段二）。

### 5.6 反审核闭环（08 §5 第 6 条必测）

| 步骤 | 结算单 | 工资单 | 流水 `payroll_id` | 凭证 |
| --- | --- | --- | --- | --- |
| 审核前 / 审核后 | DRAFT → APPROVED | — → DRAFT | NULL → 结算单 | 无 |
| 工资审核后 / 发放后 | APPROVED | APPROVED / **PAID** | 结算单 | 计提凭证 / 计提 + 付款凭证 |
| 工资反审核（未发放） | APPROVED | SUBMITTED | 结算单 | 计提凭证红冲 |
| 结算反审核 | SUBMITTED | 须先反审核工资 | → NULL | 无 |

> 结算单反审核前必须先处理下游工资单：若工资单已 `APPROVED`/`PAID` 则拒绝（`33001`），这是 08 §1.1 `reverse` 的「下游校验」。

### 5.7 三方对账（数量与金额必须一致）

| 对账层 | 检查 | 期望 |
| --- | --- | --- |
| 流水 → 结算行 | `SUM(qty), SUM(amount) FROM piecework_settlement_lines WHERE doc_id=:id` | = 单头 `total_qty / total_amount` |
| 结算行 → 工资行 | 按 `(employee_id, style_no, operation_no)` 分组求和 | = `payroll_details` 的 `qty / gross_amount` 之和 |
| 工资行 → 单头 / 全链路 | `Σgross - Σdeduction`；池 `piecework_logs` 该周期区间（`BETWEEN start_date AND end_date`）净流水 | = `total_gross - total_deduction = total_net`；= 结算单 `total_qty / total_amount` |
| **周期 → 流水**（REV-2026-10 新增） | 周期区间内 `payroll_id IS NULL` 的流水条数 | 结算完成后 = **0**（漏结算/区间设错的兜底闸门，ADR-0010 验证方式） |
| 发放文件 | CSV 行数、金额合计 | = `bank_payment_files.row_count / total_amount` = `total_net` |
| 凭证 | 计提凭证借贷、付款凭证借贷 | 各 `sum(debit) == sum(credit)`（INV-5） |

> 建议实现为 SQLAlchemy Core 的原生 SQL 脚本 + 单测（01 §5.3 要求写 SQL 单元测试），随发布脚本一起跑（10 §1「对账测试每次发布前必跑」）。

## 7. 并发与幂等

| # | 场景（10 §5.3） | 期望 | 兜底手段 |
| --- | --- | --- | --- |
| P1 | **同周期重复结算**（同一周期+车间 20 并发 `POST /settlements`） | 只允许一张结算单；成功的返回同一 `doc_no`；其余按 `33002` 或幂等返回 | `uq_piecework_settlements_period_workshop` 唯一索引 + `Idempotency-Key` |
| P2 | **结算审核与反审核竞争** | 只有一个能成功；另一个 `10003`（乐观锁） | `WHERE id=? AND version=? AND status=?` 条件 UPDATE（08 R3） |
| P3 | **两条结算单抢同一条流水** | 只允许一条占用；`piecework_settlement_lines.piecework_log_id` 唯一索引兜底 | 唯一索引 + `payroll_id IS NULL` 条件 UPDATE |
| P4 | **发放与反审核竞争** | 已 `PAID` 时 `reverse` 必被拒（`33001`）；未 `PAID` 时先到者赢 | 状态机校验 + 乐观锁；`pay` 与 `reverse` 都带 `expected_version` |
| **P5** | **同区间并发建周期**（20 并发 `POST /payroll-periods`，同 `(start_date,end_date)`、不同 `period_code`） | 只允许一条成功；其余 `33004`（或 `Idempotency-Key` 命中幂等返回同一条） | `uq_payroll_periods_range` 唯一索引兜底（ADR-0010 §1：区间唯一性从库层面保证，不靠服务端 if） |
| **P6** | **结算审核与周期关闭竞争**（一边 `approve` 结算单、一边 `close` 周期） | 两者必须**串行化**：要么结算单审核成功后周期关闭（周期关闭只拦后续加单），要么 `close` 先成功、结算单 `submit`/`approve` 被拒 `33003`；不允许出现「周期已 CLOSED 却新增了 APPROVED 结算单」 | service 内对周期行 `SELECT ... FOR UPDATE` + 结算单审核时二次读 `status='OPEN'`；周期 `version` 条件 UPDATE（`rowcount=0` → `10003`） |
| **P7** | **周期关闭与重开竞争**（一边 `close` 一边 `reopen`） | 只有一个成功，另一个 `10007`（非法迁移）或 `10003`（乐观锁）；终态一致 | §4.3 状态机 + `version` |
| P8 | 导出重复点击 / 同一人跨车间重复出工资 | 复用 `bank_payment_files` 记录；跨车间由结算单车间维度决定，`uq_payroll_details_...` 只在单内生效 | 唯一索引 `payroll_sheet_id` |

**实现纪律**：批量审核**逐单独立校验**，不允许"全部通过"式放行（08 §4）；失败项单独列出；每条迁移都在同一事务内完成副作用（R4）。

- **前端**：菜单按权限过滤；`v-can="'payroll:approve'"` 控制审核按钮显隐；反审核在 `...` 下拉并 `Modal.confirm` **必填原因**（06 §2.2 / §5）。
- **分工**：计件员结算、主管审核、**财务发放**（制单与审核分离，08 §4）。
