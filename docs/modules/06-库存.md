## 1. 模块职责与边界

### 1.1 职责

① **物料库存** `material_stocks`（**批次粒度**：仓库 + 物料 + `dye_lot_no` 缸号 + `bolt_no` 匹号 + 色 + `stock_qty` + **`width_cm` 门幅 / `weight_kg` 重量 / `purpose` 采购用途**（REV-2026-10、ADR-0012）+ **`unit_cost`（批次实际成本，批次内恒定、永不改）**）；② **成衣库存** `finished_goods_stocks`（仓库 + 款号 + 色 + 码 + 批次 `bundle_no` 段 + 数量 + 单位成本 = 批次耗用成本 + 计提工价，快照不可改）；③ **台账** `stock_ledgers`（append-only 全量出入库流水，**不含** `unit_cost` / `amount`，成本由子表汇总）；④ **台账批次耗用明细** `stock_ledger_lines`（一条台账 → N 行批次耗用：缸号 / 匹号 / 数量 / 批次单价快照 / 金额）；⑤ **锁定** `stock_reservations`（单据占用，`available_qty = stock_qty - locked_qty`）；⑥ **选批规则**（人工指定批次 → FEFO → FIFO，**禁止按平均价出库**）；⑦ **单据入口**（REV-2026-10 改写）：**面料入库 = 采购单 `PO` 审核的副作用**（[ADR-0012](../adr/0012-采购原材料批次字段.md)，**无独立入库单、单号 `RC` 已取消**）；库存侧自有单据为 领料出库 `MI`、完工入库 `FG`、销售出库 `SO`、调拨 `TR`、盘点 `SC`；另含**布头入库**（裁剪单审核的副作用项，非独立单据，BR-ST-24）；⑧ **对账**（`v_stock_reconciliation` **恒为 0 行** + `v_stock_cost_check` 恒为 0 行，发布前必跑，10 §1）。

### 1.2 为什么分表（双栈）

| 维度 | `material_stocks`（物料栈） | `finished_goods_stocks`（成衣栈） |
| --- | --- | --- |
| 唯一维度 | 仓库 + 物料 + `dye_lot_no` + `bolt_no` + 色 | 仓库 + 款号 + 色 + 码 + 批次段 |
| 计量与精度 | 面料米/码、重量，**允许小数**（`numeric(14,3)`） | 成衣件数，**整数** |
| 成本算法 | **逐批（缸号）实际成本**：每个 `(仓库, 物料, 缸号, 匹号, 色)` 行有恒定的 `unit_cost`（REV-2026-10，撤销移动加权） | 单位成本 = Σ`stock_ledger_lines.amount`（该扎消耗的批次实际成本）+ Σ`piecework_logs.amount`（已计提工价），**入库即快照，之后不再平均、不再改** |
| 特有字段 | `bolt_no`、**`width_cm` 门幅 / `weight_kg` 重量 / `purpose` 采购用途**（ADR-0012、§3.1）、布头 `scrap_qty`（**入库**，BR-ST-24）、尾料 `remaining_fabric`；**尾数 `balance_qty` 不进本表**（不足一件的余量，不入库、不产生台账，09 §4.2） | `bundle_no` 段、`style_no`、`size`、订单色 `order_color`；**成衣只有整件**（BR-ST-23） |
| 出库场景 | 裁剪耗料、领辅料 | 销售出库、调拨 |
| 成本可见性 | 需 `stock:cost:view` 才返回 `unit_cost` | 同 |

**分表理由**（04 §7.2 原话「避免一堆可空列」）：两栈的主键维度、成本算法、计量单位、数量精度、入库来源完全不同；若合表，`bolt_no` 与 `bundle_no` 至少有一半为空，`CHECK` 约束写不出来、索引也会退化。**禁止**用一张大表 + JSONB 绕过（04 §8 明确禁止把核心可查询字段塞 JSONB）。

## 1.4 三段式出入库链路（REV-2026-10 重写，见 [ADR-0018](../adr/0018-出入库链路与在制品WIP.md)）

原来只有「面料」和「成衣」两栈，中间**裁完没缝完的裁片没有任何台账**，导致损耗归属不清、可销售数量对不上。现改为**三段独立台账**，互不串账：

| 段 | 台账 | 对象 | 进入 | 离开 | 权限 |
| --- | --- | --- | --- | --- | --- |
| **① 原材料** | `material_stocks` + `stock_ledger_lines` | 面料/辅料（供应商+缸号+匹号） | **到货登记**（`purchase_arrivals`） | 裁剪领料出库、布头回库 | `stock:in` / `stock:out` |
| **② 在制品 WIP** | `wip_stocks` + `wip_ledger_lines`（新增） | 裁片（款号+色+码） | **裁剪单审核通过自动入** | 工序流转、报损 | `stock:wip:read` |
| **③ 成衣** | `finished_goods_stocks` | 成衣（款号+色+码+扎段） | **最后一道工序扫码完成自动入** / 手动完单入库 | 销售出库、盘点 | `stock:in:manual` |

### 成衣入库时机（业务已决策）

| 路径 | 触发 | 校验 |
| --- | --- | --- |
| **自动（主路径）** | 该码在**最后一道工序 = 整烫（烫衣服）**（`is_final_operation = true`）**扫码计件完成** | 同一事务：WIP `OUT` + 成衣 `IN` + **一次性结转成本**；数量不符 → `40007` |
| **手动完单入库** | 漏扫 / 返修后补入库 | `stock:in:manual` + **必填原因**（`10006`）+ `document_logs` |
| ❌ 禁止 | 裁剪完成直接当成衣入库 | 会超卖且损耗无处体现 |

**最后一道工序 = 整烫（烫衣服）**（业务确认 2026-10-02）：默认按工序名含「整烫 / 烫衣」自动识别；「工序与单价」页对它打醒目徽标；款号保存时校验必须能识别到一道，识别不到则标红提示人工指定；工位机在整烫扫码时提示「本工序完成即成衣入库」。

### WIP 不计成本

`wip_ledger_lines.unit_cost` **恒为 NULL**；成衣成本在最后工序入库时一次性结转 = 面料实际成本（按布批）+ 全部已计工价，避免工序流转时反复重算。

### 供应商维度（REV-2026-10，见 [ADR-0022](../adr/0022-采购台账与库存供应商维度.md)）

`material_stocks.supplier_id` 由到货登记写入、**不可手改**（改供应商 = 退料重入库）。

库存情况列表默认列：**供应商 · 面料名称 · 颜色 · 缸号 · 匹号 · 门幅 · 重量KG · 米数 · 可用量 · 已锁定 · 单价 · 金额**，筛选：供应商 / 面料 / 颜色 / 时间区间；视图 `v_material_stock_by_supplier`，支持导出。

**裁剪选料级联**：`供应商 → 面料 → 颜色 → 可用库存 > 0 的缸号/匹号 → 输入领用重量`。领用 > 可用量 → `40006`；领用 < 整匹重量时余量走**布头回库**（`direction='IN'`、`purpose='REMNANT'`），不计损耗。

### 成本口径修订（[ADR-0019](../adr/0019-采购运费只记录不进成本.md)）

**采购侧三项费用一律不进成本**（ADR-0019 + [ADR-0024](../adr/0024-染费与加工费只记录不进成本.md)）：`unit_cost = 到货金额 ÷ 到货数量`，**不含运费 / 染费 / 加工费**；三项费用均不进领料成本、不进成衣成本、不进损益、不生成凭证行。因此**成衣毛利率不扣任何采购侧费用**，毛利报表页头固定标注「毛利未扣采购运费/染费/加工费（ADR-0019 / ADR-0024）」。三项费用只能通过采购台账查看。

## 2. 业务规则

| # | 规则 | 详细口径 | 强制手段 |
| --- | --- | --- | --- |
| BR-ST-01 | 结余 = 台账之和 | 每条 `stock_ledgers` 的有符号 `qty` 之和必须等于对应 `stock_qty` | 视图 `v_stock_reconciliation` 恒 0 行 + 每次发布跑对账 |
| BR-ST-02 | 可用 = 结存 - 锁定 | `available_qty = stock_qty - SUM(active reservations.qty)`；出库既校验可用也校验锁定 | 条件 UPDATE（§7） |
| BR-ST-03 | 台账 append-only | 禁止 `UPDATE stock_ledgers` / `DELETE`；纠错一律新增反向行（红冲） | 应用层禁用 + DB 层 REVOKE（04 §7.6 同款做法） |
| BR-ST-04 | **成本快照在批次耗用明细** | `stock_ledgers` **不再有** `unit_cost` / `amount`；每条台账对应 `stock_ledger_lines`（N 行批次耗用），`unit_cost` / `amount` 写在明细行上 = **该批次当时的成本**，事后调采购价不影响历史 | `stock_ledger_lines.unit_cost numeric(12,6)`、`.amount numeric(18,4)`；台账金额由 `SUM(明细.amount)` 汇总 |
| **BR-ST-05** | **逐批实际成本（REV-2026-10，撤销移动加权）** | **不再有 `unit_cost = (原金额+入库金额)/(原数量+入库数量)` 这套**。库存粒度 = 批次，`material_stocks.unit_cost` 在**入库审核那一刻确定，此后永不改变**（04 §7.2 + [ADR-0011](../adr/0011-面料批次实际成本.md)） | 结存行按 `(warehouse_id, material_id, dye_lot_no, bolt_no, color)` 唯一；成本写路径不存在（BR-ST-06） |
| **BR-ST-05a** | **入库如何定批次成本**（04 §7.2.1） | ① **到货登记入库**（REV-2026-10，ADR-0012 → ADR-0015 → **ADR-0019**）`unit_cost = 到货行金额 ÷ 入库数量`，精确 6 位，**不含运费**；② 生产退料**沿用原批次** `unit_cost`；③ 盘盈取**同物料同缸号**最近批次，无同缸则取同物料最近批次 + 写日志；④ **成本调整禁止 UPDATE**，必须红冲原入库单 + 重新入库（`40002`） | service 算一次写入；DB 层不给普通账号 `UPDATE (material_stocks.unit_cost)` 授权；`40002` |
| BR-ST-06 | INV-4 批次成本不可篡改 | 已入库批次的 `unit_cost` 与其明细行 `unit_cost` / `amount` 均不可 `UPDATE`；只能红冲原单重入或盘点差异 | 拒绝写路径 + 迁移时不给普通账号 UPDATE 授权 + `40002` |
| BR-ST-07 | 成衣成本构成 | 成衣单位成本 = 该扎消耗的**批次实际成本合计**（`Σstock_ledger_lines.amount`）+ 该扎**已计提工价合计**（`Σpiecework_logs.amount`）；跨批次时**求和不平均**；入库即快照，之后不可改 | 完工入库审核时算，落 `finished_goods_stocks.unit_cost / material_cost / labor_cost` |
| BR-ST-08 | 审核即生效 | 审核 = 加/减库存 + 生成台账 + **生成批次耗用明细** + 锁定释放 + 往来/凭证，**同一事务** | 08 §1.2 R4 |
| BR-ST-09 | 反审核全链路反向 | 同事务冲销库存、台账、锁定、往来、凭证，**不删原始记录** | 08 §1.2 R5；08 §5 第 6 条必测 |
| BR-ST-10 | 单据与台账解耦 | 库存表不存 `status`；状态只在单据表，库存是单据审核后的**结果** | 08 R7 |
| BR-ST-11 | 成本可见性 | 无 `stock:cost:view` 时，接口层过滤 `unit_cost` / `amount` / `total_cost` 字段（不是置 null，是不返回） | 07 §5；列表 Schema 按权限选列 |
| BR-ST-12 | 超卖必须被数据库挡住 | 出库用 `SET stock_qty = stock_qty - n WHERE id = ? AND stock_qty - locked >= n`，`rowcount = 0` 即 `40001` | §7 条件 UPDATE |
| BR-ST-13 | 盘点生成差异单 | 盘点只记录实盘数，**不直接改库存**；审核时按差异生成盘盈入库 / 盘亏出库台账并过凭证 | 走单据状态机，不走后门 |
| BR-ST-14 | 安全库存预警 | 低于 `safety_stock` 发 SSE `stock_low`（01 §5.4），只提醒不阻断 | 事件在出库后计算 |
| BR-ST-15 | 幂等 | 所有写接口支持 `Idempotency-Key`；台账按 `(source_doc_type, source_doc_id, line_no, direction)` 唯一 | 唯一索引兜底 |
| **BR-ST-17** | **出库选批优先级（强制）** | ① **人工指定批次**（行上带 `dye_lot_no` / `bolt_no`；裁剪按客户指定缸号配料，**最常见**）② **FEFO**（有过期日的辅料，按到期日升序，无到期日用入库日）③ **FIFO**（默认，按入库日升序）。三级都命中不了才报错 | 单据行必带 `batch_rule`（`EXPLICIT` / `FEFO` / `FIFO`）；选批函数签名见 §5.2 |
| **BR-ST-18** | **禁止跨批次按平均价出库** | **严禁**把多个批次的数量合并后按算术平均单价出库（这正是被撤销的移动加权，会造成成本漂移、色差无法追溯到缸） | 选批函数返回 N 行 `BatchPick`，数量不足抛 `40001`，**不部分出库** |
| **BR-ST-19** | **每条台账必有批次耗用明细** | `stock_ledger_lines.ledger_id` 必建 FK；出库台账 ≥ 1 行（N 批次），入库 / 调拨 / 盘点调整台账 = 1 行（记录该批入库定价或结转定价）；无明细的台账视为非法 | FK 兜底 + `v_stock_cost_check` 恒 0 行（§3.7） |
| **BR-ST-20** | **报表按实际批次成本出账** | 毛利分析、款式成本、缸号对账**一律按实际批次成本**，不得使用任何平均价，也不得用 `v_stock_reconciliation` 的结余反推均价 | 报表 SQL 只读 `stock_ledger_lines.amount` 汇总；单测断言毛利 = 收入 − Σ批次耗用金额 |
| **BR-ST-21** | **调拨只改仓库** | 调拨**不产生成本变化**：`unit_cost` 随批次整行搬移（`OUT` 与 `IN` 明细金额相等），同缸不同价时必须**分别建行**，禁止合并 | `TR` 审核时 `OUT`/`IN` 明细 `unit_cost` 逐行相等的断言 |
| **BR-ST-22** | **库存不足不部分出库** | 选批后总可用 < 需求量 → 整行拒绝 `40001`，已扣批次在同事务内回滚 | 条件 UPDATE + 同事务回滚（§7.1） |
| BR-ST-16 | 精度与尾料布头 | 面料 `numeric(14,3)`、成衣 `integer`、金额 `numeric(18,4)`、单价 `numeric(12,6)`（04 §4）；裁剪剩余整段布记 `remaining_fabric`（红冲耗料入库，沿用原批次 `unit_cost`）；布头 `scrap_qty`（仍可再裁的整段布）**入库为布料批次**，批次实际成本（09 §1.2/§1.6/§4.2、BR-ST-24） | 04 §4 / 09 §1.2 / 09 §4.2 |
| **BR-ST-23** | **完工入库只入整件成衣（整件口径）** | 09 §4.2 / 00 INV-6：生产数量**向下取整到整件**——裁剪 `output_qty = floor(可裁件数)`，余量记 `balance_qty` 并计入 `cut_waste_qty`；打菲只对整件生成码。因此**成衣库存里只有整件**：完工入库单（`FG`）行 `qty` 必须为**正整数**（`CHECK (qty > 0 AND qty = trunc(qty))`），**无尾数入库单据**——入库环节**不接收、不换算、不生成 `balance_qty`**；也不存在「先入尾数再盘盈」的过渡路径 | `finished_goods_receipts` 行 `qty` DB `CHECK` + 接口层 `40004`；§4.1 `FG approve` 前置校验 |
| **BR-ST-24** | **布头入库归本模块；尾数不入库、不产生台账** | **布头 vs 尾数必须区分**（09 §4.2）：<br>**① 布头 `scrap_qty`**（裁完**仍可再裁**的整段布，数米以上）**入库为布料批次**：`stock_type='MATERIAL'`、`direction='IN'`、`source_doc_type='CuttingOrder'`（08 §2.1 审核副作用⑤），**批次沿用被裁的缸号匹号**（`dye_lot_no` / `bolt_no` / `color`），`unit_cost` = **该缸批次实际成本**（ADR-0011，永不改变）。<br>**② 尾数 `balance_qty`**（产出**不足一件**的余量）**不入库、不锁量、不生成任何台账与明细**，只计入裁剪 `cut_waste_qty`；成本已随损耗摊入耗料，**不单独计价**。 | service 分支：`scrap_qty > 0` 才建 `IN` 台账 + 1 行明细（BR-ST-19）；`balance_qty` 在本模块**无写路径**；`v_stock_reconciliation` / `v_stock_cost_check` 恒 0 行（§3.7） |
| **BR-ST-25** | **REV-2026-10 返修布：照常入库、照常领用，成本单独口径** | 采购单行 `purpose='REWORK_RECEIPT'`（[04 §7.4.2](../04-数据库规范.md)、ADR-0012）审核后生成的批次带 `purpose`：**① 正常入库 `material_stocks` + 正常台账**；② **可被裁剪单正常选批领用**（不进独立仓库、不加特殊流转，返修布也要能再裁）；③ 但因为**批次实际成本独立成立**（BR-ST-05 / ADR-0011），返修布的成本**天然与正常布料分开** —— 凭证走 **`5403 制造费用-返修补布费`**（不是 `1405 库存商品-面料`）；④ **款式毛利报表必须单独列示**返修补布费，不混入主料成本；⑤ `purpose='REWORK_RECEIPT'` 时 `rework_note` **必填**（写明哪款哪单返修回来），缺失 → `10006`。其余取值：`NORMAL`（正常）/ `RETURN`（客供料退回，冲减 `1406 在产品`）/ `SAMPLE`（样布，`6602 管理费用-样品费`，不进产品成本） | `material_stocks.purpose` 冗余落库（03 §3.1）+ 报表 SQL 按 `purpose` 分组；TC-35 |
| **BR-ST-26** | **REV-2026-10 计量三件套差异 > 5% 只警告不阻断** | 采购单行的**匹数 `bolt_count` / 每匹米数 `length_per_bolt_m` / 总米数 `total_length_m` / 重量 `weight_kg`** 允许各自独立录入（ADR-0012 §2）：三者**不强制一致**（染厂缩水、布头剪除必然造成差异）。`abs(总米数 − 匹数 × 每匹米数) ÷ 总米数 > 5%` 或 **`abs(重量 − 理论重量) ÷ 重量 > 5%`** 时返回**警告**并回显各值，**不阻断提交与审核**（阻断会让采购员做不了真实业务）。`total_length_m` 未填时由服务层按 `bolt_count × length_per_bolt_m` 计算。报表**以重量为准**（重量是布料主计量，09 §1.1） | 04 §7.4.2「关键规则」；service 返回 `warnings[]`（非 `errors[]`），`can_commit` 不受影响；无专用错误码（**不新增**） |

> ✅ **`stock_type` 取值已统一（2026-10-01）**：全局枚举为 **`MATERIAL`（面料/物料栈）/ `FINISHED_GOODS`（成衣栈）**（见 [04 §7.2](../04-数据库规范.md)）。[02 裁剪](./02-裁剪.md) C11 的布头入库已回写为 `stock_type='MATERIAL'`。枚举变更必须走 PG `ALTER TYPE ... ADD VALUE` 迁移。

### 2.1 成本口径速查（REV-2026-10 整段重写，权威依据 [ADR-0011](../adr/0011-面料批次实际成本.md) + [04 §7.2](../04-数据库规范.md)）

**已撤销**：移动加权平均。`unit_cost = (原金额 + 入库金额) / (原数量 + 入库数量)` 这套算法**在本项目不再存在**，代码里不得出现该计算；04 §7.2 的「移动加权平均」条款已由 ADR-0011 取代。
**为什么撤销**：服装面料同款不同缸号存在色差，代工厂常按缸号与面料商/客户对账摊销损耗；加权会把低价缸与高价缸抹平，色差追溯与损耗责任定位都做不了。业务方明确否决（ADR-0011 备选方案表第 1 行）。

| 环节 | 口径 | 落库位置 |
| --- | --- | --- |
| 入库定价 | **到货登记入库** `到货行金额 ÷ 入库数量`，精确 6 位，**不含运费**（ADR-0019）；生产退料沿用原批次；盘盈取同缸最近批次；**成本调整禁止 UPDATE，只能红冲 + 重入** | `material_stocks.unit_cost`（该批次行，此后恒定） |
| 出库选批 | ① 人工指定批次 ② FEFO ③ FIFO；**禁止跨批次按平均价出库**；数量不足整行拒绝 | 单据行 `batch_rule` + `dye_lot_no` |
| 出库成本 | 每批次一行耗用明细，`unit_cost` 取**该批次**成本快照 | `stock_ledger_lines`（`ledger_id` + 缸号 + 匹号 + `qty` + `unit_cost` + `amount`） |
| 成衣成本 | `Σ(stock_ledger_lines.amount)` + `Σ(piecework_logs.amount)`，跨批次**求和不平均** | `finished_goods_stocks.unit_cost / material_cost / labor_cost`（快照不可改） |
| 报表毛利 | 一律按**实际批次成本**出账 | 报表 SQL 汇总 `stock_ledger_lines.amount` |
| 调拨 | 不产生成本变化，批次成本随批次走 | `OUT` / `IN` 明细 `unit_cost` 逐行相等 |
| 盘点差异 | 盘盈生成新批次（成本按上表「盘盈」规则）；盘亏扣原批次并写负向明细 | 台账 `direction='ADJUST'` + 明细 |
| **采购用途（REV-2026-10）** | 批次继承采购行 `purpose`：`NORMAL` / `REWORK_RECEIPT`（→ `5403 制造费用-返修补布费`，毛利单独列示）/ `RETURN`（冲减 `1406`）/ `SAMPLE`（→ `6602`，不进产品成本）；**成本算法不变**（返修布也是逐批实际成本） | `material_stocks.purpose` + 报表按 `purpose` 分组（BR-ST-25） |

## 3. 数据模型

### 3.1 `material_stocks`（面料 / 辅料结存表，**批次粒度**，REV-2026-10 重写）

一行 = **一个批次在一个仓库的结存**（批次 = 缸号 `dye_lot_no` + 匹号 `bolt_no`），成本在批次维度恒定。

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `warehouse_id` / `material_id` | `uuid` | 是 | **联合唯一** | 仓库 + 物料档案（面料 `F-CT-000128` / 辅料 `T-ZL-000456`） |
| `dye_lot_no` / `bolt_no` / `color_code` | `varchar(32/64)` | ✅ | **联合唯一** | 缸号 / 匹号 / 缸号对应色；**无缸号或不分匹时填 `-`**（Q-ST05）。⚠️ REV-2026-04：`dye_lot_no` 由可空改 `NOT NULL DEFAULT '-'` —— 它在唯一键里，而 PG 的 NULL 不参与唯一判定，可空会让「无缸号」的批次重复插入；本列原先叫 `color`，与款号侧的 `color_code` 对齐 |
| `batch_no` | `varchar(64)` | 否 | 否 | 对外批次号（09 §1.6），**展示用，不进唯一键**。⚠️ REV-2026-04：业务确认「**现在不存在同缸不同价**」，所以它不承担区分价格的作用 —— 原写的「同缸不同价必须有不同 `batch_no`」作废（ADR-0011 的「批次内成本恒定」已足够） |
| `stock_qty` / `locked_qty` | `numeric(14,3)` | 是 | 否 | 账面结存（04 §7.2 视图口径字段名）/ 冗余锁定量缓存，与 `stock_reservations` 聚合一致 |
| `unit_cost` | `numeric(12,6)` | 是 | 否 | **批次实际成本**：入库审核时按 §2.1 规则确定，**批次内恒定、永不改变**（BR-ST-05）。**无 `stock:cost:view` 不返回** |
| `total_amount` | `numeric(18,4)` | 是 | 否 | `ROUND(stock_qty × unit_cost, 4)`，冗余列供报表；**扣减/入库后按同一批次 `unit_cost` 重算，成本分量不动**；不可手工改（INV-4） |
| **`width_cm`** | **`numeric(8,2)`** | 是 | 否 | **门幅 / 幅宽（cm）**，布料**裁剪关键参数**（09 §1.1）。**有效门幅 = `width_cm` − 左右布边 − 对格损耗**，裁剪单审核时用它做门幅校验（[02-裁剪](./02-裁剪.md) C24）。值来自采购行，**同缸不同批可有差异**（缩水 / 织造偏差），所以建在**批次**上而不是只在 `materials` 上。**布料必填**；辅料可空（`CHECK (width_cm IS NULL OR width_cm > 0)`） |
| **`weight_kg`** | **`numeric(14,3)`** | 是 | 否 | **重量（kg），布料主计量**（09 §1.1「重量 Net Weight」）。染厂交货与结算大量按 kg，**核账第一依据**；报表以重量为准，匹数 / 米数只作辅助（BR-ST-26）。值来自采购行 `weight_kg`，**批次维度快照**，与后续进出一致增减 |
| **`purpose`** | **`purchase_purpose`** | 是 | 否 | **采购用途**，继承采购单行的 `purpose`（[04 §7.4.2](../04-数据库规范.md)、ADR-0012）：`NORMAL` / `REWORK_RECEIPT` / `RETURN` / `SAMPLE`，默认 `NORMAL`。**这是返修布成本天然分开的唯一依据**（BR-ST-25）；出库台账明细可按它把返修布耗用单独归集，毛利报表单独列示 |
| `in_date` / `expiry_date` | `date` | 是 / 否 | 否 | 入库日期（FIFO 排序键）/ 到期日（**FEFO 排序键**，无则 FIFO）；`expiry_date` 为空即视为 FEFO 不适用 |
| `safety_stock` | `numeric(14,3)` | 否 | 否 | 安全库存，低于触发 `stock_low` |
| `id` + 公共字段 | 见 04 §2 | 是 | — | `uuid` PK + 审计/软删/乐观锁/`remark` |
| 约束 | — | — | — | `CONSTRAINT uq_material_stocks_dim UNIQUE (warehouse_id, material_id, dye_lot_no, bolt_no, color)`；`CHECK (stock_qty >= 0)`；`CHECK (locked_qty >= 0 AND locked_qty <= stock_qty)`；`CHECK (unit_cost >= 0)` |

> **同缸不同价**必须分行：唯一键含 `bolt_no`，同缸不同匹天然分行；若同缸同匹却要改价，**不能 UPDATE**（`40002`）—— ⚠️ **REV-2026-04：业务确认「不存在同缸不同价」，所以唯一键不含 `batch_no`，也没有第二条行可插**。唯一出路是**走红冲重入**（BR-ST-05a ④）：原批次作废、新批次用新的 `bolt_no`。原文写的「换 `bolt_no` 或换 `batch_no`」中「换 batch_no」那半句作废。
> **`in_date` / `expiry_date` 是 REV-2026-10 新增列**：FIFO / FEFO 选批必须能稳定排序（BR-ST-17）。迁移按 ADR-0011「迁移路径」分两步走，先加可空列再回填。
> **`width_cm` / `weight_kg` / `purpose` 是 REV-2026-10 新增列（ADR-0012）**：按 ADR-0012「迁移路径」**分两次 ALTER**：① 先加可空列；② 按采购单回填（无采购单来源的历史批次按 `purpose='NORMAL'`、`width_cm` 留空并写 `remark`）；③ 加约束 `CHECK (width_cm IS NULL OR width_cm > 0)` / `CHECK (weight_kg IS NULL OR weight_kg >= 0)`，并对**布料批次**（`materials.material_type='FABRIC'`）在 service 层要求 `width_cm` / `weight_kg` 非空。**不加进唯一键**（`uq_material_stocks_dim` 不变），避免历史批次被迫拆行。

**`purpose` 如何让返修布成本「天然分开」（BR-ST-25 落地机制）**：

| 环节 | `purpose='NORMAL'` | `purpose='REWORK_RECEIPT'` | 依据 |
| --- | --- | --- | --- |
| 入库 | 批次 `unit_cost` 按 `到货行金额 ÷ 计量` 定（**不含运费**） | **同样定，逐批实际成本独立成立**（BR-ST-05 / ADR-0011），不与正常布料混算 | 04 §7.4.2；ADR-0011 |
| 入库凭证 | 借 `1405 库存商品-面料` | 借 **`5403 制造费用-返修补布费`** | ADR-0012 §3 |
| 裁剪领用 | 正常选批、正常扣减 | **照常选批、照常扣减**（返修布要能再裁） | BR-ST-25 ② |
| 耗用归集 | `stock_ledger_lines` 正常明细 | 同一张明细，**按 `purpose` 分组汇总即可分开**（无需另立成本模型） | BR-ST-25 ③ |
| 毛利报表 | 混入主料成本 | **单独列示「返修补布费」**，不污染正常布料毛利 | BR-ST-25 ④ |

> 关键点：**不需要独立仓库、不需要拆物料档案**。ADR-0012 已否决这两种方案（会割裂库存、且用途可能随批次变化）；成本分开完全由「批次实际成本 + `purpose` 字段」承担。

**布头入库（REV-2026-10，09 §4.2，BR-ST-24）——本模块职责**：

裁剪后剩下的**布头 `scrap_qty`** 是「仍可再裁的整段布」，**必须入库**，否则这缸布的成本就断了。它与「尾数 `balance_qty`」是两回事：

| 项 | 布头 `scrap_qty` | 尾数 `balance_qty` |
| --- | --- | --- |
| 是什么 | 裁完**仍可再裁**的整段布（数米以上） | 产出**不足一件**的余量 |
| 是否入库 | ✅ **入库**（本表 `material_stocks`） | ❌ **不入库** |
| 台账 | `stock_type='MATERIAL'`、`direction='IN'`、`source_doc_type='CuttingOrder'`（`source_doc_id` = 裁剪单 id、`source_line_no` = 裁剪行号） | **无任何台账**（不写 `stock_ledgers`，也不写 `stock_ledger_lines`） |
| 批次 | **沿用被裁的缸号匹号**（`dye_lot_no` / `bolt_no` / `color` 原样带入，**不新造缸号**） | — |
| 成本 | **该缸批次实际成本**（`unit_cost` 取批次当前值，永不改变，ADR-0011） | **不计成本**（已随 `cut_waste_qty` 摊入耗料） |
| 锁定 | 可被后续裁剪单锁定出库 | 无 |

- 必写 `stock_ledger_lines` **1 行**（`qty` 正、`unit_cost` = 该批次成本快照、`amount = ROUND(qty × unit_cost, 4)`），否则 `v_stock_cost_check` 非空（BR-ST-19、§3.7）。
- `scrap_qty = 0` 时**不建台账**（无明细即非法台账，BR-ST-19）。
- 触发方：裁剪单 `approve` 的副作用⑤（[08 §2.1](../08-单据状态机规范.md)）；反审核按同一批明细逐条反向冲回（§7.3 K8）。
- **尾数对本模块零写路径**：不建 `material_stocks` 行、不建台账与明细、不建 `stock_reservations`。对账断言见 §11 TC-33。

### 3.2 `finished_goods_stocks`（成衣结存表）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `warehouse_id` / `style_no` / `color` / `size` / `batch_no` | — | 是 | **联合唯一** | 仓库 + 款号 + 订单色 + 尺码 + 成衣批次（`bundle_no` 段） |
| `stock_qty` / `locked_qty` | `integer` | 是 | 否 | 件数（**整数**）/ 锁定量；**整件口径**：成衣只有整件，入库单（`FG`）行 `qty` 同样受 `CHECK (qty > 0 AND qty = trunc(qty))` 约束，**无尾数成衣**（BR-ST-23、09 §4.2） |
| `unit_cost` | `numeric(12,6)` | 是 | 否 | 单位成本 = **该扎消耗的批次实际成本合计** + **已计提工价合计**（BR-ST-07）；完工入库时快照，**之后不可改** |
| `total_amount` | `numeric(18,4)` | 是 | 否 | `stock_qty × unit_cost` |
| `material_cost` / `labor_cost` | `numeric(18,4)` | 是 | 否 | 拆开存，便于款式毛利分析（09 §2 痛点「老板看不清哪个款赚钱」）；`material_cost = Σstock_ledger_lines.amount`（该扎），`labor_cost = Σpiecework_logs.amount`（该扎已计提） |
| `id` + 公共字段 | 见 04 §2 | 是 | — | — |
| 约束 | — | — | — | `CONSTRAINT uq_finished_goods_stocks_dim UNIQUE (warehouse_id, style_no, color, size, batch_no)`；`CHECK (stock_qty >= 0)`；`CHECK (locked_qty >= 0 AND locked_qty <= stock_qty)`；入库侧 `finished_goods_receipts` 行 `qty` 另加 `CHECK (qty > 0 AND qty = trunc(qty))`，保证成衣只入整件（BR-ST-23） |

### 3.3 `stock_ledgers`（台账，append-only，照抄 [04 §7.2](../04-数据库规范.md) 字段清单；REV-2026-10 移除成本列）

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `stock_type` / `stock_id` | `varchar(16)` / `uuid` | 是 | 联合唯一 | `MATERIAL` / `FINISHED_GOODS` + 结存行 id（跨表逻辑引用，不建 FK） |
| `warehouse_id` | `uuid` | 是 | 否 | 冗余仓库，报表免 join |
| `direction` | `varchar(16)` | 是 | 联合唯一 | `IN` 入库 / `OUT` 出库 / `ADJUST` 盘点调整 |
| `qty` | `numeric(14,3)` / `integer` | 是 | 否 | **有符号**：`IN` 正、`OUT` 负（对账视图直接 `SUM`） |
| ~~`unit_cost` / `amount`~~ | — | — | — | **REV-2026-10 移除**。台账是「一次动作」，一条动作可能跨 N 个批次，单行放不下也不准确。**成本改为由 `stock_ledger_lines` 明细汇总**：台账金额 = `SUM(明细.amount)`，台账成本单价 = `SUM(明细.amount) / 台账 qty`（**仅报表汇总用，不作为出库定价依据**，定价一律取明细行的批次 `unit_cost`） |

**哪些动作不写台账（REV-2026-10，09 §4.2）**：

| 动作 | 是否写 `stock_ledgers` | 理由 |
| --- | --- | --- |
| **采购单审核入库**（`source_doc_type='PurchaseOrder'`）/ 领料出库 / 完工入库 / 销售发货 / 调拨 / 盘点调整 | ✅ 写（1 条或多条） | BR-ST-01 结余 = Σ台账 |
| **布头入库**（裁剪单 `approve`） | ✅ 写 `IN`（`source_doc_type='CuttingOrder'`） | 布头仍可再裁，必须入库（BR-ST-24） |
| **尾数 `balance_qty`** | ❌ **不写**（连明细也不写） | 不足一件的余量已计入裁剪 `cut_waste_qty`，**不入库、不产生台账**；写台账会让 `v_stock_cost_check` 因「有台账无明细」而报警（BR-ST-19、BR-ST-24） |

### 3.4 `stock_ledger_lines`（**台账批次耗用明细，REV-2026-10 新增**，照抄 04 §7.2 字段清单）

一条台账 → N 行批次耗用。这是「这件成衣用了哪几缸布、各多少米、各多少钱」的唯一答案来源（BR-ST-19）。

| 字段 | 类型 | 必填 | 唯一 | 说明 |
| --- | --- | --- | --- | --- |
| `ledger_id` | `uuid` | 是 | — | `REFERENCES stock_ledgers(id) ON DELETE RESTRICT`；必建 FK（04 §7.2.4「每条出库都有批次耗用」） |
| `material_id` | `uuid` | 是 | — | 物料档案（成衣栈台账此列为 `NULL`） |
| `stock_id` | `uuid` | 是 | 否 | 被扣减的 `material_stocks` 行 id（逻辑引用，便于反查当前批次结存；批次行软删不影响明细追溯） |
| `dye_lot_no` / `bolt_no` / `color` | `varchar(32)` | 是/否 | 否 | **批次快照**（缸号 / 匹号 / 色）。即使批次行后来归零软删，这里仍可追溯 |
| `qty` | `numeric(14,3)` | 是 | — | **有符号**：出库负、入库正（与父台账 `direction` 同向），红冲为反向 |
| `unit_cost` | `numeric(12,6)` | 是 | — | **该批次的成本快照**（BR-ST-04），出库取批次当前 `unit_cost`，**永不被后续改价影响** |
| `amount` | `numeric(18,4)` | 是 | 否 | `ROUND(qty × unit_cost, 4)`；报表汇总的唯一成本来源（BR-ST-20） |
| `reversal_of_id` | `uuid` | 否 | 否 | 红冲明细指向原明细行（反审核**按同一批明细逐条反向冲回**，§7 K6） |
| `id` + 公共字段 | 见 04 §2 | 是 | — | `uuid` PK + 审计/软删/乐观锁/`remark`；明细**不可 UPDATE/DELETE**，纠错走红冲 |
| 约束 | — | — | — | `CONSTRAINT ck_stock_ledger_lines_qty CHECK (qty <> 0)`；`CONSTRAINT ck_stock_ledger_lines_amount CHECK (ROUND(qty * unit_cost, 4) = amount)`；`CONSTRAINT uq_stock_ledger_lines_batch UNIQUE (ledger_id, dye_lot_no, bolt_no)`（同一台账内同批次只允许一行，避免重复扣减） |

**索引**（04 §5 / §7.2，生产用 `CREATE INDEX CONCURRENTLY`）：
- `idx_stock_ledger_lines_ledger_id` → `(ledger_id)`：台账详情页按行展开。
- `idx_stock_ledger_lines_material_lot` → `(material_id, dye_lot_no, created_at DESC)`：**缸号级耗用追溯与对账**主路径（§8 T11）。
- `idx_stock_ledger_lines_reversal_of_id` → `(reversal_of_id)`：红冲链追溯。
- 唯一约束 `uq_stock_ledger_lines_batch` 兼作 `(ledger_id, dye_lot_no, bolt_no)` 前缀索引。

**方向覆盖说明**：04 §7.2 / ADR-0011 把本表定义为「出库批耗明细」（出库 N 行）。本模块在此基础上**把入库 / 调拨 / 盘点调整也统一写 1 行**（记录该批入库定价或结转定价），理由：`v_stock_cost_check` 才能对**全方向**校验「台账金额 = Σ 明细金额」（§3.7），否则入库侧成本无留痕，无法反查「这批料当时按多少钱入的」。入库台账的明细行即该批次 `unit_cost` 的**首次快照**。

### 3.6 实体关系

`material_stocks` / `finished_goods_stocks` 1:N → `stock_ledgers`（`stock_id`，逻辑引用）；`stock_ledgers` 1:N → `stock_ledger_lines`（`ledger_id`，**必建 FK**）；`stock_ledger_lines.stock_id` → `material_stocks.id`（逻辑引用）；`material_stocks` / `finished_goods_stocks` 1:N → `stock_reservations`；单据（**`purchase_orders`（REV-2026-10：取代已取消的 `purchase_receipts`，ADR-0012）** / `cutting_orders` / `material_issues` / `finished_goods_receipts` / `sales_deliveries` / `stock_transfers` / `stocktakings`）1:N → 台账 + 明细 + 锁定（`source_doc_id` / `doc_id`）。

| 关系 | 基数 | 外键约束 | 说明 |
| --- | --- | --- | --- |
| `stock_ledger_lines.ledger_id` → `stock_ledgers.id` | N:1 | **必建 FK** + 索引 | 明细是台账的成本载体；台账无明细即非法（BR-ST-19） |
| `stock_ledger_lines.reversal_of_id` → `stock_ledger_lines.id` | N:1 自引用 | 必建 FK + 索引 | 反审核逐条反向冲回（INV-4 红冲链） |
| `stock_ledgers.stock_id`、`stock_reservations.stock_id` → 结存表 | N:1 | **不建 FK**（按 `stock_type` 多态） | 跨表多态无法建 FK；由 service 保证 + `40003` 对账兜底 |
| `stock_ledgers.reversal_of_id` → `stock_ledgers.id` | N:1 自引用 | 必建 FK + 索引 | INV-4 红冲链 |
| `stock_ledgers.source_doc_id` → 各单据表 | N:1 | **不建 FK** | 单据可整体软删/反审核，FK 会阻止合法操作 |

### 3.7 对账视图（照抄 04 §7.2 + §7.2.4，**两者都必须恒为 0 行**）

```sql
-- ① 数量对账：台账流水与结余必须可对账，报表脚本每次发布后跑
CREATE OR REPLACE VIEW v_stock_reconciliation AS
SELECT s.id, s.stock_qty, COALESCE(SUM(l.qty), 0) AS ledger_qty
FROM material_stocks s
LEFT JOIN stock_ledgers l ON l.stock_id = s.id AND l.deleted_at IS NULL
GROUP BY s.id, s.stock_qty
HAVING s.stock_qty <> COALESCE(SUM(l.qty), 0);
-- 视图非空 = 账实不一致，必须为 0 行

-- ② 成本对账（REV-2026-10 新增）：台账必有批次耗用明细，且明细数量 = 台账数量
CREATE OR REPLACE VIEW v_stock_cost_check AS
SELECT l.id AS ledger_id,
       l.source_doc_type, l.source_doc_id, l.direction,
       l.qty AS ledger_qty,
       COALESCE(SUM(d.qty), 0)    AS line_qty,
       COALESCE(SUM(d.amount), 0) AS line_amount
FROM stock_ledgers l
LEFT JOIN stock_ledger_lines d ON d.ledger_id = l.id AND d.deleted_at IS NULL
GROUP BY l.id, l.source_doc_type, l.source_doc_id, l.direction, l.qty
HAVING COUNT(d.id) = 0                              -- 无批次明细（BR-ST-19）
    OR l.qty <> COALESCE(SUM(d.qty), 0);           -- 台账数量 ≠ 明细数量合计
-- 视图非空 = 成本明细缺失或数量不符，必须为 0 行
```

补充要求（不改动上面的 SQL）：① 成衣栈需同样的 `v_stock_reconciliation_fg`（表名换 `finished_goods_stocks`）；② 关联 `l.stock_id` 必须带 `l.stock_type` 条件，否则两栈 uuid 可能撞上；③ 视图加 `WHERE s.deleted_at IS NULL` 排除软删；④ 迁移后**立即**跑 `SELECT count(*) FROM v_stock_reconciliation` 与 `SELECT count(*) FROM v_stock_cost_check` 断言为 0，否则闸门 4 不过；⑤ `v_stock_cost_check` 只校验「有无明细 + 数量一致」，**金额一致性由 `ck_stock_ledger_lines_amount`（行级 CHECK）保证**，因为台账已无 `amount` 列（§3.3）。

| 动作 | 触发 | 实现 |
| --- | --- | --- |
| 锁定 `reserve` | 单据 `submit` 时按明细预占 | 插入 `stock_reservations`（`released_at NULL`）+ 条件 UPDATE `locked_qty = locked_qty + n WHERE stock_qty >= locked_qty + n` |
| 释放 `release` | 单据 `reverse` / `cancel` | 置 `released_at = now()` + 条件 UPDATE `locked_qty = locked_qty - n WHERE locked_qty >= n` |
| 释放（审核时） | 出库类单据 `approve` | 出库成功后把对应 reservation 置 `released_at`（数量已实际扣减） |
| 过期释放 | 单据长期 `DRAFT` 超 N 天 | worker 定时任务置 `released_at`；**N 待业务确认**（见 §12 Q-ST04） |

### 4.3 非法动作

| 场景 | 错误码 |
| --- | --- |
| 库存不足 / 可用为负 / 出库量超锁定量；选批后数量不足（**不部分出库**） | `40001` |
| 试图 `UPDATE` 已入库批次的 `unit_cost` / 明细 `amount`；试图给已存在批次改入库价 | `40002` |
| 对账视图非空（结余 ≠ Σ台账） | `40003` |
| **反审核采购单但该缸批次已被下游裁剪消耗**（REV-2026-10） | **`40005`**（批次成本已结转到在产品与成衣成本，冲不回来，必须先冲销下游裁剪单） |
| 反审核领料出库但库存已被下游再消耗 | `40001` |
| 反审核但下游凭证已过账 | `60002`（走凭证红冲） |
| 制单人自审；`reverse/reject/cancel` 未填原因；期末已关账；乐观锁不符 | `10002` / `10003`（关账校验在 finance 侧） |

## 5. 核心流程

### 5.1 面料入库（**= 到货登记 `purchase_arrivals` 的副作用**，REV-2026-10 二次改写：入库入口从「采购单审核」改为「到货登记」，ADR-0015）

> [ADR-0012](../adr/0012-采购原材料批次字段.md) 决策：**入库入口 = 采购单审核**，**不产生独立入库单据，单号 `RC` 已取消**。采购单本体（头：供应商 / 日期 / 发票号 / 仓库 / 到货时间；行：缸号 / 颜色 / **门幅** / **重量** / **匹数** / **用途** / 备注）归 [10-采购](./10-采购.md)；本节只描述**库存侧的副作用**（04 §7.4.3）。

1. 采购员建采购单 → 选供应商、仓库、发票号；逐行录 `material_id` / `color_code` / **`dye_lot_no` 缸号** / **`width_cm` 门幅** / **`weight_kg` 重量** / **`bolt_count` 匹数** / `length_per_bolt_m` / 单价 / **`purpose` 用途** / 备注；`purpose='REWORK_RECEIPT'` 时 **`rework_note` 必填**（哪款哪单返修回来，缺失 → `10006`）。
2. `submit`：校验供应商启用 + 行必填齐全 + `purpose` 与 `rework_note` 一致性；**计量三件套差异 > 5% 只返回警告**（BR-ST-26，`warnings[]`，`can_commit` 不受影响）；`total_length_m` 未填由服务层按 `bolt_count × length_per_bolt_m` 算。
3. **`approve`（权限 `purchase:approve`，制单人 ≠ 审核人）——同一事务内完成 5 件事**（08 R4，跨采购 + 库存 + 往来 + 凭证四个模块但**不跨事务、不异步**）：
   1. **按行建批次**：找或建 `material_stocks` 行（`uq_material_stocks_dim` 冲突则**复用**），写入 `dye_lot_no` / `bolt_no` / `color` / **`width_cm`** / **`weight_kg`** / **`purpose`**；
   2. **定批次成本** `unit_cost = ROUND(到货行金额 ÷ 计量, 6)`（**不含运费**，04 §7.2.1 / ADR-0019）—— **行已存在则只加数量，绝不改 `unit_cost`**（BR-ST-05a / `40002`）；
   3. **写台账**：`stock_ledgers.direction='IN'` + **`stock_ledger_lines` 1 行**（该批次入库定价快照，`amount = ROUND(qty × unit_cost, 4)`）；
   4. **生成应付** `ap_ledgers` + **生成入库凭证**（**按 `purpose` 选科目**：正常 `1405`、返修 `5403`、样布 `6602`，BR-ST-25）；
   5. 更新 `total_amount = ROUND(stock_qty × unit_cost, 4)`，释放锁定。
4. 同缸多匹 → **按 `bolt_count` 拆成多行批次**（`bolt_no` 天然分行，§12 Q-ST09）；若 `stock_qty` 触发 `safety_stock` 提醒 → 发 `stock_low`（BR-ST-14）。
5. **返修布照常入库**：`purpose='REWORK_RECEIPT'` 的批次**与正常布料一样可被裁剪单选批领用**，只是凭证走 `5403`、毛利单独列示（BR-ST-25）。
6. **反审核（权限 `purchase:reverse`）**：① **若该缸批次已被下游裁剪消耗 → 拒绝 `40005`**，必须先冲销下游裁剪单（批次成本已结转到在产品与成衣成本，冲不回来）；② 否则按同一批 `stock_ledger_lines` **逐条反向冲回**；③ 冲销应付与凭证；④ 成本已影响后续出库时提示「必须红冲后续单据，人工确认」（INV-4）。**要改入库价只能红冲本单 + 重新入库，不存在改价路径**（BR-ST-05a ④ / `40002`）。

### 5.2 裁剪耗料出库（`MI-20260815-000088`，由 02-裁剪审核触发）—— **按缸号选批的完整链路**

1. 裁剪单 `approve` 计算耗用量（面料米数 + `usage_qty` + `waste_rate`），生成领料行；行上带**客户指定的 `dye_lot_no` / `bolt_no`**（BR-ST-17 优先级 1，最常见场景）。
2. **按缸号选批 → 条件 UPDATE 扣减 → 写台账 → 写批次耗用明细**，四步缺一不可（骨架照抄 [04 §7.2.2](../04-数据库规范.md)）：

```python
async def select_batches(repo, material_id, need_qty, rule: BatchRule) -> list[BatchPick]:
    # 按规则选批，返回批次耗用计划。数量不足必须抛 STOCK_INSUFFICIENT，不许部分出库
    if rule.explicit:                       # ① 人工指定缸号
        return await repo.pick_specified(repo, material_id, rule.explicit, need_qty)

    stocks = await repo.list_available(     # ② FEFO（有到期日）/ ③ FIFO
        material_id=material_id,
        order_by=("expiry_date", "in_date") if rule == BatchRule.FEFO else ("in_date",),
    )
    picks, remaining = [], need_qty
    for stock in stocks:
        if remaining <= 0:
            break
        take = min(stock.stock_qty, remaining)
        picks.append(BatchPick(stock=stock, qty=take, unit_cost=stock.unit_cost))
        remaining -= take
    if remaining > 0:
        raise BusinessError(ErrorCode.STOCK_INSUFFICIENT, "库存不足")   # 40001，不部分出库
    return picks
```

```python
ledger = await StockLedger.create_issue(
    stock_type="material", direction="OUT",
    source_doc_type="CuttingOrder", source_doc_id=order.id,
)
for pick in picks:                                   # 一个批次一次条件 UPDATE，绝不合并后按均价扣
    await self.session.execute(
        update(MaterialStock)
        .where(MaterialStock.id == pick.stock.id, MaterialStock.stock_qty >= pick.qty)
        .values(
            stock_qty=MaterialStock.stock_qty - pick.qty,
            total_amount=func.round((MaterialStock.stock_qty - pick.qty) * MaterialStock.unit_cost, 4),
            updated_at=func.now(),
        )
    )   # rowcount = 0 → 该批次不足，重新选批或整行拒绝（40001）
    await self.session.execute(
        insert(StockLedgerLine).values(
            ledger_id=ledger.id, material_id=line.material_id, stock_id=pick.stock.id,

            qty=-pick.qty,
            unit_cost=pick.unit_cost,               # 批次实际成本快照，写死不改（BR-ST-04）
            amount=func.round(-pick.qty * pick.unit_cost, 4),
        )
    )
```

3. 裁剪后三类剩余物**口径不同，必须分开处理**（09 §4.2、BR-ST-24）：**正常裁损 `cut_waste_qty` + 尾数 `balance_qty`** 计入损耗、**不扣库存、不写台账**；**布头 `scrap_qty`**（仍可再裁的整段布）**写 `IN` 台账入库，沿用被裁缸号匹号与该批次 `unit_cost`**（必写 1 行明细）；**尾料 `remaining_fabric`** 走红冲入库（**入库沿用原批次 `unit_cost`**）。
4. **成衣完工入库时汇总该扎批次耗用金额**：`SELECT SUM(d.amount) FROM stock_ledger_lines d WHERE ...` → `material_cost`，再加计提工价得成衣单位成本（§5.4）。上面四步构成「这件成衣用了哪几缸布、各多少米、各多少钱」的完整追溯链（ADR-0011 验证方式「成本可追溯率 100%」）。
5. 库存不足 → 整单拒绝（`40001`），**不部分扣减**（BR-ST-22；除非裁剪单显式允许部分，阶段一不允许）。

### 5.3 领辅料出库（`MI`，独立领料）

辅料通常无缸号/匹号，`dye_lot_no` / `bolt_no` 填 `-`（Q-ST05）；按 `material_id` + 仓库 + 色 归集。有保质期的辅料走 **FEFO**，无保质期走 **FIFO**（BR-ST-17）；成本取**所选批次**的 `unit_cost` 并写入明细行。出库给某款号时在 `source_doc_type='MaterialIssue'` 的扩展字段里记 `style_no` 供成本归集（放独立列或 `extra_data`，**不塞进核心可查询字段以外的 JSONB**，04 §8）。

### 5.4 完工入库（`FG-20260816-000201`）

1. 输入：已完工的 `bundle_no` 段（款号 + 色 + 码）、数量；**数量必须是正整数件**（BR-ST-23 —— 尾数已在裁剪段取整为损耗，**不生成尾数入库单据**，非正整数 → `10001`）。
2. 成本（BR-ST-07，**批次实际成本口径**）：
   - `material_cost` = 该扎 `bundle_no` 段对应耗料出库的 `Σ(stock_ledger_lines.amount)`（跨批次**求和不平均**）
   - `labor_cost` = 该扎在 [04-计件](./04-计件.md) 已计提的工价金额（读 `piecework_logs` 净额，不重算；计件只按整件，天然无尾数，09 §4.2）
   - `unit_cost = ROUND((material_cost + labor_cost) / qty, 6)`，拆存 `material_cost` / `labor_cost`；**入库即快照，之后不可改**
3. 写 `IN` 台账 + 落 `finished_goods_stocks` 行；INV-6 结转校验：`打菲数量 ≥ 已完工入库数量 + 在制数量`（**两侧均按整件**），违反返回裁剪/打菲段的错误码。**尾数既不来自上游也不由本单产生**，不参与结转校验。
4. 工价尚未结算时阶段一**允许入库**，按已结算金额计，差额在下一批或盘点时补，**差异写入 `remark`**，不阻塞生产（见 §12 Q-ST02）。

### 5.5 销售出库（`SH-20260820-000067`）

1. 按款号 + 色 + 码 + 仓库出库，优先扣**已锁定**批次（销售单 `submit` 时已锁定）。
2. `approve` 同一事务：扣 `finished_goods_stocks.stock_qty` + `OUT` 台账 + 释放锁定 + 生成应收 + 出库凭证。成本从 `finished_goods_stocks.unit_cost`（快照）出账，按 BR-ST-20 计入毛利。
3. 反审核：加回库存 + 释放锁定 + 冲应收与凭证；已收款需先冲销核销（08 §2.6）。

### 5.6 调拨（`TR-20260816-000007`）

调出仓减、调入仓加，成本**结转不变**（`unit_cost` 随批次整行搬移），台账成对生成（`OUT` + `IN`），明细也成对且 **`OUT` 与 `IN` 明细的 `unit_cost` 逐行相等**（BR-ST-21：调拨只改仓库，批次成本随批次走）。调入维度不匹配时必须建新行（`dye_lot_no` / `bolt_no` 不同不能并入同一行；同缸不同价也必须分行）。

### 5.7 盘点（`SC-20260831-000003`）

1. 仓管按仓库 / 物料 / 批次录实盘数（`actual_qty`），系统算差异 `diff_qty = actual - stock_qty`。
2. 盘点单**不直接改库存**（BR-ST-13）。
3. `approve`：按差异生成台账（`direction='ADJUST'`，盘盈 `IN` 正、盘亏 `OUT` 负）+ 过盘点凭证（盘盈借 存货 / 贷 待处理财产损溢；盘亏反向）。
4. **盘盈批次成本**（已由 ADR-0011 §2 决策）：取**同物料同缸号**最近批次的 `unit_cost`；无同缸则取**同物料最近批次**成本并写 `remark` + 日志（BR-ST-05a ③）。
5. **盘亏**按**原批次** `unit_cost` 写负向明细（成本不被盘亏改写）。
6. **整件差异处理（REV-2026-10）**：成衣栈按**整件**盘，`diff_qty` 取整；**不足一件的余数直接报损、不入库**（不足件不成衣，09 §4.2）——不生成 `IN` 台账、不改 `stock_qty`，在盘点单 `remark` 记「不足一件，按损耗报损」并计入损耗统计。物料栈不受此约束（`numeric(14,3)`，BR-ST-23）。
7. 反审核：反向台账 + **按同一批明细逐条反向冲回** + 冲凭证，盘点记录与实盘数保留。

## 7. 并发与幂等

### 7.1 出库防超卖：条件 UPDATE（首选，10 §5.2 强制）

```sql
-- 单批次单次原子扣减，绝不出现负数，也绝不跨批次合并扣（BR-ST-18）
UPDATE material_stocks
   SET stock_qty = stock_qty - :n,
       total_amount = ROUND((stock_qty - :n) * unit_cost, 4),
       version = version + 1,
       updated_at = now(), updated_by = :operator
 WHERE id = :stock_id
   AND deleted_at IS NULL
   AND stock_qty - locked_qty >= :n;     -- 判定用可用量（BR-ST-02）
-- rowcount = 0 → 该批次不足 → 40001（不部分出库，BR-ST-22）
```

判定条件必须用**可用量** `stock_qty - locked_qty >= n`（不是 `stock_qty >= n`，BR-ST-02）；不做「先查后改」（查与改之间有窗口，条件 UPDATE 压进一条语句）；`total_amount` 用**扣减后**的 `stock_qty` 与**该批次恒定的 `unit_cost`** 重算，否则冗余列与结存不一致；条件 UPDATE 成功后再插台账与 `stock_ledger_lines` 且同事务，任一步失败整体回滚（明细里 `unit_cost` 取扣减前读到的批次成本快照）。

### 7.2 `SELECT ... FOR UPDATE` 的适用场景

| 场景 | 手段 | 理由 |
| --- | --- | --- |
| **选批 → 扣减**（REV-2026-10） | `select_batches` 后逐批次条件 UPDATE；条件不满足即 `40001` | 批次成本**不需要**串行重算（已撤销移动加权）；但要保证「选到的量还在」，靠条件 UPDATE 而不是行锁 |
| 入库定价 | 计算 `unit_cost` 只依赖采购单快照，**不加锁**；只有写结存行时条件 UPDATE | 批次成本互不影响，两笔并发入库不会互相污染 |
| 库存与台账 + 明细一起写 | 条件 UPDATE 后插台账再插明细 | 单语句原子性够用；插入同事务 |
| 调拨 | 先锁调出行，再锁调入行 | 固定加锁顺序，避免两笔对向调拨互相等锁（死锁） |
| 盘点审核 | 锁全部涉及行，**按 id 升序** | 批量锁必须固定顺序，否则死锁 |

### 7.3 并发场景 K1~K8（[10 §5.2](../10-测试规范.md) 必测；K6~K8 为 REV-2026-10 新增）

| # | 场景 | 期望 | 兜底 |
| --- | --- | --- | --- |
| K1 | **出库 20 并发**：库存 10，20 个并发各要 1 | 成功 10 个、失败 10 个（`40001`）、`stock_qty = 0`、**绝不为负**、台账 10 条 `OUT` | 条件 UPDATE `rowcount` |
| K2 | **入库 20 并发**（同批次，同价） | 全部成功；**`unit_cost` 始终等于第一次入库确定的值（不变）**；`stock_qty` = 20 笔之和；`total_amount = ROUND(stock_qty × unit_cost, 4)` 精确；写 20 条 `IN` 台账 + 20 条明细 | 条件 UPDATE + `ck_piecework_...` 同款做法：成本列无写路径 |
| K3 | **扣减与锁定竞争**：锁定 8 后出库 10 | 失败 `40001`（可用仅 2），不得把锁定部分扣掉 | 条件含 `locked_qty` |
| K4 | **同单据重复审核**（双击 / 重试） | 只加一次库存、只写一次台账与一批明细、凭证只 1 张 | 状态机 + `uq_stock_ledgers_source` + `uq_stock_ledger_lines_batch` + `Idempotency-Key` |
| K5 | **对向调拨** | 不死锁；两笔都成功或一方明确失败 | 固定加锁顺序 |
| **K6** | **同批次被多单同时扣减**（REV-2026-10）：批次 A 结存 10，3 张单各要 6 米，并发审核 | 最多 1 张成功（或先到者扣 6，第二张按剩余 4 报 `40001`）；**结存绝不为负**；成功张数的 `Σ abs(明细.qty) = 扣减总量`；每张单的明细各写各的批次快照，互不串价 | 逐批次条件 UPDATE `WHERE stock_qty - locked_qty >= n` + `CHECK (stock_qty >= 0)` |
| **K7** | **选批与扣减之间的并发**（REV-2026-10）：两单同时对同一批次跑 `select_batches` | 选批结果可能同时认为够（读到同一 `stock_qty`），但**扣减阶段**条件 UPDATE 保证只有一方成功；失败方整单回滚，不留半条明细 | 条件 UPDATE 在事务内；`rowcount=0` → 抛 `40001` 回滚 |
| **K8** | **反审核按同一批明细逐条反向冲回**（REV-2026-10）：一张跨 3 批次的耗料单 `approve` 后 `reverse` | 生成 1 条反向台账 + **3 条反向明细**，`reversal_of_id` 逐条指回原明细；`Σ反向明细.qty = -Σ原明细.qty`；3 个批次结存**逐一**回到出库前；`v_stock_reconciliation` 与 `v_stock_cost_check` 均回到 0 行；**原始台账与明细保留**（INV-4 / 08 R5） | 明细 `reversal_of_id` 自引用 FK + 同事务条件 UPDATE |

**并发测试纪律**（10 §5.4）：真并发（`asyncio.gather` + 每任务独立 session）；断言最终 `stock_qty` 与成功/失败条数，不接受「大概对」；只靠业务层 `if` 检查不算兜底（条件 UPDATE `rowcount` + 唯一约束才算）。
