# 07 销售模块

> 销售订单 → 发货/销售出库 → 扣成衣库存 → 生成应收 → 生成出库凭证，是 P4/P5 阶段的现金入口。
> 关联规范：[09 领域术语 §1.1/§1.6/§1.7](../09-领域术语与编码规则.md)、[00 业务蓝图 §5.1/INV-3/INV-4](../00-项目概述与业务蓝图.md)、[04 数据库 §2/§3/§4/§7.3/§7.4](../04-数据库规范.md)、[05 接口 §3/§4/§6/§7](../05-接口设计规范.md)、[07 认证权限 §2.2](../07-认证与权限规范.md)、[08 状态机 §1.1/§2.6](../08-单据状态机规范.md)、[10 测试 §3/§5](../10-测试规范.md)。

## 1. 模块职责与边界

| 项 | 内容 |
| --- | --- |
| 负责 | 销售价目表、客户订单（含**尾批零星发货行**与变更版本）、发货/销售出库单、扣成衣库存、销售台账与销量报表 |
| 不负责 | 成衣入库（库存模块 `finished_goods_stocks`）、应收核销（08 客户与往来）、凭证分录内容（09 财务与凭证） |
| 上游 | 库存模块（成衣 `available_qty`）、[01 基础资料](./01-基础资料.md)（`style_no`、`customers`）、`sale_prices` |
| 下游 | `ar_ledgers` 应收流水、出库凭证、销售台账 / 销量 / 订单进度报表；库存扣减由 [06 库存](./06-库存.md) 执行（单据归属冲突见 [Q-S-10](#12-待决问题)） |
| 硬边界 | 本模块**只创建**应收与出库凭证（`DRAFT`），**不过账**；核销与过账分别属于 08、09 模块 |
| 关键不变量 | INV-3（价目变更只影响未来订单）、INV-4（成衣批次成本不可篡改，只走红冲/盘点）、INV-7（软删）、INV-8（权限双校验）；凭证借贷平衡 INV-5 由 [09 财务与凭证](./09-财务与凭证.md) 保证 |

单据号（09 §2.1）：销售订单 `sales_orders` = `SO-YYYYMMDD-NNNNNN`；发货/销售出库单 `sales_deliveries` = `SH-YYYYMMDD-NNNNNN`；订单变更 `sales_order_revisions` = `RV-YYYYMMDD-NNNNNN`。

> ✅ 单据归属（REV-2026-10 定）：**发货单 `SH` 归本模块**（销售），审核动作 `sales:ship` → `sales:approve`，权限 `sales:*`；审核时触发 06 库存模块的**扣减成衣库存 + 生成应收 + 生成出库凭证**。
> 09 §2.1 已修订为「发货单 `SH`（发货即出库）」，取消独立「销售出库单」，本文口径即为规范口径。

## 2. 业务规则

| # | 规则 | 落地方式 |
| --- | --- | --- |
| S-01 | 订单按「款号 + 色 + 码」分行，行集合 = `color` × `size` | `uq_sales_order_lines_doc_color_size(sales_order_id, color, size)` |
| S-02 | `currency` 阶段一恒 `CNY`、`exchange_rate` 恒 `1`（00 §3.2 不做跨境） | `CHECK (currency = 'CNY' AND exchange_rate = 1)` |
| S-03 | 行 `amount = round_half_up(order_qty × sale_price, 2)`（舍入到分）；表头 `total_amount = Σ 行 amount`，服务端算，前端传值忽略 | service `_calc_line_amount` |
| S-04 | 舍入尾差 `rounding_diff = total_amount - Σ(qty × sale_price)`（未舍入值），非 0 时凭证生成尾差分录 | 09 §3 `6051.02 / 6602.01`，归属见 [Q-S-05](#12-待决问题) |
| S-05 | 价目维度 = `customer_id + style_no + color_group`（09 §1.1 色组，`'*'` 为默认价），`sale_price` 为 `numeric(12,6)` | `sale_prices` 唯一索引 |
| S-06 | **价目变更只影响未来订单**（INV-3）：用 `effective_from`/`effective_to` 区间，调价 = 结束旧行 + 插新行，**永不 UPDATE `sale_price`** | 订单行 `sale_price` 落库即快照 |
| S-07 | 订单行可手工覆盖单价，但必须填 `price_override_reason`，且覆盖前后的价目快照写入 `sales_order_revisions` | 审核时必填校验 |
| S-08 | 发货量 `delivery_qty ≤ order_qty - delivered_qty - fulfilled_qty`；`fulfilled_qty`（已结清）由 08 模块核销回写，订单结清后不可再发货 | 条件 UPDATE，见 §7 |
| S-09 | 出库审核扣 `finished_goods_stocks`（FINISHED 栈），`stock_qty` 与 `locked_qty` 同时减；同事务生成 `ar_ledgers`（`source_doc_type='SalesDelivery'`）+ 出库凭证（`DRAFT`，`source_type='SALES_DELIVERY'`） | 库存模块 `issue_for_sale`、08 §2.6、09 §4 |
| S-10 | **整件口径 + 尾批零星发货行**（REV-2026-10，09 §4.2）：生产端**尾数（`balance_qty`，不足一件的余量）不入库、不计件**，所以**成衣库存里只有整件**（[06 库存](./06-库存.md) BR-ST-23）。由此两条硬约束：① `order_qty` 与 `delivery_qty` **必须为正整数件**（`CHECK (qty > 0 AND qty = trunc(qty))`），**非正整数 → `10001`**；**发不出不足一件的数量**，`< 1` 件的订单行与发货行一律拒绝。② `is_balance_line` 语义改为「**尾批零星发货行**」——**数量小但仍是整数件**（如订单 1050 件的末批只发 8 件，`order_qty = 8`），只用于报表分组与对账标识，**不做任何数量口径放宽** | 行级布尔字段 `is_balance_line`；DB `CHECK` + `10001` |
| S-11 | 订单变更（改数量/改交期）必须走变更申请：新 `revision_no` + 必填 `reason`，**不原地覆盖已审核数据**；变更后 `order_qty` 不得低于 `delivered_qty + fulfilled_qty`（否则报 `10001`） | `sales_order_revisions` |
| S-12 | 成衣出库成本取 `finished_goods_stocks.unit_cost` 快照进 `sales_delivery_lines.unit_cost/cost_amount`（INV-4），事后不可改 | 落库即快照 |
| S-13 | 出库单 `cancel` 仅限 `DRAFT`/`REJECTED`；已审核只能 `reverse` | 08 §1.1 R6 |
| S-14 | 出库审核时 `doc_date` 所属会计期间必须未关账 | 09 §4 期间校验，报 `10002`（码缺口见 Q-S-07） |

## 4. 单据与状态机

`SalesOrder` 迁移（动作名取 08 §1.1）：

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `create` | — | DRAFT | `sales:order:create` | 客户与款号启用；行非空 | 生成 `doc_no`；按生效日价目取 `sale_price` 快照；算 `total_amount`（S-03） |
| `update` | DRAFT / REJECTED | 同 | `sales:order:create` | 改 `order_qty` 不得 < `delivered_qty`（S-11）；改价必填原因（S-07） | 重算行金额与表头；写 `document_logs`（04 §7.4） |
| `submit` | DRAFT / REJECTED | SUBMITTED | `sales:approve` ⚠️ | 行非空；`delivery_date >= doc_date`；价目存在 | 写日志 |
| `approve` | SUBMITTED | APPROVED | `sales:approve` | 制单人 ≠ 审核人（08 §4） | 写日志；价目快照生效 |
| `reject` | SUBMITTED | REJECTED | `sales:approve` ⚠️ | **必填原因** | 写日志 |
| `withdraw` | SUBMITTED | DRAFT | `sales:order:create` | 撤回人 = 制单人 | 写日志 |
| `reverse` | APPROVED | SUBMITTED | `sales:approve` ⚠️ | **必填原因**；已有发货单 → 拒绝（`50001`） | 写日志；`revision_no` 不回退 |
| `cancel` | DRAFT / REJECTED | CANCELLED | `sales:order:create` | 必填原因 | 软删级联置 `deleted_at`（INV-7），终态 |

⚠️ 07 §2.2 仅登记 `sales:read` / `sales:order:create` / `sales:ship` / `sales:approve`，缺 `submit/reject/reverse/cancel` 独立权限点。本文暂把 `submit/reject/reverse` 映射到 `sales:approve`，缺口见 [Q-S-03](#12-待决问题)。

`SalesDelivery` 迁移（严格照 08 §2.6）：

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 | `reverse` 反向副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| `create` | — | DRAFT | `sales:ship` | 订单 `APPROVED`；**`delivery_qty` 必须为正整数件**（S-10，非正整数 → `10001`）；`delivery_qty` ≤ 可发量（S-08） | 生成 `doc_no`；锁定成衣批次（`stock_reservations`） | 释放锁定 |
| `update` | DRAFT / REJECTED | 同 | `sales:ship` | 数量重新校验（S-08 + **正整数件 S-10**） | 重算金额与成本 | — |
| `submit` | DRAFT / REJECTED | SUBMITTED | `sales:approve` ⚠️ | 可用库存 ≥ 发货量 | 写日志 | — |
| `approve` | SUBMITTED | APPROVED | `sales:approve` | ① 制单人 ≠ 审核人；② 期间未关账（S-14）；③ 可用库存足，不足 → `40001` | ① 扣 `finished_goods_stocks`（`stock_qty`/`locked_qty`）；② 写 `stock_ledgers`；③ `delivered_qty` 条件 UPDATE 累加；④ 生成 `ar_ledgers`；⑤ 生成出库凭证 `DRAFT`（S-09） | ① 加回库存 + 反向台账；② `delivered_qty` 减回；③ 冲销 `ar_ledgers`；④ 删除未过账凭证 / 已过账则红冲（08 R5） |
| `reject` | SUBMITTED | REJECTED | `sales:approve` ⚠️ | 必填原因 | 释放锁定 | — |
| `withdraw` | SUBMITTED | DRAFT | `sales:ship` | 撤回人 = 制单人 | 写日志 | — |
| `reverse` | APPROVED | SUBMITTED | `sales:approve` ⚠️ | **必填原因**；**已有核销 → 拒绝**（08 §2.6，报 `50001`） | 写日志 | 与 `approve` 严格对称 |
| `cancel` | DRAFT / REJECTED | CANCELLED | `sales:ship` | 必填原因 | 释放锁定；终态 | — |

凭证侧约束（09 §4）：出库单 `reverse` 前，出库凭证必须**先**被红冲；凭证已过账未红冲时，源单据反审核直接拒绝（`60002`）。

## 5. 核心流程

1. **建价目**：按 `customer + style_no + color_group` 写 `sale_prices`；调价 = 结束旧区间 + 插新行，永不 UPDATE `sale_price`（S-06）。
2. **录订单**：`POST /sales-orders`，行按 `color × size` 展开；服务端取生效日价目快照（INV-3），`amount` 服务端算。
3. **改订单**：仅 DRAFT/REJECTED 走 `PATCH`；已审核走第 5 步。
4. **发货出库**：`POST /sales-deliveries`（传 `sales_order_line_id + batch_no + delivery_qty`）→ 校验可发量并锁定批次 → `submit` → `approve` 同事务完成 5 件事（S-09），**审核 = 生效**（08 R4）。
5. **已审核订单变更**：`POST /sales-orders/{id}/revisions`（`change_type` + `reason` 必填）→ 校验新 `order_qty >= delivered_qty + fulfilled_qty`（S-11）→ 写新 `revision_no` 行并 PATCH 生效值 → 金额增加时由 08 重算应收；若已发货，差额**追加新出库单**，不允许直接改已审核金额。
6. **尾批零星发货与毛利**：`is_balance_line=true` 的**尾批零星发货行**（末批只有几件，如订单 1050 件末批 `order_qty=8`）**照常走 S-08/S-09**，数量**仍是正整数件**，**不做任何数量口径放宽**；非正整数（0.5 / 0 / 负数）→ `10001`。**不存在可发货的 `< 1` 件尾单**——因为生产端尾数不入库，成衣库存里只有整件（09 §4.2）。毛利 = `total_amount - total_cost_amount`，成本取批次快照（S-12）不重算。

## 7. 并发与幂等

| 风险 | 场景 | 方案 | 配套测试 |
| --- | --- | --- | --- |
| **并发超发** | 同一订单行 20 并发各发 5 件，可发量 60 | 条件 UPDATE 原子累加：<br>`UPDATE sales_order_lines SET delivered_qty = delivered_qty + :n, version = version + 1 WHERE id = :id AND deleted_at IS NULL AND order_qty - delivered_qty - fulfilled_qty >= :n`<br>`rowcount == 0` → 报 `10001`（可发量不足） | TC-S-09 |
| **跨行并发** | 同一订单多行并发导致表头合计错乱 | 审核时先 `SELECT ... FROM sales_orders WHERE id = :id FOR UPDATE` 再逐行累加 | TC-S-09 |
| **同单重复审核** | 双击审核 / 网关重试 | 乐观锁 + 状态条件 `WHERE id = :id AND status = 'SUBMITTED' AND version = :v`，`rowcount == 0` → `10003`（08 R3） | TC-S-10 |
| **重复创建出库单** | 客户端重试 | `Idempotency-Key`（05 §5）；未传时业务唯一键 `(sales_order_line_id, batch_no, doc_date)`，命中返回首次结果 HTTP 200 | TC-S-11 |
| **库存被他人先扣** | 出库审核时库存不足 | 扣减走库存模块条件 UPDATE，失败 → `40001`，本事务整体回滚（无半截扣减） | TC-S-06 |
| **价目被并发改价** | 建单时正好调价 | 建单读价目在事务内 `FOR SHARE`，取到区间后立即快照；调价只插新行（S-06） | TC-S-02 |
| **发货凭证重复生成** | 审核事务重试 | 凭证 `uq_vouchers_source (source_type, source_id)` 唯一索引兜底，重复插入转幂等 | 09 §8 |

并发纪律（10 §5.4）：每任务独立 session，`asyncio.gather` 真并发，断言最终条数与失败类型；**只靠业务层检查 = 未通过**。
