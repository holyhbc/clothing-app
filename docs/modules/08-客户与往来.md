# 08 客户与往来模块

> 应收应付台账 + 收付款 + 核销 + 对账单 + 账龄分析 + 银行流水对账（阶段二），是 P4 阶段「客户对账能对平」的落点；客户/供应商主数据由 [01 基础资料](./01-基础资料.md) 拥有。
> 关联规范：[09 领域术语 §1.7](../09-领域术语与编码规则.md)、[00 业务蓝图 §5.1/INV-7/INV-8](../00-项目概述与业务蓝图.md)、[04 数据库 §2/§3/§4/§7.3/§7.4](../04-数据库规范.md)、[05 接口 §3/§4/§6/§7](../05-接口设计规范.md)、[07 认证权限 §2.2/§3.2](../07-认证与权限规范.md)、[08 状态机 §1.1/§2.7](../08-单据状态机规范.md)、[10 测试 §3/§5](../10-测试规范.md)。

## 1. 模块职责与边界

| 项 | 内容 |
| --- | --- |
| 负责 | `ar_ledgers` / `ap_ledgers` 往来台账、`receipts` / `payments` 收付款、`settlements` 核销、`statements` 对账单、账龄分析、银行流水对账（阶段二预留） |
| 共管 | `customers` / `suppliers` **主数据由 [01 基础资料](./01-基础资料.md) 拥有**（该文 §3.5、§6 已定义 `code`/`settlement_period_days` 与 `base:*` 权限）；本模块只读引用并定义往来扩展字段（账期、结算方式、信用额度、默认仓库、价格表关联），字段名差异见 [Q-F-07](#12-待决问题) |
| 不负责 | 应收应付的**发生**（由销售出库 / 采购入库在各自模块审核时创建流水）、凭证过账（09 财务与凭证） |
| 上游 / 下游 | 上游：销售出库（`SalesDelivery`）、采购入库（`PurchaseReceipt`）、工资发放（`PayrollSheet`）审核时写流水；下游：[09 财务与凭证](./09-财务与凭证.md) 收付款凭证 + 账龄与往来对账报表 |
| 硬边界 | 往来流水**只增不改余额语义**：`balance` 由 `occur_amount - settled_amount` 计算得出，不允许直接写 `balance` |
| 关键不变量 | INV-5（凭证借贷平衡，由 09 保证）、INV-7（软删）、INV-8（权限双校验）、AGENTS §2.2「审核动作必填原因 + 记日志」 |

单据号（09 §2.1，REV-2026-10 已修订）：收款单 `receipts` = `SK-YYYYMMDD-NNNNNN`；付款单 `payments` = `PY-YYYYMMDD-NNNNNN`；核销单 `settlements` = `ST-YYYYMMDD-NNNNNN`；对账单 `statements` = `SN-YYYYMM-NNNN`（09 §2.1 已登记）。

> ✅ 09 §2.1 收款单前缀 `RC` 与采购入库单 `RC` 重复的问题**已于 2026-10 修订**：收款单改用 `SK`，采购入库保留 `RC`；`ST`（核销）、`SN`（对账单）已正式登记。见 09 §2.1。

## 2. 业务规则

| # | 规则 | 落地方式 |
| --- | --- | --- |
| F-01 | 客户与供应商编码 `code`（01 §3.5）全厂唯一，转大写存储；往来流水一律用 `party_id` 引用，不复制编码 | `uq_customers_code` / `uq_suppliers_code` |
| F-02 | 账期天数（客户侧 `credit_days` / 供应商侧 `payment_period_days`）与 `credit_limit`（信用额度）非空；`credit_limit` 阶段一**只做提醒不做阻断**（阻断口径见 Q-F-01） | 字段必填 + 报表标记 |
| F-03 | 结算方式 `settlement_method`：`PREPAY`（先款后货）/ `COD`（货到付款）/ `NET`（月结）；`PREPAY` 时销售出库审核需校验已全额核销（Q-S-01 联动） | 枚举，见 Q-F-02 |
| F-04 | `ar_ledgers` / `ap_ledgers` **两张独立表**，不做方向字段：`occur_amount` 一律正数存储含义（应收 = 客户欠款 / 应付 = 我方欠款），`balance` **只读派生** = `occur_amount - settled_amount` | 禁止直接写 `balance`（DB 生成列或 service 双重保护） |
| F-05 | `due_date` = 发生日 + 账期天数（客户 `credit_days` / 供应商 `payment_period_days`）；`aging_days` = `due_date` 与当前日期差（未到期为负），**存储值 + 报表实时重算双口径** | 存储 `aging_days` 供列表展示，报表用 SQL 现算 |
| F-06 | 收付款单审核后：① 写往来流水（未核销状态）；② 生成凭证 `DRAFT`（`source_type='RECEIPT'/'PAYMENT'`） | 08 §2.7 |
| F-07 | **核销额 ≤ 未核销额**，且必须 `> 0`；支持部分核销 | DB CHECK + 条件 UPDATE，见 §7 |
| F-08 | 核销分阶段：阶段一仅核销 `receipts`/`payments` ↔ `ar_ledgers`/`ap_ledgers`（不产生独立凭证，因为收付款凭证已入账）；阶段二支持预收/预付冲应收 | 08 §2.7「核销产生分录（可选阶段二）」 |
| F-09 | 反审核收付款单时**已有核销 → 拒绝**（08 §2.7），报 `50001` | service 前置校验 |
| F-10 | 对账单按 `(party_id, period)` 唯一；必须含「期初 + 本期发生 + 本期核销 = 期末」四栏且**能对平**（对平脚本见 §7） | `uq_statements_party_period` + 发布前对账测试 |
| F-11 | 账龄分组：未到期 / 0-30 / 31-60 / 61-90 / 90+ 天，边界按 `aging_days` 含端点 | SQL `CASE` 分组 |
| F-12 | 银行账户 `bank_accounts` 与流水 `bank_transactions` + 对账 `bank_reconciliations` **阶段二只建表不实现**（00 §3.2 范围外） | 表结构 + 预留接口 |
| F-13 | 客户/供应商被单据引用后**不可删除**，只能停用 `is_active=false`（`20003`）；全表金额一律 `numeric(18,4)`、响应统一字符串（05 §3），禁止 float（03 §1.1 规则 8） | 04 §6 软删 + 全表约束 |

## 4. 单据与状态机

`Receipt` / `Payment`（严格照 08 §2.7，动作名取 08 §1.1）：

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 | `reverse` 反向副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| `create` / `update` | — / DRAFT / REJECTED | DRAFT / 同 | `finance:receipt` / `finance:payment` | 往来单位启用；`amount > 0`；`method` 合法；改金额不得 < `settled_amount` | 生成 `doc_no`；重算 | 软删 |
| `withdraw` / `cancel` | SUBMITTED / DRAFT / REJECTED | DRAFT / CANCELLED | 同上 | 撤回人 = 制单人；`cancel` 必填原因 | 写日志 | 终态 |
| `submit` | DRAFT / REJECTED | SUBMITTED | 同上 | 期间未关账（09 `accounting_periods`，09 §4） | 写日志 | — |
| `approve` | SUBMITTED | APPROVED | 同上 | ① 制单人 ≠ 审核人（08 §4）；② 期间未关账；③ 信用额度（Q-F-01） | ① 写往来流水（未核销，F-06）；② 生成收付款凭证 `DRAFT`（借银行存款/贷应收账款，收款；反向付款） | ① 冲销往来流水（置 `CANCELLED`，保留记录）；② 冲销凭证 |
| `reject` | SUBMITTED | REJECTED | 同上 | **必填原因** | 写日志 | — |
| `reverse` | APPROVED | SUBMITTED | 同上 | **必填原因**；**已有核销 → 拒绝**（F-09，报 `50001`） | 写日志 | 与 `approve` 严格对称（08 R5） |
| `cancel` | DRAFT / REJECTED | CANCELLED | 同上 | 必填原因 | 终态 | — |

⚠️ 07 §2.2 往来段只有 `finance:ar:read` / `finance:ap:read` / `finance:receipt` / `finance:payment` / `finance:settle` / `finance:statement`，**没有 `finance:receipt:submit/reject/reverse` 与 `finance:payment:submit/reject/reverse` 独立点**。本文把收付款单的 `submit/approve/reject/reverse` 全部映射到 `finance:receipt`（收）/ `finance:payment`（付），缺口见 [Q-F-03](#12-待决问题)。

`Settlement` 核销（08 §2.7：核销**不是** `document_status` 迁移，而是往 `settled_amount` 写值的事实记录，故本表无「起始/目标」列）：

| 动作 | 权限点 | 前置校验 | 副作用 | 反向 |
| --- | --- | --- | --- | --- |
| `create` | `finance:settle` | 收付款单 `APPROVED`；`settled_amount + settle_amount <= amount`（F-07）；`sum(明细) == total_amount`；期间未关账 | 台账 `settled_amount` 条件累加；收付款单 `settled_amount` 累加；`fulfilled_qty` 回写 07 | **无反核销动作**：只能对收付款单 `reverse` 或新增反向核销（见 Q-F-06） |
| `cancel` | `finance:settle` | 仅当来源收付款单仍 `DRAFT` 时允许（正常链路不会命中） | `deleted_at` 软删 + 双侧 `settled_amount` 减回 | — |

`Statement` 对账单：`create`（`finance:statement`，DRAFT）→ `submit`（发出，`SUBMITTED`）→ `update`（仅 DRAFT）→ `cancel`（必填原因）。对账单**不参与记账**，无审核动作。

## 5. 核心流程

1. **建往来单位**：走 [01 基础资料](./01-基础资料.md) §6（`code` 唯一）；本模块只维护扩展字段（结算方式/账期/信用额度/默认仓库/价格表关联）；被引用后只能停用（F-13）。
2. **业务发生挂账**：销售出库审核 → 写 `ar_ledgers`（`source_doc_type='SalesDelivery'`）；采购入库/工资单审核 → 写 `ap_ledgers`。本模块不生成流水，只被回调。
3. **收单**：`POST /receipts`（或 `/payments`）→ `submit` → `approve` 同事务写往来流水 + 生成凭证（F-06），**审核 = 生效**（08 R4）。
4. **核销**：选收付款单 + 选待核销台账（按 `due_date` 升序，支持手工指定）→ 校验每笔 `settle_amount ≤ 台账未核销额` 且 `Σ明细 == total_amount`（F-07）→ 条件 UPDATE 累加台账与单据的 `settled_amount`（§7）；阶段一**不产生独立凭证**（F-08），因为收付款凭证已确认银行存款/应收账款。
5. **对账单**：按 `party_id + period` 生成，逐单明细 = 该期间所有台账（含期初行）；`closing = opening + occur - settle`（F-10）；发出前跑对平脚本。
6. **账龄分析**：按 `due_date` 现算 `aging_days`，分未到期 / 0-30 / 31-60 / 61-90 / 90+（F-11）；同时回写台账存储值。
7. **反审核收付款**：`reverse` 必填原因；若 `settled_amount > 0` 直接拒绝（F-09）；否则冲销流水 + 凭证。
8. **银行对账（阶段二）**：导入 `bank_transactions` → 与 `bank_flow_no` 匹配 → 记 `is_reconciled`；本期只留表与接口。

## 7. 并发与幂等

| 风险 | 场景 | 方案 | 配套测试 |
| --- | --- | --- | --- |
| **并发核销同一笔款** | 同一 `receipt_id` 两笔核销并发，都基于 `amount=1000, settled=800` | 条件 UPDATE 原子累加：<br>`UPDATE receipts SET settled_amount = settled_amount + :n, version = version + 1 WHERE id = :id AND status = 'APPROVED' AND settled_amount + :n <= amount`<br>`rowcount == 0` → 报 `10002`（核销超额） | TC-F-08 |
| **并发核销同一台账** | 两个收付款单同时核销同一笔应收 | 台账同样用条件 UPDATE `settled_amount = settled_amount + :n WHERE id = :id AND settled_amount + :n <= occur_amount`，`rowcount == 0` → 拒绝；**两侧累加必须同事务同顺序**（先单据后台账，失败整体回滚） | TC-F-09 |
| **重复提交核销** | 网关重试 / 双击 | `Idempotency-Key`（05 §5）+ `uq_settlement_details_line(settlement_id, line_no)`；同键同 body 返回首次结果 HTTP 200 | TC-F-10 |
| **重复挂账** | 出库单审核事务重试 | `uq_ar_ledgers_source (source_doc_type, source_doc_id)` 唯一索引兜底 | TC-F-10 |
| **重复审核收付款** | 双击审核 | 乐观锁 + 状态条件，`rowcount == 0` → `10003`（08 R3） | TC-F-11 |
| **对账单并发生成** | 同客户同期间两人同时生成 | `uq_statements_party_period (party_id, period)`；冲突转「返回既有单」而非报错 | TC-F-12 |

### 对平脚本（发布前必跑，10 §1 对账测试）

| 检查 | SQL 判定 | 通过标准 |
| --- | --- | --- |
| 台账余额自洽 | `occur_amount - settled_amount <> balance` | 0 行 |
| 核销双边一致 | `SUM(settlement_details.settle_amount) GROUP BY ledger_id` ≠ 台账 `settled_amount` | 0 行 |
| 收付款单核销一致 | `receipts.settled_amount` ≠ 其 `settlement_details` 汇总 | 0 行 |
| 对账单四栏对平 | `opening_balance + occur_amount - settle_amount <> closing_balance` | 0 行 |
| 跨期连续 | `statements[t].closing_balance <> statements[t+1].opening_balance` | 0 行 |

## 8. 索引与查询场景

| 场景 | SQL 条件 | 索引 |
| --- | --- | --- |
| 往来单位按编码/名称 | `WHERE deleted_at IS NULL AND (code = ? OR name LIKE ?)` | `uq_customers_code` / `uq_suppliers_code` + `idx_customers_name (name)` |
| 台账按往来单位 + 未核销（含账龄分组） | `WHERE party_id = ? AND settled_amount < occur_amount AND status <> 'CANCELLED' GROUP BY CASE WHEN due_date >= :as_of ... END` | `idx_ar_ledgers_party_unsettled (party_id, due_date) WHERE deleted_at IS NULL AND settled_amount < occur_amount` |
| 收付款单按往来单位 + 日期 | `WHERE party_id = ? AND doc_date BETWEEN ? AND ? ORDER BY doc_date DESC` | `idx_receipts_party_date (party_id, doc_date DESC)` |
| 核销单按收付款单 / 单据号 | `WHERE receipt_payment_id = ?` / `WHERE doc_no = ?` | `idx_settlement_details_receipt (receipt_payment_id)` + `uq_settlements_doc_no` |
| 对账单按客户 + 期间 / 明细按单 | `WHERE party_id = ? AND period = ?` / `WHERE statement_id = ? ORDER BY line_no` | `uq_statements_party_period (party_id, period)` + `idx_statement_lines_doc (statement_id)` |
| 银行流水去重导入 | `WHERE bank_account_id = ? AND flow_no = ?` | `uq_bank_transactions_flow` |
| 单据日志 | `WHERE doc_type = 'Receipt' AND doc_id = ?` | `idx_document_logs_doc`（04 §7.4） |

台账与明细均必建外键索引（04 §5 强制）；部分索引 `WHERE deleted_at IS NULL` 保持索引紧凑。
