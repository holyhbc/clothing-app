# 09 财务与凭证模块

> 会计科目表 + 记账凭证（借贷平衡 INV-5）+ 凭证模板自动过账 + 会计期间关账 + 红字反向凭证，是 P5 阶段「一笔销售全流程自动生成三张凭证且借贷平衡」的落点。
> 关联规范：[09 领域术语 §1.7/§4.2](../09-领域术语与编码规则.md)、[00 业务蓝图 §5.1/INV-4/INV-5/§7 P5](../00-项目概述与业务蓝图.md)、[04 数据库 §2/§3/§4/§5/§6.1/§7.4](../04-数据库规范.md)、[05 接口 §3/§4/§6/§7](../05-接口设计规范.md)、[07 认证权限 §1.1/§2.2/§3.3/§5](../07-认证与权限规范.md)、[08 状态机 §1.1/§2.8/§3.3](../08-单据状态机规范.md)、[10 测试 §1/§3/§5/§8](../10-测试规范.md)。

## 1. 模块职责与边界

| 项 | 内容 |
| --- | --- |
| 负责 | `accounts` 会计科目表与初始科目集、`accounting_periods` 会计期间与关账、`vouchers` / `voucher_entries` 记账凭证、`voucher_templates` 凭证模板与自动过账、红冲 `reversal_vouchers`、阶段二 `general_ledger_entries` 表结构、对账视图 `v_voucher_balance` |
| 不负责 | 凭证**业务来源**（各单据审核时调用本模块生成 DRAFT 凭证）、往来余额与核销（[08 客户与往来](./08-客户与往来.md)）、成本计算（库存模块） |
| 上游 | 采购入库 / 销售出库 / 裁剪耗料 / 完工入库 / 工资计提 / 工资发放 / 收付款（各模块审核时调用 `VoucherService.build_from_source`） |
| 下游 | 报表（总账、发生额汇总，阶段二）、对账脚本 `v_voucher_balance` |
| 硬边界 | **已过账凭证不可 UPDATE/DELETE**（08 §2.8、INV-5），只能生成红字反向凭证；本模块是唯一能改 `vouchers.status` 的地方（08 R1/R7） |
| 关键不变量 | **INV-5 借贷平衡**（DB 约束 + service 双检 + 测试）、INV-7（软删）、INV-8（权限双校验）、AGENTS §2.2「金额 numeric(18,4)，禁止 float」 |
| 凭证状态 | 08 §2.8 定义 `DRAFT` → `POSTED` → `REVERSED`，**不在** 04 §3 的 `document_status` 枚举内，需新增独立 PG enum `voucher_status`（见 [Q-FV-07](#12-待决问题)） |

单据号（09 §2.1）：`vouchers` = `VO-YYYY-MM-NNNNNN`（例 `VO-2026-08-000123`）；红字反向凭证沿用 `VO` 号段（生成后永不复用，09 §2.1）。

## 2. 业务规则

| # | 规则 | 落地方式 |
| --- | --- | --- |
| FV-01 | **INV-5 借贷平衡**：`SUM(voucher_entries.amount WHERE direction='DEBIT') == SUM(... WHERE direction='CREDIT')` | 三重保障：DB 延迟约束触发器 + service 双检 + `v_voucher_balance` 视图（§7） |
| FV-02 | 凭证号唯一 `uq_vouchers_voucher_no`；号段在**数据库层**用序列生成，禁止 `count(*)+1`（09 §2.1） | `voucher_no_seq` 序列 + 唯一索引 |
| FV-03 | 每张凭证必须属于一个 `period`（`YYYY-MM`），且至少 2 条分录、至少 1 借 1 贷 | service 校验 + `CHECK` |
| FV-04 | 凭证创建要求 `period` 未关账；`accounting_periods.status = 'CLOSED'` 时拒绝新增/修改该期间凭证 | 见 [Q-FV-08](#12-待决问题) 错误码缺口 |
| FV-05 | 反关账必须 `super_admin` + **必填原因**，写 `document_logs`；关账后该期间单据禁止新增与修改（含源单据审核） | `accounting_periods` 状态 + service 前置校验 |
| FV-06 | 分录方向用 `DEBIT` / `CREDIT`（09 §1.7 `debit`/`credit`），金额恒正；红冲靠**整张反向凭证**表达，不靠负数分录（04 §4 明确金额 CHECK `>= 0`） | 列 CHECK `amount > 0` |
| FV-07 | 科目必须是 `is_detail = true` 且 `is_active = true` 的明细科目；不允许记到非明细科目 | service 校验，报 `20001` |
| FV-08 | 凭证 `source_type` + `source_id` 唯一（`uq_vouchers_source`），保证一张源单据只生成一张凭证（重复审核幂等兜底） | 唯一索引 |
| FV-09 | 凭证模板按 `source_type` 定义固定分录行；自动过账时按模板生成 DRAFT 凭证，**不自动过账**（过账必须人工触发） | `voucher_templates` |
| FV-10 | 舍入尾差分录：出库/入库金额已按分舍入，与模板计算额不一致时差额记入尾差科目（见 [Q-S-05](./07-销售.md#12-待决问题)） | 模板行 `amount_basis = 'ROUNDING_DIFF'` |
| FV-11 | 原币与汇率：`currency` 恒 `CNY`、`exchange_rate` 恒 `1`（00 §3.2 不做跨境），字段预留阶段二多币 | `CHECK` 同 07 S-02 |
| FV-12 | 凭证摘要 `summary` 必填，长度 ≤ 200，对账单据号与来源类型，便于人工查找 | service 校验 |
| FV-13 | 已过账凭证的红冲：生成一张新的 POSTED 凭证（`is_reversal = true`），`reversal_of_id` 指向原凭证，原凭证置 `REVERSED`；**禁止 UPDATE/DELETE 已过账凭证**（报 `60002`） | 08 §2.8 |
| FV-14 | 冲销顺序：**先冲下游凭证，再冲源单据**。源单据 `reverse` 时若凭证仍 `POSTED` 未红冲 → 拒绝（`60002`） | service 编排，见 §5.6 |
| FV-15 | 凭证过账需 2FA（07 §1.1「财务与总经理角色强制要求」）并在 `remark` 写操作事由 | service 校验 `auth_context.two_fa_verified` |
| FV-16 | `accounts` 是 04 §6.1 **硬删禁令表**，只能停用；已被凭证引用的科目禁止停用（`20003`） | DB 权限 + service 校验 |
| FV-17 | **尾数不入库，不产生收入与成本**（REV-2026-10，09 §4.2）：尾数 `balance_qty`（裁剪产出**不足一件**的余量）已计入裁剪 `cut_waste_qty`，**不入库、不计件、不产生台账**（[06 库存](./06-库存.md) BR-ST-23/BR-ST-24）。① 无尾数相关**收入**（`6051` 用途中的「尾单收入」已删除）；② 无尾数**存货结存**，不参与 `1405`/`1406`/`1407` 结转，也不进 `5401`/`6401` 成本结转；③ 尾数余料成本**已随裁剪损耗摊入耗料金额**（`CUTTING_ISSUE` 凭证），**不再单独计价或单独出凭证** | service 无尾数分支；尾数无台账 → 无尾数凭证；TC-FV-23 |

## 4. 单据与状态机

`Voucher` 迁移（严格照 08 §2.8，动作名 `create` / `post` / `reverse`，`post` 为 08 §2.8 专用动作，见 [Q-FV-07](#12-待决问题)）：

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 | 反向副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| `create` | — | DRAFT | `finance:voucher:create` | ① 借贷平衡（DB + service 双检，FV-01）；② 至少 1 借 1 贷、≥2 行（FV-03）；③ 科目 `is_detail` 且启用（FV-07）；④ `period` 未关账（FV-04）；⑤ `source_type + source_id` 不重复（FV-08）；⑥ 摘要非空（FV-12） | 由序列生成 `voucher_no`；写分录；算 `total_debit/total_credit` | `DRAFT` 可软删（未过账） |
| `update` | DRAFT | DRAFT | `finance:voucher:create` | 同 `create`；`expected_version` | 重算合计；写 `document_logs` 字段级 diff（04 §7.4） | — |
| `post` | DRAFT | POSTED | `finance:voucher:post` | ① 借贷平衡复检；② 期间未关账；③ 2FA 已验证且 `remark` 写事由（FV-15）；④ 制单 ≠ 过账（08 §4） | 写 `document_logs`（`action='APPROVE'`）；阶段二写 `general_ledger_entries` | `DRAFT` 时可撤回重填（08 §1.1 `withdraw` 口径，见 Q-FV-07） |
| `reverse` | POSTED | REVERSED | `finance:voucher:reverse` | ① **必填原因**；② 原凭证未被红冲过；③ 原凭证为 `POSTED`（`60002` 口径禁止删改） | 生成新 `vouchers`（`is_reversal=true`，借贷逐行反向，`status=POSTED`）并回填 `reversed_by_id`；写日志 | 不可逆（红冲凭证本身若填错，只能再红冲它） |
| `cancel` | DRAFT | CANCELLED | `finance:voucher:create` | 必填原因；仅 `DRAFT` | 软删；终态 | — |

`AccountingPeriod` 关账动作（**不属 `document_status`，独立小状态机**；动作名 `open` / `close` / `reopen` 已在 08 §1.1 登记）：

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `create` | — | OPEN | `finance:voucher:post` | `period` 唯一；与上一期间连续 | 建期间 |
| `close` | OPEN | CLOSED | `finance:voucher:post` | ① 该期间无 `DRAFT` 凭证；② 该期间源单据无 `SUBMITTED` 挂起；③ 必填原因 | `status=CLOSED` + 关账人/时间/原因；此后该期间凭证与单据**禁止新增/修改**（FV-04） |
| `reopen` | CLOSED | OPEN | `super_admin` | ① **必填原因**（FV-05）；② 写全量日志 | `status=OPEN` + 反关账人/时间/原因；允许重做凭证 |

凭证反向顺序（FV-14）：源单据 `reverse` 前必须先 `VoucherService.reverse` 该来源凭证；若凭证为 `POSTED` → 强制先红冲；为 `DRAFT` → 允许直接软删凭证再反审核源单据。凭证不存在（`source_id` 无对应行）不拦截。

## 5. 核心流程

1. **初始化**：迁移幂等插入 3.2 初始科目集 + 3.6 凭证模板 + 当期及上期 `accounting_periods`（`status=OPEN`）。
2. **源单据审核触发**（例：销售出库 `approve`）：service 调 `VoucherService.build_from_source(source_type='SALES_DELIVERY', source_id=...)` → 按模板生成 `vouchers(DRAFT)` + `voucher_entries` → 回写源单据 `voucher_id`（同事务，08 R4）。
3. **借贷校验**：生成时 service 计算 `total_debit/total_credit`，不等直接抛 `60001`（FV-01）；DB 延迟约束在事务提交时二次校验。
4. **凭证过账**：财务在凭证列表点「过账」→ `post` → 2FA + 事由 → `status=POSTED`；阶段二同时写 `general_ledger_entries`。
5. **红冲**：凭证填错 → `reverse`（必填原因）→ 生成红字反向凭证，原凭证置 `REVERSED`。**已过账凭证永不 UPDATE/DELETE**（`60002`）。
6. **源单据反审核**：`SalesDeliveryService.reverse` 先调 `VoucherService` 处理凭证：已过账必须先红冲（否则拒绝），未过账可直接软删；再冲销应收与库存。
7. **期末关账**：检查无 `DRAFT` 凭证与挂起单据 → `close`（原因）→ 该期间冻结；打误操作只能 `super_admin` 反关账并留痕。
8. **对账校验**：每次发布前跑 `v_voucher_balance` 视图，必须 **0 行**（10 §1 对账测试，§7）。

## 7. 并发与幂等

| 风险 | 场景 | 方案 | 配套测试 |
| --- | --- | --- | --- |
| **并发过账同一凭证** | 10 并发点「过账」 | 条件 UPDATE：`UPDATE vouchers SET status='POSTED', version=version+1, updated_at=now() WHERE id=:id AND status='DRAFT' AND version=:v`；`rowcount==0` → `10003` | TC-FV-10 |
| **并发红冲同一凭证** | 10 并发点「红冲」 | 同一条件 UPDATE 加 `AND reversed_by_id IS NULL`；第二、三次必 `rowcount==0` → `10002`；`uq_vouchers_reversal (reversal_of_id)` 唯一索引兜底，保证一张原凭证最多一张红冲凭证 | TC-FV-11 |
| **并发创建同来源凭证** | 源单据审核事务重试 / 双击 | `uq_vouchers_source (source_type, source_id)` 唯一索引；冲突转幂等返回既有凭证（05 §5） | TC-FV-12 |
| **期间并发关账** | 两个会计同时关同一期间 | 条件 UPDATE `WHERE period=:p AND status='OPEN'`；`rowcount==0` → 已关账，拒绝（FV-04）。关账前校验与 UPDATE 必须**同事务** | TC-FV-13 |
| **关账与建凭证竞态** | 会计 A 正在建凭证，会计 B 同时关账 | 建凭证事务内 `SELECT ... FROM accounting_periods WHERE period=:p FOR SHARE` 取锁；关账取 `FOR UPDATE`，二者互斥（行锁顺序固定：先期间后凭证） | TC-FV-14 |
| **重复红冲导致双倍反向** | 网络重试 | 红冲接口 `Idempotency-Key` + 上条唯一索引 | TC-FV-11 |
| **借贷不平被绕过** | 绕过 service 直接 SQL 插入分录 | DB 延迟约束触发器（提交时校验）+ `v_voucher_balance` 视图 | TC-FV-04 |

### 借贷平衡的三重保障（INV-5 落地）

| 层 | 手段 | 失败码 |
| --- | --- | --- |
| service | 生成/更新/过账时 `assert_balanced(voucher_id)`：借贷合计不等 → 抛 `60001` | `60001` |
| DB | `CREATE CONSTRAINT TRIGGER trg_voucher_balance ... DEFERRABLE INITIALLY DEFERRED`，在 `vouchers` 提交时校验 `total_debit = total_credit` 且与分录汇总一致 | 事务回滚 |
| 对账脚本 | 视图 `v_voucher_balance`：逐凭证比对表头合计与分录汇总，不等则出一行 | 发布前必须 0 行 |

```sql
-- v_voucher_balance：视图非空 = 借贷不平，必须为 0 行（发布前必跑）
CREATE OR REPLACE VIEW v_voucher_balance AS
SELECT v.id, v.voucher_no, v.period, v.total_debit, v.total_credit,
       COALESCE(SUM(e.amount) FILTER (WHERE e.direction = 'DEBIT'), 0)  AS entry_debit,
       COALESCE(SUM(e.amount) FILTER (WHERE e.direction = 'CREDIT'), 0) AS entry_credit
FROM vouchers v LEFT JOIN voucher_entries e
  ON e.voucher_id = v.id AND e.deleted_at IS NULL
WHERE v.deleted_at IS NULL AND v.status <> 'CANCELLED'
GROUP BY v.id, v.voucher_no, v.period, v.total_debit, v.total_credit
HAVING v.total_debit <> v.total_credit
    OR v.total_debit  <> COALESCE(SUM(e.amount) FILTER (WHERE e.direction = 'DEBIT'), 0)
    OR v.total_credit <> COALESCE(SUM(e.amount) FILTER (WHERE e.direction = 'CREDIT'), 0);
```

## 8. 索引与查询场景

| 场景 | SQL 条件 | 索引 |
| --- | --- | --- |
| 凭证列表按期间 + 状态 | `WHERE deleted_at IS NULL AND period = ? AND status = ? ORDER BY voucher_date DESC` | `idx_vouchers_period_status (period, status, voucher_date DESC)` 部分索引 |

| 期间状态取锁 | `SELECT * FROM accounting_periods WHERE period = ? FOR UPDATE` | `uq_accounting_periods_period (period)` |

禁止为不存在的查询建索引（04 §5）；`accounts` 为低基数小表，只建 `uq_accounts_code` + `idx_accounts_category (account_category, is_active)`。
