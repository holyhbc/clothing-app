# 10 采购

> **REV-2026-10（ADR-0015，本篇最大口径变更）：采购拆成「订单确认」与「到货登记」两个动作。**
> **采购单审核只确认订单（锁定价/锁数量/锁缸号、生成应付承诺），不入库**；**入库的唯一入口是「到货登记」**（支持一张 PO 分多次到，逐次登记即入库）。
> ⚠️ 这条修订了 [ADR-0012](../adr/0012-采购原材料批次字段.md) 的「一张 PO 一次到齐」「入库 = 采购单审核的同事务副作用」两条（ADR-0012 其余内容仍有效）。
> **不再有独立的「采购入库单」**（`RC` 单号已取消），库存模块只提供批次与台账能力。
> 关联规范：[04-数据库规范 §7.5 / §7.5.2.1 / §7.5.2.2 / §7.5.3](../04-数据库规范.md)、[08-单据状态机规范 §2.5](../08-单据状态机规范.md)、[09-领域术语 §1.1 / §4.1](../09-领域术语与编码规则.md)、[05-接口设计规范 §4 / §9](../05-接口设计规范.md)。ADR：[0012](../adr/0012-采购原材料批次字段.md)、**[0015](../adr/0015-采购分批到货与运费.md)**

## 1. 模块职责与边界

| 负责 | 不负责 |
| --- | --- |
| 采购单：供应商、日期、缸号、颜色、门幅、重量、匹数、单价、用途、**运费 `freight_amount` + 运单号 `freight_no`**、预计到货日、备注 | 布料的裁剪与领用（属裁剪模块） |
| **采购单审核 = 确认订单**：锁定价/锁数量/锁缸号 + 生成应付承诺（`ap_ledgers` 状态 `PENDING_ARRIVAL`），**不入库**（ADR-0015） | **委外加工 / 外裁**（业务方明确**没有外裁**，不建委外模块，PR-19） |
| **到货登记 = 入库的唯一入口**：一张 PO 可分多次到，逐次登记当场建批次 + 台账 + 冲应付 + 凭证（单事务） | 批次成本核算算法本身（属库存模块，只调用） |
| **运费 + 染费 + 加工费全部单据级录入，★ 只做台账记录，不摊进批次成本**（REV-2026-10，见 [ADR-0019](../adr/0019-采购运费只记录不进成本.md) + [ADR-0024](../adr/0024-染费与加工费只记录不进成本.md)） | ~~运费分摊规则表 / 运价库~~ 全部取消；三项费用只在采购台账展示 |
| 到货行**缸号可覆盖**采购行缸号（分批染色常见）、门幅以到货行为准 | 付款与核销（属往来模块） |
| 到货反审核（冲回该次批次与凭证）与单据反审核的**两级粒度** | 凭证借贷平衡规则（属财务模块） |
| 返修布（`REWORK_RECEIPT`）的用途标记与单独成本口径 | 返修工序计件（属计件模块） |
| 采购单 Excel 批量导入（三步式，**只建 DRAFT**，不产生入库） | 计件流水、库存台账等事实数据的导入（**禁止**） |

## 2. 业务规则

| 编号 | 规则 |
| --- | --- |
| PR-01 | 一张采购单可含**多个缸号**，缸号在**行**级；头级是供应商 + 单据日期 |
| PR-02 | 行的必填项：`material_id`、`color_code`、`dye_lot_no`、`bolt_count`、`weight_kg`、`width_cm`、`unit_price` |
| PR-03 | **计量三件套允许独立录入**：重量（kg，主）、门幅（cm，必填）、匹数、每匹米数、总米数。三者不一致时**只警告不阻断**（差异 > 5% 提示） |
| PR-04 | `purpose = REWORK_RECEIPT`（返修补回）时 **`rework_note` 必填**（`10006`），写明哪款哪单返修回来 |
| PR-05 | 返修布**照常入库、照常可被裁剪领用**，但成本走 `5403 制造费用-返修补布费`，毛利报表**单独列示**，不污染正常布料毛利 |
| PR-06 | 批次成本在**到货登记时**一次确定（`到货行金额 ÷ 计重量`，6 位小数，**不含运费**，ADR-0019），此后**永不修改**（INV-4 / ADR-0011）。⚠️ **不在采购单审核时确定**（审核不入库，无批次可定价） |
| PR-07 | 批次唯一键 `UNIQUE(warehouse_id, material_id, dye_lot_no, bolt_no)`，同缸同匹不会重复入库 |
| PR-08 | **到货登记是同事务**：建批次 + 台账 + 批次明细 + 冲减应付 + 凭证，任一失败整体回滚（ADR-0015 决策表「单次到货原子」）。⚠️ 采购单审核**只**汇总金额 + 生成应付承诺 |
| PR-09 | **到货反审核前置校验**：该次到货生成的批次已被下游裁剪消耗 → 拒绝 `40005`，必须先冲销下游裁剪单 |
| PR-10 | 制单人不能审核自己的单（`10005`）；审核/驳回/反审核/作废均必填原因（`10006`） |
| PR-11 | 供应商停用后不能新建采购单，但历史单可查、可反审核 |
| PR-12 | 采购单 Excel 导入走**三步式**（下载模板 → 上传校验 → 确认入库），有错误行时禁止提交；**导入只建 `DRAFT`，不产生库存、不产生应付**，必须人工走审核 → 到货登记 |
| **PR-13** | **采购审核只确认订单，不入库**（ADR-0015）。审核 = **承诺收货**：① 汇总 `total_amount`（不含运费）② 生成应付承诺 `ap_ledgers` 状态 `PENDING_ARRIVAL` ③ 锁定价 / 数量 / 缸号。**不建任何 `material_stocks` 批次、不写 `stock_ledgers`、不生成入库凭证**。理由：订单是"承诺"，到货是"事实"，混在一起会让库存账出现"没有货却有余额" |
| **PR-14** | **分批到货录入：一张 PO 可分多次到，逐次登记即入库**（ADR-0015）。新增 `purchase_arrivals`（第几次到）+ `purchase_arrival_lines`（本次到多少）；**入库的唯一入口是到货登记**（权限 `purchase:arrival`）；展示编号 `PO-20261018-000012 / 第 2 次`。分批是常态（面料商常分 2-3 次送），"一次到齐"会让账实严重滞后，甚至催着采购员提前录入造成虚假库存 |
| **PR-15** | **到货行缸号可覆盖采购行缸号**（分批染色常见，ADR-0015 §2）。采购行 `dye_lot_no` 只是**下单时的预期缸号**（默认）；`purchase_arrival_lines.dye_lot_no` 为**到货时的最终缸号**，染厂中途换缸是常事，**以到货行为准**，未填时默认取采购行缸号。门幅同理（ADR-0015 §4：以到货行实测值为准，到货行**必填** `width_cm`） |
| **PR-16b** | **染费 / 加工费只记录不进成本**（ADR-0024）：`purchase_orders.dyeing_amount`（染费）、`processing_amount`（加工费），**单据级各录一次**，默认 `0`；与运费同口径——不进批次成本、不进领料成本、不进成衣成本、不进损益、不生成凭证行；**不新增分摊字段**；已到货后可改（不动已锁定批次成本）+ 写 `document_logs`；台账汇总卡与明细表展示「总染费 / 总加工费」 |
| **PR-16** | **运费单据级录入，★ 只记录不进成本**（ADR-0019 **取代** ADR-0015 §3 的分摊规则）。字段仍在 `purchase_orders.freight_amount` / `freight_no` / `freight_date`，**批次成本 = 到货金额 ÷ 到货数量，不含运费**；运费**不进领料成本、不进成衣成本、不进损益、不生成凭证行**；因此成衣毛利率不扣任何采购侧费用，毛利报表页头须标注「毛利未扣采购运费/染费/加工费」。三项费用**只能在采购台账查看与导出**（`purchase:ledger:read`）。运费**可在已到货后修改**（只改台账记录，不影响已锁定批次成本），但需写 `document_logs` |
| **PR-17** | **累计到货 ≤ 订单量，超出报 `50011`**。校验口径 `Σ(该采购行所有未冲销到货行 bolt_count) + 本次 bolt_count ≤ 采购行 bolt_count`（重量同理）；超了 → `50011`（05 §4 已登记，`details` 回传已到 / 应到数量）。到齐后自动标 `ARRIVED_ALL`（**内部标记，不改状态机状态**） |
| **PR-18** | **反审核粒度：先按到货冲销，未冲完不许反审核单据（`50012`）**。两级：① **到货级反审核**（`purchase:arrival:reverse`）冲回该次批次 + 台账 + 凭证 + 应付；② **单据级反审核**（`purchase:reverse`）**必须先冲完全部到货**，仍有未冲销到货 → **`50012`**（05 §4 已登记，提示"先逐次冲销到货"）。顺序反了会留下无来源的库存 |
| **PR-19** | **无委外加工（业务方明确"没有外裁"）**（ADR-0015 §5）。**不建**委外发出 / 委外收回模块，Q-PO-07 关闭。若未来出现委外，需**新增独立模块**（采购单不能代替委外单）。连带：`is_outsourced` 之类字段一律不引入（01 §12 Q-B06 同向） |

### 2.1 `purchase_purpose` 取值与成本科目

| 值 | 含义 | 借方科目 | 毛利报表 |
| --- | --- | --- | --- |
| `NORMAL` | 正常采购 | `1405 库存商品-面料` | 混入主料成本 |
| `REWORK_RECEIPT` | 返修补退回厂 | `5403 制造费用-返修补布费` | **单独列示** |
| `RETURN` | 客供料退回 | 冲减 `1406 库存商品-在产品` | 单独列示 |
| `SAMPLE` | 样布 | `6602 管理费用-样品费` | 不进产品成本 |

### 3.3 关联

```
suppliers 1:N ── purchase_orders 1:N ── purchase_order_lines N:1 ── materials
purchase_orders 1:N ── purchase_arrivals 1:N ── purchase_arrival_lines N:1 ── purchase_order_lines
                                                            │
                                                            ├──> material_stocks（到货时按 dye_lot_no + bolt_no 拆行建批次）
                                                            └──> stock_ledgers (IN) ──> stock_ledger_lines
purchase_order_lines ──> colors (color_code)
purchase_orders ──> ap_ledgers（**审核**生成应付承诺 PENDING_ARRIVAL；**到货**按到货金额冲减）
purchase_arrivals ──> vouchers（每次到货的入库凭证，反审核时红冲）
document_logs (doc_type='PurchaseOrder' / 'PurchaseArrival'，含 changed_fields)
```

> **批次与台账挂在「到货行」上，不再挂在「采购行」上**（ADR-0015）：同一采购行可分多次到、每次缸号/匹数/重量都不同，所以 `purchase_arrival_lines.stock_id` 回写生成的批次。

| `stock_id` | uuid | ⬜ | — | **生成的库存批次**（入库后回写）；反审核按它反向冲回 |
| …公共字段 | | | | |

约束与索引：`uq_purchase_arrival_lines UNIQUE (arrival_id, line_no)`、`ck_pal_bolt CHECK (bolt_count > 0)`、`ck_pal_weight CHECK (weight_kg > 0)`；建议 `idx_purchase_arrival_lines_order_line (order_line_id) WHERE deleted_at IS NULL` 供累计到货校验与 `50011` 判定（04 §7.5.2.2）。

### 3.6 关键约束汇总（ADR-0015）

| # | 约束 | 落点 |
| --- | --- | --- |
| 1 | **单次到货原子**：建批次 + 台账 + 批次明细 + 应付冲减 + 凭证，**一个事务**，任一失败整体回滚 | §5.2 |
| 2 | **累计到货 ≤ 订单量**，超了 `50011`；`arrived_amount <= total_amount` 由 DB `CHECK` 兜底 | PR-17、04 §7.5.2.2 |
| 3 | **未到货不建批次**：采购行没到货就完全没有库存批次；**采购单审核绝不建批次** | PR-13/PR-14 |
| 4 | **到货行缸号 / 门幅可覆盖采购行**，以到货行为准 | PR-15 |
| 5 | ~~运费按到货金额比例同步分摊~~ **取消**；运费原样记在单据头，不进任何成本 | PR-16 / ADR-0019 |
| 6 | **反审核必须先到货级**，未冲完 `50012` | PR-18 |
| 7 | 应付两态：`PENDING_ARRIVAL`（已确认未到）→ 到货后按金额冲减；`ap_ledgers.arrival_status` 需在 04 回写（见 §12 待登记） | PR-13 |

## 4. 单据与状态机

> **REV-2026-10 / ADR-0015**：单据本身的状态机**不变**，但**审核语义改了**：审核 = **确认订单**，**不入库**。**入库入口是新动作「到货登记」**（独立于状态机，见下）。
> 迁移表严格对齐 08 §2.5（动作名 `submit`/`approve`/`reject`/`withdraw`/`reverse`/`cancel`）。

| 动作 | 起始 | 目标 | 权限点 | 前置校验 | 副作用 |
| --- | --- | --- | --- | --- | --- |
| `create` | — | DRAFT | `purchase:create` | 供应商启用；仓库启用 | 生成 `doc_no` |
| `update` | DRAFT/REJECTED | 同 | `purchase:update` | 行字段白名单可改；**运费 `freight_amount` / `freight_no` 只在本态可改**（PR-16）；已有到货记录时改运费被拒 | — |
| `submit` | DRAFT/REJECTED | SUBMITTED | `purchase:submit` | 行必填齐全（含 `dye_lot_no`/`bolt_count`/`weight_kg`/`width_cm`）；`REWORK_RECEIPT` → `rework_note` 必填（`10006`）；`freight_amount >= 0`；重量/米数差异 > 5% 弹**警告**但可提交 | — |
| **`approve`（= 确认订单，不入库）** | SUBMITTED | APPROVED | `purchase:approve` | 制单人 ≠ 审核人（`10005`） | **① 汇总 `total_amount`（货值，不含运费）② 生成应付承诺 `ap_ledgers` 状态 `PENDING_ARRIVAL` ③ 勾了「一次到货」且 `arrival_expected_date` 已到 → 自动生成第 1 次到货并走入库流程。❌ 不建批次、不写台账、不生成入库凭证（PR-13）** |
| **`arrival`（到货登记，**入库唯一入口**）** | APPROVED | APPROVED（**不改状态**） | **`purchase:arrival`** | **① 单据必须 `APPROVED`；② 累计到货 ≤ 订单量（超 → `50011`）；③ 到货行 `width_cm` 必填（→ `10001`）、`bolt_count`/`weight_kg` > 0；④ 供应商未停用** | **① 按到货行建 `material_stocks` 批次（缸号 + 匹号 + 颜色 + 门幅 + 重量 + `purpose` + **`supplier_id`**），`unit_cost = 行金额 ÷ 计重量`（**不含运费**，ADR-0019；ADR-0011 定后不改）② 写 `stock_ledgers.direction='IN'` + `stock_ledger_lines` ③ 按到货金额冲减应付 ④ 生成入库凭证（按 `purpose` 选科目）⑤ `arrival_count += 1`、`arrived_amount += 本次金额`、`arrived_at = now()`；到齐标 `ARRIVED_ALL` ⑥ 回写 `purchase_arrival_lines.stock_id` ⑦ 写 `document_logs`（`doc_type='PurchaseArrival'`）。全链路**单事务**（PR-14/PR-08）** |
| `reject` | SUBMITTED | REJECTED | `purchase:reject` | **必填原因** | — |
| `withdraw` | SUBMITTED | DRAFT | `purchase:update` | 撤回人 = 制单人 | — |
| **`arrival-reverse`（到货级反审核）** | APPROVED | APPROVED（**不改状态**） | **`purchase:arrival:reverse`** | **① 该次到货的批次已被下游裁剪消耗 → `40005`；② 必填原因（`10006`）；③ 该次应付已有核销 → `50007`** | **① 按该次到货的同一批 `stock_ledger_lines` 逐条反向冲回；② 反向出库 / 冲减批次 `stock_qty`；③ 红冲该次入库凭证（`60002` 口径）；④ 冲减该次应付；⑤ `arrival_count -= 1`、`arrived_amount -= 本次金额`；⑥ 写 `reversed_at/by/reason` + `document_logs`** |
| **`reverse`（单据级反审核）** | APPROVED | SUBMITTED | `purchase:reverse` | **① 必填原因；② 必须先冲完全部到货 —— 仍有未冲销到货 → `50012`；③ 该采购单的批次已被下游裁剪消耗 → `40005`** | 冲销应付承诺（`ap_ledgers` 转 `CANCELLED`）；`arrival_count` 应已为 0；**不再有任何批次要冲**（批次在到货级已冲完） |
| `cancel` | DRAFT/REJECTED | CANCELLED | `purchase:cancel` | 必填原因 | 终态 |

### 4.1 非法迁移

| 动作 | 当前状态 | 结果 |
| --- | --- | --- |
| `approve` | DRAFT | `10007` |
| `approve` | APPROVED | `10008`（重复审核） |
| `arrival` | DRAFT / SUBMITTED | `10008`（**必须先审核确认订单**） |
| `arrival` | 累计超量 | `50011` |
| `reverse`（单据级） | DRAFT/SUBMITTED | `10007` |
| `reverse`（单据级） | 仍有未冲销到货 | **`50012`** |
| `arrival-reverse` | 批次已消耗 | `40005` |
| 任意 | CANCELLED | `10007`（终态） |

### 4.2 两级副作用对称表（**到货级 → 单据级**，ADR-0015）

| 到货登记做 | 到货反审核反向做 |
| --- | --- |
| 建 `material_stocks` 批次（+`stock_qty`） | **冲减 / 软删批次行**（该批次尚未被任何台账引用时才允许；已引用 → `40005`） |
| 写 `stock_ledgers.direction='IN'` | 写**反向行**（append-only，不删原行） |
| 写 `stock_ledger_lines`（批次明细） | 按**同一批明细**逐条反向冲回 |
| 冲减应付（`ap_ledgers`） | 回冲该次到货金额（已有核销 → `50007` 拒绝） |
| 生成入库凭证（POSTED） | 红字反向凭证（`60002` 口径，不删原凭证） |
| `arrival_count += 1` / `arrived_amount += 本次金额` | `arrival_count −= 1` / `arrived_amount −= 本次金额` |
| 写 `purchase_arrivals` + `purchase_arrival_lines` | 标 `reversed_at` + 必填 `reverse_reason`（**记录保留，不删**） |

| 单据审核做 | 单据反审核反向做 |
| --- | --- |
| 汇总 `total_amount` | 回滚汇总 |
| 生成应付承诺（`ap_ledgers`，`PENDING_ARRIVAL`） | 冲销应付承诺（转 `CANCELLED`）；**前置：全部到货已冲回（`50012` 拦截）** |
| 锁定价 / 数量 / 缸号 | 解除锁定 |
| ❌ **不建批次 / 不写台账 / 不生成入库凭证** | ❌ 无库存副作用要冲（批次在到货级已冲完） |

## 5. 核心流程

> **REV-2026-10 分两条流程（ADR-0015）**：**5.1 下单到审核确认（承诺，不入库）** 与 **5.2 分批到货登记（事实，入库）**。采购员"货没到就录了库存"是老口径最大的坑，现在系统层面堵死。

### 5.1 下单到审核确认（**承诺，不入库**，14 步）

```
[1] 采购员新建采购单（PO-YYYYMMDD-NNNNNN）
     头：供应商 / 单据日期 / 收货仓库 / 发票号 / 预计到货日 arrival_expected_date
[2] 逐行录入（一张单可多缸）
     物料 / 颜色 / 缸号 / 用途 / 匹数 / 每匹米数 / 重量kg / 门幅cm / 单价 / 备注
[3] 选用途 purpose：
     · NORMAL 正常采购
     · REWORK_RECEIPT 返修补回 → 必须填 rework_note（哪款哪单）
     · RETURN 客供料退回 / SAMPLE 样布
[4] ★ 录运费（单据级，PR-16）：
     · freight_amount 运费金额（按收到的运费单据填；0 = 供方包邮）
     · freight_no 运费单 / 运单号（仅备查，不参与计算）
     · 不按行录、不做运价规则表、不做分摊；**只在本单头部记录一次**，采购台账可查看与导出
[5] 系统实时算：总米数 = Σ(匹数 × 每匹米数)；行金额 = 重量 × 重量单价 或 米数 × 单价
[6] 系统提示：重量 / 米数 / 匹数 三者一致性检查（差异 > 5% 黄色警告，可继续）
[7] 提交 submit → 行必填校验（含门幅）；REWORK_RECEIPT 的 rework_note 校验（10006）；
     freight_amount >= 0
[8] 主管/采购经理审核 approve
[9]   ├─ 制单人 ≠ 审核人校验（10005）
[10]  ├─ 汇总 total_amount（货值合计，不含运费）
[11]  ├─ 生成应付承诺 ap_ledgers（PENDING_ARRIVAL：承诺收货，尚未形成实物）
[12]  ├─ 若勾了「一次到货」且 arrival_expected_date 已到 → 自动生成第 1 次到货并走 5.2
[13]  └─ ❌ 不建 material_stocks 批次、不写 stock_ledgers、不生成入库凭证（PR-13）
[14] 同事务提交；status → APPROVED，写 document_logs
```

> **界面必须明确写「审核不产生库存」**（ADR-0015 风险 ④）：审核页顶部提示条 + 审核后引导「货到了 → 登记到货」按钮，避免采购员把审核当入库。

### 5.2 分批到货登记（**入库唯一入口**，14 步）

```
[1] 仓管/采购员在已审核（APPROVED）的采购单上点「登记到货」
     · 一张 PO 可分多次到：第 1 次 / 第 2 次 / 第 3 次…（arrival_no 服务端分配）
     · 界面显示「已到 N 次 / 已到金额 X / 订单金额 Y / 累计到货进度」
[2] 填本次到货日期 arrival_date + 到货备注 remark（破损、短少等）
[3] 按采购行逐行录本次到货量（同一采购行可多次到）：
     · 点某行 → 弹出「本次到货」：bolt_count 本次匹数 / weight_kg 本次重量 /
       total_length_m 本次米数 / dye_lot_no 本次缸号 / width_cm 本次实测门幅
[4] ★ 缸号可覆盖（PR-15）：默认带出采购行缸号（= 下单时的预期缸），
     分批染色换缸时**改成实际到货缸号**；不改就等于按预期缸入账，对不上账
[5] ★ 门幅以到货行为准（ADR-0015 §4）：width_cm **必填**，为空 → 提交被拒（10001）；
     物料主数据 materials.width_cm 只作新建单据时的预填值
[6] ★ 累计超量拦截（PR-17）：Σ历史未冲销到货 + 本次 > 采购行量 → 50011
     （响应 details 回传 已到 / 应到 数量）
[7] 系统算本次到货金额 Σ行金额
[8] ★ 运费只记录（PR-16，ADR-0019，**原分摊逻辑全部删除**）：
     · 本次分摊运费 = purchase_orders.freight_amount × (本次金额 ÷ total_amount)
     · `purchase_orders.freight_amount` 原样落库（`numeric(18,4)`），**不做任何分摊计算**
     · 批次单位成本 = 到货金额 ÷ 到货数量（**不含运费**）；成衣成本结转链路同样不含运费
     · 唯一读取入口：采购台账汇总卡「总运费」与明细导出
     · 毛利报表页头固定标注「毛利未扣采购运费（ADR-0019）」
     · 可先调 GET /freight-allocate 试算再提交
[9] 单事务开始：
[10]   ├─ 建 material_stocks 批次：按 bolt_count 拆匹号；缸号/颜色/门幅/重量/purpose 取到货行
     │   └─ unit_cost = (行金额 + 行分摊运费) ÷ 计重量，6 位小数（ADR-0011 定后永不改）
[11]   ├─ 写 stock_ledgers(direction='IN') + stock_ledger_lines（快照门幅/重量/purpose）
[12]   ├─ 按到货金额冲减应付（ap_ledgers 承诺转已到货部分）+ 生成入库凭证
     │   └─ 凭证：借 批次成本合计（含分摊运费） / 贷 2202 应付账款；按 purpose 选科目
[13]   └─ 累加 arrival_count、arrived_amount；arrived_at = now()；
         到齐 → 标 ARRIVED_ALL（内部标记，不改状态机状态）；回写 stock_id
[14] 同事务提交（任一步失败整体回滚，不留半截批次）+ 写 document_logs(doc_type='PurchaseArrival')
```

**幂等与防重**：`purchase_arrivals` 的 `UNIQUE (doc_id, arrival_no)` + 批次唯一键 `UNIQUE(warehouse_id, material_id, dye_lot_no, bolt_no)` 双保险；接口支持 `Idempotency-Key`（05 §5）。

### 5.3 反审核（**先到货级，后单据级**，ADR-0015）

```
【第一级：到货反审核】purchase:arrival:reverse
[1] 选「冲销某一次到货」（purchase_arrivals 任一未冲销记录），填必填原因（10006）
[2] 校验：该次到货生成的批次是否已被下游裁剪消耗？
     ├─ 是 → 拒绝 40005（提示先冲销下游裁剪单）
     └─ 否 → 继续
[3] 校验：该次应付是否已有核销？→ 是则 50007 拒绝
[4] 按该次 stock_ledger_lines 逐条反向冲回台账（append-only，不删原行）
[5] 反向出库 / 冲减 material_stocks.stock_qty（释放批次或软删该批次行）
[6] 红冲该次入库凭证（60002 口径，不删原凭证）
[7] 回冲该次应付金额；arrival_count -= 1；arrived_amount -= 本次金额
[8] 标 reversed_at / reversed_by / reverse_reason（记录保留，不删）；写 document_logs

【第二级：单据反审核】purchase:reverse
[9] 校验：是否还有未冲销的到货？→ 是则 50012（提示先逐次冲销到货）
[10] 校验：该采购单相关批次是否已被下游裁剪消耗？→ 是则 40005
[11] 冲销应付承诺（ap_ledgers 转 CANCELLED）；解除定价/数量/缸号锁定
[12] 回滚 total_amount 汇总；status → SUBMITTED；写 document_logs
```

> ⚠️ **顺序不可颠倒**：先反审核单据会留下"没有来源的库存"。因此 `50012` 是**硬拦截**，不是警告。

### 5.4 Excel 批量导入（三步式，见 [05 §9.2](../05-接口设计规范.md)）

```
[1] 下载模板（含字段说明页 + 示例行）
     列：供应商编码 | 单据日期 | 物料编码 | 物料名称 | 颜色编码 | 缸号 |
         用途 | 匹数 | 每匹米数 | 总米数 | 重量kg | 门幅cm | 单价 |
         运费金额 | 运费单号 | 预计到货日 | 返修说明 | 备注
[2] 上传校验（不写库）
     → 返回 { total, valid, invalid, can_commit, errors[{row,field,message}] }
     → 有错误时显示错误行表格 + 「下载错误明细」，提交按钮禁用
[3] 确认导入（单事务入库，幂等 upload_id）
     → 写入 document_logs(action='IMPORT')
```

**注意**：导入只创建 **DRAFT** 单据，**不自动提交**，更**不产生库存**（无到货登记就没有批次）；必须人工走「审核 → 到货登记」。

## 6. 采购台账（供应商维度，REV-2026-10 新增，见 [ADR-0022](../adr/0022-采购台账与库存供应商维度.md)）

**为什么需要**：业务要"按供应商看清账"——总布料数量、总货值、总运费、应付/已付/未付，并能按时间查明细。原有采购列表按单据组织，看不出某供应商一共买了多少布、还欠多少钱。

### 6.1 页面结构

| 区块 | 内容 | 筛选 |
| --- | --- | --- |
| **供应商汇总卡** | 总重量KG · 总匹数 · 总货值 · **总运费 · 总染费 · 总加工费（三项只记录，ADR-0019 / ADR-0024）** · 应付 · 已付 · 未付 | 供应商 + 收货日期区间 |
| **到货明细表** | 收货日期 · 供应商 · 面料名称 · 缸号 · 颜色 · **重量KG** · **单价** · **金额（= 重量 × 单价）** · 采购单号 · 到货单号 · 操作人 | 收货日期区间 + 供应商 + 面料 + 缸号/颜色关键字 |
| **操作** | 导出（复用 `purchase:export`） | — |

**只读页**：无任何写操作，权限 `purchase:ledger:read`。

### 6.2 口径

| 指标 | 口径 |
| --- | --- |
| 总重量 / 总匹数 / 总货值 | `v_purchase_supplier_summary` 按 `supplier_id` + 收货日期区间聚合，**只统计已到货**（未到货不计入） |
| 总运费 | `SUM(purchase_orders.freight_amount)`（**按单据头一次计**，同单多次到货只计一次；ADR-0019） |
| 应付 | `SUM(purchase_arrivals.amount)`（**不含运费**） |
| 已付 | 该供应商付款单**核销**合计（`finance_payment_allocations`） |
| 未付 | 应付 − 已付；已付 > 应付 → `50013` |

### 6.3 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |

## 8. 并发与幂等

| 风险 | 场景 | 方案 |
| --- | --- | --- |
| 同缸同匹重复入库 | 同一缸同一匹号被登记两次到货（网络重试 / 双人同时点） | `UNIQUE(warehouse_id, material_id, dye_lot_no, bolt_no)` 兜底；命中则整个事务回滚并提示"该批次已入库（可能重复提交）"；接口另支持 `Idempotency-Key`（05 §5），同键同 body 返回首次结果 |
| **★ 并发登记到货导致累计超量（PR-17）** | 两人（或两个进程）同时对同一采购行登记到货，各自校验时都"没超"，合起来超 | **不能"先 select 校验再 insert"**：登记事务内对**该采购行 + 到货行**按固定顺序 `SELECT ... FOR UPDATE` 锁住（`purchase_orders` 行 → `purchase_order_lines` 行 → `purchase_arrival_lines`），再在锁内重算累计并 INSERT；数据库层再兜 `CHECK (arrived_amount <= total_amount)` 与唯一索引。**超量的并发方拿 `50011`**，且 `arrival_count` / `arrived_amount` / 批次 / 台账**零副作用**（整事务回滚） |
| **★ 到货反审核 vs 裁剪领用竞争** | 仓管在冲销第 2 次到货的同时，车间正领用该批次 | 双方都对 `material_stocks` 同一批次行**条件 UPDATE**：`arrival-reverse` 用 `WHERE stock_qty >= :qty AND locked_qty = 0`，裁剪领用用 `WHERE (stock_qty - locked_qty) >= :qty`；**谁先拿到锁谁成功**，后到者 `40005`（已被消耗）或 `40001`（可用不足）。加锁顺序全模块统一（`purchase_arrivals` → `material_stocks` → `stock_ledgers`），防死锁 |
| **★ 单据级反审核 vs 新的到货登记** | 有人在冲销采购单的同时，另一人正在登记第 N 次到货 | 单据级 `reverse` 事务内先 `SELECT ... FOR UPDATE` 锁 `purchase_orders` 行，**在锁内**检查"未冲销到货数 = 0"，非 0 → `50012`；到货登记也必须先锁同一行 → 二者串行化，**不可能出现"反审核通过后又冒出一次到货"** |
| **★ 并发切费用率 / 并发调价** | 运费在 `DRAFT` 被两人同时改 | 乐观锁 `WHERE id=? AND version=?`，后到者 `10003`；且有到货记录时服务端直接拒（PR-16 修改限制） |
| 重复审核 | 状态机 `10008` + 乐观锁 `WHERE id AND version AND status='SUBMITTED'` | 双保险，`rowcount == 0` → `10003` |
| 库存并发扣减 | 审核建批次的同时裁剪在扣同缸库存 | 建批次 INSERT 不受影响；裁剪的条件 UPDATE `WHERE stock_qty >= n` 兜底 |
| 反审核与裁剪竞争 | 反审核查"未消耗"后，裁剪立刻领用 | 审核/反审核都在**同一缸的行上 `SELECT ... FOR UPDATE`**；反审核先拿锁再校验 |
| 应付重复生成 | 重复审核 | `ap_ledgers` 加 `source_doc_type + source_doc_id` 唯一索引；到货时的**冲减**用 `source_doc_type='PurchaseArrival' + source_doc_id=arrival_id` 唯一索引，避免同一批到货冲两次 |
| 导入重复提交 | 用户连点两次 commit | `upload_id` + `Idempotency-Key`；命中返回首次结果 |
| 导入部分失败 | 中间某行违反业务规则 | commit 全部行**一个事务**，任一行失败整体回滚，不留半截数据 |
