## 4. 与 `cutting` 的联动点

| 联动点 | 方向 | 落点 |
| --- | --- | --- |
| 来源裁剪单 | `bundling_orders.source_cutting_order_id → cutting_orders(id)` | 建单时校验 `status='APPROVED'`（B8）；迁移 0009 已建 `cutting_orders` |
| 件数与手数权威源 | `bundling_order_lines.cutting_size_line_id → cutting_order_size_lines(id)` | 建单每行必填（B26）；**件数/手数直接取该行的 `qty_per_hand` / `hands`**（Q-B15 2026-10-06 闭环） |
| 可用量预占 | `submit` 预占 `cutting_outputs.reserved_qty`，快照 `available_qty_before` | **依赖 `cutting_outputs` 表存在**（§7.7.5 DDL 已就绪，但建表属 `T-BASE-009-2`） |
| 审核结转 | `approve` 累加 `cutting_outputs.bundled_qty`、清零 `reserved_qty` | 同上 |
| 反审核冲销 | `reverse` 减回 `bundled_qty`、重新预占 | 同上；并校验无计件流水（`32003`） |
| 可打菲来源列表 | `GET /bundling-orders/{id}/available-outputs` 读 `v_cutting_output_available` | 视图随 `cutting_outputs` 在 `T-BASE-009-2` 建 |
| 改单联动 | 裁剪改手数 → 未打印码软删重建 / 已打印未计件码 `VOIDED`（`31007`） | ADR-0021 / `08 §2.1.1`；属打菲侧，见 `T-BUND-005b` 的 `reverse` 与后续改单联动卡（本拆解未单开，见待决 Q-B19） |

**接口依赖顺序结论**：`T-BUND-001/002/003/004` 可在 `T-BASE-009-2` 之前开工；
**`T-BUND-005a`（`submit` 预占）起必须等 `cutting_outputs` 建好**。

## 5. 单据号与 `bundle_no`

- **单据号**：`BD-{YYYYMMDD}-{6 位}`（`09 §2.1`）。`core/numbering.py::take_doc_no(session, prefix="BD")`
  **直接可用** —— `cutting_doc_no_sequences` 的 `prefix` 列就是为「将来分单据类型」预留的
  （`04 §7.17` 注释原文），**不新增计数器表、不新增迁移**。`T-BUND-002` 只做接线与测试。
- **`bundle_no`**：`{doc_no}-{尺码码 1~3 位}{手序号2位}-{件序号4位}`，由 `T-BUND-002` 提供纯函数
  `build_bundle_no(...)`；审核时 `T-BUND-005b` 逐手调用。✅ **Q-B18 2026-10-06 已闭环**：
  尺码码允许 1~3 位（覆盖 `S`/`XL`/`XXL`/`3XL`），手序号固定 2 位；正则
  `^BD-[0-9]{8}-[0-9]{6}-[A-Z0-9]{1,3}[0-9]{2}-[0-9]{4}$` 已落 `04 §7.0` / `03 §5.2` DB CHECK。
