## 4. 与 `piecework_logs` 的联动点

| 联动点 | 方向 | 落点 |
| --- | --- | --- |
| **取数（唯一口径）** | 只读 `piecework_logs` | `05 §2.1` SQL：`work_date BETWEEN :start_date AND :end_date AND workshop_id=? AND payroll_id IS NULL AND deleted_at IS NULL`，GROUP BY 员工/组别/款号/工序 |
| **周期区间来源** | `payroll_periods` → 结算 service | 日期**从周期表读，不接受前端传日期**（BR-PR-20）；`period_start_date`/`period_end_date` 只是冗余快照 |
| **审核占用** | `approve` → 回写 `payroll_id` | 同事务 `UPDATE piecework_logs SET payroll_id=:id WHERE ... AND payroll_id IS NULL`；`rowcount` 与行数核对（P3 兜底） |
| **反审核释放** | `reverse` → 清空 `payroll_id` | 同事务 `SET payroll_id=NULL`；流水立即可重新结算，对账视图回零（`05 §4.1`） |
| **`payroll_id` 外键** | `piecework_logs.payroll_id → piecework_settlements(id)` | **`T-PAY-001` 补建 FK**，并同步 `04 §7.1`（现文写「由工资建表卡补」）。⚠️ 只建 `REFERENCES`，**不加 `ON DELETE`**（结算单只软删，PG 默认 `NO ACTION` 即可；硬删被 `INV-7` 禁止） |
| **索引复用** | 迁移 0019 已建 | `idx_piecework_logs_work_date_workshop_id_style_no`（取数）+ `idx_piecework_logs_unsettled`（`WHERE deleted_at IS NULL AND payroll_id IS NULL` 部分索引）——**工资侧不重复建索引** |
| **计件侧拒绝红冲** | 结算 APPROVED → 流水锁定 | `32003`（`04-计件` BR-PW-10）；**计件模块已有**，工资侧不实现、不复登 |

**对账（`05 §5.7`）**：周期内 `payroll_id IS NULL` 条数结算完成后须 = 0（ADR-0010 验证方式），
由 `T-PAY-010` 的对账脚本 + 集成测试落成（`04 §7.4` 取数索引已就绪，不需要新索引）。
