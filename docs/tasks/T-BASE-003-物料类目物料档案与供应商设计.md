## 目标

`cutting_order_lines` 外键引用 `materials` / `suppliers`，而这两张表**在 `04` 与所有模块设计里都没有 DDL** —— `materials` 连字段表都没有。照现在的规范**建不出裁剪单表**（L-071）。

本卡把三张表的设计定下来并写进 `04 §7.15`，让 T-CUT-001 能直接照着建迁移。

## 为什么是「只出设计稿」而不是直接建表

这三张表都不是「照着既有实现搬」：

- `materials` 此前**没有任何字段定义**，字段集是**新决策**
- 物料编码 `F-{类目码}-{6位}`（`09 §2.3`）依赖一个**从未定义**的类目码来源
- `suppliers` 的字段散落在 01 §3.5 与 08 §3.1 两处且**互相冲突**（Q-F-07）

所以必须走 AGENTS §1 的第 2 步「出设计」，不能直接写迁移。

## 业务决策（2026-10-04 已确认，不得自行更改）

| # | 问题 | 决策 |
| --- | --- | --- |
| D1 | 物料编码里的「类目码」从哪来 | **建 `material_categories` 字典表**（与 `colors`/`sizes` 同构：code/name/sort/is_active + 公共字段），物料档案外键引用。理由：编码规则已在用它，自由文本一定会出现 `CT`/`ct`/`Ct` 三种写法 |
| D2 | `materials` 字段范围 | **最小集**：`code` / `name` / `material_type` / `category_id` / `uom_unit_id` / `is_active` + 公共字段。⚠️ `width_cm`/`weight_kg`/缸色**都在批次上**（`modules/06 §3.1` 明确），不重复放档案层 |
| D3 | 物料与供应商的关联 | **不建关联表**。采购单行同时选供应商与物料。理由：同一物料常从多家采购，「默认供应商」会与实际采购不符 |
| D4 | `suppliers` 银行四项必填性 | **改为可空**。理由：辅料商 / 个体工商户常无对公账户；建档是低频动作（卡住它会让人绕过系统），付款才是提示补录的正确时机 |
| D5 | 账期字段名（Q-F-07） | **统一 `settlement_period_days`**。理由：跟随 `customers` 上的既有实现（迁移 0003 已落），AGENTS §2.3 要求跟随既有模式 |
