## 目标

按 ADR-0017 的**三层结构**把一张裁剪单看清楚：布批行 → 行内颜色 → 尺码明细，
表头汇总与各层小计**照抄后端**。

## 为什么这一版是只读

三层写接口全是**全量替换**（`PUT /lines` `PUT /colors` `PUT /size-lines`），
页面要敢开放编辑必须先处理两件事：

1. **版本链**：每次成功写之后要把响应里的新 `version` 存下来继续用；而 PUT 会软删旧行
   → 行 `id` 会变 → 三层都要按新结构重挂。用旧版本的下一次就是 `10003`。
2. **比例建议的副作用**：`GET /suggest-lines` 会把比例快照写进行内颜色，
   必须绑在用户明确的「按比例带出」动作上，不能「打开详情就拉一次」。

这两件属于 T-CUT-001c-3。

## 三条最容易做错的

| # | 陷阱 | 正确做法 |
| --- | --- | --- |
| 1 | 前端把各层相加当表头出数 | C6：表头五列由 service 重算并返回。前端再算一遍就是**第二份真相**（TC-CUT-D2 专门守这条） |
| 2 | 用 `colors` / `size_lines` 直接当数组 | 生成类型里它们是**可选**的（模型有 `default_factory`）→ `:data-source="undefined"` 会被 antd 当非数组，渲染空表且不报错 |
| 3 | 断言 `route.params.orderId` 是 `string` | vue-router 给的是 `string \| string[]`；断言会让「参数缺失」变成「把 undefined 发给后端」，用户看到 10001 而不是「地址不对」（TC-CUT-D6） |

## 抓到的两个坑

| # | 坑 | 为什么难发现 |
| --- | --- | --- |
| 1 | 用 tbody 的**下标算层级** | DOM 里三层是交错的，而**空的尺码子表不一定渲染 tbody** → 「每 3 个一循环」会错位，用例只看得到第一行的颜色就假绿。解法：页面上给两层子表各挂 class（`layer-colors` / `layer-sizes`），测试按 class 取 |
| 2 | 挂载**之后**再改 mock 去构造错误态 | 页面在挂载时就拉完了，错误提示不会出现，用例只能靠别的断言侥幸通过 —— 绿灯但什么都没测到 |
