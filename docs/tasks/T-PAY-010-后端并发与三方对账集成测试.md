## 目标

把 `05 §7` 的 P1~P8 与 §5.7 的三方对账落成**真并发 + 真提交**集成测试，
证明唯一约束、条件 UPDATE、`payroll_id` 占用这些兜底真的有效。

## 范围

**要做**：
- [ ] 并发：P1 同周期重复结算（20 并发）、P2 审核/反审核竞争、P3 两单抢同流水、
      P4 发放/反审核竞争、P5 同区间并发建周期、P6 审核 vs 周期关闭、P7 关/重开竞争
- [ ] 对账（`05 §5.7`）：流水/结算行/工资行/单头/代发文件五层数量金额一致；周期内未结算流水 = 0
- [ ] 反审核回归 TC-13：全部反审核后差异列表为空
- [ ] TC-35 整件口径：`qty=0.4` 被 DB CHECK 拒；结算 `total_qty` 不含尾数
- [ ] 每用例自带精确清理（`purge_side_effects` 按 `doc_id`/前缀，避免 `docs/10 §5.4` 的脏数据复发）

**不做**：
- 不测凭证层（M9 未建，Q-PL09）
- 不改 `app/**`（发现缺陷另开修复卡）

## 实现要点

- [ ] 真并发：`asyncio.gather` + 每任务独立 session（`10 §5.4`）；`NullPool`（**T-BUND-008 的教训**：QueuePool 会把连接留在池里，`dispose()` 之后才开的 session 的 socket 没人关；见 L-094 / L-099）
- [ ] 必须断言**数据库兜底生效**（唯一索引 / 条件 UPDATE），只靠业务层检查判为未通过
- [ ] 对账用 SQLAlchemy Core 原生 SQL（`01 §5.3`）
- [ ] 删除 `FOR UPDATE` 等兜底后用例应变红（反验锁的有效性）

## 验收标准

- [ ] `pytest tests/modules/test_payroll_concurrency.py tests/modules/test_payroll_reconciliation.py -q` 全过
- [ ] 每条并发用例能反证：删掉兜底 → 断言红
- [ ] 闸门 3 全量通过，无脏数据残留
