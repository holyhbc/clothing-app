## 二、部署到已有 Nginx

### 1. 上传产物

```bash
# 在本机
cd /root/opencode/prototype && npm run build
scp -r dist/* root@<VPS>:/var/www/garment-erp-prototype/
```

### 2. Nginx 站点配置

你已有 nginx，直接加一个 server 段即可（**不要动现有站点**）：

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name prototype.example.com;   # 改成你的域名或 IP

    root /var/www/garment-erp-prototype;
    index index.html;

    # 单页应用：所有路径回落到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 带 hash 的静态资源缓存
    location /assets/ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 原型不需要 HTTPS；如果要走 HTTPS，取消下面注释并申请证书
    # location /.well-known/acme-challenge/ { root /var/www/certbot; }
    # return 301 https://$host$request_uri;
}

# 启用 HTTPS 时：
# server {
#     listen 443 ssl http2;
#     server_name prototype.example.com;
#     root /var/www/garment-erp-prototype;
#     index index.html;
#     ssl_certificate     /etc/letsencrypt/live/prototype.example.com/fullchain.pem;
#     ssl_certificate_key /etc/letsencrypt/live/prototype.example.com/privkey.pem;
#     location / { try_files $uri $uri/ /index.html; }
#     location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }
# }
```

```bash
nginx -t && systemctl reload nginx
```

访问 `http://<域名或IP>/` 即可。

> **必须保留** `try_files $uri $uri/ /index.html;` —— 本原型用 hash 路由，少了这行在某些 nginx 版本下会 404。

## 六、这份原型**不是**什么

- ❌ 不是可交付界面：交互是模拟的，数据不落库
- ❌ 没有 Ant Design Vue / Vant 组件：为了保证单文件可跑，用**手写 token 还原视觉**，保证脱离网络也能看
- ❌ 扫码是真扫：工位机页用 `window.addEventListener('keydown')` 真实模拟 HID 扫码枪，但"识别一个有效码"是本地 mock
- ❌ 二维码是示意图：`QrBox` 是按 `bundle_no` 生成的伪点阵占位，**不可真扫**；真实实现见 ADR-0004
- ❌ 打印是浏览器打印预览，未做 `@page` 40mm 实测

正式开发时，`docs/06` §2 的 Ant Design Vue 组件会替换掉手写样式，但**design token、布局结构、交互规则不变**。

## 七、业务决策已落地（2026-10-01 第四轮）

| 议题 | 决策 | ADR |
| --- | --- | --- |
| **打菲单位** | **按手**，不是按件。比例 1:2:2:1 → 6 手；加一个 → 7 手 | [0016](./docs/adr/0016-打菲按手与扫码得件数.md) |
| **一码 = 一手 = 一个员工** | `bundle_no` = `BD-单号-{尺码码}{手序号2位}-{件序号4位}`，如 `BD-20261018-000031-XL02-0001`。XL 打 2 手 = XL01/XL02 两个码，**两人各认一手，追溯清楚** | 同上 |
| **扫码就知道这手数量** | 数量存 `bundles.bundle_qty`，**不写进二维码**（改数不用重打） | 同上 |
| **部分生产** | 扫一下**默认整手件数**；可手写更小的数量；**超过该手件数拒绝（32006）**，超产必须追加手 | 同上 |
| **一床多颜色** | 裁剪**行 = 布批（缸号+匹号）**，行内可裁多个颜色；**耗料记行（布的属性）**、**出数记尺码明细（颜色的属性）** | [0017](./docs/adr/0017-裁剪按布批与行内多颜色.md) |

**核心链路现在完整**：
```
采购单（缸号/门幅/重量/运费） → 分批到货入库 → 裁剪（按布批 + 一床多色 + 三种录入模式）
  → 打菲（一手一码 + 手序号） → 扫码计件（默认整手，可部分生产） → 工资结算（周期区间）
  → 完工入库 → 销售出库 → 应收 → 凭证
```

| **改单联动** | 已计件的手**冻结**；唯一合法路径 = 红冲反计件 → 反审核 → 改 → 重审 → 重打菲 | [0021](./docs/adr/0021-裁剪改单与打菲联动.md) |
| **采购台账** | 按供应商看清账；库存带供应商维度；裁剪选料级联到缸号/匹号并扣减 | [0022](./docs/adr/0022-采购台账与库存供应商维度.md) |
| **页面重排** | 生产 5 页 → **裁剪单（矩阵）+ 打菲（按手）+ 生产追踪**；全链路溯源链 | [0023](./docs/adr/0023-生产单据页面重排与溯源链.md) |

**核心链路（第五轮）**：

## 十一、需要你确认的 UI 问题

1. **密度**：现在表格行高 11px 内边距、中文字号 13px，工厂长时间看是否够大？要不要加"大字模式"开关？
2. **侧边栏分组**：现在是「总览 / 生产 / 基础资料 / 仓储 / 经营 / 财务 / 系统」，组长和主管看到的是同一套菜单（靠权限隐藏），是否符合实际？
